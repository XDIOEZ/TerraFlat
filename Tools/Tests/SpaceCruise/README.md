# 太空巡航离线回归

在仓库根目录运行：

```powershell
dotnet run --project Tools/Tests/SpaceCruise/SpaceCruise.Tests.csproj -c Release
```

需要 .NET 8 SDK，直接编译项目中的巡航引导、对接、拓扑缓存、光纤、船体质量汇总与引擎安装规则生产代码，不启动、暂停或刷新 Unity。

覆盖速度上限、反向刹车、部分燃料推进、不同固定步长和初速度的到点停车、最短转向、星体中心航点及穿过星体的航线、实时质量与动量、对接断开与接口损坏、碎片接口重新归属、光纤断开修复，以及稳定拓扑和光纤工作区的热路径分配。

喷嘴分配回归直接编译 `ShipThrustAllocation`：覆盖四向与斜向按反向喷口推进、船体和对接成员旋转、按推力需求而非已有速度选择制动喷嘴、单轴缺油、部分供油、同向引擎容量加权与不倍增加速度、Q/E 力矩方向、纯转向不附加平移，以及松键和工作区复用。燃料出力作为领域输入给定，不代表已在 Unity 验证机器供油或喷焰效果。

惯性与降落领域回归覆盖十秒松键滑行、横向推力保留已有漂移、反向渐进制动、无动力保留碰撞超速、部分动力比例、包含船半径的降落范围、星体画面内起步/经过/穿越而不截停、实际降落姿态，以及独立乘员的星体接触入口。直接编译生产 `ShipLandingGuidance` 和 `UniverseSimulation`，不代表已操作控制台按钮或验证场景迁移。

质量回归覆盖旋转矩形部件、货物、乘员和舱气的质量、重心、惯量；载荷变化后保持船体物理坐标与点速度；重复来源只计重一次、非法质量或身份拒绝、零质量以及工作区跨船复用。预热后还检查无舱室时 165 部件、16 项载荷连续汇总的线程分配量。

直接编译生产载荷池，检查来源前缀、物品身份和共享罐所有者变化；复用时清理支撑、类别、坐标、重量和惯量；载荷变少或清空后不留旧重量；不同船的池不共享样本；稳定来源预热后 10000 轮复用没有线程分配。

引擎回归直接调用 `ShipEnginePlacement`：检查四个外缘的喷口朝向、船内安装、严格一格占地、负坐标、旋转矩形地板与设备、凹形船体、跨过空格后的阻挡、缺口另一边的地板、失去支撑和销毁状态；后续安装地板或设备不能堵住现有喷口，正式 Wire/Pipe/Fiber 类型不算阻挡。静态读取 GM 船模板、四份相关物品 JSON 与机械目录，展开重复成员并读取继承后的占地和层级，确认六台引擎有效、结构层无重叠、边缘引擎封住舱壁开口。此项没有启动固定结构生成事务、机器运行或 Unity 场景。

末尾输出相同船体输入下重复重建与缓存刷新各 1000 次的耗时、线程分配量，并输出 165 部件、16 项载荷的领域质量汇总 10000 次基准。耗时会受机器负载和运行时预热影响；该结果仅针对这些算法，不是游戏帧率或整个太空系统的内存占用，也不包含质量读取中的 JSON、二进制快照或嵌套库存还原。

`TestDoubles.cs` 只替代非测试目标的 Unity 资源入口和舱气质量输入；控制台检查与船体质量汇总使用生产代码。测试直接给定舱气重量，不测试气体组分密度计算；气密拓扑、舱气释放与分裂入口会拒绝调用，避免误以为已经覆盖。未模拟完整机器供能、燃料库存、场景迁移或 Unity 物理。起飞、降落、导航交互、语言切换与船体碰撞仍需真实场景检查。

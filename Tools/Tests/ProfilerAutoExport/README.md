# 性能 JSON 自动导出回归

在仓库根目录运行：

```powershell
dotnet run --project Tools/Tests/ProfilerAutoExport/ProfilerAutoExport.Tests.csproj -c Release
```

直接编译生产 `ProfilerAutoExporter.cs` 和 PuerTS `UnityMcpProfilerSnapshot.cs`，用替身提供 Unity 事件、Profiler 帧与时间戳、附件和数据源，不启动、暂停或刷新用户的 Unity。覆盖阈值、旧帧过滤、启动与恢复缓冲、暂停先于导出、窗口内最慢帧及附加 JSON、全部文件写完后自动继续、导出卡顿不进入下轮、录制恢复、无效帧、目标变化、用户操作与异常清理。

快照回归实际写入并解析生产导出的 schema 5 JSON：摘要默认60邻帧、独立筛选范围默认300邻帧、额外详情默认3帧，均不含目标帧，无50ms门槛。覆盖摘要外的慢帧、范围与数量分别配置、同耗时排序、两侧不足不补齐、奇数分配、无效帧、关闭摘要/详情、极大数量裁剪、只发布指定摘要和详情、附件发布及播放/暂停/录制保持。设置窗口对摘要>300、筛选>1000或详情>10显示黄色警告，仍允许该设置。

「持续时间（秒）」默认 5 秒，独立于启动/继续缓冲。缓冲结束后先观察满整个窗口，再滚动统计最近这段时间：低于 FPS 阈值的累计耗时至少占 80% 才触发，5 秒对应累计至少 4 秒，无需连续。按 CPU 帧时间区间计算，裁掉窗口外的部分，空档不算低帧率，不重复累计重叠区间；不是慢帧数量占比。专项覆盖恰好 80%、不足 80%、短暂掉帧、间断累计、过期与部分帧裁剪、长帧、数据缺失以及设置修改后的重新累计。

`auto-trigger.json` schema 3 记录持续时间、观察秒数、低帧率累计秒数、实际/要求比例及 Profiler 时间轴窗口边界。`selectedDisplayFrame/frameTimeMs/measuredFps/selectedFrameStartProfilerTimeMs` 对应窗口内仍在缓存的最慢帧，`triggerDisplayFrame/triggerFrameTimeMs` 对应累计达标帧；最高耗时相同时选择较早帧。延迟导出前核对选中帧耗时和起始时间戳，避免取证期间替换旧帧。世界、日志和截图仍属于暂停导出现场，不回放历史游戏状态。

成功发布完整报告后才恢复本次自动暂停，再从新帧开始启动/继续缓冲；导出失败则保持暂停、关闭自动模式。导出期间用户改设置、关闭自动模式、手动控制暂停或退出 PlayMode 时，不覆盖其播放状态。本工具属于 Editor 自动化，`systems.catalog.json` 没有对应玩法 Lua 系统，回归使用本离线控制器测试。

这些检查不代替真实 Unity 的编译、顶栏布局、暂停回调时序和完整报告导出验收。编辑器空闲时验证：打开 `FlatWorld/性能分析/自动导出设置`，进入测试 PlayMode，设置足够高的 FPS 阈值，等待启动缓冲和完整持续时间；确认达标后先暂停，报告含 `auto-trigger.json` 与原有性能/日志/世界/截图，选中帧是窗口内仍保留的最高耗时帧；完整报告写出后自动继续，重新经过缓冲和观察窗口可再次触发。测试后关闭自动模式并恢复设置。

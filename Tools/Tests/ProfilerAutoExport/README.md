# 性能 JSON 自动导出回归

在仓库根目录运行：

```powershell
dotnet run --project Tools/Tests/ProfilerAutoExport/ProfilerAutoExport.Tests.csproj -c Release
```

直接编译生产 `ProfilerAutoExporter.cs`，用替身提供 Unity 事件、Profiler 新帧及其时间戳和导出接口，不启动、暂停或刷新用户的 Unity。覆盖阈值、旧帧过滤、启动与恢复缓冲、暂停先于导出、触发帧及附加 JSON、同次暂停不重复导出、录制恢复、无效帧、目标变化、取消与异常清理。

「持续时间（秒）」默认 5 秒，独立于启动/继续缓冲。缓冲结束后先观察满整个窗口，再滚动统计最近这段时间：低于 FPS 阈值的累计耗时至少占 80% 才触发，5 秒对应累计至少 4 秒，无需连续。按 CPU 帧时间区间计算，裁掉窗口外的部分，空档不算低帧率，不重复累计重叠区间；不是慢帧数量占比。专项覆盖恰好 80%、不足 80%、短暂掉帧、间断累计、过期与部分帧裁剪、长帧、数据缺失以及设置修改后的重新累计。

`auto-trigger.json` schema 2 记录持续时间、观察秒数、低帧率累计秒数、实际/要求比例及 Profiler 时间轴窗口边界。导出的是窗口达标时的触发帧，当前帧可能已经恢复正常；判断原因见窗口累计值。延迟导出前同时核对帧耗时与时间戳，避免取证到被替换的帧。

这些检查不代替真实 Unity 的编译、顶栏布局、暂停回调时序和完整报告导出验收。编辑器空闲时验证：打开 `FlatWorld/性能分析/自动导出设置`，进入测试 PlayMode，设置足够高的 FPS 阈值，等待启动缓冲和完整持续时间；确认观察进度与低帧率累计达到条件后先进入暂停，报告含 `auto-trigger.json` 与原有性能/日志/世界/截图，手动继续后重新经过缓冲和观察窗口可再次触发。测试后关闭自动模式并恢复设置。

## Lua 接口与职责

```lua
test.space("catalog", function(data)
    assert(#data.sectors > 0, "没有配置星区")
    -- 这里遍历实际数据并编写业务断言。
    return "已检查全部配置星区"
end, "宇宙目录")

test.space("sector_transition", function(data)
    assert(data.crossed.spaceView, "没有进入太空")
end, "向右跨区", "right")
```

C# 仅提供白名单操作、准备独立夹具、采样正式状态并等待实际流程；业务断言保留在 Lua。数据转换使用 Lua 原生表，不开放 `CS`、`require` 或任意代码执行。每次 Lua 编排或断言回调有 100 万条指令预算。星区 `long` 编号返回字符串，位置/速度返回 double，不经过 float；Lua 不能把巨大星区编号转成普通浮点再比较。

截图由 PlayMode 宿主定时采集而非 Lua 编排，短用例或失败用例结束时补拍；游戏画面不可用会留下取图错误并导致用例失败。定时图不保证恰好覆盖某个瞬时太空阶段，业务判断必须继续使用 Lua 断言。

每个操作的原始实际采样保存在用例 JSON 的 `steps` 中，命令为 `space_sample`，即使后面的 Lua 断言失败也会保留，可据此查看输入、轨道位置、速度、燃料或星区租约。

通用等待/移动仍受原来的单步 30 秒、累计 180 秒限制。`test.space` 的真实迁移操作使用各自的有界等待；物理采样按正式会话的 `SimulationSeconds` 等待并保留真实时间超时，编辑器卡顿不能算作已推进物理。整轮仍受测试场景的总超时限制；未来大量增加船型或星区后，应同步调整场景总时间上限。

领域用例使用独立对象，不推进当前宇宙；真实会话用例会准备管理员无敌条件，并在结束或异常后恢复原无敌状态、释放租约和夹具。跨场景后的玩家从正式 ItemMgr 重新取得，不能继续使用迁移前的引用。

## 测试夹具与覆盖边界

`live_session` 的镜头夹具不接管玩家实际相机，只创建禁用输出的独立组件，读取正式跟随接口作用后的 FramingTransposer 与 Brain 状态；Lua 检查锁定时阻尼/前探/预测平滑为零、统一 LateUpdate，重复申请与缩放/玩家偏好变更保持锁定，切回普通模式或释放后恢复最新玩家偏好与原 Brain 更新方式。偏好通过正式 setter 临时变更，并在同步 `finally` 恢复原值及原键存在状态，不跨帧保留修改；这些设置契约不证明高速航行的画面平滑度。本轮未执行这些断言，实际高速航行效果由用户验收。

`live_session` 还同步创建独立乘员位姿夹具，调用正式 `ShipSurfacePresentation.SetPassengerPose/ClearPassenger`；Lua 检查根节点、刚体和手持物共同升高，重复同步不累加，地面基准稳定，离地取消实体阻挡、落地/重复释放/禁用恢复，已有 Trigger 与独立子刚体保持原态，以及新增碰撞体的接管和恢复。夹具不推进物理场景，不代表树木接触、完整起降、单独下落或双客户端验收；本次仅补充断言，按用户要求未执行。

`ship_ground_combat_projection` 在实际地表隔离世界模拟船外玩家自由移动后乘员坐标仍是旧值、世界键缺失的场景，检查武器投影与当前攻击位置一致；它不替代真实挥砍碰撞验收。`ship_damage_live` 用正式 `AddPiece/CommitPiece` 和模板资源初始化入口创建自有长船，在空星区对指定部位施加已经结算的伤害，并等待 `SimulationSeconds` 实际推进触发正式分裂事务。自有夹具关闭温压的被动结构伤害，避免将极冷空域环境伤害混入部位血量保持断言。它同时读取每个整体的表现刚体/合并碰撞器、原生模拟刚体/两类合并形状、唯一飞行记录，以及 `ShipWreckView` 单 Item 外壳、冷设备无运行节点、培育器真实库存和正式会话捕获快照。尾部保留原船身份，故意检查转冷不能清掉新船首的点火与迁移导航。这是分裂事务现场，不代替武器投射物命中、防御投送、完整供电供油逃跑或多人战斗验收。

培育器基线先等待正常播种，再通过正式机器捕获接口读取当前种子、肥料和已播种槽位；不把放置时的旧快照当成分裂前库存。首次转为冷残骸后另施加 3 点非致命部位伤害，断言部位血量、冷机器核心 HP、后续碎块及正式保存快照一致，库存与已播种槽位保持不变。GUID 为 32 位整数，Lua 用数值等值校验，避免浮点 `tostring` 的 `.0` 格式造成伪失败。

真实伤害用例继续摧毁培育器下面的地板，等待正式固定步把失去支撑的设备移交为单部件、无地板的冷残骸；再依次摧毁另一小块的两块地板，检查最后地板消失后该整体、飞行记录、实际残骸 Item 和原生模拟刚体全部清理。尾部预先受伤的保存基准选最终仍存活的第九格锚点地板，另一个被主动摧毁的小块按死亡拒绝查询检查。每阶段核对真实 `FindPiece` 所属船和对象身份、唯一外壳 GUID 与实际 Item GUID；最终检查五块死亡地板均无法查询，八个存活部件及冷库存/血量/外壳身份被正式快照保留。定时截图不保证覆盖船首与残骸中间阶段；业务仍以 Lua 断言为准，不代表武器、供电供油或多人验收。

`live_flight` 的松键惯性环节把本用例刚生成的船体预置到空星区，保留实际推进后的速度，再等待至少半秒正式模拟，检查速度、位移、引擎停推和燃料不再消耗；之后恢复起飞星区继续转向、导航和降落。星体引力范围内存在正式引力与大气阻力，不能直接用速度不变断言惯性。船体跨区环节只把自有船体预置到空星区边缘并设置起始速度，之后由正式固定步完成跨区和场景过渡。它检查跨区机制，不把夹具预置计作从星球一直导航至边界的完整航程。`live_collision` 使用正式地板物品生成自有船体，提高这些夹具的耐久以隔离冲量规则；不把这一环节当作正常材料耐久/战斗毁船验收。

每个真实迁移操作完成采样与 Lua 断言后，在下一条玩法命令之前或脚本结束时恢复起始测试世界并清理；定时截图不阻挡这一流程。清理复用中立乘员迁移事务，不把清理传送记作降落成功。`live_flight` 的降落断言来自真实 RequestLanding 流程，定时图片不能替代起飞/巡航的过程断言。

`ship_landing` 没有预置太空船位姿，GM 建筑经过正式点火和起飞后直接调用 `RequestLanding`，等待当前地表的真实下降表现，再等待所有原 Guid 建筑接回普通地面。加油站在真实落地后邻接搭建：只给独立源气罐初始化氢氧，普通管道和定向 `FluidOutlet` 按正式世界固定步送入原 Guid 燃料罐。裸管不会仅因压差自行输送；断言读取目标增量、源减量及包含中间管段的总 mol。尚未覆盖预建站旁的精确驾驶落点、失败装配回滚、断电缺油救船、海上落船或多人客户端。截图展示最终落地和接管现场，不替代各阶段数据断言。

`ship_damage_gameplay.lua` 在残骸场景操作后显式检查恢复后的 `world_ready` 和 `player_ready`。下一条玩法命令先恢复起始隔离地表，宿主从 ItemMgr 重新绑定同档案玩家；两个检查证明后续 Lua 仍能沿用就绪的世界和当前玩家，避免迁移前的旧玩家引用导致后续生命周期、区块或存档案例被跳过。

本模块覆盖上表已实现的单机内容与行为入口，不宣称代码行或所有组合路径达到 100%。以下仍需专项或人工验收：多人网络与两端画面、GPU 星体外观/星空/浮动原点视觉、完整 UI 点击与相机手感、性能与设备表现、磁盘退出重载、活跃冷地表差量、断电缺油救船/海上落船/重生/战斗毁船和散落物回收的完整场景链。领域断言或一张截图不能替代这些验收。

# 加工状态纯规则回归

- `fuel_absorption` 调用正式 `FuelAbsorptionState` 与真实库存扣料事务，覆盖三秒长满才消费一份、同来源保持进度、提前取回/换实例清零、提交时再次核验身份、重复提交拒绝、非法时间及状态序列化。此项新增后尚未执行；不覆盖点火/燃料耗尽的炉体时间线、真实面板遮罩、联机或跨世界调度。

2026-10-15：本系统登记的快速规则和 PlayMode 入口均已执行通过，见 [缓存与全系统 DEBUG](../../缓存与38系统DEBUG循环_2026-10-15.md)。以下功能缺口继续有效，玩法验收由用户进行。

- 使用自有库存与 `RecipeProcessor.SelectRecipe`，检查同配方进度保持、切换/清除、非法工时；使用 `SlotProcessingState.Observe` 检查来源变化清计时/待产物、未变来源保留已抽定产量。
- `atomic_output` 通过加工器公开扩展回调接入生产 `CraftingTransaction.CanCreate/TryCreate/Commit`，在独立库存内真正扣原料/放两个产物；检查满输出保留工时、不部分产出、清空间后的恢复和再次满输出暂停。复用实体探针的独立物品构造，不注册全局物品目录。
- 扩展回调只负责连接正式事务，不重算库存算法；本样本显式提供配方匹配结果，因此未覆盖目录配方选择和材料匹配。炉体温度与燃料结算、烘干/堆肥实际产出和场景机器调度仍未覆盖。
- `material_heat` 采样炉内材料复用的正式 `ItemMatterRuntime.Advance` 入口，检查每游戏秒补上实际炉温与材料温差的 1%、连续升温逐渐变慢、不同炉温、小温差、升降温、相同总时长分步一致、零/负时长、长时间不越界及材料数量不变。本项为 2026-10-17 新增，尚未执行；不覆盖 `FurnaceLogic` 现场调度、燃料和实际熔炼产出。
- 生产状态属于加工组，背包/配方通用事务应在其对应系统组和集成专项覆盖。无截图。
- `cold_fuel_candidates` 使用正式后台炉体筛选/排序入口，在 826 份远处记录之外检查本格距离顺序、飞行与拾取资格、重复身份、记录删除/移位/档案替换和独立环绕；`cold_fuel_transfer` 通过正式燃料转移函数检查真实库存接纳量、满槽拒绝、分堆身份与数量守恒。它们不覆盖真实世界切换、燃料资格配置或实际炉火燃烧。
- `cold_motion_workspace` 调用正式冷物运动推进，检查分次轨迹、跨世界同身份隔离、着地拾取、浮起/沉没结束、重复身份异常后的清理，以及预热后 32 步不再创建模拟器工作数据。此项为 2026-10-17 新增，尚未执行；不覆盖真实地表水流、区块差量更新、切回地球后的表现或 Unity 帧率。

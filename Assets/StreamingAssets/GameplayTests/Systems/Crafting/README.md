# 制作加工测试

- `rules.lua`：直接调用 `CraftingMaterialAllocator.TryAllocate`。覆盖 Exact/Tag 重叠的全局可行扣料计划、改变声明顺序、总量跨堆叠、缺料拒绝、零消耗工具必须存在、不直接扣除预检库存。
- 同脚本调用 `CraftingTransaction.TryCreate/Commit/Complete/Rollback`，覆盖真实输入输出快照、满包多产物不扣料/不部分产出、材料不足、一次提交、回滚及结构变化拒绝过期计划。
- 夹具：独立内存槽位与配方材料，调用真实容量流分配器，不加载生产配方目录、不修改玩家库存。
- `gameplay-suite.json` / `gameplay.lua`：使用正式隔离玩家的已加载 `Mod_HandCraftTable`，打开真实手工制作面板，在真实输入库存放入三份 `Twine`，调用面板合成按钮的现有监听。Lua 检查完成前不扣料/不产出，最后一次点击才扣除三份材料并产生正式配方的绳子；产量按当前难度正式倍率读取。
- 下一子检查清除自有产物、填满全部真实输出槽，再放三份藤蔓，重复按钮流程；Lua 检查材料、阻塞物和绳子数量，满槽不得扣料、覆盖原物品或产生部分产物。显式截图保留这次拒绝后的正式面板。
- 夹具要求玩家手工输入/输出原本为空，拒绝覆盖其他案例的物品。自有材料经真实库存事务放入/清理，Lua 收尾恢复面板打开状态及快捷转移目标，失败与中断也逆序清理。
- 只准备三份藤蔓，保证正式目录里只有制绳候选；这是合成按钮与生产配方/服务/事务的链路，没有调用私有方法或复制扣料逻辑。
- 缺口：多个候选的用户选择、鼠标/触控点击落点、世界工作台、品质/防腐产物继承和整场保存重进；机器加工关键流程另见机械动力测试。

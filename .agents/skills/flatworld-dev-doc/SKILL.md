# FlatWorld 开发文档

开发规划文档优先参考：

`开发文档文件夹/待实现功能文件夹/机械动力系统规划.md`

只参考它的**结构、颗粒度和表达方式**，不要复制机械系统的具体内容。

## 推荐结构

1. 先写 `## 1. 系统定位`：用几句话说明用途、范围和当前暂未确定的内容。
2. 后续按真实业务模块编号分章，例如动力源、传动、用力器，而不是堆“背景 / 分析 / 方案”式长文。
3. 单个复杂机制用 `###` / `####` 继续拆分；先一句话说明作用，再用短条目写规则。
4. 临时方案明确标注“当前 / 首轮 / 临时”，不要和最终设计混在一起。
5. 复杂连接、流程或层级关系优先使用简短文本图或代码块表达。
6. 首批实现内容适合用 `- [ ]` 清单集中列出。
7. 文档末尾保留“后续待规划”，只列尚未决定的问题，不提前编造答案。

## 写作要求

- 使用简单直接的中文，一条规则只表达一个重点。
- 重点记录**设计结论、约束、边界和禁止行为**，少写过程性讨论。
- 能确定的内容写明确；不能确定的参数、数值和实现细节直接留待规划。
- 涉及数据、表现、交互、存档、跨系统关系时，必要时分小节写清，不把它们混成一大段。
- 修改已有文档时优先补到对应章节，保持原有编号和风格，不追加聊天记录式流水账。
- 不为了“看起来完整”强行增加无实际内容的章节。

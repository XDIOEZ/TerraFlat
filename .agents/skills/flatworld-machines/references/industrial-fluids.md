# 工业气液 V1

- 气、液按类型独立连接。管、阀、过滤管、出口没有库存或免费容量；`FluidNetworkGraph` 只保正式端口有向边及按腔体缓存的液网连通成员。不能搜索绕过方向、关闭阀门、过滤或端口指定组分。
- 每台储罐、泵或消费者工作腔独立保存物质，普通罐不互相自动搬料。气量用标准 L，液量用 L；只算物质、数量、容量、每秒速率，不结算工业压差、压缩功、换热、蒸发冷凝或超压爆炸。
- `IndustrialFluidTransfer` 是共用原子数量转移。普通气体按真实混合比例，过滤只取指定组分原有份额，剩余留来源。单液冲突拒绝，不转换或丢料；整液网异种检查按 `(节点, 腔体)`，不误并独立副产物腔。
- `CollectFluidSupplyRoutes` 逆向取源，`CollectFluidDeliveryRoutes` 正向找接收设备；`GetFluidRouteFilter` 统一读取路径筛选与端口限制。`GetFluidRouteCharge` 将筛选后净量还原为输入混气流量，所有共享路径预算按该流量扣，防多目标放大过滤能力。
- 每步先释放上一轮运行预约、冻结全部真实来源及节点流量，再给引擎预约。空管只保轻量节点预算，不复制库存快照。引擎在动力分配前预约真实原料，实际负载结算才消耗；无负载不扣料。氢发动机必须有真实氢、氧。
- 气泵有动力、真实环境气源和接收容量才抽取；一次取得真实混气，未接收组分归还来源。水泵通过正式地表接口取整份，可保最多一份本机余量，再按本轮管路预算送出；余量由泵自己的快照保存。
- `NaturalFillFraction` 默认 .2，只限制自然补气目标，不排已有超量。动力泵可达到 `GasCapacityStandardLiters`。铁/钢便携罐沿同一固定容量规则，不因充满运行旧超压逻辑。
- 气/液装填设备各有三个真实容器槽，按0→1→2装，满槽或不适合槽可跳过；实际物品和权威库存走原有库存命令。液体通过 `ILiquidTransferPort` 装实际液体容器。
- 出口 `OutputLitersPerSecond` 支持0关闭，负初值使用定义默认速率。气体按组分比例排入所属环境；液体按 `(出口,物质)` 累积不足一份的额度，单步可排多整份，通过正式地表接口接收；拒绝保留来源，部分接收退回余量。
- `PullFromNetwork` 用于既有供气器/培育器等消费者，从可达来源补充自己的工作腔；普通储罐不启用。外部船舱、呼吸、天气仍复用共用物质定义和热力学，工业不再调用那些求解器。
- 保存、联机、拆回都只带各设备本地库存；快照排除 `engine:` 运行预约。迁移先撤运行预约再整批交接，失败恢复本地库存。销毁逐成功批次交给环境或持久液体溢流，失败保留未完成部分，不走化学爆炸队列。
- 固定结构工业模板用 `gas.standardLiters` 与固定容量校验；`CabinGas` 继续原有气压初始化。线协议随序列化结构变化升版，不做旧存档兼容。
- 离线生产回归：`dotnet run --project Tools/Tests/IndustrialGasNetworks/IndustrialGasNetworks.Tests.csproj --configuration Release`。正式Lua按 IndustrialFluids 清单执行；离线不等于Unity玩法或真实双端验收。用户PlayMode时不刷新、暂停、退出或切场景。

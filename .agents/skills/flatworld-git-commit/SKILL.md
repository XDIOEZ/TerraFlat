# FlatWorld Git 提交

## 适用时机

- 默认只修改并保留工作区，不自动暂存、创建提交或推送；完成一个功能、跨文件修复或达到复杂度边界，都不等于获得提交授权。
- 只有用户在当前任务明确要求“提交”“创建 commit”或“提交并推送”时，才进入提交流程；不得沿用其他任务或此前对话的提交授权。
- 用户只要求修复 Bug、修改功能、整理提交历史或解决重复记录时，不得顺便把工作区已有改动提交进去。
- 当前任务明确要求“不要提交”时停止；明确要求立即提交时，可跳过复杂度判断，但仍必须通过范围和安全检查。
- 获得授权后，以一个完整功能、系统切片或修复作为提交边界，不要在每个小编辑后提交。
- 本 Skill 的常规流程只负责已授权的本地 `git commit`；push 必须另有明确授权，不自动合并、rebase、reset、clean 或修改历史。

## 提交边界

只有同时满足“本次任务已获得提交授权”“本次任务已完成”和“改动可以安全隔离”时才提交。以下条件只用于划分提交边界，不得作为自动提交的触发器：

- 一个完整的用户可见功能或系统切片已经闭环，且包含运行时代码与其必要的配置、Prefab、资源、编辑器接线或数据定义。
- 改动跨越两个以上逻辑层，或涉及公共接口、存档/序列化结构、网络协议、输入契约、核心生命周期等高影响边界。
- 一个跨文件的完整 Bug 修复已经形成稳定的可回滚点；即使只有一个文件，只要它改变了权威配置、公共契约或独立运行时行为，也可以提交。

以下情况通常不提交，保留改动等待同一系统的后续工作：文档或格式整理、单个低风险文案/数值调整、临时调试代码、未完成的 WIP、仅生成文件变化，或无法确认属于本次任务的改动。

## 范围保护

1. 先查看 `git status --short`、`git diff --stat` 和相关路径差异；若任务开始前已有工作区改动，将其视为受保护内容。
2. 只根据本次对话实际修改的文件建立提交清单，禁止使用 `git add -A`、`git add .` 或 `git commit -am` 扩大范围。
3. 对每个候选文件检查差异；一个文件同时混有旧改动和本次改动时，不要提交该文件，除非能安全拆分，否则暂停并说明需要用户处理。
4. Unity 新增或改名的资源应连同对应 `.meta` 一起检查；不要提交 `Library/`、`Temp/`、`Logs/`、`UserSettings/`、密钥、临时目录或其他生成物。

## 防止重复提交与重复历史

- 同名提交不一定重复，不同哈希也不代表不同改动；排查时核对父子关系、文件树、补丁与时间，禁止只按提交标题批量删除。
- 拉取前检查分支与 upstream 的关系。常规拉取只允许快进；本仓库的 `pull.ff=only` 是默认保护，不得用显式 `--ff` 或直接 merge 绕过。发现远端强制更新、历史改写或大量同内容不同哈希的提交时，停止自动整合，先定位对应历史。
- 不把历史改写前的旧分支、旧工作树直接合回已改写的主分支；不要对已整合的改动再次 cherry-pick 或重建提交。需要迁移旧工作树时，先确认哪些改动确实尚未整合。
- 用户明确要求修复历史时，先保留旧 tip 的本地备份引用，再核对候选历史。仅修复重复祖先关系的任务必须保留每个有效提交的文件快照、作者、时间和说明，并验证工作区文件、未跟踪文件、暂存区及最终文件树未变化。
- 历史修复不得顺便打包未提交文件、清理其他工作树或推送远端；切换分支引用时使用带预期旧值的原子更新，检测到并发变化立即停止。

## 提交流程

取得本次任务的明确授权并达到提交边界后，按以下顺序操作：

```powershell
git status --short
git diff -- <本次任务文件>
git add -- <本次任务文件>
git diff --cached --check
git diff --cached --stat
git diff --cached -- <本次任务文件>
git commit -m "<type>: <简短说明>"
git status --short
```

- 提交信息优先使用 `feat:`、`fix:`、`refactor:`、`data:` 或 `chore:`，说明具体系统和结果；不要使用无信息的“提交”“修改”等描述。
- 提交前必须确认暂存区只包含本次任务；发现范围不明、冲突、钩子失败或身份配置问题时停止，不使用 `--no-verify`，也不擅自修复无关问题。
- 不自动运行游戏测试、构建或重型验证；沿用当前任务已完成的静态检查和 Unity Console 检查结果。提交后向用户报告提交短哈希、提交说明，以及仍保留的未提交文件（如有）。

## 未获授权或未达到边界时

不创建提交、不暂存文件，保留工作区并报告本次实际修改。未获提交授权时，不把已经完成的工作描述为未完成；后续只有用户明确要求提交时，才重新核对当时的任务范围和工作区状态。

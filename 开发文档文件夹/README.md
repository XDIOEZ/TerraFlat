# FlatWorld 开发文档导航

开发文档按**游戏系统**分类，不再使用“待实现 / 已完成 / AI策划”作为一级目录。

同一系统的规划、待办、重构记录和已完成设计放在同一个系统目录中；状态通过文件名和文档正文表达。只有已经失去当前维护价值、内容跨系统且不值得再拆分的旧记录放进 `99_历史归档`。

## 目录结构

| 目录 | 负责内容 |
| --- | --- |
| `00_项目总览与路线` | 项目核心说明、跨系统路线、阶段规划、全局重构清单 |
| `01_世界生成与环境` | 地形、世界生成、气候、水文、液体、光照、雪地等世界环境系统 |
| `02_实体AI与ECS` | AI、AIECS、实体运行时、ECS 架构与 GameObject 桥接 |
| `03_生存制作与农业` | 食物、制作、容器、种植、农业、钓鱼等生存生产玩法 |
| `04_战斗工具与成长` | 伤害、防御、工具、武器、资源硬度与成长数值 |
| `05_工业机械与能源` | 机械动力、机器世界、电力、工业生产链与相关素材规范 |
| `06_交通建筑与交互` | 运输、矿车、轨道、建筑及世界交互类设计 |
| `07_网络存档与底层架构` | 联机、坐标域、世界流送、分区存档、性能与底层架构 |
| `08_内容策划与世界观` | 世界观、叙事背景、宏观内容设定 |
| `09_美术素材` | 素材缺口、通用美术资源清单 |
| `90_测试验证` | 调试、验收、验证截图和可复用测试证据 |
| `99_历史归档` | 旧代办、随手记录、过时设计和无法合理按当前系统继续维护的历史材料 |

## 放置规则

1. 新文档先选择一个**主要归属系统**，不要再创建“待实现功能”“已完成功能”这类状态目录。
2. 跨系统文档放到最主要的消费方；真正覆盖全项目的路线或架构说明放到 `00_项目总览与路线`。
3. 系统专属图片放在对应系统目录下的 `image/`；通用验证截图放在 `90_测试验证`。
4. “完成”不等于归档。仍然描述当前系统架构或维护约束的文档继续留在所属系统目录。
5. 只有内容已经过时、混杂且主要用于追溯时才进入 `99_历史归档`。
6. 移动文档后必须同步修正文档间链接和图片相对路径，优先使用相对路径，避免写死本机绝对路径。
7. 一个主题已有文档时优先更新原文档，不为同一系统反复创建“新版 / 最终版 / 再整理”文件。

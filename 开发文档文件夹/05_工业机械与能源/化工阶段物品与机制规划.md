# FlatWorld 化工阶段物品与机制规划

## 1. 系统定位

化工阶段接在基础电力之后，让玩家从运输固体、驱动机械，发展到采集、运输、储存和加工液体与气体。

本阶段的核心是：**液体泵、气体泵、通用管道、气体筛选管道、储液罐、气罐、气罐方块、过滤器、电解器、气体压缩机、换热器和两种气压探针**。气体泵由机械动力驱动，按抽取速度与世界时间累计进度，完成一份进度后才按星球当前大气成分的概率抽出一份具体气体；星球大气总量有限但非常巨大，实际抽取会扣减对应气体储量，最终可以抽干。

**液体和气体共用一套流体运输与存储系统，气罐和管道都允许两相共存。上下连接优先输出液体，左右连接优先输出气体；首选相无法有效输出时尝试另一相，只有一种相态时四个方向都可输出。** 玩家可以利用温度、压力和不同物质的相变条件进行分相与分离。

本文为 2026-10-08 的规划草案，不表示设备或机制已经实现；统一流体状态、气液相变、方向优先级、状态方程、压缩与探针均属于待实现设计。设备容量、功率、流量、加工时间与精确配方暂不锁定。

- 首轮先做采集、运输和储存，再接液体过滤、气体筛选分流与电解加工。
- 化工产物必须有实际用途，避免只有中间材料、没有消费设备。
- 气相采用游戏版状态方程，液相占用容积后会改变剩余气相空间与压力；运输与相变统一结算真实物质量和热量，不展开完整流体力学。星球大气压独立参与生存，并受有限大气容量限制。
- 不同星球拥有不同大气压，玩家和生物各有安全气压范围，防护服通过扩展耐受范围提供保护。
- 化学能不是电能之后的更高级能源；本阶段主要扩展生产能力和资源种类。

### 1.1 与已有规划的关系

- [电力系统规划](电力系统规划.md)：提供设备供电、功率与供电比例规则。
- [机械动力系统规划](机械动力系统规划.md)：提供落地机器、加工、交互和运行状态的组织方式。
- [矿物线路策划优化](矿物线路策划优化.md)：提供湿法处理、铝工业、电解、气瓶和航天用途的上游路线。
- [容器输入输出接口待办](../03_生存制作与农业/容器输入输出接口待办.md)：提供拟定的类型化端口、可靠转移与 MOD 扩展边界；这些统一端口仍属于待实现内容。
- [液体流动模拟开发文档](../01_世界生成与环境/液体流动模拟开发文档.md)：负责地表液体；封闭管道内的流体单独保存，不直接写进地表液深。
- [太空场景开发待办](../01_世界生成与环境/太空场景开发待办.md)：在管道、气体、气压防护与供气基础完成后接入航空燃料、宇航服推进及船内供气；移动船体沿用本规划的统一流体能力。

截至本规划日期，读取的 `WorldLiquidSystem` 已提供有限世界液体抽取入口，液体容器操作已使用 `LiquidId`、份数和温度。源码检索未发现大气成分查询或工业气体运输系统，相关能力列为待新增内容。

## 2. 阶段成长与生产链

### 2.1 第一轮：把流体送到设备里

```text
世界液体 → 液体泵 → 管道 → 储液罐 → 用液设备

所在地大气 → 气体泵 → 不同气体依次进入管道 → 气体筛选管道 → 对应气罐方块 → 用气设备
```

- 玩家先学会连接源、管道和目标，再学习加工。
- 基础运输设备不要求先取得氢气、纯氧或铝，避免制作前置形成循环。
- 世界液体和星球大气都是有限来源；液体从世界格扣量，大气从所属星球共享储量扣量，来源适配器把各自计量换算为统一工业物质量，不把来源计量直接当作管内体积。

### 2.2 第二轮：从原料取得新材料

```text
原水 → 过滤器 → 过滤水 → 蒸馏器 → 工业纯水 → 电解器
                                                    ├→ 氢气 → 独立管线 → 气罐方块
                                                    └→ 氧气 → 独立管线 → 气罐方块

所在地大气 → 气体泵 → 气包管线 → 气体筛选管道（选择氧气）
                                  ├→ 输出1：氧气 → 氧气罐方块
                                  └→ 输出2：其他气体 → 继续筛选、储存或显式排放
```

两条链各有用途：大气抽取与管道筛选提供当地本来存在的气体；水电解提供氢气与氧气，不受当地是否含氧限制，但必须有水和电。

### 2.3 首轮消费出口

- 氧气接入增氧燃烧设备，帮助已有燃料实现更高温的工业加工；氧气自身不是燃料。
- 氢气与氧气接入气体发动机，转换成机械动力、水和热；机械动力可直接驱动设备，也可连接已有发电机转成电力，形成可运输的储能用途。
- 氮气先允许储存和排放；惰性保护、包装和肥料生产属于后续扩展，不用无用途的氮气强制堵住全部生产。
- 矿浆过滤和铝工业复用本阶段端口与过滤能力，具体冶金配方继续由矿物线路负责。

加工首轮应同时提供增氧燃烧接口和气体发动机，不能只完成产气设备。

## 4. 流体资源与承载状态

### 4.1 液体资源

| 内容 | 来源 | 主要去向 | 规则 |
|---|---|---|---|
| 原水／脏水 | 现有世界水源 | 过滤、水处理 | 保留原有液体身份和饮用效果 |
| 过滤水 | 允许的原水经普通过滤 | 蒸馏、允许使用过滤水的设备 | 去掉悬浮杂质，不自动视为饮用水或纯水 |
| 饮用水 | 现有水处理路线 | 生存补给 | 不与工业纯水强制合并 |
| 工业纯水 | 允许的含水原料经蒸馏 | 水电解、后续精细加工 | 独立稳定液体身份，纯度为首轮加工等级抽象 |
| 盐水 | 对应水源或已定义配制路线 | 蒸馏及后续盐化工 | 普通过滤不能把它变成淡水 |
| 矿浆／工艺液 | 后续湿法配方 | 过滤、沉淀、提纯 | 由具体配方定义，不因“加水”自动生成 |

不把所有水都改名为纯水，不默认现有蜂蜜、岩浆或任意 MOD 液体都能通过基础泵和管道。

### 4.2 气体资源

| 内容 | 来源 | 主要去向 | 规则 |
|---|---|---|---|
| 氧气 | 含氧大气按概率抽取、水电解 | 增氧燃烧、气体发动机、后续呼吸供气 | 管内使用明确氧气身份；大气中没有氧气库存时抽取概率为零 |
| 氮气 | 含氮大气按概率抽取 | 气罐、显式排放、后续工业用途 | 管内使用明确氮气身份，不由水电解生成 |
| 氢气 | 水电解；其他来源由星球或反应定义明确配置 | 气体发动机、后续化工与推进系统 | 不能默认从普通空气大量取得 |
| 二氧化碳等其他主要气体 | 后续星球定义或反应 | 对应气罐、后续化工 | 接入时使用独立气体身份；稀有气体和未使用的微量成分暂不纳入 |

大气按各具体气体的储量记录，是气体泵的来源；管内不保存一种模糊的“空气”物品。气体资源保存在管道、独立气罐、气罐方块和设备腔体内。气罐与气罐方块分别保存各具体气体身份及数量，不为不同充装量创建新物品。

### 4.3 数量与身份

- 工业流体使用拟定的稳定 `FluidId` 表示物质，气相／液相表示状态；氧气与液氧使用同一物质身份，水与水蒸气同理，不用两个互不相关的 ID 偷换数量。
- 统一库存按 `FluidId → 气相物质的量、液相物质的量` 记账，内部守恒量使用 `mol`。世界现有 `LiquidId`、容器份数和星球大气标准体积通过来源适配器换算，本文的 `GasId` 指气相物质索引，不另建一套物质定义。
- 管格首轮分别提供一个气相内容槽和一个液相内容槽，同格两相可以属于不同物质；每个相槽仍只容纳一种具体物质，另一相有内容不会阻止空相槽接收。不同气包或液体批次可以在不同管格依次通过。
- 气罐和组合罐的气相允许多种气体，按第 9 章随机出气；液相首轮只接收一种液体身份。相变产物也必须符合目标相槽的内容兼容规则，不凭相变覆盖已有物质。
- 管格、容器与设备腔保存实际各相余量和统一热模型的总内能，温度由这些状态推导；相变潜热纳入同一热模型，不能由面板独立改写温度或新增热量。
- 换星球或更改大气配置不能重写已经抽出的气包、罐内气体身份或数量。
- 液体显示实际 `L`、`L/s`，由物质量与液体密度换算；气体显示第 4.4 节参考温压下的“标准 L”，由气相物质量换算。两者只是显示与设备限流口径，不能直接相加或一升换一升。
- 世界液深、既有容器份数和显示体积分别换算。世界取液沿用定义中的 `DepthPerServing`，每份对应多少显示体积另行配置，不能默认为一份就是一升。
- 化学反应按配方核算物质的量和质量守恒；相变保持同一物质的总量及品质标记，只在两相间搬运份额，不把原水凭空变成工业纯水。

### 4.4 游戏版气体状态方程与耐压

内部气压由实际气相物质量、剩余气相空间与温度共同决定。首轮采用理想气体的游戏简化，液体密度与相变另读物质配置；不把理想气体方程直接套到液体上，以下概念均未新增代码。

| 状态／参数 | 含义 | 口径 |
|---|---|---|
| 气体标准体积 `Q` | 由实际气相物质量换算的显示气量，混装时相加 | 标准 `L`，不含液相份额 |
| 内部容积 `V_total` | 管格、设备腔或罐体的总几何容积 | `L`，有限正数 |
| 液相占用 `V_liquid` | 液相物质量乘摩尔质量，再除以对应液体密度 | 实际 `L` |
| 气相空间 `V_gas` | 总容积减去实际液体占用 | 实际 `L`，首轮保留最小正空间 |
| 流体温度 `T` | 首轮同腔两相采用共同温度，由内能推导 | 计算用 `K`，界面用 `℃` |
| 当前气压 `P` | 由气量、容积、温度推导的绝对压力 | `kPa`，只读派生值 |
| 额定耐压 `MaxSafePressureKPa` | 管件或罐体材质的承压上限 | `kPa`，有限正数 |

本体统一使用游戏参考温压 `P_ref = 100 kPa`、`T_ref = 293.15 K（20℃）`；标准升是这个参考状态下的气量单位：

```text
T_K = 温度℃ + 273.15
Q_标准L = 气相物质的量_mol × R × T_ref / P_ref
V_liquid_L = 液相物质的量_mol × 摩尔质量_kg每mol / 液体密度_kg每L
V_gas_L = V_total_L - V_liquid_L
P_kPa = P_ref × (Q_标准L / V_gas_L) × (T_K / T_ref)
参考储气容量_标准L = (额定耐压 / P_ref) × V_gas_L

R 使用 kPa·L/(mol·K) 口径；混合气的 Q 取各气相份额之和。
```

- 参考容量用于展示；气液共用同一个罐体空间，实际可接收量统一检查接收后的液体占用、气相空间、温度、相变与耐压，不能让气液各占一份完整罐容量。
- 首轮设置最小正气相空间和液体充装上限，达到上限时拒收更多液体；不靠除零或把空间截成零模拟满液罐，完全充液后的液压、热膨胀与水锤另行扩展。
- 气相物质量为零时本气压模型读数为零，液体不直接当作气体参与方程；有物料时温度必须有限且大于绝对零度，摄氏温度不能直接代入比例。
- 同气相空间、同温度下增加气量会提高压力；同气量、同空间下升温会提高压力；向带气罐加液体会缩小气相空间并可能提高气压。
- 压缩不改变物质身份或同一物质的总物质量；发生液化时减少的气相份额进入真实液相库存，不凭空删除。向固定罐充装后按实际两相量、空间和内能重算气压，不保证始终只增加气相标准体积。
- 压力不独立累加、保存或由面板改写；气相／液相数量、容积或内能变化后统一重新推导温度和压力。
- 密封完好的固定容积气管／气罐可以保持与大气不同的压力，不按时间把内压自动插值到大气压；与大气均压必须通过第 8.4 节的实际气体交换。
- 流体定义提供各相正热容、液体密度和相变热参数；混装按实际物质量、统一能量基准和相态求温度，不直接平均温度或给两相各领取一份热量。
- 组合储罐按实际总气相空间与真实气相量计算统一压力，额定耐压取最弱承压件；同材质参考容量可相加，不同耐压材质组合时按最弱耐压重算。
- 入气前预检接收后的温度、压力与耐压；超出额定耐压的充装不提交，来源保留实际气体。
- 已存流体因受热、空间变化或相变超压时保留真实读数，显示警报并沿耐久／破坏流程结算受压损伤；超压与外部受击扣同一份罐体血量，不截断压力或偷偷删物料。
- 气罐血量归零后沿第 9.5 节释放真实两相库存并结算压力爆炸；周围罐体只有被伤害打到归零才继续爆炸。组合罐共享库存只释放一次，气相回排受第 7.1 节大气上限约束，液相按实际泄出处理，不把液体直接增加到星球大气里。
- 探针设定上限与材料耐压分开：探针负责提前切动力，材料耐压提供结构约束，探针不提高罐体承压能力。

方程参考 [NASA 气体状态方程](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/equation-of-state/)。参考温压与简化边界是本游戏的设计选择。

### 4.5 压缩做功、热量与制冷扩展

首轮压缩机把来源气体增压后送入管道或气罐，按机械／电力驱动变体提供对应端口；一台运行实例只采用一种动力预算，不重复折算两种输入。

- 压缩机配置额定流量、最大增压能力和效率，不内置玩家可设的目标压力启停；压力控制由第 8.5 节的机械或电子气压探针完成。
- 做功来自实际机械输入或电能预算，不把转速、标称功率视为已收到无限能量。
- 每次增压同时计算实际做功、输出温度与损耗；游戏采用分批气包的有损热模型，气体增加的内能与设备损耗之和不得超过实际输入做功。
- 绝热温升可用下式作为理想参考，再按可用做功和效率限制本次气量与增压程度；绝热指数由热容参数一致推导。

```text
理想输出温度_K = 输入温度_K × (输出绝对气压 / 输入绝对气压)^((γ - 1) / γ)
压缩输入做功 = 气体内能增加 + 设备散热损耗
```

- 入口无气或压力为零时不计算压缩比；动力不足、出口堵塞或超过设备增压能力时停止对应增压，保留真实气体与未完成状态。
- 探针断开后停止新做功；已有热气、压力和缓冲继续存在，不把停电／停轴等同于瞬间放气或降温。
- 换热按实际温差和能量搬运，热端减少的能量进入另一端或明确的环境散热预算；与既有材料／环境温度机制共用能量口径。
- 状态方程本身不产生冷量；普通阀门或管格间自由扩散不默认降温，也不凭压差自动生成机械能。
- 基础换热器接入加工首轮，搬运两侧真实热量并支持第 4.6 节的相变；有功气体膨胀机与完整制冷回路后续扩展。膨胀机回收机械能不超过气体实际损失的能量，损耗有明确去向。

```text
压缩机（做功升温）→ 热端热交换器（放热）
    → 气体膨胀机（降压做功、降温）
    → 冷端热交换器（吸收目标区域热量）→ 回到压缩机
```

这提供玩家搭建循环空调的扩展路线。首轮先落地状态、压缩、基础换热与探针，膨胀机和区域制冷另行接入；闭环热端放热量等于冷端吸热量加净输入做功，不生成无限冷量或能量。

温升参考 [NASA 压缩过程](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/isentrophic-compression/)；常见空调还需换热与膨胀环节，参考 [DOE 制冷循环说明](https://www1.eere.energy.gov/buildings/pdfs/residential_hvac_research_opportunities.pdf)。

### 4.6 气液相变与压力分离

同一种物质可以在液相和气相间转换，罐内与管格内允许两相共存；转换条件同时取决于温度、压力和可用热量，不能设成所有气体共用的一个液化压力。

- 物质定义配置液体密度、各相热容、汽化潜热、饱和蒸气压曲线与临界温度，以及模型支持的温压范围；未配置相变数据的物质不自动转换。
- 纯物质可按当前温度下的饱和蒸气压判定冷凝／汽化方向；超过临界温度时不执行普通加压液化。氧气临界温度约为 `154.58 K（−118.57℃）`，常温下只加压不能得到液氧。[参考：NIST 氧气相变数据](https://webbook.nist.gov/cgi/cbook.cgi?ID=C7782447&Mask=4)
- 混合气的首轮近似使用各气体分压 `p_i = 气相摩尔占比_i × 总气压`，对比该物质的配置相变曲线；不把罐总压当成每一种气体各自的压力，不模拟完整多组分汽液平衡。
- 汽化吸收潜热，冷凝释放潜热；相变与换热、压缩在同一能量预算里提交，保留同一物质的总物质量，不直接把一升液体改成一标准升气体。
- 潜热与两相内能基准保持一致；封闭、无做功且无换热时总内能不变，相变只调整各相份额和温度，不能把冷凝放热再额外增加到已经守恒的总内能中。
- 在有限世界 Tick 中求可转换量，同时核对源相余量、目标相空间与内容兼容、热量及耐压；更新两相份额后重新求温度、气相空间与压力。每轮转换量有上限与平衡容差，不能在同一帧反复变相生成额外热量。
- 普通管格仍保留各相单种物质约束；目标相已有另一种物质或空间不足时，挂起本次受控相变及其关联换热，保留原物质和热量。混合气的加压分离先在允许多组分的罐／设备内进行，液相首轮只收一种产物。
- 压缩会升温，液化通常还要配合散热或冷源；玩家选择合适温度与压力窗口，使目标气体液化，再从液相出口取走，余下气相组成随实际扣量改变。
- 同时有多种物质满足液化条件时不能保证一次取得纯产物；可分段调温、调压并排出上一段液体，或结合气体筛选管道。方向输出优先级只选相态，不按物质名称筛选。
- 固化、冻堵、超临界流体、液体互溶与真实闪蒸另行扩展，超出已配置模型范围时明确提示，不强行标成普通液体。

```text
混合气 → 压缩并散热／调温 → 目标物质部分液化
                              ├→ 液相：取出冷凝产物
                              └→ 气相：未液化组分继续运输
```

温压决定相态与两相共存的关系参考 [OpenStax 相图](https://openstax.org/books/chemistry-2e/pages/10-4-phase-diagrams)，相变吸放热参考 [OpenStax 相变](https://openstax.org/books/chemistry-2e/pages/10-3-phase-transitions)；首轮曲线、分压近似与有限步长属于游戏简化。

## 5. 液体泵

液体泵用于从已有世界液体来源取液，并把实际取出的内容送入封闭生产线。

- 第一轮使用电力驱动，保留额定流量和接受的液体种类配置。
- 取液口指向一个明确的世界格；只有该格存在允许的液体时才工作。
- 出液口通过统一流体入口连接相邻管道或兼容储罐，不把液体直接塞进任意附近设备；气罐及气罐方块也可作为液体接收目标。
- 每次抽取先检查下游身份、容量和本次流量预算，再可靠地提交世界扣量与入管。
- 最终世界抽取复用 `WorldLiquidSourceResolver` 与 `WorldLiquidSystem.TryPump`，不通过地块名称猜测水源。
- 无水、无电、目标液相空间已满、液体不匹配或温度超出设备能力时停止抽取；目标已有气相不直接拒收，仍检查加液后的气相压力与耐压。
- 供电不足时降低实际流量；不把额定流量当作已经搬运的数量。
- 储罐向其他储罐转移也可使用液体泵的容器取液模式；该模式使用端口，不重复调用世界取液入口。

## 6. 气体泵与大气来源

### 6.1 气体泵的职责

**气体泵由机械动力驱动，通过“抽取速度 × 实际工作时间”累计进度，完成一份进度后才抽出一份具体气体。** 此时按所在地星球当前大气成分的概率选择 `GasId`，实际进入泵缓冲腔的数量同时从对应气体余量扣除，之后按气包进入管道。

- 第一轮具备环境进气口、气体输出口和机械输入轴口；电力可通过已有电动机转换为机械输入。
- 进气口读取当前位置所属星球、维度和环境的大气定义。
- 沿用机械系统规则：输入扭矩达到设备需求且转速非零时才能工作，转速绝对值决定抽取速度；扭矩不足时暂停，不按不足比例继续加工。

```text
有效抽取速度（份／世界秒） = 基础抽取速度 × 输入转速绝对值 / 基准转速
本次进度增量（份） = 有效抽取速度 × 本次实际工作的世界时间（秒）
累计进度达到 1 份 → 按当前大气成分抽签 → 扣减对应气体余量 → 生成一份气包
```

- 基础速度、正值基准转速和所需扭矩由设备配置；速度随输入转速线性变化，气体概率与普通气包大小不随转速改变。
- Tick 只负责结算本次工作时间，不再规定每 Tick 产出一份；进度不足一份时不产气、不抽签、不扣大气。
- 转速发生变化后按各段实际速度累计；成功生成一份气包才消耗一份进度，有效工作形成的小数余量保留到下一份，不直接清零。
- 完成周期按先后结算，每生成一包都核对缓冲容量；前一包已送完且仍有管网转移预算时才继续下一份。吞吐不足时暂停，只累计真正工作的时间，不积存多份完整的待产气进度。
- 玩家不能在普通泵上指定只抽氧气；想持续把氧气送往同一支路，使用气体筛选管道按气包种类分流。
- 泵保留一个单种气体缓冲腔，容量至少容纳一份；已有气包未送完时保留该气体并暂停下一份进度，不覆盖或混装。
- 输出堵塞时保留已抽出的气包与未完成进度，不能反复重新抽签直到得到下游需要的气体，也不能自动丢掉氮气。
- 抽签、余量检查、扣量、气包入腔与进度消耗由同一次权威结算提交；失败不扣量、不消耗进度，之后向管道转移不能再次扣大气。
- 真空、大气已抽空、未配置可抽取大气、进气口浸在液体里、无动力、扭矩不足、出口堵塞或下游装着液体时暂停抽取，保留已有进度；恢复条件后继续，不补计停机时间。
- 停动力只停止抽取，缓冲中已有气包仍可按管网运输规则送出。
- 首轮按机械输入决定抽取速度；低密度大气对速度的影响留待平衡，不通过缩小普通气包来替代进度。
- 抽入气体初温来自实际环境，有做功增压时沿第 4.5 节更新温度，不把压缩输出强制恢复为环境温度。
- 气泵缓冲和输出也参与压力计算；基础泵具备有限增压能力，不无限向高压管道送气，实际做功不得超过机械输入预算。

### 6.2 大气配置

大气来源是需要新增的环境能力，以下内容属于规划：

- 星球大气的容量上限、初始总体积和当前剩余总体积；初始量及运行余量均不得超过上限。
- 大气中各主要气体的稳定 `GasId`、初始成分比例、当前剩余标准体积和有效密度；稀有气体暂不纳入。
- 有大气的星球，初始成分比例须为有限非负值并归一化为 100%；未配置或当前余量为零的气体不参与抽取。
- 所在维度引用哪个大气来源；共享同一星球大气的维度引用同一份储量，不各自复制一份气量。
- 来源查询返回每种气体的当前余量、成分比例、温度与密度，由权威侧统一抽签并决定实际抽取量。

**大气是有限但总量非常巨大的气体储备，确实可以被抽干净。** 初始数值应远大于普通泵和气罐的处理规模，日常采集可以长期持续；即使储量很大，每次有效抽取也必须扣量。余量为零后停止从该来源产气，不自动补满。

例如当前大气为氧气 20%、氮气 80%，每完成 1 份抽取进度，抽中氧气的概率为 20%，抽中氮气的概率为 80%；抽中哪一种就生成 1 份该气体。短期结果可以有随机偏差，不强制每五份固定输出一份氧气。

```text
抽中某气体的概率 = 该气体当前剩余标准体积 / 全部可抽取气体当前剩余标准体积之和

20% 氧气、80% 氮气的来源
    ↓ 每完成一份抽取进度，抽签一次
可能依次输出：氮气包 → 氮气包 → 氧气包 → 氮气包 → 氧气包
```

- 1 份对应固定的配置标准体积，普通气包大小一致，泵缓冲与基础气管容量须能容纳一份；动力只改变完成一份所需时间。
- 抽取和回排改变各气体余量后，重新按当前余量比例计算概率；某种气体耗尽后概率为零，总量为零时停机。
- 抽中气体的余量不足一份时，仍须完成一份进度，再生成该种气体的最后一包余量；这是抽干来源的尾量例外，不能为凑满一份混入另一种气体。

氧气和氮气作为初始大气的主要成分参考，20%／80% 是游戏示例配置；不同星球各自配置，不能硬编码在泵里。[参考：NOAA 大气组成](https://www.noaa.gov/jetstream/atmosphere)

### 6.3 星球大气体积字段

建议在星球运行与存档数据中规划以下核心字段，尚未修改 `PlanetData` 代码：

| 拟定字段 | 含义 | 计量方式 |
|---|---|---|
| `PlanetData.AtmosphereGasVolume` | 星球当前剩余的大气气体总体积 | 统一参考温压下的标准 `m³`，有限非负值 |
| `PlanetData.AtmosphereGasCapacity` | 星球可容纳的大气标准体积上限 | 标准 `m³`，有限非负值 |
| `PlanetData.AtmosphereGasVolumeByGasId` | 按具体 `GasId` 记录每种大气气体的剩余体积 | 与总量共用标准 `m³`，各项有限非负 |

- 新世界从星球定义读取非常巨大的初始体积，按初始成分比例分配各气体余量；无大气星球初始化为零，具体初值后续平衡。
- 大气总量必须等于各具体气体余量之和；两者由同一次权威事务更新，不能形成两份互不一致的库存。
- 该字段表示剩余气量，不是只读的初始规模或抽取统计；存档恢复当前值，不因进出星球、维度切换或重启游戏重新填满。
- 与管道、气罐的标准体积共用同一参考温压，`1 标准 m³ = 1000 标准 L`；不把实际大气层的几何空间直接当作可抽取量。
- 一颗星球上的所有气体泵、自然进气口、玩家和共享大气的维度共同使用这一字段；每个取气入口不能持有各自独立的可抽取副本。
- 权威侧先核对泵缓冲容量与抽中气体余量，再在一次可靠转移中完成该气体扣量、总量更新和气包入腔；失败不扣，多个泵不能重复领取最后一份气体。
- 抽中气体余量不足一份配置体积时，只抽走真正剩余的部分，并把该气体余量结算为零；不能出现负体积。
- 大气总量非常大，计量必须保留小额抽取的累计精度；不能因使用低精度大数而让普通泵的扣量消失。具体数值表示、范围与最小单位在实现时确定。
- 抽中哪种气体只扣该种库存；回排按 `GasId` 返还同种气体，同时受星球剩余容量限制，按第 7.1 节可靠更新总量及比例。
- 大气储量与星球气压按下一章的首轮规则联动；抽空停机、异常气压伤害和服装防护属于本阶段，完整呼吸与天气反馈后续细化。

现实大气储量的规模可参考 [NASA 地球资料](https://nssdc.gsfc.nasa.gov/planetary/factsheet/earthfact.html)，游戏初始体积仍由星球配置决定。气体计量需要统一温压口径，可参考 [NIST 气体流量计量](https://www.nist.gov/laboratories/tools-instruments/gas-flow-standards)。

## 7. 星球大气压与生物生存

### 7.1 星球气压数据

大气压使用绝对压力，统一显示为 `kPa`；不同星球各自配置基准气压，不能让所有星球共用一个固定数值。

下表为拟定数据与查询概念，尚未新增代码：

| 拟定字段／属性 | 含义 | 归属 |
|---|---|---|
| `AtmosphereReferenceGasVolume` | 产生该星球基准气压时的大气气体标准体积 | 星球基准参数，标准 `m³` |
| `AtmosphereReferencePressureKPa` | 上述基准体积对应的星球大气压 | 星球基准参数，`kPa` |
| `AtmosphereGasVolume` | 当前剩余气体标准体积，动力抽气或自然进气时扣减、回排时增加 | 星球权威运行与存档状态 |
| `AtmosphereGasCapacity` | 大气标准体积上限，限制回排接收量 | 星球有限基准参数 |
| `AtmosphereMaxPressureKPa` | 容量上限对应的最高气压 | 只读派生上限，`kPa` |
| `AtmospherePressureKPa` | 根据基准参数与当前储量得到的当前气压 | 只读派生值，`kPa` |

首轮采用明确的游戏简化，固定有效大气空间与温度口径，按剩余气量比例改变气压：

```text
0 ≤ 当前大气标准体积 ≤ 大气容量上限
当前气压 = 基准气压 × 当前大气标准体积 / 基准大气标准体积
最高气压 = 基准气压 × 大气容量上限 / 基准大气标准体积
```

- 有大气或允许接收大气的星球必须配置有限正数的气压基准参数；初始量不得超过容量。容量为零时，当前气压和最高气压直接取零，不运行基准体积为零的除法。
- 无大气的环境气压为零；抽空后的当前气压也为零，不能因存在基准参数而继续返回正常气压。
- 星球定义提供有限大气容量；本体默认等于初始基准体积，所以补回初始气量后达到该星球最高气压。MOD 可设置其他有限上限，不能提供无限容量。
- 回排接收量受来源实际气量、端口预算和星球剩余容量共同限制；自然回排另受第 8.4 节的均压限额约束，按气体身份更新余量、总量与气压。
- 大气满时停止回排，未接收气体留在管内／容器，不先扣来源再默默截去超出部分；多个回排口共用剩余容量预算。
- 开放大气首轮维持固定温度与有效空间口径，回排不修改气压基准，故不能无限提高星球气压；不把每包热气升级为整颗星球热模拟。
- 无大气且容量为零的星球不接收普通回排；明确真空排放或破裂逸散属于不可回收流失，不新增无限大气来源。
- 气压基准、大气容量与当前储量随同一星球保存和恢复；当前气压和最高气压均派生，不另存相互冲突的压力真值。
- 同一星球相同大气来源的玩家、生物和设备读取同一个权威气压；维度通过其实际大气来源查询。
- 以上是首轮运输与生存联动规则，不宣称完整复现重力、海拔、温度和大气组分变化造成的真实气压。

### 7.2 生物安全气压范围

每种需要气压生存判定的生物，在自己的定义中配置基础安全范围：

- `SafePressureMinKPa`：能够安全生存的最低环境气压。
- `SafePressureMaxKPa`：能够安全生存的最高环境气压。
- 最低值不得小于零，最高值不得低于最低值，两个值都必须有限。
- 玩家、普通动物、异星生物使用各自配置；不能默认所有生物拥有相同的地球式耐受范围。
- 低于下限进入低压危险，高于上限进入高压危险，处于闭区间内则气压安全。
- 原生生物的生成与栖息条件应匹配其星球气压；大气被改变后，它们也会受到对应环境影响。
- 不需要气压判定的实体通过能力配置明确排除，不按名称猜测机械体、幽灵或某种生物是否免疫。

```text
星球当前气压
    ↓
生物基础范围 + 当前装备修正
    ↓
低于下限 → 低压危险
高于上限 → 高压危险
范围以内 → 气压安全
```

### 7.3 衣服与气压耐受

现有 `EquipmentInstance_ThermalInsulation` 通过 `SetSafeTemperatureRangeModifier` 扩展耐寒／耐热范围。气压防护采用相同的“装备修正安全范围”方式，使用独立气压属性，不复用温度数值。

拟定服装属性：

- `LowPressureToleranceIncreaseKPa`：增加低压耐受能力，用于降低安全下限。
- `HighPressureToleranceIncreaseKPa`：增加高压耐受能力，用于提高安全上限。

```text
有效安全下限 = max(0, 生物基础下限 - 当前装备低压耐受增量之和)
有效安全上限 = 生物基础上限 + 当前装备高压耐受增量之和
```

- 衣服扩展生物耐受范围，不改变星球气压，也不替生物改写基础种族参数。
- 耐压属于穿戴后生效的被动属性，和衣服的保温、保暖能力采用相同思路，不消耗氧气、电力、燃料或服装耐久；脱下衣服时撤销耐压修正。
- 多件装备按独立来源登记和撤销修正；脱下、替换、销毁、重载或回收时清掉对应来源，不重复叠加。
- 普通衣服默认没有气压防护；低压防护服、高压防护服和组合防护服通过配置提供相应增量。
- 首轮将服装的密封与承压能力抽象为安全范围修正，具体内部服压和逐部位泄漏模型后续再做。
- 同一件衣服可以同时配置耐寒、耐热、耐低压和耐高压，四项能力各自结算；耐寒不自动等于耐低压。
- 达到安全范围后，气压伤害停止；防护不足时仍持续受到异常气压伤害。
- 气压防护不自动提供氧气，也不自动解除有毒气体风险；供氧与可呼吸气体条件单独规划。
- 装备面板分别显示低压与高压保护增量，角色面板显示穿戴后的有效安全气压区间。

压力防护和供氧在现实防护服中承担不同职责，可参考 [NASA 舱外服组成](https://www.nasa.gov/centers-and-facilities/johnson/spacewalk-spacesuit-basics/)。这里采用面向玩法的服装耐受抽象，不展开完整生命保障设备模拟。

### 7.4 异常气压伤害与死亡

异常气压像异常温度一样构成持续环境危险；超出有效范围且保护不足的玩家和生物会掉血，长期停留可以死亡。

- 低压和高压使用不同的危险状态、来源标识与伤害配置，不能把上下限两侧都叫作高压挤压伤。
- 首轮通过气压危险缓冲和周期伤害表现；缓冲容量、恢复速度、伤害间隔与每次伤害量由生物配置，不预设最终数值。
- 气压危险缓冲独立于温度缓冲；低压与高压切换继续消耗同一份气压缓冲，不能切换危险类型就重新获得完整保护时间。
- 回到有效安全范围立即解除当前气压危险来源，缓冲按配置逐步恢复；穿脱装备或手动清 Buff 不能直接补满缓冲。
- 缓冲耗尽后，低压或高压危险挂载对应环境伤害来源，按独立时钟周期扣血，不每帧直接减生命。
- 生命结算接入现有统一伤害与死亡流程：GO 目标走 `DamageReceiver`，原生 ECS 目标走对应权威结算；气压查询、面板和装备模块不直接写 HP。
- 物理护甲的常规防御不自动抵消气压伤害；气压保护由有效耐受范围决定，避免普通金属护甲意外获得完整环境免疫。
- 低压、高压、冷热和其他伤害来源各自管理时钟；解除对应危险、死亡、重生或回收时清理该来源的伤害时间债务。
- 重生重新初始化新生命的气压缓冲和装备修正，不让上一条生命的延迟伤害继续扣血。
- 同一危险只提交一次伤害，不由气压模块、气压 Buff 和界面各自扣一遍；也不把同一笔低压伤害再重复记为缺氧伤害。

### 7.5 伤害表现与现实边界

- 低压表现可以使用呼吸困难、低压不适、失压损伤等提示；高压表现使用挤压不适或压力损伤提示。
- 肺部、耳部等压差伤害来自体内外气体空间的压力差及其变化，不宜把全部情况统称为“内爆肺泡”。[参考：CDC 压力损伤说明](https://www.cdc.gov/yellow-book/hcp/environmental-hazards-risks/scuba-diving-decompression-illness-and-other-dive-related-injuries.html)
- 首轮统一结算低压／高压环境生命损失；具体肺部损伤、压力骤变伤害和永久性部位损伤后续再接现有身体部位系统，不给所有物种凭空假设一套人类肺部。
- 提示玩家“气压过低”“气压过高”“当前服装防护不足”，同时显示当前气压和安全范围，方便玩家判断是否需要换衣服或离开环境。

### 7.6 宇航服配置页面与供氧气罐

宇航服使用同一个配置页面管理供氧气罐；手持入口和装备界面入口都操作对应的宇航服实例，不各自保存一份配置。

#### 7.6.1 手持宇航服右键打开

- 玩家手持宇航服时，右键打开这件宇航服的配置页面。
- 未穿戴的宇航服也能配置气罐；打开页面不自动穿戴宇航服，也不单独触发供氧或额外耗氧。
- 页面显示当前宇航服、气罐插槽、气体内容、剩余氧气和空罐状态。

#### 7.6.2 从装备界面打开

- 玩家装备界面为支持配置的宇航服提供配置按钮，点击后打开同一个宇航服配置页面。
- 页面绑定按钮对应的那件装备，不能误改背包中的另一件宇航服。
- 穿脱或替换宇航服后，配置页面应关闭或明确切换绑定对象，不能继续操作已经失效的装备槽引用。

#### 7.6.3 拖入氧气罐与替换空罐

- 首版提供一个独立气罐插槽；玩家从背包把适配、带有可用氧气的气罐拖入插槽，不把固定储气建筑当作服装附件。
- 插槽为空时装入气罐；插槽已有气罐时，拖入新罐完成替换，原来的空罐或剩余气罐返回拖入来源槽或背包可用位置。
- 替换作为一次完整的物品交换处理；没有位置容纳原罐时拒绝替换并提示原因，不删除、复制或静默丢弃原罐。
- 气罐耗尽后保留空罐，页面显示需要更换；玩家可以拖出旧罐，再拖入带氧气的新罐。
- 插槽沿用纯氧供气要求：只接受无液相、气相仅含氧气且有可用余量的适配独立气罐；混装罐应先分离并重新充装，气罐方块不能拖入服装插槽。首轮不提供液氧汽化供氧附件，不能把液氧或含部分氧气的罐当作合格供气罐。
- 实际供氧才消耗罐内氧气；供氧启停条件和耗氧速度由呼吸系统配置，界面只展示和提交换罐操作。
- 没有气罐、气罐为空或供气不适配时停止供氧并提示；宇航服的被动耐压仍然生效，不因氧气耗尽而扣除耐压能力。
- 气罐与剩余内容属于宇航服实例的配置，随装备移动和存档保存；切换两个入口、关闭或重开页面不能生成新气罐或恢复氧气。
- 宇航服继续用独立气罐纯氧供气，内部压力与充装接入第 4.4—4.5 节；两类气罐沿运输首轮安排，完整服内压力／泄漏另行扩展。
- 太空阶段另设独立推进气罐入口，与本节供氧插槽分开；两罐各自保存和扣量，推进不消费呼吸氧气，推进气种与耗量由对应能力配置。

## 8. 通用管道与连通规则

### 8.1 同一种管道允许两相共存

- 管道使用独立流体覆盖层，与电线及机器主体按各自端口连接。
- 空管道、已有气体的管道和已有液体的管道都使用同一种物品与同一套运输逻辑；不会因为第一次入管而锁死全网相态。
- **同一管网、同一管格都允许气相与液相共存。** 气相与液相分别记录物质身份及数量，共用总几何容积、热量和承压校验。
- 首轮同一管格的每个相槽各只保存一种 `FluidId`，两相可以是不同物质；同相已有另一种物质时等待，不覆盖或混成未知内容。
- 内容兼容按目标能力判断：储罐气相可混装多种气体，普通管格的气相仍只有一种气体；液相首轮只接收同种液体，允许不同液体在不同格依次通过。
- 放置、开阀与每次转移检查真实内容、材质、接收后占用和压力，以及端口方向与可接收相态；不再使用整网气液互斥检查。
- 原来运气的管路与运液的管路可以连接；保留各格实际两相库存，再按兼容性和第 8.3.1 节的方向优先级输送，不因接管复制、删除或自动换相。
- 多腔设备的不同端口彼此隔离；电解器的水腔、氢气腔和氧气腔不会因为属于同一台机器而连成一张流体网。

### 8.2 连接与分支

- 管道按上、右、下、左四个方向连接兼容的相邻管道及设备端口。
- 设备端口区分输入、输出或双向，朝向随设备旋转；没有端口的设备不会自动接入。
- 普通直管、弯管和三通由连接形状派生，不为每种形状新增库存物品；气体筛选管道因具有端口分流与配置能力，是独立的三通管件。
- 支路共享实际来源与流量预算，不让两个出口各取得一份完整来源量。
- 相邻放置但没有兼容端口的管网保持独立；首轮不增加跨管桥，确有布线需求时再规划。

### 8.3 首轮流动机制

- 每格保存实际两相物质量、总内能、几何容积、额定耐压与有限吞吐能力；气相压力使用扣除液体占用后的空间计算，不能只保存全网总数。
- 液相首轮按填充比例差计算候选流量，仍检查目标压力和加液后的气腔承压；不能靠比例差免费向高压罐注液。气相沿有效输出逐格转移，只允许高压向低压自然输送，并限制到本轮可达到的压力平衡。
- 液体泵提供有限扬程，压缩机／气泵提供有限气相增压，做功受实际输入动力限制；搬运统一结算物质量与携带热量，预检接收后的温度、相变、压力和耐压。
- 在固定世界 Tick 中先读取同一批存量并计算候选转移，再按来源存量、目标余量和边流量上限统一缩放并提交。
- 单次实际转移不超过 `最大流量 × 本次世界时间步长`，也不超过对应源相存量或目标余量；两相按配置折算共同占用一份边吞吐预算，不各自领取完整流量。
- 同一轮收到的流体不能沿任意长度管线反复转移，避免管线长度越大反而无限加速。
- 气包进入空的气相槽或同种气体的可接收槽，液体批次进入空液相槽或同种液体的可接收槽；另一相有内容时仍可接收，目标同相有不同物质时等待。
- 多种物质同轮竞争同一个空相槽时只接收其中一种，按稳定节点 ID 轮转选择，其余保留在来源；气相与液相分别判内容兼容，同时核对共同容积、热量、耐压和吞吐。
- 循环管网、多来源和分支采用稳定的结算顺序；满目标不能继续吞掉来源。
- 液体与气体共用发现、候选转移、统一预算和提交入口；不同相态只提供物性与流动计算策略，不另建并列运输系统，也不借用地表液体的流动算法。

#### 8.3.1 上下优先液体，左右优先气体

方向按世界格中输出连接的上、下、左、右判断，是游戏中的端口优先级；上下两口采用相同规则，不模拟真实重力中的液体下沉与气体上浮。

| 来源内容 | 上／下输出边 | 左／右输出边 |
|---|---|---|
| 气液都有 | 先尝试液相，不能有效流出时再尝试气相 | 先尝试气相，不能有效流出时再尝试液相 |
| 只有液体 | 输出液相 | 输出液相 |
| 只有气体 | 输出气相 | 输出气相 |
| 两相都空 | 不输出 | 不输出 |

- 每条有效输出边先查首选相是否有余量、下游是否接收、压差／动力是否允许和吞吐是否有余额，能实际转移才扣量；首选相无有效转移时检查另一相，不把试探失败记为已流出。
- 同一条边在本 Tick 优先转移一种相态，下一 Tick 重新评估；多个方向共享真实库存和总吞吐预算，不各复制一份液体或气体。
- 方向不赋予额外动力，不绕过单向端口、阀门关闭、耐压、物质兼容或机器指定相态；旋转管件后按实际输出边方向重新判断。
- 默认方向只是优先级，不能保证长期输出纯相；稳定分离时让下游端口明确只接收液相或气相，首选相堵塞后也不能把另一相送入不兼容目标。

### 8.4 阀门、与大气均压和排空

- 阀门关闭会切断连通关系，但保留阀门及两侧管段已有内容。
- 开阀前重新检查两侧内容、材质、压力和端口能力是否兼容，两相共存本身不构成拒绝原因。
- 新增另一相不要求排空；同一管格的某相要换成另一种物质时，应先取尽该相的实际余量，不要求删除另一相。允许气相混装的储罐按自身组分规则接收。
- 优先把流体转移到兼容容器；液体只有具备有效世界承载定义时才可排到地表。
- 与大气连通的开放口只交换气相，按内外压差决定自然流动方向，仍遵守第 8.2 节的输入、输出或双向权限；不会因为方位回退而把液体加入大气，没有开放通路时不交换气体。
- 双向开放口在内压高于大气压时向外排气，低于大气压时让大气进入容器／管段，两侧压力趋向一致。
- 单向进气口只允许大气进入，单向回排口只允许向外排气；反向压差不会绕过端口限制或让回排口倒灌。
- 数值误差范围内视为均压，净转移量为零并保留实际余量；首轮不模拟同压时的组分扩散。
- 大气直接流入允许混装的气罐时，按星球当前各气体余量比例分摊实际接收的标准气量，将这份气体的混合组成带入瓶内；同一次权威转移扣除大气各气体余量并增加罐内对应库存，不能只接收想要的成分。
- 大气先进入普通管格或单种设备腔的气相槽时，仍按当前大气占比选择单种气包，实际接收多少才扣除对应库存；堵塞保留选中批次、不换签，后续进入气罐时按实际送达气包累加。
- 进气核对管格气相身份、剩余气相空间和目标接收规则；已有液体不直接阻止进气，但会减少气相空间。普通管格已有其他气体时等待，允许混装的储罐按实际余量更新组分。
- 自然交换受来源存量、目标可接收量、端口流量与第 7.1 节大气边界限制，单次转移不超过两侧按实际气量和温度重算后的均压量；多个开放口共用预算，不能一步越过均压或重复扣量。
- 自然进气无需机械做功，但只能沿有效压差输送；大气抽空、回排目标已满或通路堵塞时暂停，不凭均压目标创造气体或热量。
- 均压不等于空罐，罐内余量仍可供低压目标取用；普通回排口不能自动把余量排成零。
- 彻底排空需要分别取尽两相；气相用有效抽气／回收路径，液相用兼容取液路径，不能把“气相已空”当成整个容器已空。向大气排放仍需实际排放端压力高于环境，转入容器仍校验容量与耐压。
- 气体交换同步结算实际气量与携带热量，按状态方程重算温度和压力，不直接把内压设置成大气压；大气进气使用所在地环境温度口径，目标无法接收时保留来源。
- 主动拆除含流体的管段或罐体前要求排空，不能把“拆除”当成免费删除内容或换介质按钮。
- 气罐受伤和血量归零后的压力爆炸沿第 9.5 节进入首轮；未归零时的细小泄漏、管道战斗破坏及气体扩散仍留待后续。

密封容器保留压差、开阀后气体流动至均压的原理参考 [OpenStax 压力测量](https://openstax.org/books/university-physics-volume-1/pages/14-2-measuring-pressure)；压差驱动净流动的简化依据参考 [OpenStax 流量与压差关系](https://openstax.org/books/college-physics-2e/pages/12-section-summary)，本游戏不直接照搬完整管流公式。

### 8.5 机械气压探针与电子气压探针

两种探针安装在管道上，读取所在管格的内部绝对气压；测量口不搬运气体，不直接切断气管，也不是泄压阀。

#### 8.5.1 测点、阈值与自动恢复

- 玩家设定断开上限 `DisconnectPressureKPa`，另有较低的恢复阈值 `ReconnectPressureKPa`；默认回差由配置提供，高级设置可调整。
- 两阈值均有限且 `0 ≤ 恢复阈值 < 断开上限`；管压严格超上限时断开，降到恢复阈值或以下时自动接通，中间区间保持原状态，避免频繁开断。
- 读数来自所附管格，不冒用星球大气压、全网平均压力或远处罐压；控制气罐时，测点应位于与罐口实际压力连通的管段。
- 有效空管格或无气相物质量时，本首轮气压模型读数为零；两相都有时读取共同气压，液体占用会通过气相空间影响读数，不因有液体就失效。管道被拆除或读数无效时保持动力连接断开并提示，测点恢复后再判断。
- 断开后继续测压，自动恢复不依赖受控支路的供电／转动。
- 固定世界 Tick 先读压力和更新探针，再解机械／电网与机器做功；本轮新超限进入下轮控制，允许有界一步超调，耐压预检仍独立约束实际充装。
- 探针只切断自身受控连接；另铺轴路、电线路或另一动力源形成旁路时，设备仍可能工作，面板显示真实供能状态。

#### 8.5.2 机械气压探针

- 具有两个机械连接轴端口，默认相对布置，随放置朝向旋转。
- 接通时沿现有机械网络传递有符号转速与可用扭矩，不制造动力或改变传动倍率。
- 超压时断开两端之间的传动边，按真实端口拆分／重算机械网络，不直接关闭全网机器。
- 管道与机械轴使用独立覆盖层，可同格重叠；探针装在测压管格，两端连接两侧轴段。
- 探针所在格的受控轴连接只由探针状态决定，同格普通轴不能绕过断开的传动边；真正另铺的旁路仍按实际连接供能。

#### 8.5.3 电子气压探针

- 具有两个电线连接端口，替代机械探针的轴端口；默认相对布置，随放置朝向旋转。
- 接通时连接两端电路，超压时断开两端电气边，沿现有电网分网和重算功率，不切机械轴。
- 两端为独立电气端点，不能因同格铺线或使用 `cell` 接入而自动桥接；不要求玩家区分正负极。
- 电线、气管和机械轴保持各自覆盖层，可同格共存，不合并为一张拓扑图。
- 首版作为测压联动开关，不另设独立传感器耗电或第三供电端口；断开受控电路后测压继续有效。

```text
机械动力源 → 机械气压探针的两轴端 → 机械压缩机
                         ↑ 监听出口管格气压

电源 → 电子气压探针的两电线端 → 电动压缩机
                   ↑ 监听出口管格气压
```

两种探针共用测点、阈值和显示，只改变被控制的动力连接；不能替代阀门、容器耐压或散热。

## 9. 储液罐、独立气罐与气罐方块

### 9.1 储液罐的定位

- 储液罐是偏向储液的统一容器变体，与气罐共用库存、端口、相变和运输逻辑；区别由实际容积、额定耐压、材质和携带能力配置表达，不另建储液系统。
- 允许符合材质与耐压的气液内容，包括相变产生的蒸气；液相首轮仍只接收同种液体，保留有限容量及真实两相余量，不默认低耐压储液罐能承受任意高压气体。

### 9.2 独立气罐

**气罐是可携带的独立承压容器；气罐方块是世界中的组合容器，两者使用不同物品身份，但都可以装液体、气体或两相共存的内容。**

- 独立气罐有自己的几何容积与真实两相库存，可以携带，并通过适配的统一容器装卸入口转移对应相态的流体。
- 独立气罐不能通过与另一只气罐相邻摆放来合并扩容，放入背包或宇航服也不会自动接入世界管网。
- 独立气罐的气相允许一种或多种气体，液相首轮允许一种液体；两相共享罐内几何空间，同物质同相按实际数量累加，液体挤占气相空间后重算压力。
- 宇航服供氧使用独立气罐，供氧插槽只接受无液相、气相仅含氧气且有可用余量的适配罐；混装或液氧罐不能直接供氧，须先分离、完成有热量预算的汽化并重新充装。太空推进使用另一只独立罐，不复用供氧库存。
- 独立气罐不是额外一套“便携气瓶”系统；后续高压气罐是它的容量或材质升级。

### 9.3 气罐方块与组合储罐

**气罐方块的流体储存功能只在世界放置后运行，多个相连方块组成一个更大的组合罐。**

- 气罐方块不能装入宇航服插槽；待放置物品不作为背包中的装流体容器使用。
- 首轮按上、右、下、左四邻接连接同类气罐方块，斜角接触不合并；每个连通组形成一个组合储罐。
- 组合实际容积等于有效方块内部容积之和，世界格保留真实位置；同材质参考容量可相加，混用耐压材质时按最弱耐压重算。
- 同组方块共享一份按物质记录的两相库存和总内能；不能每个方块或管口各持有一份相同库存副本。
- 每个气罐块有独立最大／剩余耐久，沿第 9.5 节用血量表达；攻击任意一块只扣该块耐久，该块归零后在自身位置爆炸，其他块须被实际伤害打到归零才继续爆炸。
- 气罐方块提供统一流体输入、输出口，可接液体泵、气体泵、其他储罐和用流体设备；输出沿第 8.3.1 节按连接方向优先选相，再检查下游能力。
- 不同气体可从同一或不同输入口进入气相，液相也可接收兼容液体；同时检查实际物质量、接收后温度／压力、气相空间、最弱耐压和端口流量。
- 空方块只增加容积；并组前检查液相物质是否兼容，不同液体的已装组不能直接形成同一单液相组合。合法并组后合并真实两相库存与内能并重算温度和压力，不凭合并创造物料或删除超压库存。
- 只通过管道连接两个方块组时，两者仍是独立储罐，按真实输入输出搬运气体，不因管道连通而共享总容量。
- 多个端口共享本组合储罐的真实来源与余量；同一轮输入输出按统一预算结算，不重复领取库存或剩余空间。
- 主动拆除仍先排空所在组；受击或超压导致任一方块血量归零时，沿第 9.5.4 节结算由范围伤害触发的连锁，存活成员保留血量并重建为空罐组，复杂带气拆分和细小泄漏后续细化。
- 容量与承压按第 4.4 节结算；组合组使用实际总容积与共享两相物质量，显示内部压力、额定耐压和两相实时可接收量。
- 首轮组合液体按各块几何容积比例占用内部空间，各块可分配气相空间之和等于整组气相空间；不为每块重复分配整组气腔，具体液面与重力分布后续细化。

### 9.4 两相库存、混合气与随机输出

独立罐和组合罐先按输出口方向／接收能力选择相态；气相有多种物质时，每次仍按实际气相余量选出一种具体气体，液相首轮输出当前唯一液体。按相态分离不会直接赋予按物质名称筛选的能力。

- 气瓶中的“概率性混合气体”使用实际气相组分库存表示：进气后按物质和实际气相数量合并，液化或汽化后也重新计算气相占比，不把液相库存参与随机出气。
- 至少两种气体有正余量时显示为混合气罐；原本单一且只流入同种气体时仍保持单一，空罐直接吸入多组分大气也会形成混合库存。
- 库存按第 4.3 节的 `FluidId → 气相mol、液相mol` 保存；标准气量、液体升数、气相概率与气相空间均由实际余量推导，不另存互相脱节的容量或概率真值。
- 接收新气体时逐种累加到原有库存，瓶内最终比例同时包含原有气体和新流入气体，不能直接用外界比例覆盖原有组成；混合温度和压力沿第 4.4 节重算。
- 入气或相变提交后更新后续新输出批次的选择概率；已有待输出批次保留已选物质和总物质量，不因流入或堵塞重新抽签。真实相变可更新该批次的两相份额，目标不能接收对应相时保留批次。
- 纯氧气罐混入非氧气后成为混合气罐，不再满足第 7 章的纯氧供气要求；适配检查读取当前实际组分，不沿用气罐名称或曾经装过的气体。
- 只有一种气体时，只能抽出该气体；有多种气体时，参照第 6 章的大气抽取方式，按当前可抽取余量比例选择一种气体。
- 随机选择在有效气相出气 Tick 中进行，不按渲染帧抽签；气包大小和最大出气量受端口流量、下游余量与抽中物质当前气相余量限制，不能临时从液相免费补足。
- 某种气体耗尽后不再参与抽签；不足一份时只输出该种气体剩余部分，不用另一种气体凑满同一个气包。
- 待输出批次的各相份额仍计入容器库存、内能和占用，预留与正式送出不能各扣一次来源；相变也不得绕过这些批次创造第二份物质。
- 多个输出口由权威端统一结算真实库存、待输出批次和容量，不能因为有多个方块或管口而复制同一份气体。
- 输出进入管道后遵守每格每相一种物质的首轮约束，允许气液共存；同相气体混装发生在储罐，不把多个气体直接混进普通管格的气相槽。
- 玩家可按第 4.6 节调温调压液化目标物质并取走液相，或使用气体筛选管道取得目标气包；未经相变或筛选，随机出气仍不能只抽想要的物质。
- 混装不自动发生化学反应或燃爆；已配置的物理相变沿第 4.6 节结算，未配置的物质不强行转换。
- 太空阶段可按第 14.4 节把接近氢气 : 氧气 = 2 : 1 的气相库存识别为可用航空燃料；这个用途判定不改变上述普通管口随机出气和管格单种规则。
- 背包内的手动装卸按玩家指定相态与目标能力办理，方向优先级只适用于存在世界方位的连接口。

```text
抽中某气体的概率 = 该物质当前可抽取气相mol / 全部可抽取气相mol之和

原有气罐：10 标准 L 氧气
    ↓ 直接流入 10 标准 L 混合大气（氧气 20%、氮气 80%）
新流入：2 标准 L 氧气 + 8 标准 L 氮气
合并库存：12 标准 L 氧气 + 8 标准 L 氮气
    ↓ 每个有效出气 Tick 按瓶内当前占比选择一种
氧气概率 60%，氮气概率 40%
    ↓ 实际扣除抽中气体后，重新计算余量与概率
单种气包 → 管道 → 气体筛选管道 → 对应储罐或设备
```

- 示例数量与比例仅演示流入混合和输出规则，不是固定容量、流量或最终气包大小。
- 面板分别显示实际液体占用、气相空间、各物质两相余量、气相占比、随机出气概率、待输出内容和堵塞原因；组合储罐同时显示方块数量，不把液体升数与标准气量相加。

同一参考温压下的标准体积占比对应物质的量占比，组成关系参考 [OpenStax 混合气体与组分占比](https://openstax.org/books/chemistry-2e/pages/9-3-stoichiometry-of-gaseous-substances-mixtures-and-reactions)；按占比选择单种输出气包属于游戏运输抽象。

### 9.5 罐体血量、受击与压力爆炸

独立气罐和气罐方块都有罐体耐久，首轮直接用血量表达；落地或安装在世界中时可受伤，血量归零后破裂，爆炸程度取决于破裂前的真实压力与储气规模。

#### 9.5.1 血量与受伤状态

- 罐体使用有限正数 `MaxHp` 和 `0..MaxHp` 的当前 `Hp`；拟接入现有 `Mod_DamageReceiver` 的生命、受伤和死亡权威，不另存一份独立耐久与血量互相覆盖。
- 独立气罐丢到地面或安装后获得世界受击资格，可被攻击及附近爆炸伤害；气罐方块安装后同样可受伤。落地本身不额外触发摔落伤害。
- 首轮背包、手持或装备插槽中的气罐保留实际血量，不作为独立场景目标受击；拾取、再次丢下和装卸不能回满血量或重置气体。
- 组合罐共享两相库存、内能和气压，每个方块仍保存自己的血量；合并或重建组合不平均、复制或恢复成员血量。
- 血量与额定耐压分别表达结构损伤和承压限制，首轮掉血不自动降低额定耐压；超压持续伤害沿第 4.4 节扣同一份血量，归零后走同一个破坏入口。
- 只要血量归零就发生破裂，不要求当时超过额定耐压；攻击可以打破仍在安全压力范围内的带气罐。

#### 9.5.2 爆炸程度

首轮使用明确的游戏强度指标，正压差和有效气相空间共同决定爆炸范围与伤害：

```text
正压差_kPa = max(罐内绝对压力 - 所在地大气绝对压力, 0)
压力爆炸强度 = 正压差_kPa × 破裂前气相空间_L
```

- 压力由真实气相量、扣除液体占用后的气相空间和温度推导，不能用额定耐压、填充百分比或物品名称代替；混合罐使用全部气相组分共同产生的压力。
- 同环境、同气相空间下内压越高，爆炸越强；同环境、同内压下气相空间更大的罐影响更大。该指标用于游戏平衡，不等同于真实可释放爆炸能量。
- 无气相或内压不高于大气压时破坏罐体并泄出实际内容，不产生向外的气相压力爆炸伤害；液体不能按完整几何容积冒充压缩气体。液化气快速闪蒸、满液承压和低压内向破裂另行扩展，不额外复制爆炸预算。
- 爆炸中心为归零罐体的世界位置；强度通过从零开始、单调不减且有有限上限的配置曲线映射为伤害和半径，伤害随距离衰减，半径之外不命中，首批参数待平衡。
- 范围伤害作为物理伤害进入现有统一结算，护甲和有效命中规则继续生效；附近玩家、生物、可受伤建筑和其他气罐均可受到影响，不因气罐归属自动豁免玩家。
- 该爆炸来自压力释放，氮气等不可燃气体也可产生；首轮不额外叠加氢气燃烧、点火或混合气化学爆炸。

#### 9.5.3 破坏结算

- 血量归零时先登记该实例的一次性破坏状态；独立罐保存破裂前两相库存、内能、温度、压力、气相空间与世界位置，组合罐成员领取第 9.5.4 节的自身份额。断开受影响储罐的输入输出，使尚未提交转移失效；爆炸读取破裂快照，不读取清空后的零压力。
- 破裂释放全部实际两相库存，待输出批次已计入库存，不再额外加一份；气相大气接收量受容量上限约束，剩余量记为不可回收逸散。液相有有效世界承载定义时提交实际泄出，无法承载部分记为不可回收流失，不直接变成大气或免费汽化爆炸。
- 罐体或组合腔已出现破口，因此清空原库存；首轮组合罐一处破裂会释放整组共享流体，但不会直接扣光其他成员血量。完整罐的自然均压仍按第 8.4 节保留余量，两种状态不能混用。
- 独立气罐在自身位置产生一次压力爆炸；组合气罐只为实际归零的成员创建爆炸事件，共用一次库存释放，不在触发点额外叠加一次全组容积的大爆炸。
- 爆炸通过距离衰减、护甲和有效命中规则扣周围罐体血量，只有扣到零的目标才进入破坏与爆炸队列；仍有血量的罐体只保留受损状态。后续爆炸可再次伤害并击杀其他目标，连锁在没有新增归零目标和待处理爆炸时停止。
- 同组成员、独立气罐和其他组合罐都遵守同一伤害触发条件；连锁按权威爆炸队列逐个结算，不递归重放同一事件，其他组的首个归零成员按其真实库存建立自己的有限预算。
- 同一爆炸对同一有效目标只结算一次，不因多个碰撞体重复伤害；事件保留来源实例身份、世界／维度和唯一标记，客户端只应用结果和表现。
- 破坏与气体释放不受“主动拆除前先排空”的操作限制；破坏后的掉落不能再生成完整带气气罐，碎片回收与具体掉落后续平衡。

#### 9.5.4 组合气罐块的伤害连锁与共享气体结算

角落、中间或其他任意位置的一块被打碎后，先在该块位置产生影响周围的爆炸；其他罐体是否继续爆炸，逐个由实际伤害和剩余血量决定。四邻接只决定储罐组合，不决定爆炸传播，爆炸可以影响范围内不相连的罐体。

- 首块归零时锁定成员身份、位置、各块几何容积与分配气相空间、共同压力和所在地大气压，登记该组一次破裂批次；只预留各成员的有限强度份额，不把存活成员自动加入爆炸队列。
- 组合腔一处破裂会泄放共享流体；本轮连锁沿用首次破口的压力快照，每个成员只有血量实际归零时才能领取一次自身份额。单块分配气相空间按其几何容积占比分摊整组气相空间，不能每块都使用完整组气腔。
- 首个归零块先爆炸，范围伤害经过统一受伤结算；受到伤害后仍有血量的成员存活，血量归零的成员才在自己的位置继续爆炸。后续不同爆炸的伤害可以累积，不直接替目标设置零血量。
- 传播顺序由实际击杀产生的爆炸队列决定，同步新增事件按稳定顺序入队；短间隔使用世界 Tick 配置，每次伤害结算与对应爆炸表现一起发生。

```text
块_i分配气相空间 = 整组气相空间 × 块_i几何容积 / 整组几何容积
单块可用强度_i = 首次破口时正压差 × 块_i分配气相空间
实际爆炸强度之和 = 已归零且领取过份额的块强度之和
实际爆炸强度之和 ≤ 首次破口时正压差 × 整组气相空间

A 块归零 → 压力爆炸 → B 块受伤后仍有血量：存活，不继续爆炸
                    → C 块受伤后血量归零：继续爆炸，再伤害周围罐体
```

- 组内共享两相库存在首次破口时统一清空并记账一次，单块事件只消费自己的气相压力爆炸预算，不再次释放整组流体；不能把完整组强度复制给每块，也不能由已拆出的空罐再领取一份。
- 本轮连锁结算期间暂停该组流体输入输出、拾取、合并和主动拆改；同组同时归零或被本轮爆炸击杀的成员共用这次批次，重复死亡回调不领取第二份预算。链外新死亡按当时真实库存处理，不沿用旧压力。
- 队列中本轮连锁的爆炸与伤害全部处理完后，丢弃存活成员未使用的强度份额，记为未形成额外爆炸的压力逸散；按存活方块四邻接重建一个或多个空组，保留各块剩余血量并恢复操作。以后再次受击不能重放旧压力爆炸。
- 仅通过管道连接或完全不相连的其他罐体同样只在范围伤害使其血量归零后继续爆炸；距离、当时血量和防御会决定连锁能否继续，不保证整片罐体全部爆炸。
- 没有正压差或气体已空时，仅破坏实际归零的块，压力爆炸伤害与半径为零，其余块不会因此自动破坏。

压力容器破裂可能产生气体冲击和碎片，即使不发生燃烧也存在压力释放危害，可参考 [HSE 压力设备说明](https://www.hse.gov.uk/pressure-systems/about.htm)。爆炸损伤周围设备并导致事故扩展的关系可参考 [HSE 设备布局与多米诺效应](https://www.hse.gov.uk/comah/sragtech/techmeasplantlay.htm)；血量触发、共享预算、强度指标和伤害曲线均为游戏设计，不是精确的压力波模拟。

## 10. 过滤器与蒸馏器

### 10.1 过滤器

过滤器用于液固分离，不是能够消除所有杂质的通用净化器。

- 具备液体输入腔、过滤液输出腔和固体残渣槽，由电力驱动加工。
- 具体可过滤的原料、滤材要求、液体产物和残渣来自材料／配方定义，设备不按物品名称硬编码。
- 普通过滤移除允许的悬浮颗粒，不直接去掉溶解盐，也不自动消除全部饮用风险。
- 水处理产物为对应过滤水；是否可以饮用仍由该液体定义与后续处理决定。
- 矿浆过滤必须有明确的输入、滤液和固体产物，不能把任意矿粉加水直接变成纯金属。
- 滤材消耗或清理周期作为配置；残渣槽满、液体出口满、滤材不足或无电时停止加工。
- 加工预留全部产物容量，再在一次事务中扣原料与滤材、提交产物，不先吞输入再等待空槽。
- 普通液体过滤器不处理气包；按气体种类筛选分流由下一章的气体筛选管道负责。

### 10.2 蒸馏器

蒸馏器负责蒸发并冷凝允许的含水原料，补齐“过滤水到工业纯水”的生产步骤。

- 消耗实际供热和冷凝能力，产出工业纯水与配方声明的浓缩残液或固体残留。
- 首轮把蒸发、冷凝封装为同一设备，不要求玩家先铺蒸汽回路；外部端口仍只收配方允许的液相原料与产物，不因通用管道允许两相就把内部蒸汽任意排到产物口。
- 不把现有的煮沸饮用水处理自动当成工业蒸馏。
- 蒸馏产量受实际水含量和加工预算限制，纯水及所有残留物合计遵守物质守恒。
- 只接受已定义蒸馏规则的原料；不能宣称任意未知污染物都能靠蒸馏完全去除。
- 供热不足、冷凝能力不足或任一产物存储满时停止。

过滤、消毒、膜处理和蒸馏在现实中承担不同作用。此处的“工业纯水”是游戏加工等级，不宣称一种设备能处理所有污染物。[参考：CDC 水处理方式](https://www.cdc.gov/drinking-water/about/about-home-water-treatment-systems.html)

## 11. 气体筛选管道

气体筛选管道是一件可配置的三通管件，具有一个输入口和两个输出口，按配置目标分流输入的单种气体包。

### 11.1 三个端口与分流规则

```text
输入：不同种类的气包依次到达
                 ↓
气体筛选管道（配置目标：氧气）
                 ├→ 输出1：只输出氧气包 → 氧气罐方块
                 └→ 输出2：其他气体包 → 继续筛选、储存或排放
```

- 三个端口接统一流体网络但只收发气相，分别固定为输入、输出1和输出2，随管件朝向旋转；液体保留在上游，不因方位回退进入筛选管件，输出口不能反向充当输入口。
- 输入气包的 `GasId` 等于配置目标时，只送往输出1；其他气体只送往输出2，不把它们统一改名为氮气。
- 输出2表示筛掉目标气体后剩余的其他气包；每个气包仍只有一种气体，输出2管格的气相槽也保持一种气体，液相槽按通用管道规则独立存在。
- 管件复用气管的容量、流量与固定 Tick，不额外增加独立分离加工流程；首轮不增加电气口。
- 物质身份、气相物质量和热量随原气包转移；筛选只改变路径，不生成或消耗物质，也不承担免费液化／汽化。两个筛选出口的指定角色优先于普通管口方位偏好。

### 11.2 配置 UI

- 玩家交互已放置的气体筛选管道，打开对应管件的配置页面。
- 页面选择一个已注册的目标气体，并明确显示“输出1：选定气体”“输出2：其他气体”，同时标出三个端口实际方向。
- 未选择目标气体时暂停转发并提示选择；不能悄悄默认改变气包方向或内容。
- 配置更新后按新目标判断尚未输出的气包；已经进入下游的气体保持原身份和数量。
- 保存目标 `GasId`、管件朝向和当前缓冲气包；UI 提交配置意图，由权威端校验并更新，页面不直接搬运气体。

### 11.3 堵塞与可靠转移

- 每次只检查该气包实际对应出口的容量与气体兼容性；另一个出口满不会直接阻止当前气包通过。
- 对应出口已满、未连接或目标管格装着不同气体时，保留当前气包并等待，不能改走另一出口。
- 阻塞气包占用管件缓冲时，后续不同气体不能穿过、覆盖或被自动删除；玩家需要疏通对应支路。
- 同种气体允许按容量部分转移，剩余量保留原气体身份；两个出口不能各得到一份完整输入。
- 输出2需要排放时必须接明确排放口，按实际气包种类和数量回到星球对应库存；筛选管道不会自行丢弃未选中气体。

## 12. 电解器与气体消费

### 12.1 水电解器

电解器消耗工业纯水和电力，分别向两个气体腔输出氢气与氧气。

```text
2 H₂O + 电能 → 2 H₂ + O₂
```

该式表示物质的量比例，不表示“两升水产生两升氢气和一升氧气”。[参考：DOE 水电解制氢](https://www.energy.gov/cmei/fuels/hydrogen-production-electrolysis)

- 首轮水电解配方只接受定义允许的工业纯水，不把原水、盐水和任意液体按同一规则电解。
- 具备一个液体输入腔、一个氢气输出腔和一个氧气输出腔；两个气体出口分别连接管道。
- 两种气体必须在同一反应事务中按比例生成，不能只有接通的一侧产气。
- 任一气体输出腔满时，限制或停止整次反应；不默认删除另一种气体。
- 首轮采用欠供电降速规则，实际反应量受取得电能、输入量、输出容量和设备额定能力共同限制。
- 电极寿命、加工效率和散热能力使用配置；催化材料没有消耗规则时不能按每次反应额外吞掉。
- 电解余热来自已定义的能量预算，不在反应产物之外再凭空增加加热能力。
- 氧化铝电解等高温工艺后续接入相同加工／端口框架，但使用独立条件和设备等级，不宣称普通水电解器可以直接炼铝。

### 12.2 增氧燃烧

- 氧气通过独立输入接口供给炉类加工，与现有燃料、供热和材料反应共同结算。
- 实际温度提升受燃料、氧气供给和炉体耐温限制；氧气不能单独生成燃料热量。
- 停止供氧时按设备配方退回普通空气燃烧或停止对应增氧工艺，不把缺氧时的上一轮增益继续保留。
- 新增供氧能力复用现有炉类加工，不创建与 `FurnaceLogic` 并列的第二套炉体业务。

### 12.3 气体发动机

气体发动机燃烧可燃气体，输出机械动力，作为机械网的新动力源；需要发电时连接已有发电机。

```text
氢气 + 氧气 → 气体发动机 → 机械动力 → 机械设备
                                      └→ 已有发电机 → 电力网络
```

- 首轮使用实际氢气与氧气输入；普通空气、氧气和氮气不能单独当作燃料，缺少任一必要输入时停机。
- 实际燃烧量受气体输入、设备额定能力、机械负载和回收水输出余量共同限制；停用或无可用负载时停止燃烧。
- 输出扭矩、带符号转速和机械轴口接入已有机械网，转速冲突与负载分配沿用既有规则；发动机自身不直接向电网提供电力。
- 首轮将机内冷却、冷凝抽象为回收水出口，按实际氢气燃烧量生成水；出口堵塞时停机，不默认删除产物。
- 机械输出与余热共用实际燃料能量预算，不能各自领取一份完整燃料能量；效率、额定转速和扭矩后续平衡。
- 从电解、存气、气体发动机到发电机的总电能回收率必须小于 100%，不形成循环发电增益。
- 用途是把基地多余电力转成可运输的气体储备，在远处提供机械动力，并通过已有发电机提供电力。
- 后续其他可燃气体使用各自反应配方、燃值和产物，不把所有气体都按氢气燃烧产水处理。

内燃机将燃料的化学能转换为机械能，发电机再将机械能转换为电力；本体采用上述加工抽象。[参考：DOE 内燃机与机械能说明](https://www1.eere.energy.gov/hydrogenandfuelcells/pdfs/hydrogenenergyfuture_web.pdf)

## 13. 交互与状态表现

- 放置预览显示连接端口和方向；液体口、气体口、电气口和机械轴口在形状和图标上可区分，不只依赖颜色。
- 通用管道逐格显示两相内容、液体占用、气相余量与流向；输出箭头标出上下优先液体、左右优先气体及当前回退相态，外观变化不改变物品身份。
- 选择设备时显示实际连接的输入、输出和当前内容，不要求玩家逐台猜测流向。
- 管道与气罐分别显示标准气量、实际液体升数、剩余气相空间、温度、气压和耐压；超压警报不由填充比例代替，两种升数不合并成一个填充百分比。
- 探针面板显示测点、管压、断开／恢复阈值、双端方向和接通状态；大气开放口显示内压、大气压、端口方向、当前流向与大气余量／容量，暂停原因区分“已均压”“方向受限”“大气已抽空”和“大气已满”。
- 气罐显示各物质两相余量、气相单一／混合状态、气相占比与出气概率，进出料和相变后及时更新；选择组合任一块时显示真实共享库存。相变面板显示当前温压、液化／汽化进度和所需换热，不显示不存在的纯度保证。
- 气罐显示罐体当前／最大血量、受损状态与高压破裂危险；组合罐显示当前选中方块血量和组内共享压力，不显示一份会掩盖弱成员的平均血量。
- 气体泵面板显示输入转速、扭矩是否足够、当前抽取速度、下一份的 0%—100% 进度、缓冲气包与暂停原因，并提供大气各组分余量和当前概率；真空或总余量为零时说明没有可抽取大气。
- 气体筛选管道的配置 UI 显示选定气体、输入及两个输出端口、当前气包与对应出口的堵塞原因。
- 环境与角色面板显示所在星球当前气压、角色有效安全区间及低压／高压危险；穿脱装备后立即更新保护范围，不能只显示衣服的基础描述。
- 过滤器显示原料、滤材、产物和残渣；电解器显示两种气体余量及各自堵塞状态。
- 状态说明使用“没有电”“没有动力”“动力不够”“入口没有水”“液体空间已满”“气相槽还有氮气”“冷源不够冷”“液相已有其他物质”“输出1被堵住了”等直白文案，不把管中有另一相当作禁止连接的原因。
- 普通工作面板沿用现有非模态交互；显示只读取权威数据，不在界面里累加流量或生成产物。

## 14. 数据、运行与扩展边界

### 14.1 机器与运输

- 落地设备复用现有 `MachineWorld` 生命周期、交互和库存组织方式；机械、电力和流体保留各自独立拓扑。
- 本规划不另建并列的化工机器世界；新增流体图负责连通与转移，气体筛选管道使用其端口分流能力，液体过滤与反应留在设备加工逻辑。
- 液体与气体使用同一个拟定流体端口模型、库存模型和转移服务；端口能力声明可接收相态、物质与方向，相态策略提供密度、气压和流量换算，不另建两套运输服务。现有世界取液及容器接口通过来源适配器接入，统一工业端口仍属新增能力。
- 两端搬运和多产物加工都由权威侧提交；预检不扣量，失败必须保持原有内容。
- 探针在现有机械图／电气图切换受控边，按真实端点分网与重算；同格管、轴、线覆盖及防自动桥接由正式放置／端口规则表达。
- 世界气罐受击拟接入当前 `Mod_DamageReceiver`，超压、普通攻击和压力爆炸共用生命与死亡权威；气罐模块负责一次性破裂、库存释放与爆炸事件，不从表现层直接扣目标血量。
- 材料和配方定义接受条件与结果，设备提供容量、温度、机械输入、供电及加工能力，不集中维护按内容名称排列的特殊分支。

### 14.2 保存、休眠与联机

- 保存各物质真实气相／液相物质量与总内能，容积和耐压来自载体配置／实例材质；温度、压力、标准气量和液体体积恢复时重新推导，不另存相互冲突的真值。
- 保存大气容量与气压基准；探针保存测点、朝向、两个阈值和开断状态，恢复测点及双端拓扑后再解算，不读档默认接通。
- 压缩做功、换热、气液相变、方位选相、压力开断与超压损伤由权威端在世界 Tick 结算；休眠冻结对应进度与控制，不由客户端或面板各算一遍。

- 保存每段管道和设备腔的具体 `FluidId`、两相余量、内能、待转移批次与调度状态；阀门状态、加工余量及筛选配置继续按对应设备保存，端口相态限制也需保存。
- 独立气罐保存实际两相库存、内能与出流状态；组合罐同时保存方块位置、有效连接、唯一共享库存、随机状态与待输出批次，不在每块或每口复制库存。相变后读档不能恢复已转化的旧气相或液相副本。
- 同时保存各气罐实例／方块的当前血量和破裂消费状态；库存释放与爆炸入队作为一次权威事务提交，尚未结算的事件快照随权威队列保存，读档只恢复未完成事件，不重放已完成爆炸。
- 组合罐破裂批次保存锁定成员、压力快照、每块位置／分配气相空间／强度份额、已领取标记及事件处理进度；读档只恢复实际归零入队且未完成的事件，不为存活成员补建爆炸，不重建完整库存或再次领取组预算。
- 恢复组合气罐拓扑与库存后再启动输入输出；读档、方块合并或界面重开不能恢复已消耗的气体，也不能重抽当前待输出批次。
- 保存气泵未完成的抽取进度、缓冲中的具体气包及抽取随机状态，恢复后继续原进度和原气包；读档不能清零进度、重新抽签或重抽一份库存。
- 星球大气总量与每种气体余量沿星球存档保存和权威同步，恢复时保持总量等于各项之和；不在区块或每台泵中复制一份来源库存。
- 同时保存星球气压基准参数，恢复后从真实剩余储量推导当前气压；生物保存自己的剩余气压缓冲，基础耐受参数读取生物定义，装备修正按当前穿戴重新建立。
- 不只保存全网总量，否则拆分网络、关阀和卸载后无法知道流体在哪一段。
- 恢复节点和全部连接后再开始结算；视图卸载不能删除管网内容。
- 首轮整条相连流体网络共同激活或休眠，不只让可见半段持续工作；具体活动窗口和网络规模上限待规划。
- 休眠期首轮不追算产量，停止运输和加工，气泵进度冻结；供电、抽水与取气使用一致的激活边界，唤醒后不补计休眠时间。
- 以上为普通世界网络的休眠规则。后续运行中的太空船需要维持关键供电、燃料和供气网络活动，不能仅因玩家回地表或视图卸载而休眠；按第 14.4 节的船体作用域接入。
- 联机客户端发送操作意图，服务端校验来源、容量与连接；气泵进度、概率抽取与筛选配置由权威端结算，客户端不独立推进进度、抽签、抽水、抽气或电解。
- 气压危险、缓冲推进、伤害与死亡由状态权威端统一结算，客户端仅展示气压与生存状态。
- 气罐破裂、范围伤害和连锁爆炸同样由权威端结算；视图重建、重复死亡通知、网络重发或对象池复用不重放旧实例爆炸。

### 14.3 MOD

- 液体、具体气体、星球大气成分、设备能力和加工规则使用稳定内容 ID；MOD 使用自己的命名空间。
- 内容型 MOD 可以配置已注册能力，新增流体不要求修改每种泵、管道或罐体的核心逻辑。
- 自定义端口／反应算法需要正式注册扩展能力，不能把 JSON 当作可直接装入新 C# 行为的机制。
- 配置发布前检查相态、数量单位、大气初始比例与各气体余量、每份气量、气泵基础速度及正值基准转速、所需扭矩、筛选目标、三通端口、容量和反应守恒；未知气体和错误端口明确报错，不静默改成水或氧气。
- MOD 星球、生物和衣服共用大气容量、储量、气压基准、安全范围与装备修正；数值有限合法，不绕过统一伤害与死亡结算。
- 流体定义统一配置稳定身份、摩尔质量、液体密度、各相热容、相变热量与饱和曲线；管件、气罐与探针配置容积、最小气相空间、耐压、增压能力和控制回差，不自建冲突的数量单位或能量预算。
- 气罐材质定义最大血量、防御和压力爆炸曲线；配置值有限合法，零强度对应零压力爆炸伤害与半径，MOD 不绕过统一受伤和一次性破裂入口。

### 14.4 太空阶段接入与前置边界

- 开发顺序为统一流体端口、管道运输、气罐与气压生存，再接宇航服及船内供气基础，之后完成[太空场景开发待办](../01_世界生成与环境/太空场景开发待办.md)；这些仍属于待实现依赖。
- 航空燃料由独立气罐或气罐方块内接近氢气 : 氧气 = 2 : 1 的混合气提供，氢氧来源复用已有规划的水电解等明确来源；不新增液体燃料，不把两个组分改写成第三种物质库存。
- 比例按第 4.3 节气相 `mol` 判断，界面使用同一参考温压下的标准气量；比例容差和允许杂质由燃料配置声明，空罐、单一气体或大量杂质不自动合格。
- 混合发生在支持多组分的罐内；普通管格仍每相单种，分别把实际氢气和氧气输送到接收罐。共享方块组只保存一份库存，多个独立罐不能只合计数值就视为已经混合。
- “航空燃料可用量”从真实氢氧余量推导，可配对份数为 `min(氢气mol / 2, 氧气mol)`；配比不合格时不可供给引擎，不因旧标签保留资格，进出气、相变和恢复后重新判定。
- 化学引擎作为反应设备按配方一次性扣除两种气体，检查资格、余量和预算后一起提交；普通输出口仍随机选单种气包。反应消费不是普通管口的免费筛选能力，也不在每块罐或每个引擎复制储备。
- 宇航服推进气罐与第 7.6 节纯氧供氧罐分开，独立配置气种、保存余量与消费；气体推进是太空新增能力，供氧插槽不等同于已完成推进或完整呼吸系统，两者耗尽都不撤销被动耐压。
- 船内有有效舱体与实际工作的供气设备才具备安全气压，供气复用统一气体库存。舱门首轮抽象为自动气体隔离门，开门不泄压，不展开逐格密封与泄漏模拟。
- 移动船体的管道、设备端口及第 8.3.1 节出相方向使用船体本地格子；地表仍使用世界格子。飞船旋转不改写管网连通、气液优先级或实际库存。
- 不同船体作用域的库存保持独立；双方控制台确认结构连接后，再按有效流体端口建立网络，不因画面接近或同处一个 Scene 自动共享流体。
- 无人太空船持续运行时，其必要供电、燃料转移和供气按世界 Tick 保持活动；暂停菜单或退出游戏才整体停止，不补算暂停和离线时间。
- 太空阶段航空燃料受毁时扩展化学燃爆，复用第 9.5 节的唯一事件队列、范围伤害与连锁入口，并同步接入爆炸表现；不改变本阶段首轮仅结算气罐压力爆炸的边界。
- 气压爆炸强度与航空燃料燃爆强度分别读取同一破裂快照的压力和可反应氢氧余量；燃烧消费后仅释放剩余库存，已燃烧的气体不能再全量返还大气。组合罐共享一次释放与有限预算，不在每块罐复制整组强度。
- 船内供气参数、宇航服推进气种与耗量、燃料配比容差和燃烧排放、完整呼吸耗氧的完成范围仍待配置；推进与供氧分罐、航空燃料氢氧配比来源已确定。

- [ ] 接入便携供氧气罐插槽、拖入装罐与空罐替换，正确返还原罐并保存实际氧气余量。
- [ ] 将异常气压伤害、死亡与重生接入各实体的既有权威流程。
- [ ] 显示当前环境气压、有效安全范围、服装保护和危险状态。

### 15.4 后续由用户进行的游戏观察

- [ ] 双向开放口在高压时排气、低压时进气，均压后停止净转移；多开放口与大时间步不越过均压限额或重复扣量。
- [ ] 关闭阀门的密封罐保持真实压差；单向回排口不倒灌，自然进气核对气相身份、实际气相空间与耐压，液相不会被回排口直接算入大气，彻底排空取尽两相。
- [ ] 回排达到大气容量后停机，多回排口不重复占用余量，星球气压不突破派生上限。
- [ ] 气相量、内能和剩余气相空间正确影响压力，加液会压缩气腔；混装、相变、压缩和搬运不复制物质或热量，液体充装上限避免零气相空间。
- [ ] 两探针严格超上限时分别断轴／断线，降至恢复阈值后接通；同格、旋转、断管、旁路和读档不绕过状态。
- [ ] 探针断开只停止新做功，既有热气和压力仍存在；超出材料耐压时按实际状态损伤，不截断压力读数。
- [ ] 地面与已安装气罐可受伤，拾取／装卸不回满血量；普通受击和超压消耗同一份血量，归零破裂一次。
- [ ] 同环境、同气相空间的高压罐比低压罐爆炸更强，同内压时按实际气相空间计算；无气相和均压罐不产生向外压力爆炸，液体泄出不复制大气或压力预算。
- [ ] 击杀组合罐角落或中间的一块后，只有受爆炸伤害后血量归零的罐体继续爆炸；未被击杀的成员存活，连锁可在中途停止，不因同组或相邻强制引爆。
- [ ] 实际成员爆炸强度之和不超过共享组预算，共享库存只释放一次；同时击杀、重复通知、多个碰撞体、读档和联机重发不重复爆炸、伤害或掉落。
- [ ] 连锁结束后，存活方块按四邻接重建为空组并保留剩余血量，未用压力预算失效，后续打碎空罐不重放旧爆炸。
- [ ] 范围内其他独立罐、仅用管道连接的其他组和不相连的组只有被实际伤害击杀才继续爆炸；距离衰减、血量、防御及不同爆炸伤害累积能正确影响连锁结果。

- [ ] 液体泵取液后，世界来源实际减少，罐内实际增加。
- [ ] 扭矩足够时，转速改变完成一份所需的时间；进度不足一份时没有气包、大气扣量或提前抽签。
- [ ] 无动力、扭矩不足、堵塞与休眠时暂停进度；恢复和读档后继续原进度，不补出停机期间的气包。
- [ ] 调整 Tick 步长后同样实际工作时长对应同样有效进度；有效小数余量保留，高转速产气仍受单包缓冲与管网吞吐限制。
- [ ] 多台气体泵共同减少同一星球的大气余量，抽空后停止产气，余量不足时只抽取剩余部分。
- [ ] 极大初始储量下的小额抽气仍能累计扣量，存档重进不重新填满；回排不会同时保留管内气体而复制储量。
- [ ] 按大气配比概率输出具体气体，单次气包只有一种 `GasId`；零余量成分和真空不能产气，回排按实际种类返还。
- [ ] 不同气包能在同一管道不同格依次通过；每格气相仍只装一种气体，同时可有液相，堵塞不重抽物质，真实相变后保留对应物质总量。
- [ ] 同一管网和同一管格允许气液共存；目标同相身份不兼容时等待，另一相有内容不直接拒收，接管、开阀和读档保留实际两相库存。
- [ ] 两相都有时上下优先液体、左右优先气体；首选相空、堵塞或无法有效转移时仅在目标兼容条件下尝试另一相，只有液体或只有气体时四向都可输出。
- [ ] 多个方向与两相共用真实存量和边吞吐预算，方向不免费增压；只接收某相的设备不会被回退送入另一相，旋转后的规则按实际输出方向判断。
- [ ] 气罐装液体与气液共存时空间、温度和气压正确；宇航服首轮只用无液相的纯氧气罐，液氧不免费直接供氧。
- [ ] 调温调压使满足条件的物质液化并取走液相，剩余气相组成更新；临界温度、分压和潜热约束有效，无法取得纯产物时不显示虚假纯度。
- [ ] 汽化与冷凝保持物质总量并结算相变热；目标相不兼容、液相已满或换热不足时保留未提交物料与热量，读档不重复相变或恢复旧相库存。
- [ ] 满罐、分支、循环管、断电与重进游戏不会复制、吞掉或换掉内容。
- [ ] 独立气罐可携带和装入适配宇航服，气罐方块仅在世界运行；混装罐不能绕过纯氧供气要求。
- [ ] 相邻气罐方块按真实块数扩容并共享库存；仅通过管道连接的方块组保持独立，空方块加入不增加气体。
- [ ] 多组分大气直接流入气罐后形成实际混合库存，原有气体与流入量共同决定新占比；原本单一且只流入同种气体时不会误标为混合罐。
- [ ] 混装气罐按各气体当前余量概率输出单种气包，抽中气体不足时只输出余量；流入、堵塞、多出口、合并和读档不复制库存或重抽已有待输出批次。
- [ ] 普通过滤不会把盐水变成纯水，残渣和各加工产物不会被默认删除。
- [ ] 电解任一产物出口堵塞时按规则停机；筛选管道只向对应出口转移，出口堵塞时保留当前气包。
- [ ] 筛选管道 UI 更换目标、旋转和读档后，输入及两条输出的角色正确，气包身份和数量不被配置改写。
- [ ] 电解、存气、气体发动机和发电机闭环有能源损耗，机械输出与产物有明确去向。
- [ ] 不同星球和不同生物使用各自气压参数，耐受范围外会按规则持续掉血并可能死亡。
- [ ] 穿脱防护服正确改变有效范围，耐温与耐压互不冒用，重载后不重复叠加保护。
- [ ] 大气抽取减少气压、回排恢复对应气压，抽空后为零；跨维度和读档不会恢复一份虚假的正常大气。
- [ ] 重生、解除危险和对象回收后没有旧气压伤害继续结算，联机不会由客户端再扣一次血。

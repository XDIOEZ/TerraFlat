# FlatWorld 化工阶段物品与机制规划

## 1. 系统定位

化工阶段接在基础电力之后，让玩家从运输固体、驱动机械，发展到采集、运输、储存和加工液体与气体。

本阶段的核心是：**液体泵、气体泵、通用管道、气体筛选管道、储液罐、气罐、过滤器和电解器**。气体泵由机械动力驱动，按抽取速度与世界时间累计进度，完成一份进度后才按星球当前大气成分的概率抽出一份具体气体；星球大气总量有限但非常巨大，实际抽取会扣减对应气体储量，最终可以抽干。每节气管只装一种气体，同一条气管可以依次运输不同气体；同一条连通管网不能让液体与气体共存。

本文为 2026-10-08 的规划草案，不表示设备或机制已经实现。设备容量、功率、流量、加工时间与精确配方暂不锁定。

- 首轮先做采集、运输和储存，再接液体过滤、气体筛选分流与电解加工。
- 化工产物必须有实际用途，避免只有中间材料、没有消费设备。
- 管内运输采用容量和流量限制，不要求玩家计算真实管内压力或管径损耗；星球大气压作为独立环境生存条件参与玩法。
- 不同星球拥有不同大气压，玩家和生物各有安全气压范围，防护服通过扩展耐受范围提供保护。
- 化学能不是电能之后的更高级能源；本阶段主要扩展生产能力和资源种类。

### 1.1 与已有规划的关系

- [电力系统规划](电力系统规划.md)：提供设备供电、功率与供电比例规则。
- [机械动力系统规划](机械动力系统规划.md)：提供落地机器、加工、交互和运行状态的组织方式。
- [矿物线路策划优化](矿物线路策划优化.md)：提供湿法处理、铝工业、电解、气瓶和航天用途的上游路线。
- [容器输入输出接口待办](../03_生存制作与农业/容器输入输出接口待办.md)：提供拟定的类型化端口、可靠转移与 MOD 扩展边界；这些统一端口仍属于待实现内容。
- [液体流动模拟开发文档](../01_世界生成与环境/液体流动模拟开发文档.md)：负责地表液体；封闭管道内的流体单独保存，不直接写进地表液深。

截至本规划日期，读取的 `WorldLiquidSystem` 已提供有限世界液体抽取入口，液体容器操作已使用 `LiquidId`、份数和温度。源码检索未发现大气成分查询或工业气体运输系统，相关能力列为待新增内容。

## 2. 阶段成长与生产链

### 2.1 第一轮：把流体送到设备里

```text
世界液体 → 液体泵 → 管道 → 储液罐 → 用液设备

所在地大气 → 气体泵 → 不同气体依次进入管道 → 气体筛选管道 → 对应气罐 → 用气设备
```

- 玩家先学会连接源、管道和目标，再学习加工。
- 基础运输设备不要求先取得氢气、纯氧或铝，避免制作前置形成循环。
- 世界液体和星球大气都是有限来源；液体从世界格扣量，大气从所属星球的共享储量扣量，两者使用各自的数量单位和来源适配器。

### 2.2 第二轮：从原料取得新材料

```text
原水 → 过滤器 → 过滤水 → 蒸馏器 → 工业纯水 → 电解器
                                                    ├→ 氢气 → 独立管线 → 气罐
                                                    └→ 氧气 → 独立管线 → 气罐

所在地大气 → 气体泵 → 气包管线 → 气体筛选管道（选择氧气）
                                  ├→ 输出1：氧气 → 氧气罐
                                  └→ 输出2：其他气体 → 继续筛选、储存或显式排放
```

两条链各有用途：大气抽取与管道筛选提供当地本来存在的气体；水电解提供氢气与氧气，不受当地是否含氧限制，但必须有水和电。

### 2.3 首轮消费出口

- 氧气接入增氧燃烧设备，帮助已有燃料实现更高温的工业加工；氧气自身不是燃料。
- 氢气与氧气接入气体发动机，转换成机械动力、水和热；机械动力可直接驱动设备，也可连接已有发电机转成电力，形成可运输的储能用途。
- 氮气先允许储存和排放；惰性保护、包装和肥料生产属于后续扩展，不用无用途的氮气强制堵住全部生产。
- 矿浆过滤和铝工业复用本阶段端口与过滤能力，具体冶金配方继续由矿物线路负责。

加工首轮应同时提供增氧燃烧接口和气体发动机，不能只完成产气设备。

## 4. 流体资源与承载状态

### 4.1 液体资源

| 内容 | 来源 | 主要去向 | 规则 |
|---|---|---|---|
| 原水／脏水 | 现有世界水源 | 过滤、水处理 | 保留原有液体身份和饮用效果 |
| 过滤水 | 允许的原水经普通过滤 | 蒸馏、允许使用过滤水的设备 | 去掉悬浮杂质，不自动视为饮用水或纯水 |
| 饮用水 | 现有水处理路线 | 生存补给 | 不与工业纯水强制合并 |
| 工业纯水 | 允许的含水原料经蒸馏 | 水电解、后续精细加工 | 独立稳定液体身份，纯度为首轮加工等级抽象 |
| 盐水 | 对应水源或已定义配制路线 | 蒸馏及后续盐化工 | 普通过滤不能把它变成淡水 |
| 矿浆／工艺液 | 后续湿法配方 | 过滤、沉淀、提纯 | 由具体配方定义，不因“加水”自动生成 |

不把所有水都改名为纯水，不默认现有蜂蜜、岩浆或任意 MOD 液体都能通过基础泵和管道。

### 4.2 气体资源

| 内容 | 来源 | 主要去向 | 规则 |
|---|---|---|---|
| 氧气 | 含氧大气按概率抽取、水电解 | 增氧燃烧、气体发动机、后续呼吸供气 | 管内使用明确氧气身份；大气中没有氧气库存时抽取概率为零 |
| 氮气 | 含氮大气按概率抽取 | 气罐、显式排放、后续工业用途 | 管内使用明确氮气身份，不由水电解生成 |
| 氢气 | 水电解；其他来源由星球或反应定义明确配置 | 气体发动机、后续化工与推进系统 | 不能默认从普通空气大量取得 |
| 二氧化碳等其他主要气体 | 后续星球定义或反应 | 对应气罐、后续化工 | 接入时使用独立气体身份；稀有气体和未使用的微量成分暂不纳入 |

大气按各具体气体的储量记录，是气体泵的来源；管内不保存一种模糊的“空气”物品。气体资源保存在管道、气罐和设备腔体内，便携气瓶保存具体气体身份与数量，不为每种充装量创建新物品。

### 4.3 数量与身份

- 每个存储腔保存相态、稳定内容身份、实际数量和温度；气包保存明确的 `GasId`，例如氧气或氮气。
- 一节气管、一只单腔气罐或一个气体设备腔，同一时刻只保存一种 `GasId`；同种气体可以在容量内合并，剩余量清零后才能换种类。
- 同一条气管可以让氧气、氮气等气包在不同管格依次通过，每个气包仍只有一种气体身份。
- 换星球或更改大气配置不能重写已经抽出的气包、罐内气体身份或数量。
- 液体界面容量和流量拟用 `L`、`L/s`；气体拟用固定参考温压下的标准体积，界面明确标为“标准 L”，不表示罐内实际几何体积。
- 世界液深、既有容器份数和显示体积分别换算。世界取液沿用定义中的 `DepthPerServing`，每份对应多少显示体积另行配置，不能默认为一份就是一升。
- 化学反应以物质的量和质量守恒核算，再转换为存储单位；不能直接按液体升数生成同升数的气体。

## 5. 液体泵

液体泵用于从已有世界液体来源取液，并把实际取出的内容送入封闭生产线。

- 第一轮使用电力驱动，保留额定流量和接受的液体种类配置。
- 取液口指向一个明确的世界格；只有该格存在允许的液体时才工作。
- 出液口连接相邻管道或储液罐输入口，不把液体直接塞进任意附近设备。
- 每次抽取先检查下游身份、容量和本次流量预算，再可靠地提交世界扣量与入管。
- 最终世界抽取复用 `WorldLiquidSourceResolver` 与 `WorldLiquidSystem.TryPump`，不通过地块名称猜测水源。
- 无水、无电、下游满、管网装着气体、液体不匹配或温度超出设备能力时停止抽取。
- 供电不足时降低实际流量；不把额定流量当作已经搬运的数量。
- 储罐向其他储罐转移也可使用液体泵的容器取液模式；该模式使用端口，不重复调用世界取液入口。

## 6. 气体泵与大气来源

### 6.1 气体泵的职责

**气体泵由机械动力驱动，通过“抽取速度 × 实际工作时间”累计进度，完成一份进度后才抽出一份具体气体。** 此时按所在地星球当前大气成分的概率选择 `GasId`，实际进入泵缓冲腔的数量同时从对应气体余量扣除，之后按气包进入管道。

- 第一轮具备环境进气口、气体输出口和机械输入轴口；电力可通过已有电动机转换为机械输入。
- 进气口读取当前位置所属星球、维度和环境的大气定义。
- 沿用机械系统规则：输入扭矩达到设备需求且转速非零时才能工作，转速绝对值决定抽取速度；扭矩不足时暂停，不按不足比例继续加工。

```text
有效抽取速度（份／世界秒） = 基础抽取速度 × 输入转速绝对值 / 基准转速
本次进度增量（份） = 有效抽取速度 × 本次实际工作的世界时间（秒）
累计进度达到 1 份 → 按当前大气成分抽签 → 扣减对应气体余量 → 生成一份气包
```

- 基础速度、正值基准转速和所需扭矩由设备配置；速度随输入转速线性变化，气体概率与普通气包大小不随转速改变。
- Tick 只负责结算本次工作时间，不再规定每 Tick 产出一份；进度不足一份时不产气、不抽签、不扣大气。
- 转速发生变化后按各段实际速度累计；成功生成一份气包才消耗一份进度，有效工作形成的小数余量保留到下一份，不直接清零。
- 完成周期按先后结算，每生成一包都核对缓冲容量；前一包已送完且仍有管网转移预算时才继续下一份。吞吐不足时暂停，只累计真正工作的时间，不积存多份完整的待产气进度。
- 玩家不能在普通泵上指定只抽氧气；想持续把氧气送往同一支路，使用气体筛选管道按气包种类分流。
- 泵保留一个单种气体缓冲腔，容量至少容纳一份；已有气包未送完时保留该气体并暂停下一份进度，不覆盖或混装。
- 输出堵塞时保留已抽出的气包与未完成进度，不能反复重新抽签直到得到下游需要的气体，也不能自动丢掉氮气。
- 抽签、余量检查、扣量、气包入腔与进度消耗由同一次权威结算提交；失败不扣量、不消耗进度，之后向管道转移不能再次扣大气。
- 真空、大气已抽空、未配置可抽取大气、进气口浸在液体里、无动力、扭矩不足、出口堵塞或下游装着液体时暂停抽取，保留已有进度；恢复条件后继续，不补计停机时间。
- 停动力只停止抽取，缓冲中已有气包仍可按管网运输规则送出。
- 首轮按机械输入决定抽取速度；低密度大气对速度的影响留待平衡，不通过缩小普通气包来替代进度。
- 输出温度来自实际环境，不能默认所有星球都输出常温空气。

### 6.2 大气配置

大气来源是需要新增的环境能力，以下内容属于规划：

- 星球大气的初始总体积，以及当前剩余总体积。
- 大气中各主要气体的稳定 `GasId`、初始成分比例、当前剩余标准体积和有效密度；稀有气体暂不纳入。
- 有大气的星球，初始成分比例须为有限非负值并归一化为 100%；未配置或当前余量为零的气体不参与抽取。
- 所在维度引用哪个大气来源；共享同一星球大气的维度引用同一份储量，不各自复制一份气量。
- 来源查询返回每种气体的当前余量、成分比例、温度与密度，由权威侧统一抽签并决定实际抽取量。

**大气是有限但总量非常巨大的气体储备，确实可以被抽干净。** 初始数值应远大于普通泵和气罐的处理规模，日常采集可以长期持续；即使储量很大，每次有效抽取也必须扣量。余量为零后停止从该来源产气，不自动补满。

例如当前大气为氧气 20%、氮气 80%，每完成 1 份抽取进度，抽中氧气的概率为 20%，抽中氮气的概率为 80%；抽中哪一种就生成 1 份该气体。短期结果可以有随机偏差，不强制每五份固定输出一份氧气。

```text
抽中某气体的概率 = 该气体当前剩余标准体积 / 全部可抽取气体当前剩余标准体积之和

20% 氧气、80% 氮气的来源
    ↓ 每完成一份抽取进度，抽签一次
可能依次输出：氮气包 → 氮气包 → 氧气包 → 氮气包 → 氧气包
```

- 1 份对应固定的配置标准体积，普通气包大小一致，泵缓冲与基础气管容量须能容纳一份；动力只改变完成一份所需时间。
- 抽取和回排改变各气体余量后，重新按当前余量比例计算概率；某种气体耗尽后概率为零，总量为零时停机。
- 抽中气体的余量不足一份时，仍须完成一份进度，再生成该种气体的最后一包余量；这是抽干来源的尾量例外，不能为凑满一份混入另一种气体。

氧气和氮气作为初始大气的主要成分参考，20%／80% 是游戏示例配置；不同星球各自配置，不能硬编码在泵里。[参考：NOAA 大气组成](https://www.noaa.gov/jetstream/atmosphere)

### 6.3 星球大气体积字段

建议在星球运行与存档数据中规划以下核心字段，尚未修改 `PlanetData` 代码：

| 拟定字段 | 含义 | 计量方式 |
|---|---|---|
| `PlanetData.AtmosphereGasVolume` | 星球当前剩余的大气气体总体积 | 统一参考温压下的标准 `m³`，有限非负值 |
| `PlanetData.AtmosphereGasVolumeByGasId` | 按具体 `GasId` 记录每种大气气体的剩余体积 | 与总量共用标准 `m³`，各项有限非负 |

- 新世界从星球定义读取非常巨大的初始体积，按初始成分比例分配各气体余量；无大气星球初始化为零，具体初值后续平衡。
- 大气总量必须等于各具体气体余量之和；两者由同一次权威事务更新，不能形成两份互不一致的库存。
- 该字段表示剩余气量，不是只读的初始规模或抽取统计；存档恢复当前值，不因进出星球、维度切换或重启游戏重新填满。
- 与管道、气罐的标准体积共用同一参考温压，`1 标准 m³ = 1000 标准 L`；不把实际大气层的几何空间直接当作可抽取量。
- 一颗星球上的所有气体泵、玩家和共享大气的维度共同使用这一字段；每台泵不能持有各自独立的可抽取副本。
- 权威侧先核对泵缓冲容量与抽中气体余量，再在一次可靠转移中完成该气体扣量、总量更新和气包入腔；失败不扣，多个泵不能重复领取最后一份气体。
- 抽中气体余量不足一份配置体积时，只抽走真正剩余的部分，并把该气体余量结算为零；不能出现负体积。
- 大气总量非常大，计量必须保留小额抽取的累计精度；不能因使用低精度大数而让普通泵的扣量消失。具体数值表示、范围与最小单位在实现时确定。
- 抽中氧气只减少氧气库存，抽中氮气只减少氮气库存；回排时按气包的 `GasId` 返还同种气体，并更新总量及成分比例。
- 大气储量与星球气压按下一章的首轮规则联动；抽空停机、异常气压伤害和服装防护属于本阶段，完整呼吸与天气反馈后续细化。

现实大气储量的规模可参考 [NASA 地球资料](https://nssdc.gsfc.nasa.gov/planetary/factsheet/earthfact.html)，游戏初始体积仍由星球配置决定。气体计量需要统一温压口径，可参考 [NIST 气体流量计量](https://www.nist.gov/laboratories/tools-instruments/gas-flow-standards)。

## 7. 星球大气压与生物生存

### 7.1 星球气压数据

大气压使用绝对压力，统一显示为 `kPa`；不同星球各自配置基准气压，不能让所有星球共用一个固定数值。

下表为拟定数据与查询概念，尚未新增代码：

| 拟定字段／属性 | 含义 | 归属 |
|---|---|---|
| `AtmosphereReferenceGasVolume` | 产生该星球基准气压时的大气气体标准体积 | 星球基准参数，标准 `m³` |
| `AtmosphereReferencePressureKPa` | 上述基准体积对应的星球大气压 | 星球基准参数，`kPa` |
| `AtmosphereGasVolume` | 当前剩余气体标准体积，抽气时扣减、回排时增加 | 星球权威运行与存档状态 |
| `AtmospherePressureKPa` | 根据基准参数与当前储量得到的当前气压 | 只读派生值，`kPa` |

首轮采用明确的游戏简化，固定有效大气空间与温度口径，按剩余气量比例改变气压：

```text
当前气压 = 基准气压 × 当前大气标准体积 / 基准大气标准体积
```

- 有大气的星球必须配置有限正数的基准体积和基准气压；初始储量通常取基准体积，具体数值由星球定义决定。
- 无大气的环境气压为零；抽空后的当前气压也为零，不能因存在基准参数而继续返回正常气压。
- 抽取减少当前储量和派生气压；回排按真实数量增加储量并更新气压，不能只恢复界面读数。
- 基准参数与当前储量属于同一星球状态，随星球保存和恢复；当前气压不再另存一份可独立修改的真值。
- 同一星球相同大气来源的玩家、生物和设备读取同一个权威气压；维度通过其实际大气来源查询。
- 以上是首轮运输与生存联动规则，不宣称完整复现重力、海拔、温度和大气组分变化造成的真实气压。

### 7.2 生物安全气压范围

每种需要气压生存判定的生物，在自己的定义中配置基础安全范围：

- `SafePressureMinKPa`：能够安全生存的最低环境气压。
- `SafePressureMaxKPa`：能够安全生存的最高环境气压。
- 最低值不得小于零，最高值不得低于最低值，两个值都必须有限。
- 玩家、普通动物、异星生物使用各自配置；不能默认所有生物拥有相同的地球式耐受范围。
- 低于下限进入低压危险，高于上限进入高压危险，处于闭区间内则气压安全。
- 原生生物的生成与栖息条件应匹配其星球气压；大气被改变后，它们也会受到对应环境影响。
- 不需要气压判定的实体通过能力配置明确排除，不按名称猜测机械体、幽灵或某种生物是否免疫。

```text
星球当前气压
    ↓
生物基础范围 + 当前装备修正
    ↓
低于下限 → 低压危险
高于上限 → 高压危险
范围以内 → 气压安全
```

### 7.3 衣服与气压耐受

现有 `EquipmentInstance_ThermalInsulation` 通过 `SetSafeTemperatureRangeModifier` 扩展耐寒／耐热范围。气压防护采用相同的“装备修正安全范围”方式，使用独立气压属性，不复用温度数值。

拟定服装属性：

- `LowPressureToleranceIncreaseKPa`：增加低压耐受能力，用于降低安全下限。
- `HighPressureToleranceIncreaseKPa`：增加高压耐受能力，用于提高安全上限。

```text
有效安全下限 = max(0, 生物基础下限 - 当前装备低压耐受增量之和)
有效安全上限 = 生物基础上限 + 当前装备高压耐受增量之和
```

- 衣服扩展生物耐受范围，不改变星球气压，也不替生物改写基础种族参数。
- 耐压属于穿戴后生效的被动属性，和衣服的保温、保暖能力采用相同思路，不消耗氧气、电力、燃料或服装耐久；脱下衣服时撤销耐压修正。
- 多件装备按独立来源登记和撤销修正；脱下、替换、销毁、重载或回收时清掉对应来源，不重复叠加。
- 普通衣服默认没有气压防护；低压防护服、高压防护服和组合防护服通过配置提供相应增量。
- 首轮将服装的密封与承压能力抽象为安全范围修正，具体内部服压和逐部位泄漏模型后续再做。
- 同一件衣服可以同时配置耐寒、耐热、耐低压和耐高压，四项能力各自结算；耐寒不自动等于耐低压。
- 达到安全范围后，气压伤害停止；防护不足时仍持续受到异常气压伤害。
- 气压防护不自动提供氧气，也不自动解除有毒气体风险；供氧与可呼吸气体条件单独规划。
- 装备面板分别显示低压与高压保护增量，角色面板显示穿戴后的有效安全气压区间。

压力防护和供氧在现实防护服中承担不同职责，可参考 [NASA 舱外服组成](https://www.nasa.gov/centers-and-facilities/johnson/spacewalk-spacesuit-basics/)。这里采用面向玩法的服装耐受抽象，不展开完整生命保障设备模拟。

### 7.4 异常气压伤害与死亡

异常气压像异常温度一样构成持续环境危险；超出有效范围且保护不足的玩家和生物会掉血，长期停留可以死亡。

- 低压和高压使用不同的危险状态、来源标识与伤害配置，不能把上下限两侧都叫作高压挤压伤。
- 首轮通过气压危险缓冲和周期伤害表现；缓冲容量、恢复速度、伤害间隔与每次伤害量由生物配置，不预设最终数值。
- 气压危险缓冲独立于温度缓冲；低压与高压切换继续消耗同一份气压缓冲，不能切换危险类型就重新获得完整保护时间。
- 回到有效安全范围立即解除当前气压危险来源，缓冲按配置逐步恢复；穿脱装备或手动清 Buff 不能直接补满缓冲。
- 缓冲耗尽后，低压或高压危险挂载对应环境伤害来源，按独立时钟周期扣血，不每帧直接减生命。
- 生命结算接入现有统一伤害与死亡流程：GO 目标走 `DamageReceiver`，原生 ECS 目标走对应权威结算；气压查询、面板和装备模块不直接写 HP。
- 物理护甲的常规防御不自动抵消气压伤害；气压保护由有效耐受范围决定，避免普通金属护甲意外获得完整环境免疫。
- 低压、高压、冷热和其他伤害来源各自管理时钟；解除对应危险、死亡、重生或回收时清理该来源的伤害时间债务。
- 重生重新初始化新生命的气压缓冲和装备修正，不让上一条生命的延迟伤害继续扣血。
- 同一危险只提交一次伤害，不由气压模块、气压 Buff 和界面各自扣一遍；也不把同一笔低压伤害再重复记为缺氧伤害。

### 7.5 伤害表现与现实边界

- 低压表现可以使用呼吸困难、低压不适、失压损伤等提示；高压表现使用挤压不适或压力损伤提示。
- 肺部、耳部等压差伤害来自体内外气体空间的压力差及其变化，不宜把全部情况统称为“内爆肺泡”。[参考：CDC 压力损伤说明](https://www.cdc.gov/yellow-book/hcp/environmental-hazards-risks/scuba-diving-decompression-illness-and-other-dive-related-injuries.html)
- 首轮统一结算低压／高压环境生命损失；具体肺部损伤、压力骤变伤害和永久性部位损伤后续再接现有身体部位系统，不给所有物种凭空假设一套人类肺部。
- 提示玩家“气压过低”“气压过高”“当前服装防护不足”，同时显示当前气压和安全范围，方便玩家判断是否需要换衣服或离开环境。

### 7.6 宇航服配置页面与供氧气罐

宇航服使用同一个配置页面管理供氧气罐；手持入口和装备界面入口都操作对应的宇航服实例，不各自保存一份配置。

#### 7.6.1 手持宇航服右键打开

- 玩家手持宇航服时，右键打开这件宇航服的配置页面。
- 未穿戴的宇航服也能配置气罐；打开页面不自动穿戴宇航服，也不单独触发供氧或额外耗氧。
- 页面显示当前宇航服、气罐插槽、气体内容、剩余氧气和空罐状态。

#### 7.6.2 从装备界面打开

- 玩家装备界面为支持配置的宇航服提供配置按钮，点击后打开同一个宇航服配置页面。
- 页面绑定按钮对应的那件装备，不能误改背包中的另一件宇航服。
- 穿脱或替换宇航服后，配置页面应关闭或明确切换绑定对象，不能继续操作已经失效的装备槽引用。

#### 7.6.3 拖入氧气罐与替换空罐

- 首版提供一个可携带供氧气罐插槽；玩家从背包把适配、带有可用氧气的气罐拖入插槽，不把固定储气建筑当作服装附件。
- 插槽为空时装入气罐；插槽已有气罐时，拖入新罐完成替换，原来的空罐或剩余气罐返回拖入来源槽或背包可用位置。
- 替换作为一次完整的物品交换处理；没有位置容纳原罐时拒绝替换并提示原因，不删除、复制或静默丢弃原罐。
- 气罐耗尽后保留空罐，页面显示需要更换；玩家可以拖出旧罐，再拖入带氧气的新罐。
- 插槽接受条件由供氧能力配置决定，首轮使用明确氧气身份的供氧气罐，拒绝不适配的物品、氮气罐或氢气罐；不能把其他气体改标签当作氧气。
- 实际供氧才消耗罐内氧气；供氧启停条件和耗氧速度由呼吸系统配置，界面只展示和提交换罐操作。
- 没有气罐、气罐为空或供气不适配时停止供氧并提示；宇航服的被动耐压仍然生效，不因氧气耗尽而扣除耐压能力。
- 气罐与剩余内容属于宇航服实例的配置，随装备移动和存档保存；切换两个入口、关闭或重开页面不能生成新气罐或恢复氧气。
- 宇航服用便携供氧气罐纳入生存首轮；其他用途的通用气瓶、完整高压模型和独立压缩设备仍按后续规划。

## 8. 通用管道与连通规则

### 8.1 同一种管道运输两种相态

- 管道使用独立流体覆盖层，与电线及机器主体按各自端口连接。
- 空管道可以接液体系统，也可以接气体系统；第一次有效入管后确定相态，气管每格另保存当前具体 `GasId`。
- **同一条实际连通管网内，液体与气体不能共存。** 不能让一半管段装水、另一半装气，再通过同一连通空间运输。
- 液体管网首轮仍只装同种液体；气体管网允许不同气体在不同管格依次运输，每格同一时刻只装一种气体。
- 不同 `GasId` 的气包不能注入同一非空管格或存储腔；同种气体按目标容量接收，目标清空后才允许换种类。
- 管道、阀门和存储腔共同参与全网相态校验，每次转移再检查目标格的具体气体身份和端口条件。
- 液体网与气体网相接、或两种不同液体网相接时拒绝放置或开阀；两条气体网不因已有不同气体而拒绝连接，但各管格保持原内容并按气包规则运输。
- 多腔设备的不同端口彼此隔离；电解器的水腔、氢气腔和氧气腔不会因为属于同一台机器而连成一张流体网。

### 8.2 连接与分支

- 管道按上、右、下、左四个方向连接兼容的相邻管道及设备端口。
- 设备端口区分输入、输出或双向，朝向随设备旋转；没有端口的设备不会自动接入。
- 普通直管、弯管和三通由连接形状派生，不为每种形状新增库存物品；气体筛选管道因具有端口分流与配置能力，是独立的三通管件。
- 支路共享实际来源与流量预算，不让两个出口各取得一份完整来源量。
- 相邻放置但没有兼容端口的管网保持独立；首轮不增加跨管桥，确有布线需求时再规划。

### 8.3 首轮流动机制

- 每段管道具有有限容量、最大转移速率和真实存量，不能只保存一个全网总数。
- 液体普通连接用填充比例差产生简化流动；气体按单种气包向有效输出逐格转移，保留相应容量与流量限制，不把调度称为真实压力。
- 在固定世界 Tick 中先读取同一批存量并计算候选转移，再按来源存量、目标余量和边流量上限统一缩放并提交。
- 单次实际转移不超过 `最大流量 × 本次世界时间步长`，也不超过来源存量或目标余量。
- 同一轮收到的流体不能沿任意长度管线反复转移，避免管线长度越大反而无限加速。
- 气包进入空格或同种气体的未满格；目标仍有其他气体时等待，不能穿过、覆盖或合并成一个多气体包。
- 多种气体同轮竞争一个空格时，只接收其中一种；按稳定节点 ID 轮转选择，其余保留在来源，不能同时灌入两种气体。
- 循环管网、多来源和分支采用稳定的结算顺序；满目标不能继续吞掉来源。
- 液体与气体共用调度流程，但保留各自单位、容量与相态校验，不借用地表液体的流动算法。

### 8.4 阀门、排空和换介质

- 阀门关闭会切断连通关系，但保留阀门及两侧管段已有内容。
- 开阀前重新检查两侧网络的相态和内容是否兼容。
- 改装水管为气管，或改装气管为水管，必须先排空实际连通的管段和存储腔。
- 优先把流体转移到兼容容器；液体只有具备有效世界承载定义时才可排到地表。
- 气体可以通过明确的排放口回到对应星球的大气储备；按气包 `GasId` 将实际移出的数量返还该种气体库存，同时更新总量和成分比例，不默认清空满罐或删除气体。
- 主动拆除含流体的管段或罐体前要求排空，不能把“拆除”当成免费删除内容或换介质按钮。
- 战斗破坏后的泄漏、损失和环境效果另外规划，不假装已有完整泄漏模拟。

## 9. 储液罐与气罐

两者都提供生产缓冲，但接受的相态不同。

- 储液罐只装液体；气罐只装气体。共用存储能力不意味着取消设备身份。
- 每个罐体首轮只有一个存储腔，具备独立输入和输出端口。
- 空罐首次接收后确定内容身份，已有内容时只允许输入相同介质。
- 一只气罐同一时刻只装一种明确气体，例如氧气、氮气或氢气；空罐可选择接收种类，已有内容时只接收同种气体。
- 气泵输出的不同气包直接进入单腔气罐时，遇到不同气体会堵塞；应先经过气体筛选管道，再分别送入对应气罐。
- 输入按剩余容量收取，输出按实际存量扣除；不因同时进出而重复结算。
- 面板显示内容、数量／容量、温度、输入流量、输出流量和停机原因。
- 气罐首轮使用固定容量与填充比例，不实现完整压力、气体压缩和温度膨胀方程。
- 便携高压气瓶属于后续阶段，必须经过压缩／灌装设备；基础气罐不自动等于高压气瓶。

## 10. 过滤器与蒸馏器

### 10.1 过滤器

过滤器用于液固分离，不是能够消除所有杂质的通用净化器。

- 具备液体输入腔、过滤液输出腔和固体残渣槽，由电力驱动加工。
- 具体可过滤的原料、滤材要求、液体产物和残渣来自材料／配方定义，设备不按物品名称硬编码。
- 普通过滤移除允许的悬浮颗粒，不直接去掉溶解盐，也不自动消除全部饮用风险。
- 水处理产物为对应过滤水；是否可以饮用仍由该液体定义与后续处理决定。
- 矿浆过滤必须有明确的输入、滤液和固体产物，不能把任意矿粉加水直接变成纯金属。
- 滤材消耗或清理周期作为配置；残渣槽满、液体出口满、滤材不足或无电时停止加工。
- 加工预留全部产物容量，再在一次事务中扣原料与滤材、提交产物，不先吞输入再等待空槽。
- 普通液体过滤器不处理气包；按气体种类筛选分流由下一章的气体筛选管道负责。

### 10.2 蒸馏器

蒸馏器负责蒸发并冷凝允许的含水原料，补齐“过滤水到工业纯水”的生产步骤。

- 消耗实际供热和冷凝能力，产出工业纯水与配方声明的浓缩残液或固体残留。
- 首轮把蒸发、冷凝封装为同一设备，不要求玩家先铺蒸汽回路；内部蒸汽不会与外部液体管网混装。
- 不把现有的煮沸饮用水处理自动当成工业蒸馏。
- 蒸馏产量受实际水含量和加工预算限制，纯水及所有残留物合计遵守物质守恒。
- 只接受已定义蒸馏规则的原料；不能宣称任意未知污染物都能靠蒸馏完全去除。
- 供热不足、冷凝能力不足或任一产物存储满时停止。

过滤、消毒、膜处理和蒸馏在现实中承担不同作用。此处的“工业纯水”是游戏加工等级，不宣称一种设备能处理所有污染物。[参考：CDC 水处理方式](https://www.cdc.gov/drinking-water/about/about-home-water-treatment-systems.html)

## 11. 气体筛选管道

气体筛选管道是一件可配置的三通管件，具有一个输入口和两个输出口，按配置目标分流输入的单种气体包。

### 11.1 三个端口与分流规则

```text
输入：不同种类的气包依次到达
                 ↓
气体筛选管道（配置目标：氧气）
                 ├→ 输出1：只输出氧气包 → 氧气罐
                 └→ 输出2：其他气体包 → 继续筛选、储存或排放
```

- 三个端口只接受气体网络，分别固定为输入、输出1和输出2，随管件放置朝向一起旋转；输出口不能反向充当输入口。
- 输入气包的 `GasId` 等于配置目标时，只送往输出1；其他气体只送往输出2，不把它们统一改名为氮气。
- 输出2表示筛掉目标气体后剩余的其他气包；每个气包仍只有一种气体，输出2管线也保持一格一种气体。
- 管件复用气管的容量、流量与固定 Tick，不额外增加独立分离加工流程；首轮不增加电气口。
- 气体身份、数量和温度随原气包转移，筛选只改变路径，不生成、消耗或转换气体。

### 11.2 配置 UI

- 玩家交互已放置的气体筛选管道，打开对应管件的配置页面。
- 页面选择一个已注册的目标气体，并明确显示“输出1：选定气体”“输出2：其他气体”，同时标出三个端口实际方向。
- 未选择目标气体时暂停转发并提示选择；不能悄悄默认改变气包方向或内容。
- 配置更新后按新目标判断尚未输出的气包；已经进入下游的气体保持原身份和数量。
- 保存目标 `GasId`、管件朝向和当前缓冲气包；UI 提交配置意图，由权威端校验并更新，页面不直接搬运气体。

### 11.3 堵塞与可靠转移

- 每次只检查该气包实际对应出口的容量与气体兼容性；另一个出口满不会直接阻止当前气包通过。
- 对应出口已满、未连接或目标管格装着不同气体时，保留当前气包并等待，不能改走另一出口。
- 阻塞气包占用管件缓冲时，后续不同气体不能穿过、覆盖或被自动删除；玩家需要疏通对应支路。
- 同种气体允许按容量部分转移，剩余量保留原气体身份；两个出口不能各得到一份完整输入。
- 输出2需要排放时必须接明确排放口，按实际气包种类和数量回到星球对应库存；筛选管道不会自行丢弃未选中气体。

## 12. 电解器与气体消费

### 12.1 水电解器

电解器消耗工业纯水和电力，分别向两个气体腔输出氢气与氧气。

```text
2 H₂O + 电能 → 2 H₂ + O₂
```

该式表示物质的量比例，不表示“两升水产生两升氢气和一升氧气”。[参考：DOE 水电解制氢](https://www.energy.gov/cmei/fuels/hydrogen-production-electrolysis)

- 首轮水电解配方只接受定义允许的工业纯水，不把原水、盐水和任意液体按同一规则电解。
- 具备一个液体输入腔、一个氢气输出腔和一个氧气输出腔；两个气体出口分别连接管道。
- 两种气体必须在同一反应事务中按比例生成，不能只有接通的一侧产气。
- 任一气体输出腔满时，限制或停止整次反应；不默认删除另一种气体。
- 首轮采用欠供电降速规则，实际反应量受取得电能、输入量、输出容量和设备额定能力共同限制。
- 电极寿命、加工效率和散热能力使用配置；催化材料没有消耗规则时不能按每次反应额外吞掉。
- 电解余热来自已定义的能量预算，不在反应产物之外再凭空增加加热能力。
- 氧化铝电解等高温工艺后续接入相同加工／端口框架，但使用独立条件和设备等级，不宣称普通水电解器可以直接炼铝。

### 12.2 增氧燃烧

- 氧气通过独立输入接口供给炉类加工，与现有燃料、供热和材料反应共同结算。
- 实际温度提升受燃料、氧气供给和炉体耐温限制；氧气不能单独生成燃料热量。
- 停止供氧时按设备配方退回普通空气燃烧或停止对应增氧工艺，不把缺氧时的上一轮增益继续保留。
- 新增供氧能力复用现有炉类加工，不创建与 `FurnaceLogic` 并列的第二套炉体业务。

### 12.3 气体发动机

气体发动机燃烧可燃气体，输出机械动力，作为机械网的新动力源；需要发电时连接已有发电机。

```text
氢气 + 氧气 → 气体发动机 → 机械动力 → 机械设备
                                      └→ 已有发电机 → 电力网络
```

- 首轮使用实际氢气与氧气输入；普通空气、氧气和氮气不能单独当作燃料，缺少任一必要输入时停机。
- 实际燃烧量受气体输入、设备额定能力、机械负载和回收水输出余量共同限制；停用或无可用负载时停止燃烧。
- 输出扭矩、带符号转速和机械轴口接入已有机械网，转速冲突与负载分配沿用既有规则；发动机自身不直接向电网提供电力。
- 首轮将机内冷却、冷凝抽象为回收水出口，按实际氢气燃烧量生成水；出口堵塞时停机，不默认删除产物。
- 机械输出与余热共用实际燃料能量预算，不能各自领取一份完整燃料能量；效率、额定转速和扭矩后续平衡。
- 从电解、存气、气体发动机到发电机的总电能回收率必须小于 100%，不形成循环发电增益。
- 用途是把基地多余电力转成可运输的气体储备，在远处提供机械动力，并通过已有发电机提供电力。
- 后续其他可燃气体使用各自反应配方、燃值和产物，不把所有气体都按氢气燃烧产水处理。

内燃机将燃料的化学能转换为机械能，发电机再将机械能转换为电力；本体采用上述加工抽象。[参考：DOE 内燃机与机械能说明](https://www1.eere.energy.gov/hydrogenandfuelcells/pdfs/hydrogenenergyfuture_web.pdf)

## 13. 交互与状态表现

- 放置预览显示连接端口和方向；液体口、气体口、电气口和机械轴口在形状和图标上可区分，不只依赖颜色。
- 通用管道逐格显示具体气体种类、填充程度与流向，让不同气包可区分；外观变化不改变管道物品身份。
- 选择设备时显示实际连接的输入、输出和当前内容，不要求玩家逐台猜测流向。
- 气体泵面板显示输入转速、扭矩是否足够、当前抽取速度、下一份的 0%—100% 进度、缓冲气包与暂停原因，并提供大气各组分余量和当前概率；真空或总余量为零时说明没有可抽取大气。
- 气体筛选管道的配置 UI 显示选定气体、输入及两个输出端口、当前气包与对应出口的堵塞原因。
- 环境与角色面板显示所在星球当前气压、角色有效安全区间及低压／高压危险；穿脱装备后立即更新保护范围，不能只显示衣服的基础描述。
- 过滤器显示原料、滤材、产物和残渣；电解器显示两种气体余量及各自堵塞状态。
- 状态说明使用“没有电”“没有动力”“动力不够”“入口没有水”“出口已满”“这条管道里装着气体”“这一格还有氮气”“输出1被堵住了”等直白文案。
- 普通工作面板沿用现有非模态交互；显示只读取权威数据，不在界面里累加流量或生成产物。

## 14. 数据、运行与扩展边界

### 14.1 机器与运输

- 落地设备复用现有 `MachineWorld` 生命周期、交互和库存组织方式；机械、电力和流体保留各自独立拓扑。
- 本规划不另建并列的化工机器世界；新增流体图负责连通与转移，气体筛选管道使用其端口分流能力，液体过滤与反应留在设备加工逻辑。
- 液体端口与气体端口共享发现、预检、可靠提交和通知流程，但保留各自相态与数量单位。拟定的气体端口属于新增能力，不视为已有接口。
- 两端搬运和多产物加工都由权威侧提交；预检不扣量，失败必须保持原有内容。
- 材料和配方定义接受条件与结果，设备提供容量、温度、机械输入、供电及加工能力，不集中维护按内容名称排列的特殊分支。

### 14.2 保存、休眠与联机

- 保存每段管道、每个罐体和设备腔体的具体内容 ID、数量与温度，同时保存阀门状态、筛选管道目标气体和加工余量。
- 保存气泵未完成的抽取进度、缓冲中的具体气包及抽取随机状态，恢复后继续原进度和原气包；读档不能清零进度、重新抽签或重抽一份库存。
- 星球大气总量与每种气体余量沿星球存档保存和权威同步，恢复时保持总量等于各项之和；不在区块或每台泵中复制一份来源库存。
- 同时保存星球气压基准参数，恢复后从真实剩余储量推导当前气压；生物保存自己的剩余气压缓冲，基础耐受参数读取生物定义，装备修正按当前穿戴重新建立。
- 不只保存全网总量，否则拆分网络、关阀和卸载后无法知道流体在哪一段。
- 恢复节点和全部连接后再开始结算；视图卸载不能删除管网内容。
- 首轮整条相连流体网络共同激活或休眠，不只让可见半段持续工作；具体活动窗口和网络规模上限待规划。
- 休眠期首轮不追算产量，停止运输和加工，气泵进度冻结；供电、抽水与取气使用一致的激活边界，唤醒后不补计休眠时间。
- 联机客户端发送操作意图，服务端校验来源、容量与连接；气泵进度、概率抽取与筛选配置由权威端结算，客户端不独立推进进度、抽签、抽水、抽气或电解。
- 气压危险、缓冲推进、伤害与死亡由状态权威端统一结算，客户端仅展示气压与生存状态。

### 14.3 MOD

- 液体、具体气体、星球大气成分、设备能力和加工规则使用稳定内容 ID；MOD 使用自己的命名空间。
- 内容型 MOD 可以配置已注册能力，新增流体不要求修改每种泵、管道或罐体的核心逻辑。
- 自定义端口／反应算法需要正式注册扩展能力，不能把 JSON 当作可直接装入新 C# 行为的机制。
- 配置发布前检查相态、数量单位、大气初始比例与各气体余量、每份气量、气泵基础速度及正值基准转速、所需扭矩、筛选目标、三通端口、容量和反应守恒；未知气体和错误端口明确报错，不静默改成水或氧气。
- MOD 星球、生物和衣服共用大气储量、气压基准、安全范围与装备修正配置；气压范围和保护增量必须有限且合法，不能绕过统一环境伤害与死亡结算。

- [ ] 提供低压、高压防护服，通过当前装备来源被动扩展耐受范围，不消耗资源，穿脱与回收正确撤销修正。
- [ ] 接入手持宇航服右键和装备界面配置按钮，两种入口复用同一个宇航服配置页面。
- [ ] 接入便携供氧气罐插槽、拖入装罐与空罐替换，正确返还原罐并保存实际氧气余量。
- [ ] 将异常气压伤害、死亡与重生接入各实体的既有权威流程。
- [ ] 显示当前环境气压、有效安全范围、服装保护和危险状态。

### 15.4 后续由用户进行的游戏观察

- [ ] 液体泵取液后，世界来源实际减少，罐内实际增加。
- [ ] 扭矩足够时，转速改变完成一份所需的时间；进度不足一份时没有气包、大气扣量或提前抽签。
- [ ] 无动力、扭矩不足、堵塞与休眠时暂停进度；恢复和读档后继续原进度，不补出停机期间的气包。
- [ ] 调整 Tick 步长后同样实际工作时长对应同样有效进度；有效小数余量保留，高转速产气仍受单包缓冲与管网吞吐限制。
- [ ] 多台气体泵共同减少同一星球的大气余量，抽空后停止产气，余量不足时只抽取剩余部分。
- [ ] 极大初始储量下的小额抽气仍能累计扣量，存档重进不重新填满；回排不会同时保留管内气体而复制储量。
- [ ] 按大气配比概率输出具体气体，单次气包只有一种 `GasId`；零余量成分和真空不能产气，回排按实际种类返还。
- [ ] 不同气包能在同一气管的不同格依次通过；每格仍只装一种气体，堵塞后不会重新抽签、混装或吞掉气体。
- [ ] 管网装水后拒收气体，装气后拒收液体；关阀、接管和排空没有绕过规则。
- [ ] 满罐、分支、循环管、断电与重进游戏不会复制、吞掉或换掉内容。
- [ ] 普通过滤不会把盐水变成纯水，残渣和各加工产物不会被默认删除。
- [ ] 电解任一产物出口堵塞时按规则停机；筛选管道只向对应出口转移，出口堵塞时保留当前气包。
- [ ] 筛选管道 UI 更换目标、旋转和读档后，输入及两条输出的角色正确，气包身份和数量不被配置改写。
- [ ] 电解、存气、气体发动机和发电机闭环有能源损耗，机械输出与产物有明确去向。
- [ ] 不同星球和不同生物使用各自气压参数，耐受范围外会按规则持续掉血并可能死亡。
- [ ] 穿脱防护服正确改变有效范围，耐温与耐压互不冒用，重载后不重复叠加保护。
- [ ] 大气抽取减少气压、回排恢复对应气压，抽空后为零；跨维度和读档不会恢复一份虚假的正常大气。
- [ ] 重生、解除危险和对象回收后没有旧气压伤害继续结算，联机不会由客户端再扣一次血。

## 16. 后续待规划

- 各设备的容量、流量、功率、反应效率、耐温和精确合成材料。
- 液体份数到显示体积的配置，以及气体标准体积的统一参考温压。
- 各星球非常巨大的初始大气体积、组分、密度，以及各维度引用的大气来源。
- 大气体积字段的数值范围、最小计量单位与精度方案，确保巨大储备下的小额抽取确实累计。
- 各星球的具体气压基准、生物安全区间、气压缓冲、伤害数值及防护服的材料与耐受增量。
- 大气密度、海拔、组分和温度对气压的进一步影响，以及主动补充大气、呼吸供气与天气反馈。
- 压力骤变、具体身体部位损伤、服装内部压力与泄漏，以及固定基地的增压／恒压设备。
- 气包每份对应的标准体积、气泵基础抽取速度、基准转速和所需扭矩，以及筛选管道吞吐与气包输送的首批平衡。
- 滤材来源与寿命、蒸馏供热和冷凝的首批实现方式。
- 液体温度运输、管道换热及冻堵是否进入后续首批。
- 气体压缩、其他用途的便携气瓶、增压设备和高压管道；宇航服供氧气罐已列入生存首轮规划。
- 呼吸供气、泄漏扩散、战斗破坏与环境影响；实际取用或返回大气的气体按对应来源统一记账。
- 气体管网的腐蚀、燃爆以及相态变化。
- 管道跨越、长距离管网规模上限及活动窗口。
- 铝工业、酸碱、电镀、肥料、石油加工和推进燃料的接入顺序。

这些内容按实际玩法需要逐项展开，不因进入化工阶段就一次实现完整工业模拟。

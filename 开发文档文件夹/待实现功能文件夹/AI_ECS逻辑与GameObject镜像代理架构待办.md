# FlatWorld 生物 AI：ECS 模块、GameObject 镜像代理与 BRG

## 1. 系统定位

正式 Actor 生物统一由 AIECS 持有生命、位置、感知、行为和战斗状态。普通生物的高频逻辑按组件组合批量运行，身体由 BatchRendererGroup（BRG）绘制。只有外部 Unity 接口确实需要对象时，才从对象池租用 GameObject 镜像代理。

当前目录中的 Bird、Seagull、Bee、Chicken、WildBoar、Wolf、Ghost、Zombie、Sheep、Rabbit、SnowLeopard 共 11 种 Actor 都走这个入口。玩家仍由 GameObject 系统驱动。新存档使用 ECS 生物快照；旧版 GameObject 生物存档不做迁移。

```text
Actor JSON（能力清单与参数）
    → 定义编译器 → ECS 组件与共享规则
    → 批量感知 / 决策 / 移动 / 生存 / 战斗
    → BRG 身体与阴影
    → 按需租用 GameObject 镜像代理，接收旧 Unity 接口的输入
```

同一生物只有一个权威状态。代理不能运行旧 AI，也不能反向持有一套生命或移动状态。

## 2. 模块组合

### 2.1 定义与装配

Actor 定义的 `ecs.capabilities` 选择共享能力，`ecs` 下相应对象填写参数。纯 ECS 新物种可以用 `ecs.health` 指定生命和防御，不必新写旧 AI 或生命模块。定义编译器检查能力名称和必需依赖，生成实体模板。生物进入世界时，只装配它启用的可选组件；系统按组件查询批量执行，不按物种名分支。

| 能力 | 作用与依赖 |
| --- | --- |
| `movement`、`perception` | 基础移动与感知；每种 Actor 都必须有 |
| `nutrition`、`feeding` | 饱食消耗与觅食；`feeding` 依赖 `nutrition` |
| `sleep`、`flee`、`chase`、`combat` | 作息、逃离、追击与战斗 |
| `flight` | 飞行高度、速度和耐力 |
| `reproduction`、`eggLaying` | 繁殖时钟与产蛋；`eggLaying` 依赖 `reproduction` |
| `hiveMember` | 蜂巢归属、巡逻、召回、警戒、护巢和采蜜状态 |
| `pack` | 同伴援助与队形 |
| `charge`、`predator` | 冲锋与捕食追击参数 |
| `darkness` | 光照采样、避光和受光伤害 |

感知、决策、移动、战斗仍使用 AIECS 共同流程。特殊能力只向共享意图、速度、目标或结算队列提供数据；不得为每个生物恢复一套 MonoBehaviour 状态机。

### 2.2 当前物种组合

| 物种 | 主要能力 |
| --- | --- |
| Bird、Seagull | 觅食、睡眠、逃离、飞行 |
| Bee | 花蜜、飞行、蜂群、追击与战斗 |

| Zombie | 追击与战斗 |

表格只记录当前配置。物种差别以 Actor JSON 为准。

## 3. 生成、世界生命周期与存档

刷怪规则默认走 Entities 后端。正式 Actor 定义在生物后端服务中统一路由到 AIECS；事件生成、直接生成和蜂巢生成使用同一实体入口。生成失败要明确报错，不静默生成旧 GameObject 生物。

蜂巢只保存成员 GUID 与蜂群所需的状态，通过 ECS 后端生成、绑定、召回、警戒和回收成员。夜间归巢与醒来继续使用同一 GUID。蜂巢所属蜜蜂由蜂巢快照管理，不再重复写入普通居民快照。

普通居民的新存档记录 GUID、物种、位置、生命和必要的可选能力状态。读档重建实体与能力组件，再恢复这些状态。旧版 GameObject 生物快照不转换；此版本无需向旧存档保持兼容。

## 4. 镜像代理

镜像代理是池化的轻 GameObject，靠近玩家时按预算绑定，远离后回池。它记录实体、Actor GUID、战斗身份与绑定代际，可把旧 Unity 接口的输入转交 ECS，例如需要 GameObject 的交互或命中回调。延迟回调必须核对绑定代际，避免对象池复用后命中另一只生物。

普通生物不常驻代理；只有确实需要物理几何的旧接口才启用代理碰撞体。代理的位置由 ECS 同步，不能决定 AI 行为、生命值或画面。

## 5. BRG 表现

生物身体使用同一动画图集与 BRG 实例数据批量绘制。实例保存变换、UV、颜色、排序和水面参数；飞行高度只影响表现位置，地面逻辑坐标仍以 ECS 为准。阴影继续使用共享批量表现服务。

当前图集包含全部 11 种 Actor。新增或修改生物动画后，要重新导出图集并核对目录、贴图及 Unity 导入设置。透明物体的 Y 排序和飞行遮挡由实际画面验收。

## 6. 新增物种的最小步骤

1. 在 Actor JSON 中定义物种，填写 `ecs.capabilities` 和所用能力的参数。
2. 准备身体与动画资源，重新导出 AIECS 生物图集。
3. 配置生成规则或调用统一实体生成入口。
4. 若现有能力无法表达新行为，再新增一个可复用组件与批处理系统；不要直接为该物种写独立 AI 循环。

定义编译和资源目录检查应能在运行前发现缺失能力、身体数据或贴图。物种配置不应依赖旧 AI Prefab 实例才能完成运行时决策。

## 7. 当前完成状态与后续待规划

当前代码已接入 11 种 Actor 的 ECS 能力配置、生成路由、蜂群桥接、居民快照、镜像代理和 BRG 身体绘制。代码编译与静态资源检查只能证明工程入口和资源关系可用；实际玩法、画面以及性能结果由项目验收确定。

后续待规划：

- 哪些旧 Unity 接口还需要长期保留镜像代理，哪些可直接改为 ECS 查询。
- 新能力超出当前组件清单时，先补共享模块还是使用一次性的事件桥。
- 联机时实体身份、蜂巢成员和居民快照的同步边界。

# FlatWorld AI：GameObject 主控与可选 ECS 后端

> **当前执行结论：所有 AI（包括僵尸）恢复完整 GameObject 主控；ECS AI、BRG 和桥梁代码保留但默认不启用。本文下方的全量 ECS 方案属于历史参考，不能再据此迁移或删除 GameObject AI。**

## 当前运行边界

- 普通生成、GM、事件、技能、MOD 与蜂巢均使用 GameObject AI；实际运行原来的行为模块、Mover 和 Animator，不是 ECS 的镜像空壳。
- 后端按物种选择，同一生物只有一个主控；ECS 物种仍允许显式配置，但当前连僵尸也选择 `gameObject`，`useAiecsBackend=false`。
- 事件和 MOD 的稳定 GUID 命令通过统一服务分发；已有战斗桥与镜像保留。完整混合 AI 的感知/战斗互通需要在以后实际启用时单独完成和验收。
- GameObject 居民恢复原有 ItemData/休眠链；已有 `EntitiesResidents` 冷快照保留，不自动转换或删除。重新进入世界后按新路由生成，不能把配置切换当作当前场景实体已经热转换。
- 树木、作物、机器和掉落物的现有后端不在本次 AI 还原范围内；GameObject AI 通过资源查询桥继续访问 ECS 树木和作物。
- 验证与验收由用户负责；不主动编译、运行测试或操作 Unity 现场。

## 历史 ECS 方案（以下保留备查，不再自动执行）

## 1. 系统定位

正式世界的唯一 Entities World 由 `WorldEntityRuntime` 持有。树木、石头、矿物与动物共用实体底座；AI 动物只是额外组合感知、决策、移动等能力的实体，不另建一套世界实体系统。玩家手持物也属于同一迁移范围，不能因为入口在快捷栏就遗漏，或另建手持专用 World。

正式 Actor 的生命、位置、感知、行为和战斗状态由 AIECS 能力运行器处理。高频逻辑按组件组合批量运行，身体由 BatchRendererGroup（BRG）绘制。只有外部 Unity 接口确实需要对象时，才从对象池租用 GameObject 镜像代理。静态资源与手持物的迁移进度分别记录，不能把共用 World 等同于所有旧模块都已迁完。

当前目录中的 Bird、Seagull、Bee、Chicken、WildBoar、Wolf、Ghost、Zombie、Sheep、Rabbit、SnowLeopard 共 11 种 Actor 都走这个入口。玩家仍由 GameObject 系统驱动。新存档使用 ECS 生物快照；旧版 GameObject 生物存档不做迁移。

```text
Actor JSON（能力清单与参数）
    → 定义编译器 → ECS 组件与共享规则
    → 批量感知 / 决策 / 移动 / 生存 / 战斗
    → BRG 身体与阴影
    → 按需租用 GameObject 镜像代理，接收旧 Unity 接口的输入
```

同一生物只有一个权威状态。代理不能运行旧 AI，也不能反向持有一套生命或移动状态。

## 2. 模块组合

### 2.1 定义与装配

Actor 定义的 `ecs.capabilities` 选择共享能力，`ecs` 下相应对象填写参数。纯 ECS 新物种可以用 `ecs.health` 指定生命和防御，不必新写旧 AI 或生命模块。定义编译器检查能力名称和必需依赖，生成实体模板。生物进入世界时，只装配它启用的可选组件；系统按组件查询批量执行，不按物种名分支。

| 能力 | 作用与依赖 |
| --- | --- |
| `movement`、`perception` | 基础移动与感知；每种 Actor 都必须有 |
| `nutrition`、`feeding` | 饱食消耗与觅食；`feeding` 依赖 `nutrition` |
| `sleep`、`flee`、`chase`、`combat` | 作息、逃离、追击与战斗 |
| `flight` | 飞行高度、速度和耐力 |
| `reproduction`、`eggLaying` | 繁殖时钟与产蛋；`eggLaying` 依赖 `reproduction` |
| `hiveMember` | 蜂巢归属、巡逻、召回、警戒、护巢和采蜜状态 |
| `pack` | 同伴援助与队形 |
| `charge`、`predator` | 冲锋与捕食追击参数 |
| `darkness` | 光照采样、避光和受光伤害 |

感知、决策、移动、战斗仍使用 AIECS 共同流程。特殊能力只向共享意图、速度、目标或结算队列提供数据；不得为每个生物恢复一套 MonoBehaviour 状态机。

### 2.2 当前物种组合

| 物种 | 主要能力 |
| --- | --- |
| Bird、Seagull | 觅食、睡眠、逃离、飞行 |
| Bee | 花蜜、飞行、蜂群、追击与战斗 |

## 3. 生成、世界生命周期与存档

刷怪规则默认走 Entities 后端。正式 Actor 定义在生物后端服务中统一路由到 AIECS；事件生成、直接生成和蜂巢生成使用同一实体入口。生成失败要明确报错，不静默生成旧 GameObject 生物。

蜂巢只保存成员 GUID 与蜂群所需的状态，通过 ECS 后端生成、绑定、召回、警戒和回收成员。夜间归巢与醒来继续使用同一 GUID。蜂巢所属蜜蜂由蜂巢快照管理，不再重复写入普通居民快照。

普通居民的新存档记录 GUID、物种、位置、生命和必要的可选能力状态。读档重建实体与能力组件，再恢复这些状态。旧版 GameObject 生物快照不转换；此版本无需向旧存档保持兼容。

## 4. 镜像代理

镜像代理是池化的轻 GameObject，靠近玩家时按预算绑定，远离后回池。它记录实体、Actor GUID、战斗身份与绑定代际，可把旧 Unity 接口的输入转交 ECS，例如需要 GameObject 的交互或命中回调。延迟回调必须核对绑定代际，避免对象池复用后命中另一只生物。

普通生物不常驻代理；只有确实需要物理几何的旧接口才启用代理碰撞体。代理的位置由 ECS 同步，不能决定 AI 行为、生命值或画面。

## 5. BRG 表现

生物身体使用同一动画图集与 BRG 实例数据批量绘制。实例保存变换、UV、颜色、排序和水面参数；飞行高度只影响表现位置，地面逻辑坐标仍以 ECS 为准。阴影继续使用共享批量表现服务。

当前图集包含全部 11 种 Actor。新增或修改生物动画后，要重新导出图集并核对目录、贴图及 Unity 导入设置。透明物体的 Y 排序和飞行遮挡由实际画面验收。

## 6. 新增物种的最小步骤

1. 在 Actor JSON 中定义物种，填写 `ecs.capabilities` 和所用能力的参数。
2. 准备身体与动画资源，重新导出 AIECS 生物图集。
3. 配置生成规则或调用统一实体生成入口。
4. 若现有能力无法表达新行为，再新增一个可复用组件与批处理系统；不要直接为该物种写独立 AI 循环。

定义编译和资源目录检查应能在运行前发现缺失能力、身体数据或贴图。物种配置不应依赖旧 AI Prefab 实例才能完成运行时决策。

## 7. 快捷栏与玩家手持物

### 7.1 入口与实体形态

手持入口是 `Items/Inventory/Inventory_HotBar.cs`，不是鼠标拖拽物所在的 `Inventory_Hand`。`LoadItemFromSlot / ConfigureItemInstance / SyncCurrentHeldItemWithSlot / UnloadCurrentItem` 负责选中、绑定与解除；物品创建统一通过 `ItemMgr.InstantiateHeldItem`。

```text
快捷栏选中槽的真实 ItemData
    → 统一实体 + 持有者 / 挂点 / 使用能力
    → ECS 模块计算与命令结算
    → 玩家挂点接口代理 + 批量手持表现
```

- 普通库存槽位保留数据，不为每个图标创建常驻 GameObject 或 ECS 实体；只有需要模拟的状态进入相应能力查询。
- 手持、落地、安装是物品的承载形态，不是各自复制一套燃料、耐久、进食和生产逻辑。
- 仅当前选中物绑定玩家挂点；没有 AI 能力的手持物不参加感知、决策或自主移动。
- 切槽、库存事务、手持状态变化和资源刷新驱动绑定更新；数量变化不重建外壳，替换 ItemData 时必须重新绑定当前数据，不能只凭同 GUID 继续引用过期对象。

### 7.2 模块与表现边界

- 迁移武器使用/攻击阶段与冷却、耐久、食物食用进度、燃料与燃烧、容器状态、工具加工和放置能力；具体物品仅组合已有能力和参数。
- ECS 只处理纯数据；输入、库存/UI、音效和 Unity 物理接口通过命令与结果桥接。同一库存的扣减、生成和交付统一提交，不能多个 Job 并行修改同一槽位。
- 代理只接收输入和反馈，不同时保留第二套权威玩法状态。未迁移模块要明确登记，不能仅建立一个 ECS 镜像就声称完成迁移。
- 挥动/瞄准等需要连续反馈的表现按帧更新；待机物品、库存数据和被动模块不能一律按帧扫描。不得为了批处理强行降低玩家操作响应频率。
- 批量手持表现保持玩家局部挂点、转身与瞄准合成、水体裁剪、受击效果及前后层级；当前 `Module_Hotbar` 的局部排序语义必须保留，不能只替换 Renderer 导致武器穿到身体后面。
- 延迟攻击/使用/表现结果必须核对世界代际、物品身份和手持绑定代际，切槽、回池、F5 换玩家后拒绝旧结果。

- [ ] 攻击、右键使用、手机与手柄输入统一提交有绑定身份的命令；远端手持只表现，不重复结算。

# 环世界局部表现与联机坐标解耦待办

## 目标

把 FlatWorld 的圆环世界统一改成：**逻辑坐标是唯一权威，Unity Transform / Renderer / Physics2D 只是每个客户端自己的局部表现投影。** 项目仍在开发阶段，不需要兼容旧实现。

## Agent 任务

1. 先阅读 `flatworld-world-model`、`flatworld-networking` 及现有 `WorldTopologyRuntime / WrappedWorld / NetworkWorldPlayer` 实现，梳理所有把 `Transform.position` 当权威世界坐标的入口。
2. 新建统一的 Local Presentation / Local Physics 坐标映射：以本地玩家/观察者为锚点，通过圆环 `ShortestDelta` 把逻辑 Chunk、玩家、Item 映射到最近的连续平面位置。ChunkView 进入窗口时决定表现 image，权威 `ChunkRuntime` 坐标不变。
3. **删除 Item 级跨边界 Collider 镜像架构**：淘汰 `WrappedItemPhysicsAdapter` 的逐实体 `FixedUpdate + Proxy Collider`。Unity Physics2D 只处理本地表现窗口；静态世界物优先由 Chunk 级碰撞表现承载，数据化系统继续使用逻辑碰撞/空间查询。
4. 联机只同步规范化逻辑坐标。`NetworkWorldPlayer`、`NetworkItemStateCoordinator`、`NetworkChunkStreamingCoordinator` 等不得把客户端 Local Presentation Position 写进网络协议或存档；远端对象在每台客户端独立投影到最近 image。
5. 服务端权威判定继续使用 `WorldTopologyDomain / ShortestDelta / Chunk 数据 / 空间索引`。攻击、拾取、建筑、导航、推动等不能依赖某个客户端的局部 Transform 坐标。
6. 保留真正需要 Rigidbody2D 的本地动态对象，但它们只是局部物理表现；跨圆环边界后逻辑坐标规范化，局部表现保持连续，不再为另一侧创建整套物理镜像。

## 验收

- 单机连续跨东西、南北边界，画面、碰撞、攻击、交互无跳变或重复实体。
- 两个联机玩家分别站在圆环两侧时，服务器逻辑距离正确；双方客户端都把对方显示在最近位置，且网络同步的仍是相同逻辑坐标。
- Chunk 流送、存档、ECS、导航全部继续使用逻辑坐标，不读取 Local Presentation Position 作为权威。
- 用 MCP/Profiler 复测大存档，确认 `WrappedItemPhysicsAdapter.FixedUpdate` 热点消失，且没有用新的逐 Item Update/FixedUpdate 代替它。
- 修改完成后更新对应 Skill；实测踩坑与性能结论写入对应 `Exp/`，不要塞进 Skill。

# FlatWorld 机械动力系统规划

## 1. 系统定位

机械动力系统用于把环境动力或人工动力，通过传动部件输送到各类用力器，形成从手工加工向机械化生产发展的玩法链。

首批定义、模块与加工链已落地。首轮合成配方与材料成本见第 6 章；第 8 章记录可配置的首版默认值，不代表最终平衡。内容清单仍作为完整游戏内验收清单，不能仅凭编译或隔离测试勾选。

### 当前临时美术规则

- 本文档内所有机械物体在首轮实现阶段统一使用 `占位符.png` 作为 Sprite。
- 在对应正式美术资源完成前，不为单个机械物体单独制作临时 Sprite；后续只替换素材，不改变物体定义与玩法规划。

### 3.4 跨轴器

当前 Sprite：`占位符.png`。

![1789890253012](../AI策划/image/机械动力系统规划/1789890253012.png)

> 上图仅作为跨轴器的外观规划参考；首轮实际实现仍统一使用 `占位符.png`。

跨轴器用于让一条机械传动线路从另一条 Layer0 线路上方跨过，并保持两条线路互不连接。

#### 数据与视觉占用

- 跨轴器的权威数据只占用 **Layer1 的一个机械格**。
- 跨轴器主体视觉以该中心格为基准。
- 两侧连接端可各向外伸出约 **0.5 格**，形成约 0.5 + 1 + 0.5 格的视觉长度。
- 两侧伸出的部分只用于视觉表现和连接相邻机械端口，**不额外占用数据格**。
- Layer0 同位置仍可存在普通传动轴、齿轮或其它合法机械线路；跨轴器与其不会自动连接。

#### Sprite 表现

- Sprite 整体表现为一个 **架高的桥式传动外壳**，主体位于 Layer1 中心格。
- 主体外形应明显高于 / 包住下方 Layer0 线路，让玩家仅通过画面就能理解“这条动力从上方跨过去”。
- 主体中央保留明显的 **跨越空间 / 下穿通道**，使同格 Layer0 传动轴仍能从视觉上连续穿过，不能把底层线路完全遮死。
- 跨轴器两端绘制清晰的 **机械接口 / 轴承座**，分别对应 A、B 两个连接端。
- 左右方向放置时，两端接口向左右各伸出约 0.5 格，与相邻 Layer0 的传动轴或齿轮视觉贴合；上下方向放置时按相同规则旋转 90°。
- 两端伸出的连接部分属于跨轴器 Sprite 的表现范围，不因此增加额外数据格或建筑占格。
- Sprite 本身不表现木 / 铜 / 铁轴的组合材质；端点连接到什么材质的轴，由相邻 Layer0 机械节点自己的 Sprite 表现，避免跨轴器素材产生组合变体。
- Layer1 的跨轴器在 Sorting 上应明确显示于同格 Layer0 线路之上，但仍需露出底层线路的连续走向，强化“跨越而非连接”的视觉语义。

#### 手持方向切换

- 跨轴器默认方向为 **横向**。
- 玩家将跨轴器拿在手上时，按下 **R** 在“横向 ↔ 纵向”之间切换。
- 切换方向后，当前放置预览立即同步旋转，并按新方向重新计算 A / B 两端的位置与连接合法性。
- 手持方向只属于当前这次选中 / 放置过程的**临时运行时状态**，不得写入跨轴器物品的堆叠数据、ItemData 或其它持久化物品状态。
- 玩家只要切换到其它物品，当前跨轴器的临时方向就立即清除；之后再次选中跨轴器时始终重新从默认的**横向**开始。
- 同一堆跨轴器不得因为横向 / 纵向产生不同物品状态、拆分堆叠或形成不同物品变体。
- 已经成功放置到世界中的跨轴器属于建筑 / 世界机械节点，其实际横向或纵向必须随世界对象正常保存；这里“不持久化”只指**背包 / 手持阶段的临时方向**。
- 拆除纵向跨轴器并返还为物品时，不继承纵向状态；返还物重新进入手持状态后仍从默认横向开始。
- R 键输入应接入现有玩家输入链，由 `GameController / InputBindingService` 统一转发，不在跨轴器模块中直接读取物理键盘。

#### 连接方式

- 跨轴器自身存储在 Layer1。
- 跨轴器拥有两个连接端点 A / B。
- A / B 分别要求相邻 Layer0 格存在方向正确、可连接的机械端口，例如传动轴或齿轮。
- 放置时只校验 Layer0 两端是否能够正确连接，不改写 Layer0 轴体、齿轮的材质、等级或其它数据。
- 机械网络构图时，由跨轴器在 Layer1 建立一条 Layer0.A ↔ Layer0.B 的桥接连接。
- 被跨越的 Layer0 线路保持原有网络关系，不会因为跨轴器位于其上方而接入跨轴器网络。

#### 实现特质

- 跨轴器本体只有一个稳定定义，不根据木、铜、铁轴的组合生成不同物品变体。
- 木制、铜制、铁制传动轴以及齿轮都可以作为跨轴器端点，只要机械端口契约允许连接。
- 拆除跨轴器时只删除 Layer1 的跨轴器数据与桥接关系，不修改 Layer0 原有机械节点。
- 跨轴器中心格属于 Layer1，因此同一 Layer1 格不能重复放置第二个跨轴器。
- 视觉连接臂可以伸入相邻格，但碰撞、存档、网络拓扑和放置权威仍以中心的单个 Layer1 格为准。

## 6. 首批合成配方

### 6.1 配方规则

- 首批机械物品统一通过世界工作台制作，落地为 `RecipeType.Crafting`，并使用 `requiredStation: "workbench"`。
- 普通合成使用无序材料规则：`inputRule: "unordered"`、`allowMirror: false`。
- 单个配方最多使用 5 种输入材料，适配当前世界工作台的 5 个输入槽。
- 优先复用现有材料，不为首批机械系统额外引入“机械零件”“螺丝”“轴承”等中间材料。
- 机械木构件优先使用钻孔木板 `DrilledPlank` 与钻孔木棍 `DrilledStick`；普通木板 `Plank`、木棍 `Stick_Wood` 主要作为它们的前置加工材料，不直接承担机械主体连接。
- 当前直接使用的已有 / 已定义材料 ID：钻孔木板 `DrilledPlank`、钻孔木棍 `DrilledStick`、绳子 `Rope`、纤维 `Fiber`、皮革 `Leather`、石头 `Ore_Stone`、铜锭 `Ingot_Copper`、粗铁锭 `Ingot_RawIron`、熟铁锭 `Ingot_WroughtIron`。
- 机械物品本身的稳定 Item ID 在正式实现物品定义时统一确定；在对应 Item 定义落地前，不把本节配方直接加入运行时 `recipe-manifest.json`，避免配方目录引用不存在的产物。

#### 手钻与钻孔木料

- 手钻是进入机械构件制作链的基础加工工具，本身不是机械动力网络节点，不接收或传递机械动力。
- 第一份钻孔原木仍允许使用现有“原木 + 火种”配方制作，作为手钻的启动材料。
- 手钻配方固定消耗：木棍 ×1 + 绳子 ×2 + 钻孔原木 ×1 + 钻头材料 ×1。
- 钻头材料可以是燧石 `Ore_Flint`，也可以是带 `Ingot` Tag 的任意金属锭。
- 当前 `Ingot` 覆盖铜锭、锡锭、青铜锭、粗铁锭、熟铁锭与钢锭；后续 MOD 金属锭只要声明同一 Tag 即可直接复用该配方。
- 手钻属于机械系统的前置便携工具，不受“首批机械设备统一使用世界工作台”的限制；手钻本体继续使用普通 `RecipeType.Crafting` 合成。
- 钻孔不再通过“手钻作为 `amount=0` 配方工具”的普通合成完成；钻孔统一进入手钻自己的输入 / 输出加工界面。

#### 手钻的手持与落地形态

手钻的交互结构参考现有钻木取火工具 `SparkMaker` 的便携设施链路：

```text
背包 / 快捷栏中的手钻
        │
        ├─ 右键使用 → 打开手钻 UI
        │
        └─ UI“放到地上” → 进入正常建筑放置流程
                                  │
                                  ▼
                              落地手钻
                                  │
                                  ├─ 右键 / 交互 → 打开同一套手钻 UI
                                  └─ UI“拆回物品” → 返回可携带形态
```

- 手钻必须支持**手持状态直接使用**，玩家不需要先把它放到地上才能钻孔。
- 手钻处于玩家快捷栏 / 背包的正式手持实例时，右键打开手钻面板，不直接开始放置。
- 手持面板显示“放到地上”按钮；点击后复用现有 `Mod_Building / BuildingPanelActions` 放置事务。
- 手钻落地后成为可交互世界对象；玩家对其右键 / 交互时打开同一套手钻面板。
- 落地面板显示“拆回物品”按钮；拆回继续走现有完整建筑拆回事务，不直接销毁世界对象再凭空生成物品。
- 手持形态与落地形态必须共享并保存加工状态；输入槽、输出槽以及后续确定的加工进度不能因为放置、拆回、保存、读档而丢失。
- 手钻实现时应采用与 `SparkMaker_Summoner ↔ SparkMaker` 相同的“可携带载体 ↔ 落地本体”身份模型。当前已有的单一 `HandDrill` 工具定义只是前期内容占位，正式实现时需要迁移到便携设施双形态，不能同时保留两套互相独立的手钻状态。
- 推荐稳定身份为：可携带形态 `HandDrill_Summoner`，落地本体 `HandDrill`；两者通过建筑快照传递同一份手钻模块状态。

#### 手钻 UI

- 新建独立正式面板 `UI_HandDrill`，视觉和交互结构参考 `UI_FireDrill`，但不直接复用同一个 Prefab，避免“摩擦生火”和“钻孔加工”业务互相耦合。
- 面板至少包含 **1 个输入槽 + 1 个输出槽**。
- 输入槽只接受当前注册的可钻孔物品；不接受的物品不得进入加工流程。
- 输出槽显示该输入对应的钻孔产物，并使用现有制作输出预览表现。
- 主操作按钮文案为“钻孔”。
- 手持和落地状态打开的都是同一套面板、同一套输入 / 输出数据与同一套加工规则。
- 输入 / 输出槽的快捷转移继续连接当前玩家的手部库存，行为与 `Mod_FireDrill` 保持一致。
- 输出槽无法容纳完整产物时，不消耗输入物品，也不允许部分完成加工。
- 钻孔过程需要加工进度；具体采用点击次数、持续时间、手钻耐久消耗以及不同钻头材料是否影响速度，当前暂不确定，后续单独平衡。

#### 钻孔输入与输出

首批所有钻孔加工均保持 **1 个输入 → 1 个对应产物**：

| 输入物品 | Item ID | 输出物品 | Item ID |
| --- | --- | --- | --- |
| 原木 | `Log` | 钻孔原木 | `DrilledLog` |
| 木板 | `Plank` | 钻孔木板 | `DrilledPlank` |
| 木棍 | `Stick_Wood` | 钻孔木棍 | `DrilledStick` |
| 石板 | `StoneSlab` | 钻孔石板 | `DrilledStoneSlab` |
| 石头 | `Ore_Stone` | 钻孔石头 | `DrilledStone` |

- 钻孔只改变物品的加工身份，不改变数量；首批统一为 1 份原料得到 1 份钻孔产物。
- 钻孔石板与钻孔石头是独立稳定 Item，不通过临时状态字段把普通石板 / 石头伪装成钻孔版本。
- 钻孔石板默认继承普通石板的重量、体积、堆叠与拾取规则；钻孔石头默认继承普通石头的对应规则，除非后续平衡明确要求修改。
- 两个新增石质钻孔物首轮继续使用统一 `占位符.png`，后续替换正式 Sprite 时不改变 Item ID。
- 手钻模块的加工关系应由可注册的“输入 Item ID → 输出 Item ID”数据表或配方目录驱动，禁止在 UI 或手钻脚本里写死五组 `if / switch`；MOD 可以继续注册新的可钻孔材料。

#### 手钻模块边界

- 手钻使用独立的钻孔模块，不把钻孔逻辑继续塞进 `Mod_FireDrill`；两者只复用便携设施、库存、UI 生命周期和建筑状态迁移等通用能力。
- 手持形态必须实际组合钻孔模块，否则只给落地本体挂模块会导致“手上右键打开 UI”的需求无法成立。
- 模块负责输入校验、输出预览、加工进度和原子转换；`BuildingPanelActions` 只负责放到地上 / 拆回物品，不接管钻孔业务。
- 加工成功时先确认输出可完整接收，再扣除一份输入并生成一份输出；任何失败路径都保持输入不变。
- 输入 / 输出与加工进度进入手钻自身状态保存；禁止把它们存进 UI Prefab 或玩家临时面板状态。

| 铁制传动轴 | 木制传动轴 ×2 + 熟铁锭 ×1 | 2 |
| 铁制齿轮 | 木制齿轮 ×1 + 熟铁锭 ×1 | 1 |
| 铁制变速箱 | 变速箱 ×1 + 熟铁锭 ×2 | 1 |
| 跨轴器 | 钻孔木板 ×2 + 钻孔木棍 ×2 + 木制传动轴 ×2 + 绳子 ×1 | 1 |

木制传动轴和木制齿轮采用批量产出，减少铺设长距离传动线路时反复制作基础零件的操作量。

铜制 / 铁制变体以木制基础件为骨架再加入金属升级，不要求先制作前一级金属版本；铜级和铁级因此是按材料能力解锁，而不是强制“木 → 铜 → 铁”逐件替换。

### 6.4 用力器

| 产物 | 材料 | 产量 |
| --- | --- | ---: |
| 石磨 | 石头 ×6 + 钻孔木板 ×2 + 木制齿轮 ×2 + 木制传动轴 ×1 | 1 |
| 机械风箱 | 钻孔木板 ×4 + 钻孔木棍 ×2 + 皮革 ×2 + 绳子 ×2 + 木制齿轮 ×1 | 1 |
| 锯木机 | 钻孔木板 ×4 + 钻孔木棍 ×2 + 熟铁锭 ×3 + 木制齿轮 ×2 + 木制传动轴 ×1 | 1 |
| 机械锻锤 | 钻孔木板 ×4 + 钻孔木棍 ×2 + 粗铁锭 ×3 + 木制齿轮 ×2 + 木制传动轴 ×1 | 1 |

机械锻锤刻意使用粗铁锭而不是熟铁锭作为本体材料。当前游戏仍存在高温把粗铁加工成熟铁的路线，但机械锻锤未来本身就是“粗铁 → 熟铁”的主要机械化设备，因此这样可以避免后续调整冶金流程时出现“必须先有熟铁才能制作生产熟铁的机器”的科技死锁。

## 7. 机械网络跨区块加载与卸载

### 7.1 卸载单位

- 机械动力不得跟随单个地图 Chunk 独立加载 / 卸载。
- 以一组**实际相互连通、能够传递机械动力的完整机械网络**作为最小加载、运行和卸载单位。
- 同一机械网络可以跨越多个地图 Chunk；Chunk 边界只负责空间划分，不能把机械网络切成两个独立运行区。
- 离合器断开、传动部件拆除等导致拓扑变化时，重新计算连通关系；分裂后的网络分别判断加载状态，重新连接后的网络合并判断。

### 7.2 单区块快速路径

- 大多数机械结构如果完整位于同一个 Chunk 内，应走 **SingleChunk 快速路径**，避免进入跨区块协调逻辑。
- 机械网络创建或拓扑变化时，根据网络 `BoundsInt` 判断是否只覆盖一个 Chunk；该判断只在放置、拆除、连接、断开、网络合并或分裂时执行，不进入每帧热路径。
- `SingleChunk` 网络只记录所属 Chunk，不注册跨 Chunk 边缘连接、不维护跨 Chunk 端口表，也不参与跨 Chunk 网络协调。
- 只要新增连接第一次跨过 Chunk 边界，该网络立即提升为 **MultiChunk**，再启用跨 Chunk 连接、整网范围和加载 / 卸载协调逻辑。
- `MultiChunk` 网络因拆除或断开而分裂后，如果某个子网络重新完全落回单个 Chunk，应降回 `SingleChunk`。
- 单区块快速路径只是性能优化，不改变机械动力、负载、存档和连接规则；同样的机械结构不能因为是否跨 Chunk 而得到不同玩法结果。
- 不应仅为了减少机械跨区块概率而扩大地图 Chunk 尺寸；地图 Chunk 大小同时影响世界生成、表现、碰撞、导航和流送，应由 WorldModel 自身需求决定。

### 7.3 玩家靠近时

- 只要任意玩家进入该机械网络任意节点的机械激活范围，**整张机械网络都必须保持加载和正常模拟**。
- 即使网络另一端已经超出地图表现 Chunk 的加载范围，也不能只卸载其中一部分机械。
- “机械网络保持加载”只要求保留该网络的机械模拟数据，不要求强制保留沿途所有 ChunkView、Sprite、Collider、Tilemap 等表现对象。

例如：

```text
Chunk A            Chunk B
水车 ── 传动轴 │ 传动轴 ── 石磨
```

只要玩家仍靠近水车或石磨任意一侧，A、B 中属于同一机械网络的机械模拟必须一起保持有效，不能出现一侧卸载、另一侧继续运行的半网络状态。

### 7.4 彻底远离后的卸载判定

- 只有当**所有玩家都远离整张机械网络**时，才允许整网卸载。
- 每张机械网络缓存一个 Unity `BoundsInt`，以 Chunk 坐标描述该网络的整数包围范围；Z 轴固定不用，只使用 X / Y。
- 玩家距离判定只使用玩家当前 Chunk 坐标与该 `BoundsInt`，不逐机械节点或逐占用 Chunk 查询。
- 激活 / 卸载判断采用“扩张 Bounds”方式：把网络 `BoundsInt` 向四周扩张指定 Chunk 数，只判断玩家 Chunk 是否落入扩张后的矩形范围。
- 该判断允许保守误判：玩家可能位于 Bounds 内的空白区域而使网络多保持一段时间加载；这是为了换取固定、极低的判断成本，不再追加第二级精确距离检测。
- 网络新增或移除边缘机械节点、网络合并或分裂时，重新维护 `BoundsInt`；正常运行时无需扫描节点重算 Bounds。
- 加载距离与卸载距离应使用不同阈值形成滞回，例如进入较近范围时加载、离开更远范围后才卸载，避免玩家在边界移动时反复加载 / 卸载。
- 超过卸载距离后应经过短暂冷却时间再真正卸载，避免玩家刚离开又立刻返回造成抖动。
- 若世界使用循环拓扑，`BoundsInt` 必须按现有世界拓扑规则处理接缝，不能把跨世界接缝的小型机械网络错误扩成覆盖大半个世界的范围。

### 7.5 整网卸载与恢复

- 达到卸载条件后，先保存该机械网络恢复运行所需的权威状态，再一次性卸载整张网络的运行时模拟数据。
- 至少需要恢复：网络拓扑、各节点稳定身份与位置、动力源状态、传动状态、用力器运行状态、库存 / 燃料 / 加工进度，以及其它会影响恢复结果的持久化状态。
- 任意玩家重新接近该网络任意部分时，先恢复并重建完整机械网络，再恢复实时模拟；禁止先启动局部节点、随后再慢慢接上远端网络。
- 机械网络卸载期间默认不执行实时 Tick；如果未来需要远距离生产，应以**整张机械网络的统一离线结算**实现，不允许只让已加载的一半继续实时工作。

### 7.6 禁止的跨区块行为

- 禁止出现“动力源所在 Chunk 已卸载，但消费者所在 Chunk 仍按最后一次转速继续无限工作”的情况。
- 禁止冻结已卸载动力源的燃料 / 水 / 其它消耗，同时让仍加载的消费者继续获得该动力；这会产生无消耗工作的漏洞。
- 禁止把“邻接 Chunk 当前未加载”直接解释为传动轴断开；是否断网只由真实机械拓扑变化决定。
- 禁止为了保持机械网络而强制加载整条网络经过的完整地图表现层；机械模拟生命周期与地图表现生命周期必须分离。

## 8. 首版默认实现

### 8.1 配置与物品身份

- 动力数值、网络距离和加工关系统一配置在 `Assets/Resources/Config/Mechanical/mechanical-catalog.json`。
- 机械物品定义位于 `GameConfig/Items/shells/mechanical.json`，工作台配方位于 `GameConfig/Recipes/crafting/mechanical.json`。每台设备均有本体与 `_Summoner` 载体；配方产出可携带载体。
- 动力源稳定 ID 为 `HandCrank`、`WaterWheel`、`Windmill`、`LargeWaterWheel`、`LargeWindmill`。
- 传动件使用 `Shaft_Wood/Copper/Iron`、`Gear_Wood/Copper/Iron`、`Gearbox_Wood/Copper/Iron`、`Clutch`、`CrossShaft`。
- 用力器使用 `Millstone`、`MechanicalBellows`、`Sawmill`、`MechanicalHammer`。
- 占位图使用项目已有的 `Assets/6_Art/Generated/ItemPlaceholder/素材占位符.png`，没有额外制作美术。

### 8.2 动力与传动

| 项目 | 首版默认值 |
| --- | --- |
| 基准转速 | 60 RPM |
| 手摇轮 | 动力 24；按住世界交互键时持续供能，不打开机械 UI；松开后只保留约 2 个机械 Tick 的输入缓冲，不再积攒数秒动力 |
| 水车 / 大水车 | 动力 48 / 96；需要沿岸放置，安装时记录水体资格，不消耗水 |
| 风车 / 大风车 | 最大动力 64 / 128；随当前维度风力变化，无风时停转 |
| 木 / 铜 / 铁传动容量 | 32 / 96 / 256 |
| 离合器 / 跨轴器容量 | 256 |
| 石磨 / 风箱 / 锯木机 / 锻锤负载 | 8 / 8 / 12 / 16 |
| 变速箱 | 0.5 / 1 / 2 倍，默认 1 倍；右侧或上侧是变速端 |

- 普通轴、离合器、变速箱与跨轴器按横向或纵向连接，手持时按 R 切换；齿轮和设备使用四向接口。
- 速比沿端口传播；加速会同比提高用力器负载。供给不足、超过整网最弱部件容量，或闭环传动比矛盾时整网停转。
- 首版采用保守的整网容量判定，不单独计算每条支路的扭矩；多个动力源按可用动力相加，以能共同维持的较低转速运行。
- 离合器断开后按真实端口关系分网；跨轴器只连接相邻两端，不连接同格下层。
- 临时手持方向不会进入物品数据；放置方向随世界保存，拆回快照清除方向，保留库存和其它设备状态。

### 8.3 加工规则

| 设备 | 首版加工 | 基准工作量 |
| --- | --- | --- |
| 手钻 | 五组既定钻孔关系，始终 1 → 1 | 木料 4 次、石料 6 次点击 |
| 石磨 | 稻谷 `RiceGrain` ×1 → 大米 `Rice` ×1 | 3 秒 |
| 锯木机 | 原木 ×1 → 木板 ×4 | 6 秒 |
| 机械锻锤 | 粗铁锭 ×1 → 熟铁锭 ×1 | 8 秒 |
| 机械风箱 | 增强相邻正在燃烧的熔炉 | 最高增加 250 度目标温度，升温速度最多翻倍 |

- 加工秒数以 60 RPM 为基准，转速改变时按比例推进；手钻每次按钮操作默认推进 1 秒工作量，不接入动力网。
- 加工不应用普通合成的难度增产倍率，避免钻孔破坏数量守恒。
- 输出必须能完整接收后才推进和扣料；输出满时保留既有进度，断动力后停止推进。输入变成另一种材料时清空原加工进度。
- 风箱不代替燃料，不突破熔炉本身的温度上限；多个相邻风箱取最强值，不叠加增温。
- 手钻使用独立 `UI_HandDrill` 和 `Mod_HandDrill`，输入、输出和进度由共享模块随手持、放置、拆回迁移。旧占位 `HandDrill` 在缺少建筑角色时重新挂到 `HandDrill_Summoner`。

### 8.4 生命周期、存档与扩展

- `ItemMgr` 每 0.1 秒驱动 `MechanicalWorld`；拓扑变化才重构端口图和 Chunk `BoundsInt`，单区块属性同步缓存。
- 网络在扩张 1 Chunk 的范围激活，所有玩家离开扩张 2 Chunk 的范围超过 5 秒后整网休眠。循环世界使用最短包围跨度处理接缝。
- 激活时先恢复整网状态再运行；休眠前先抓取整网快照，再释放加工器。地图表现只在已有可见 Chunk 中生成，远端网络无需加载 ChunkView。
- `CompactSaveEnvelope.MechanicalNetworks` 保存独立版本载荷；按维度世界键隔离。核心 `GameSaveData` 的既有 MemoryPack 布局不变，旧存档没有机械载荷时读取为空。
- 缺失 MOD 定义的快照保留，避免下一次保存静默丢失；库存恢复时按当前 ItemDefinition 刷新静态配置。
- MOD 通过 `MechanicalCatalog.RegisterDefinition/RegisterProcess` 注册节点和加工规则，通过 `MechanicalWorld.RegisterSource` 提供不依赖表现对象的动力条件。
- `IBuildingPlacementExtension` 提供分层占地、放置数据和拆回快照扩展；只有安装事务提交后才注册真实节点。

### 8.5 验证入口与范围

- `Mechanical.Core` 测试覆盖分层跨轴、拆除与离合器分网、变速、过载、循环地图范围、滞回、多玩家距离、加工数量守恒、满输出、状态序列化和共享模块转移。
- 编辑器菜单 `FlatWorld/机械动力/验证内容与面板` 执行全内容校验并渲染真实 Prefab；报告和图片写入 `Library/MechanicalValidation`。
- 测试使用隔离对象和内存数据，不读写真实玩家存档。完整世界中的手持操作、跨 Chunk 往返与退出重进仍需游戏内验收，不能用隔离测试代替。
- 当前运行与加工以单机/主机状态权威为准；远端客户端操作与完整多人同步尚未作为首版验收项。

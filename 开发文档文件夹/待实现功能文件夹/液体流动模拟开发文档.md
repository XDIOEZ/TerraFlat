# 液体流动模拟开发文档

状态：待实现  
前置：先完成《水体与地面分层开发文档》的 Ground / Liquid 分层。

## 1. 核心目标

~~~text
没变化
→ 不计算

抽水 / 放水 / 挡水结构变化
→ 唤醒附近液体

有变化
→ 按固定 Liquid Tick 继续算

稳定
→ 休眠
~~~

第一版只做格子液体流动，不做真实流体物理。

---

## 2. 使用现有数据

继续使用：

~~~text
LiquidDepth     = 当前液体深度，0~1
LiquidTypeIndex = 运行时液体编号
LiquidId        = JSON / MOD / 存档使用的稳定名字
~~~

不要再创建第二套液体深度。

---

## 3. Liquid Tick

- 单独做 Liquid Tick，不直接绑 Unity FixedUpdate。
- 默认 5Hz，必要时再调到 10Hz。
- 没活动液体时完全不跑。
- 一帧不要无限补算历史 Tick。
- 掉帧时宁可液体慢一点，也不要一帧跑很多次。

唤醒当前格时，一起唤醒：

~~~text
自己 + 左右上下
~~~

第一版不做斜角流动。

---

## 4. 流动规则

比较相邻格液面：

~~~text
液面高度 = 地面高度 + LiquidDepth
~~~

地面高度：

~~~text
世界坐标 + Seed + 冻结生成规则
→ Chunk 加载时算一次
→ 放进 GroundHeightCache
→ Chunk 卸载后丢掉
~~~

不写进存档。

流动：

~~~text
液面差 = A液面 - B液面

液面差很小
→ 不流

液面差明显
→ A 往 B 流
~~~

建议初版：

~~~text
转移量 = 液面差 × 0.5 × FlowSpeed
~~~

限制：

- 不超过来源已有 LiquidDepth。
- 目标 LiquidDepth 不超过 1。
- 小于最小变化值时忽略。
- FlowSpeed 做成配置。

---

## 5. 必须分两步计算

不要边算边改。

正确流程：

~~~text
第一步
→ 读取 Tick 开始时的数据
→ 算每格流入 / 流出多少

第二步
→ 全部算完
→ 统一写回 LiquidDepth
~~~

公式：

~~~text
新深度 = 旧深度 + 流入 - 流出
~~~

这样不会因为计算顺序不同而得到不同结果，也方便以后上 Job / Burst。

---

## 6. 活动格和休眠

每个 Chunk 记录：

~~~text
ActiveCells
ActiveCount
~~~

规则：

- 少量格变化：只算活动格。
- 一个 16×16 Chunk 大部分格都活动：直接扫描整个 256 格。
- 连续几次没有明显变化：休眠。
- 邻格以后再变化：重新唤醒。

---

## 7. 液体和阻挡

第一版：

~~~text
相同液体
→ 可以流动

液体 → 空格
→ 可以流入

不同液体
→ 暂时互相挡住
~~~

LiquidDepth = 0 后，可以清掉这一格的 LiquidTypeIndex。

至少这些东西挡液体：

- 实心墙。
- 明确声明挡液体的 Blocking 地块 / 建筑。

水上平台默认不挡下面的水。

不要用 Collider 判断液体是否能通过。

以后需要时再加：

~~~text
blocksLiquid = true / false
~~~

---

## 8. 跨 Chunk

Chunk 边界不能卡水。

~~~text
Chunk A 最右格
→ 正常检查 Chunk B 最左格
~~~

如果邻 Chunk 没准备好：

- 不直接写不存在的数据。
- 请求 / 保持必要的邻 Chunk 数据。
- 数据准备好后继续流动。
- 稳定后释放额外占用。

统一使用世界格坐标，不写第二套边界算法。

---

## 9. 海洋保护

不能因为海里一个抽水机，就把整个世界都唤醒。

第一版：

~~~text
玩家附近 / 被修改区域
→ 正常模拟

远处没被修改的自然海洋
→ 保持生成状态
~~~

以后做围海、水坝时，再增加封闭水域检测。

---

## 10. 批量更新

这是最重要的性能要求：

> 可以逐格计算，但不能逐格刷新。

不要：

~~~text
改一格
→ 发 Changed
→ 刷 BRG
→ 再改下一格
~~~

应该：

~~~text
一个 Liquid Tick 全部算完
→ 收集 DirtyCells
→ 按 Chunk 合并
→ 统一写回
→ 统一通知
~~~

然后：

- BRG 批量刷新。
- Navigation 批量更新。
- FlowField / AIECS 批量更新。
- 存档只标记数据变化，不在 Tick 里写磁盘。

当前 ChunkTerrainData 是逐格 Changed，需要给 Liquid 增加批量修改 / 批量通知入口。

---

## 11. 绘制更新

~~~text
没变化
→ 不刷新

有变化
→ Liquid Tick 结束后刷新一次

持续流动
→ 每个 Liquid Tick 刷一次变化区域

稳定
→ 停止模拟和刷新
~~~

Shader 负责视觉平滑，不需要每帧模拟液体。

---

## 12. Navigation

LiquidDepth 的小数变化不要每次马上重算导航。

第一版：

~~~text
Liquid Tick 结束
→ 批量通知 Navigation
~~~

如果以后还太频繁，再只处理重要变化：

- 无液体 ↔ 有液体。
- 跨过浅水 / 深水阈值。
- 跨过现有玩法使用的深度档位。

阈值复用现有玩法规则。

---

## 13. 动态流向

根据这一 Tick 的真实转移量，顺便计算：

~~~text
LiquidFlowX
LiquidFlowY
~~~

给：

- 漂浮物。
- 玩家水流推动。
- 水面 Shader。

LiquidFlow 不进存档。

现有 riverFlow / riverFlowX / riverFlowY 继续作为天然河流水文数据，第一版不强行合并。

---

## 14. 存档

Liquid 模拟不能每 Tick 写磁盘。

正式保存时，只保存和 Seed 原始世界不同的液体格：

~~~text
格子位置
LiquidId
LiquidDepth
~~~

加载：

~~~text
Seed 生成原世界
→ 覆盖玩家改过的 Liquid 数据
→ 再启动 Liquid 模拟
~~~

不保存：

- LiquidTypeIndex。
- LiquidFlow。
- GroundHeightCache。

---

## 15. 运行时数据

~~~text
每个活动 Chunk：

GroundHeightCache   临时地面高度
ActiveCells         需要继续算的格
PendingDepthDelta   本 Tick 准备增减多少
DirtyCells          本 Tick 真正变化的格
~~~

LiquidDepth / LiquidTypeIndex 继续放在 ChunkTerrainData。

不要给每个液体格创建 GameObject。

---

## 16. 实施顺序

### P0 修改入口
- [ ] 建立统一 LiquidDepth 修改 API。
- [ ] 抽水 / 放水都走这个入口。
- [ ] 修改后唤醒自己和四邻格。

### P1 Tick
- [ ] 独立 Liquid Tick，默认 5Hz。
- [ ] 没活动格时休眠。
- [ ] 限制单帧补算次数。

### P2 流动
- [ ] 只检查四方向。
- [ ] 使用 地面高度 + LiquidDepth 比较液面。
- [ ] 先算流量，再统一写回。
- [ ] 相同液体可流动。
- [ ] 液体可流入空格。
- [ ] 不同液体第一版互相阻挡。

### P3 活动格
- [ ] 少量活动只算活动格。
- [ ] 大量活动直接扫整个 Chunk。
- [ ] 稳定后休眠。

### P4 跨 Chunk
- [ ] 边界正常交换液体。
- [ ] 必要时保持邻 Chunk 数据。
- [ ] 稳定后释放。

### P5 批量刷新
- [ ] Tick 内不逐格刷新 BRG / Navigation。
- [ ] Tick 结束后按 Chunk 合并变化。
- [ ] 批量通知 BRG / Navigation / FlowField / AIECS。
- [ ] 存档只标记修改。

### P6 动态流向
- [ ] 根据真实转移量计算 LiquidFlowX / LiquidFlowY。
- [ ] 给漂浮物和表现读取。
- [ ] 不进入存档。

---

## 17. 验收

- [ ] 高液面会向低液面流。
- [ ] 液面接近后停止。
- [ ] 液体总量不会凭空增加 / 减少。
- [ ] LiquidDepth 始终在 0~1。
- [ ] 没变化时完全不运行模拟。
- [ ] 抽水后附近液体自动补过来。
- [ ] 稳定后自动休眠。
- [ ] 液体能跨 Chunk。
- [ ] 海洋抽水不会唤醒整个世界。
- [ ] 一个 Tick 内统一写回 LiquidDepth。
- [ ] 不会每改一格就单独刷新 BRG / Navigation。
- [ ] 没有明显 GC Alloc。
- [ ] Profiler 确认纯计算成为瓶颈后，再考虑 Job / Burst。

---

## 18. 第一版不做

- 不同液体混合。
- 真实水压。
- 波浪物理。
- 浅水方程。
- 涡流。
- 蒸发 / 降雨守恒。
- 无限范围海洋实时模拟。
- 每帧 Liquid 模拟。

第一版只做好：

~~~text
事件唤醒
→ 固定 Liquid Tick
→ 邻格流动
→ 批量写回
→ 批量刷新
→ 稳定后休眠
~~~

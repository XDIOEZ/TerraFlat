## 1. 目标

TerraFlat 没有真实 Z 轴，但地表已经存在 `height` 高度数据。

本功能的目标是：

> 把连续的二维地表高度，显示成类似 Dwarf Fortress Z-Level 的“离散高度层级”，让玩家不用真实 3D 地形也能一眼看出哪里更高、哪里更低。

最终视觉：

```text
连续 height
    ↓
离散视觉层级
    ↓
同层保持原地块外观
    ↓
不同层之间出现明确但克制的台阶边缘
    ↓
高处与低处存在轻微整体明暗差
```

核心不是把地块抬高，而是让二维地块产生“不同高度层”的视觉阅读。

---

## 2. 明确不做什么

首版禁止把这个功能扩大成真正的 3D 地形系统。

- 不修改地块真实世界坐标。
- 不移动地块顶点到不同 Z。
- 不改变 Collider、Navigation、AI 或角色移动规则。
- 不增加逐地块 GameObject。
- 不恢复视觉 TilemapRenderer。
- 不为每个高度层创建独立 Material。
- 不给每个高度层创建独立 BRG Batch。
- 不增加高度贴图或每 Chunk 高度纹理。
- 不修改世界生成算法。
- 不修改存档格式。
- 不把地表 `height` 重新计算一遍。
- 不让 Shader 结果反过来影响玩法。
- 首版不对洞穴使用这套高度分层。

本功能严格属于：

```text
ChunkTerrainData 权威数据
        ↓ 只读
ChunkTilemapRenderer 表现打包
        ↓
BRG InstanceData
        ↓
Chunk-BRG-Contact-Lit.shader
        ↓
纯视觉结果
```

## 3. 当前项目基线

### 3.1 已确认：地表已经保存 height

当前地表生成完成时会写入：

```text
terrain.SetEnvironmentValue("height", x, y, height)
```

首版表现层直接读取当前 `ChunkTerrainData` 的 `"height"`，不要为了显示高度重新采样 Noise。

### 3.2 已确认：当前 Surface Profile 的高度阈值

当前配置：

```text
terrain.seaLevel = 0.5
terrain.beachLevel = 0.51
terrain.mountainLevel = 0.72
```

这些数值只作为首轮视觉调参参考，**高度显示不能把 0.5 写死成玩法规则**。

### 3.3 已确认：基础地形已经使用 BRG

Ground / Water / Back / Blocking 的基础视觉由 `ChunkBatchRendererGroupService` 统一跨 Chunk 批量绘制。

`ChunkTilemapRenderer` 当前主要承担 BRG 提交和 Blocking Collider 兼容，因此新功能继续走 BRG。

### 3.4 已确认：BRG InstanceData 当前为 112 字节

当前布局：

```text
Transform0  float4
Transform1  float4
Data0       float4
Data1       float4
Tint        float4
FlowX       float4
FlowY       float4
```

总计 `7 × float4 = 112 bytes`。

Ground 当前：

```text
Data0 = 接触边缘信息
Data1 = Vector4.zero
```

`Transform0.w` 不参与 `TransformChunkBRGVertex` 的坐标变换。

Water 当前会复用 `Transform0.w` 保存水流种类，因此高度数据只允许在 **Ground 语义** 下复用这一位置。

### 3.5 已确认：现有脏区刷新机制可以复用

`ChunkTilemapRenderer` 已经：

- 监听本 Chunk 的 `TerrainChangeKind.Environment`。
- 环境变化刷新周围 3×3 格。
- 订阅八个相邻 Chunk。
- 相邻区块首次提交后刷新共享边界。
- 相邻区块运行时变化后刷新对应边缘。

高度台阶只依赖当前格和正交四邻格，因此不需要新增轮询系统。

### 3.6 重要边界：洞穴的 height 不是地表海拔

当前洞穴生成里的 `"height"` 会表达开放格、墙体和水深相关值，它和地表海拔不是同一视觉语义。

首版：

```text
Surface：启用
Cave：禁用
```

未来洞穴如果也需要层级视觉，应建立独立的洞穴高度/深度表现契约，不能直接复用地表规则。

## 4. 最终推荐方案

采用：

## 伪 Z-Level：离散层级 + 层差边缘 + 轻微层级明暗

### 4.1 高度离散化

Shader 把连续 `height 0~1` 切成固定层级。

建议首版：

```text
全高度范围：20 个视觉层级
```

当前海平面约为 0.5，因此自然陆地大约获得 10 个可见高度层。

相比“海平面以上硬编码 10 层”，这种方式：

- 不依赖 Presentation 获取冻结 Profile。
- 不需要把海平面复制进每个实例。
- MOD 或世界参数改变海平面时仍能工作。
- 保持 Height 的 0~1 直接语义。

建议公式：

```text
level = floor(saturate(height) * LevelCount)
level = min(level, LevelCount - 1)
```

`LevelCount = 20` 是视觉默认值，不是世界规则。

### 4.2 高低差边缘

每格比较：

```text
当前格 level
左邻 level
右邻 level
下邻 level
上邻 level
```

规则：

- 同层：不画高度边缘。
- 邻格更高：当前低格靠该方向产生暗边。
- 当前格更高：当前高格靠该方向产生很细、很弱的亮边。
- 层差越大，暗边越明显。
- 高亮永远弱于暗边，避免整张地图变成白色网格。

视觉重点：

```text
低侧阴影 > 高侧亮边
```

### 4.3 轻微层级明暗

同一种地块在不同高度允许有非常轻的亮度变化。

建议最低到最高总差异控制在约 `±4%`。

只用于辅助大区域高低阅读，不能破坏：

- 草地身份。
- 沙漠身份。
- 雪地纯白规则。
- 昼夜 Light2D 主导的光照关系。

如果和雪地冲突，优先降低层级明暗。

## 5. 数据打包方案

首版**不增加 InstanceStride**，继续使用现有 112 字节布局。

### 5.1 Ground 数据约定

建议：

```text
Transform0.w = 当前格原始 height

Data0 = 保持现有 Contact Mask

Data1.x = 左邻原始 height
Data1.y = 右邻原始 height
Data1.z = 下邻原始 height
Data1.w = 上邻原始 height
```

Shader 自己离散化，不要 CPU 预先转成固定 level。

这样可以：

- 只改 Material 参数就调整层数。
- 调层数不需要重新上传所有实例。
- 保留原始 height，后续视觉算法更自由。
- 不增加实例内存。

### 5.2 禁用哨兵

建议：

```text
Transform0.w = -1
```

表示当前 Ground 不启用高度分层。

用于：

- Cave。
- 缺失 height 数据。
- 特殊地图模式。
- 非地表兼容路径。

Shader 首先判断：

```text
currentHeight < 0
→ 完全跳过高度视觉
```

### 5.3 缺失邻居

如果邻 Chunk 尚未加载，或邻格拿不到 height：

```text
neighborHeight = currentHeight
```

即暂时不画假边缘。

等邻 Chunk 提交后，现有 `ChunkCommitted` 边界刷新机制重新上传正确值。

禁止把缺失邻居当成 `height=0`，否则会出现整齐的假悬崖。

### 5.4 水格

Water 保持自己的水深视觉。

Ground 计算邻居高度时：

```text
如果邻格是 Water
→ neighborHeight = currentHeight
```

也就是高度台阶**不负责画海岸线**，海岸线继续交给现有 Water Shore 逻辑，避免双重粗边。

## 6. Shader 设计

目标 Shader：

`Assets/9_Shaders/Shader/Chunk-BRG-Contact-Lit.shader`

不新建第二套 Ground Shader。

### 6.1 建议新增材质参数

```text
_ElevationStrength
_ElevationLevelCount
_ElevationToneStrength
_ElevationShadowStrength
_ElevationHighlightStrength
_ElevationEdgeWidth
_ElevationDeltaForMaxStrength
```

| 参数 | 作用 |
| --- | --- |
| `_ElevationStrength` | 总开关，0 完全关闭，1 正常 |
| `_ElevationLevelCount` | 高度离散层数，建议默认 20 |
| `_ElevationToneStrength` | 高低层整体轻微明暗 |
| `_ElevationShadowStrength` | 低侧暗边最大强度 |
| `_ElevationHighlightStrength` | 高侧亮边最大强度 |
| `_ElevationEdgeWidth` | 基础边缘宽度 |
| `_ElevationDeltaForMaxStrength` | 相差多少层达到最大边缘强度 |

不要用 Shader Keyword 做开关，避免额外 Variant；`_ElevationStrength = 0` 就能快速回滚。

### 6.2 离散层级

伪代码：

```text
QuantizeHeight(height):
    count = max(2, round(_ElevationLevelCount))
    return min(floor(saturate(height) * count), count - 1)
```

### 6.3 层级差

定义：

```text
delta = neighborLevel - currentLevel
```

语义：

```text
delta > 0
→ 邻居更高
→ 当前格是低侧
→ 画暗边

delta < 0
→ 当前格更高
→ 当前格是高侧
→ 画弱亮边
```

### 6.4 边缘形状

复用现有 `ComputeContact` 的世界格 UV 思路：

```text
cellUV = frac(positionWS + epsilon)
```

分别得到 left / right / bottom / top Edge，再按对应方向层差调强度。

首版不要做：

- 噪声破边。
- 法线伪造。
- 视差。
- 像素高度挤压。
- 顶点位移。

先验证“层级是否一眼可读”。

### 6.5 建议视觉初值

只作为第一轮调试起点：

```text
ElevationStrength            = 1.0
ElevationLevelCount          = 20
ElevationToneStrength        = 0.04
ElevationShadowStrength      = 0.45
ElevationHighlightStrength   = 0.12
ElevationEdgeWidth           = 0.12
ElevationDeltaForMaxStrength = 3
```

如果出现棋盘格 / 网格感，优先按顺序降低：

1. HighlightStrength
2. ToneStrength
3. LevelCount
4. ShadowStrength

不要第一反应扩大 EdgeWidth。

### 6.6 与现有 Contact Shadow 的合成

建议：

```text
基础 Sprite
→ Elevation Tone
→ 现有 Contact Shadow
→ Elevation Shadow / Highlight
→ CombinedShapeLightShared
```

要求：

- 保留现有 `_EdgeColor / _EdgeWidth / _EdgeStrength / _CornerStrength`。
- 不让高度系统覆盖水岸、石地接触等已有语义。
- 高度边缘使用独立参数。

如果实测叠加过重，可以调整合成顺序，但不要删除旧 Contact 功能。

### 6.7 Universal2D / UniversalForward

新增高度视觉必须同时检查两个活跃 Pass。

- `Universal2D` 正常。
- `UniversalForward` 不出现完全不同的基础颜色。
- 同一 Shader 的 `UnityPerMaterial` CBUFFER 布局一致。
- 禁止用材质布局不同的 `UsePass` 拼接。

## 7. C# 表现层设计

目标文件：

`ChunkTilemapRenderer.cs`

### 7.1 新增职责

只给 Ground 实例构建高度数据。

建议增加职责明确的小方法，例如：

```text
SetGroundElevationData(...)
ResolveGroundElevationHeight(...)
ResolveNeighbourElevationHeight(...)
```

名字可以按届时项目风格调整，不要求机械照抄。

不要把高度采样全部堆进 `SetBatchVisual`。

### 7.2 当前格

```text
当前维度不是 Surface
→ Disable

当前格是 Water
→ Disable

读不到 "height"
→ Disable

否则：
Transform0.w = currentHeight
Data1 = 四邻 height
```

### 7.3 四邻

只需要左 / 右 / 下 / 上，不需要对角格。

跨 Chunk 查询复用现有 `TryResolveTerrainCell` 一类解析路径。

以下情况回退当前高度：

- Chunk 未加载。
- height 不存在。
- 邻格是 Water。
- 邻格不属于当前地表高度语义。

### 7.4 脏更新

当前 `Environment` 变化已经刷新 3×3。

高度只依赖四邻，所以现有范围已经足够。

首版不要为了理论最小更新范围把现有逻辑改成十字 5 格，因为水深、岸线、接触遮罩仍共用当前刷新逻辑。

## 8. BRG 与性能约束

### 8.1 保持 112 字节实例布局

本方案复用：

```text
Transform0.w
Data1
```

所以首版不应该修改 `InstanceStride = 112`，也不需要扩大 GPU Buffer。

如果实施时发现这些字段已经被新功能占用，必须先重新评估，不能盲目覆盖。

### 8.2 不增加高度专用 Batch

高度层数不能进入 `VisualKey` 或 `MaterialKey`。

禁止：

```text
Z0 一个 Batch
Z1 一个 Batch
Z2 一个 Batch
...
```

所有高度继续使用同一个 Ground BRG 材质族。

### 8.3 预期成本

CPU：

- Bind / 脏格更新时多读取当前格和四邻 height。
- 不增加每帧 Update。
- 不增加持续轮询。

GPU：

- 每像素增加少量 floor / min / max / smoothstep / lerp。
- 不增加高度纹理采样。
- 不增加 Renderer。

Draw：

- 理论上不因高度层级增加材质或 Batch。
- 最终仍以 Frame Debugger / Profiler 实测为准。

Unity 官方 BRG 允许通过 GraphicsBuffer 给实例提供自定义数据；当前项目已经采用这一模式，因此继续沿用现有实例 Buffer，而不是另建表现系统。

## 9. 兼容性要求

### 9.1 Water

不能改变：

- 水深十档视觉。
- Shore Mask。
- 河流 Flow。
- 湖泊 / 海洋视觉。

高度系统只处理 Ground。

### 9.2 Light2D

高度效果属于地块基础颜色修饰，必须继续进入 `CombinedShapeLightShared`，不能改成 Unlit。

### 9.3 Snow

雪山当前要求纯白 `Tile_Snow`。

高度层级明暗不得把雪地明显染成灰阶。

如果冲突，降低 `_ElevationToneStrength`，不要修改雪地生成规则。

### 9.4 Grass / Ground Cover

草和 GroundCover 继续盖在 Ground BRG 之上。

首版不要求草本身根据 height 变色，不要为了同步效果把所有自然物 Shader 一起改掉。

### 9.5 Blocking / Back

首版：

```text
Back      不参与
Blocking  不参与
```

只处理 `VisualLayer.Ground`。

### 9.6 MOD

MOD 地块只要走当前 Ground BRG，并且对应地表环境存在合法 `height`，就自动得到高度效果。

不要求每个 Tile JSON 增加高度视觉字段。

如果 MOD 维度的 `"height"` 是另一种语义，应通过维度/表现契约关闭。

## 11. 验收标准

### 视觉

1. 玩家不打开调试界面，也能看出明显地势高低。
2. 大片同层地面不会出现棋盘格。
3. 高低边界像台阶/地形层，而不是普通描边。
4. 地图仍保持 TerraFlat 原来的 Tile 美术风格。
5. 水岸和高度边缘不出现双重粗黑边。

### 正确性

1. 使用现有 `height`，不重算地形 Noise。
2. Cave 不错误使用地表高度规则。
3. 未加载邻 Chunk 不产生假边缘。
4. 邻 Chunk 加载后边缘自动纠正。
5. 不修改真实坐标、碰撞、导航和存档。

### 性能

1. 不新增逐格 GameObject。
2. 不新增每 Chunk 高度纹理。
3. 不按高度层拆 Material / Batch。
4. 首版保持 112 字节 InstanceData。
5. 无每帧 CPU 高度扫描。

## 14. 风险与处理

### 风险 A：层数过多，整张地图都是碎边

优先：

```text
降低 Highlight
降低 Tone
降低 LevelCount
最后才降低 Shadow
```

### 风险 B：层数太少，只像几个大色块

提高 `LevelCount`，不要靠扩大阴影宽度假装层数增加。

### 风险 C：和 Water Shore 打架

Water 邻格按当前 Ground 高度回退，不参与 Elevation Delta。

### 风险 D：雪地被染灰

降低 `_ElevationToneStrength`；必要时让 Tone 对近白颜色衰减。

### 风险 E：Chunk 边界出现直线悬崖

先检查：

1. 邻 Chunk 未加载时是否错误回退 0。
2. 相邻 Chunk 提交后是否触发边界刷新。
3. Wrapped 世界邻区地址是否仍走现有规范化链。

不要用扩大阴影掩盖接缝数据错误。

### 风险 F：Shader 成本高

首轮优化顺序：

1. 保持无高度纹理采样。
2. 合并四向边缘数学。
3. 使用统一参数，不增加变体。
4. 实测后再决定是否减少高亮或 Tone。

不要先牺牲 BRG 批处理结构。

## 15. 回滚方案

### 15.1 视觉软回滚

```text
_ElevationStrength = 0
```

应恢复旧 Ground 外观，不需要删除 C# 高度实例数据。

适合临时关闭、对比截图和性能 A/B。

### 15.2 完整代码回滚

如果路线最终放弃：

1. 删除 Ground 高度数据打包。
2. 删除 Shader Elevation 参数和函数。
3. 删除材质对应参数。

因为本方案不改存档、不改世界数据格式、不改 Gameplay、不改 InstanceStride，所以完整回滚成本应保持很低。

# 水体与地面分层开发文档

状态：代码与资源实现完成；实际游戏验收待完成。

验收约定：以真实游戏场景中的操作和结果为准，不再增加或运行冒烟、自动化测试入口。本轮保留当前试玩，未停止游戏；下方第 11 节只在实际确认后勾选。

实现入口：

- 权威数据：`ChunkTerrainData.Liquid.cs`、`LiquidTypeCatalog.cs`；世界生成时同时准备底部 Ground 和初始 Liquid。
- 玩法修改：`WorldLiquidSystem.TrySet/TryPump`；抽取单位是 0～1 的格子液深，返回实际抽取量与稳定 LiquidId。
- 显示与接触：`ChunkTilemapRenderer` 独立提交 Ground/Liquid；`WorldLiquidBehaviour`、`TileEffectReceiver.Liquid` 独立推进液体与地面效果。
- 持久化：`SaveDataMgr.Liquids.cs`、`ChunkSaveRecord.LiquidCells`；仅保存修改格，恢复在显示和导航绑定之前。
- 配置：`LiquidDefinition.worldWater` 支持本体 Addressables 与 MOD Bundle 资源；原 Water Tile 引用已迁移，编号 2/6 保留不用。

P6 本轮提供有限抽水的统一玩法接口；本文未定义抽水机物品、配方、动力、容器份数换算或操作面板，因此未新增一台可制作的抽水机。后续设备接入时复用该接口，不另写改地块逻辑。

## 1. 目标

把“地面”和“液体”彻底分开：

```text
地块系统
→ 负责地面、湖底、河床、海底

Liquid 系统
→ 负责这里是什么液体、液体有多深
```

核心规则：

> 抽水只能改液体深度，不能在抽水时生成或修改湖底 / 河床 / 海底。

---

## 2. Liquid 层保存什么

Liquid 层核心只有：

```text
LiquidDepth     = 当前液体深度，0~1
LiquidTypeIndex = 当前运行时使用的液体数字编号
```

另外有一个长期使用的液体名字：

```text
LiquidId
```

### LiquidId

LiquidId 是液体的固定名字，给 JSON、MOD、存档使用。

例如：

```text
core:dirty_water
core:sea_water
modId:acid
```

只要液体还是同一种东西，这个名字就不要随便改。

### LiquidTypeIndex

运行时没必要让每个格子都保存一串字符串，所以游戏加载全部液体后，临时给它们编号：

```text
0 = 没液体
1 = core:dirty_water
2 = core:sea_water
3 = modId:acid
```

Chunk 格子运行时保存这个数字，可以省内存、查得快。

但这个数字可能因为 MOD 或加载内容变化而改变，所以：

- JSON 不保存它。
- MOD 不保存它。
- 存档不保存它。
- 存档保存 LiquidId。
- 进入游戏后再把 LiquidId 转成 LiquidTypeIndex。

关系：

```text
LiquidId
→ 游戏加载液体配置
→ 转成 LiquidTypeIndex
→ Chunk 运行时使用
→ 保存时再保存 LiquidId
```

### LiquidDepth

LiquidDepth 表示这一格现在有多深：

```text
0.0 = 没液体
0.1 = 1/10 深度
0.5 = 一半深度
1.0 = 满深度
```

它就是现在项目里 `WaterDepth` 的改名，不是新加第二套深度系统。

这次实现时，把现有字段、变量、API、测试里的：

```text
WaterDepth
```

统一改成：

```text
LiquidDepth
```

## 3. 地面怎么处理

`GroundTileId` 继续完全属于地块系统，不放进 Liquid 层。

世界生成时就要把水下面真正的地块生成出来：

```text
海洋
→ 先生成海底 Ground
→ 再生成 core:sea_water + LiquidDepth

湖泊 / 河流
→ 先生成湖底 / 河床 Ground
→ 再生成 core:dirty_water + LiquidDepth
```

以后抽水：

```text
只减少 LiquidDepth
→ LiquidDepth 变成 0
→ 液体消失
→ 原本已经存在的底部地块露出来
```

抽水前后 GroundTileId 必须完全不变。

---

## 4. height 怎么处理

`height` 只在世界生成时临时计算。

它可以通过：

```text
世界坐标 + Seed + 冻结的世界生成规则
```

重新算出来，所以 Liquid 系统没必要长期保存它，也不用写进存档。

生成流程：

```text
坐标 + Seed
→ 算 height
→ 算地形 / 群系 / 初始 LiquidDepth
→ Chunk 生成完成
→ 后面直接使用 LiquidDepth
```

现在还有一些旧代码会：

```text
height
→ 再反算水深
```

这次要改成直接读取 LiquidDepth。

重点检查 Renderer、Navigation、TileEffect、Farmland 等旧引用。

## 6. Chunk 最终关系

```text
ChunkTerrainData

地块数据
└─ TerrainCell[]
   └─ GroundTileId

Liquid 数据
├─ LiquidDepth[]
└─ LiquidTypeIndex[]
```

其它温度、河流、污染等数据继续属于自己的系统。

`TerrainCell.Flags.Water` 如果迁移期间必须保留，只能暂时兼容旧代码。

最终判断这一格有没有液体：

```text
LiquidDepth > 0
```

## 7. Liquid JSON

液体配置继续放在：

`Assets/StreamingAssets/GameConfig/Liquids/liquids.json`

LiquidId 继续作为液体身份。

世界里的液体可以在定义中加入显示和玩法配置，例如：

```json
"worldWater": {
  "spriteAddress": "...",
  "materialAddress": "...",
  "navigationCost": 20000,
  "shallowMoveSpeedMultiplier": 0.5,
  "deepMoveSpeedMultiplier": 0.2,
  "entryTemperatureFloor": 10.0
}
```

JSON 只保存配置和资源地址；Sprite、Material、Shader 仍是 Unity 资源。

当前 `Tile_Water_Fresh / Tile_Water_Salt` 还是旧“水也是地块”的结构。

先完成 Ground / Liquid 分层，再迁移旧 Water Tile，不要继续给旧结构加新功能。

## 8. 深水上浮时，脚下地块不能影响玩家

增加状态：

```text
LiquidFloating
```

它表示角色现在正在消耗游泳体力维持上浮，没有踩到底部地块。

触发条件复用现有游泳规则：

```text
LiquidDepth > SwimmingDepthThreshold
并且还有游泳体力
并且当前正在维持上浮
→ LiquidFloating = true
```

当 `LiquidFloating = true`：

- 脚下 Ground Behaviour 不生效。
- Liquid Behaviour 继续生效。
- 潮湿、体温、游泳、体力、氧气、液体减速、饮用等都不能被关掉。

例如：

```text
脚下是减速泥地
玩家正在水面上浮
→ 泥地减速不生效
```

下面情况要恢复 Ground Behaviour：

- 水变浅。
- 体力耗尽，开始下沉并重新接触底部。
- 离开液体。
- 其它原因结束上浮。

状态切换要求：

```text
开始上浮
→ Ground Behaviour 只 OnExit 一次

重新接触地面
→ Ground Behaviour 只 OnEnter 一次
```

不能每帧重复 OnExit / OnEnter。

现有 `effectSuppressors` 会把整个 TileEffectReceiver 都关掉，所以不能直接用它。

应该分成：

```text
Ground Behaviour
→ LiquidFloating 时暂停

Liquid Behaviour
→ 只要有液体就继续运行
```

## 9. 存档怎么保存

不要保存整个 Chunk 每一格的液体。

世界原本的液体可以靠 Seed 重新生成，所以存档只记录“玩家改过的液体格”。

例如原本：

```text
A格 = core:sea_water，深度 0.8
B格 = core:sea_water，深度 0.6
```

玩家只把 A 格抽到 0.3。

存档只记录：

```text
A格位置
LiquidId = core:sea_water
LiquidDepth = 0.3
```

B 格没改，不保存。

加载时：

```text
1. 先根据 Seed 生成原世界
2. 再读取存档里玩家改过的液体格
3. 用保存的数据覆盖这些格子
4. 最后再让显示、导航等系统开始使用这些数据
```

每个被修改的液体格保存：

```text
格子位置 + LiquidId + LiquidDepth
```

不要保存 LiquidTypeIndex。

# UI 公共控件库补全与 Prefab 复用实施方案

记录日期：2026-10-22。状态：待实现。

## 1. 目标与范围

把界面中重复的基础控件和组合结构接入真正的公共 Prefab，让后续修改字体、边框、内部排版等公共外观时，可以统一传递到使用它们的界面。

本方案基于当前仓库的静态资源与代码调查，只规划后续实现。本次没有修改游戏代码、Prefab 或配置，没有执行 Unity 运行验收。下文数量是调查时的快照，不作为未来的固定指标。

首批处理基础控件接入、设置行、滚动容器、标题栏和分区卡片。弹窗、容量仪表、列表条目分批补充。各窗口的业务流程、内容、尺寸和摆放继续由所属系统管理。

## 2. 当前基础与缺口

### 2.1 已有能力

- UI 目录共有 93 个 Prefab，56 个含嵌套 Prefab 或变体引用；这些数字不能直接理解为剩余 37 个都存在问题。
- `Common/Controls` 已有按钮、关闭按钮、页签、开关、滑块、只读进度条、下拉框、输入框和面板背景等公共资源。
- 公共构建器通过 `PrefabUtility.InstantiatePrefab` 保留嵌套关系，并提供公共控件迁移入口。
- `ReusableUIControl` 标记公共视觉的所有权边界，`ReusableUITabVisual` 负责页签选中表现。
- 设置页和机器页已有部分生成函数复用；主菜单设置与游戏内设置也已嵌套复用部分完整子页。
- 配色集中在 `ui-theme.json`。运行时主题应用与完整资源迁移是不同入口，不能把修改 JSON 理解为全部界面实时换肤。

### 2.2 本次要补的缺口

共用 `CreateRow()`、`AddSection()` 等函数，只会在构建时生成相似结构。生成后的节点仍分别保存在各个界面里，手动修改一个页面不会传递到其他页面。

本方案要求可复用部分在保存后仍保留公共 Prefab 连接。已有公共资源优先接入，缺少的组合结构再新增，避免重复建立第二套基础控件库。

## 3. 资源位置与职责

### 3.1 建议目录

| 目录 | 内容 |
| --- | --- |
| `Assets/2_Prefabs/2-1_UI/Common/Controls/` | 现有基础控件，继续复用 |
| `Assets/2_Prefabs/2-1_UI/Common/Composites/` | 设置行、标题栏、分区卡片、弹窗外壳等通用组合 |
| `Assets/2_Prefabs/2-1_UI/Common/Containers/` | 滚动视口、内容容器等通用容器 |
| `Assets/2_Prefabs/2-1_UI/Settings/Components/` | 设置系统专属组合，已有按键绑定行继续保留 |
| 各业务系统现有目录 | MOD 条目、难度条目等专属模板 |

新增目录和名称属于方案建议，实现时可根据首批样本调整。仅在多个业务都适用时才提升到 `Common`；只在一个系统内重复的模板也可以公共化，但归所属系统维护。

### 3.2 所有权边界

| 对象 | 负责内容 |
| --- | --- |
| 公共基础控件 | 字体、图片、边框、内部几何、通用交互表现 |
| 公共组合控件 | 子控件组成、内部对齐、内边距、间距、可选区域布局 |
| 使用页面 | 文案、数据、事件、选项、控件外部尺寸与位置、显示条件 |
| 业务模块或会话 | 输入校验、保存与放弃、库存事务、机器状态、气压与超压判断等规则 |
| `UIManager`、`BasePanel` | 现有生命周期、输入、焦点、排序和窗口管理 |
| 主题配置与主题应用器 | 共享配色及明确归属主题的视觉属性 |

- 组合控件内部继续嵌套现有基础 Prefab。
- 普通布局优先使用锚点与 LayoutGroup，只有布局确实需要时才增加脚本。
- 确需脚本时，优先提供序列化引用和简单的绑定、刷新接口，不建立万能配置框架。
- 公共控件不按机器 ID、装备 ID 或具体页面类型分支处理业务。
- 不为统一外观新增逐帧查找、轮询或反复扫描整棵 UI 层级。
- 当前主题有按节点名识别的逻辑，迁移时应保留相关名字，或在同批改动中明确调整规则，避免外观被意外覆盖。

## 4. 优先接入已有基础控件

以下页面的相关基础控件仍由各自构建器创建本地对象，可以先接入现有库，无须新增另一套 Button、InputField 或 Slider。

| 资源 | 已确认的接入对象 | 主要构建入口 |
| --- | --- | --- |
| `UI_NetworkMode` | 玩家名、地址、端口输入框；创建主机、加入、断开、关闭按钮 | `NetworkModePrefabBuilder.cs` |
| `UI_SaveSelectionPanel` | 进入世界、删除、载入等操作按钮；角色名输入框；冻结规则开关 | `GameSavePrefabBuilder.cs` |
| `UI_NewGameWorldContent` | 基础/高级页签、世界参数输入框、世界循环开关 | `NewGamePrefabBuilder.cs` |
| `UI_NewGameDifficultyContent` | 难度分类按钮、难度滑条 | `NewGamePrefabBuilder.cs` |

接入时保留原节点身份、序列化引用、事件、输入类型、校验限制、数值范围和默认值。页签保留真实选中状态；关闭动作继续走现有取消与确认流程。

主菜单专属大按钮、触控摇杆、物品槽等不能仅凭“看起来像按钮”就直接替换。先确认其交互和视觉职责，适合时再使用独立变体。

## 5. 新增组合控件与容器

### 5.1 设置项整行：第一优先级

当前样本包括音量页的六个音量行，界面页的缩放、动画速度、触屏透明度，以及镜头页的双指缩放、镜头前探等。网络参数与新世界参数也重复组合标题、输入框和说明文字。

建议先完成两个代表性样本，再扩展到其他类型：

| 建议资源 | 组成 | 保留给使用处的数据 |
| --- | --- | --- |
| `UI_SettingsSliderRow` | 标签＋公共滑块＋数值 | 标题、范围、步长、数值格式、绑定事件 |
| `UI_LabeledInputRow` | 标签＋公共输入框＋可选说明 | 标题、占位文字、输入限制、校验与提交 |
| `UI_SettingsDropdownRow` | 标签＋公共下拉框 | 选项身份、显示文案、当前选择 |
| `UI_SettingsToggleRow` | 标签＋公共开关 | 文案、开关值、变更事件 |

统一管理行高、标签宽度、内部间距和数值对齐。少数确需不同密度的页面使用明确变体或现有布局参数，不要求把所有页面强制改成同一尺寸。

设置数据继续接入现有 Provider 和编辑会话，不在行控件内新增保存、放弃或恢复默认逻辑。动态数值与多语言更新继续由原绑定链路提供。

### 5.2 滚动内容容器：第一优先级

调查时有 11 个设置子页分别保存 `PageViewport / PageContent`；另外 8 个机器类资源各自保存 `FWUI_StatusScroll`。存档列表、新世界参数列表、难度预设列表也分别搭建滚动结构。

建议提供纵向滚动容器，包含视口裁剪、Content、基础布局和滚动组件；根据实际用途提供列表与长文本两种配置。设置页可以再组合为自己的页壳。

- 对外暴露 Content 引用，业务节点仍由所属页面持有。
- 保留 `ItemStepScrollRect` 的现有规则：列表按条目或网格行滚动，长文本按固定步长滚动。
- 滚动条作为可选组成，不把无滚动条的 HUD 强制改成带滚动条。
- 排序、条目池、虚拟化、分页与按需创建继续留在业务系统。
- 不直接替换原生 Dropdown 内部模板；该部分已有独立布局契约。

### 5.3 标题栏与窗口外壳：第二优先级

调查时 20 个 UI 资源各自持有 `FWUI_Header` 相关节点。炉子、篝火、制作台、背包等通过 `PrepareWindow()` 创建标题、分隔线、底部栏及装饰。

先提取标题栏，再按实际重复范围提取窗口装饰外壳。设置内嵌页标题、主菜单大标题可以保留各自版本。

- 公共资源持有标题字体、对齐、边饰和内部留白。
- 窗口持有标题文案、外部尺寸、业务内容和关闭行为。
- 窗口外壳与内容应组合使用，不为所有机器建立一个包含大量开关的通用大面板。
- 保留玩法窗口背景输入透明、槽位与按钮可命中、标题或窄边框可拖动的现有规则。
- HUD、加载黑幕、主菜单背景等专属表现不强制套普通窗口外壳。

### 5.4 分区卡片：第二优先级

`UI_Furnace`、`UI_Bonfire`、`UI_HandCraftTable`、`UI_MakerTable` 中的输入、输出、配方区域，都存在由 `AddSection()` 生成的本地底板、侧标、标题和分隔线。

建议新增 `UI_SectionCard`，统一这些内部外观，对外提供标题和内容容器。使用页面继续决定外部尺寸、内容排布与槽位数量。公共卡片不持有配方或库存业务，不增加没有实际用途的装饰文字。

### 5.5 弹窗公共外壳：后续批次

退出游戏确认、设置未保存确认、存档改名等弹窗存在透明阻断层、居中卡片、消息区和操作区的重复结构。

提取共同外壳，允许业务内容和操作按钮组合。确认、改名、危险操作可以保留不同内容模板。输入锁、取消优先级、未保存确认和焦点恢复继续由现有面板流程处理，外壳只承载结构和展示引用。

### 5.6 气罐容量仪表：后续批次

`UI_FluidTank` 与 `UI_IndustrialFluid` 各自保存完整的 `FWUI_GasCapacity` 节点；构建器分别创建罐体、颈部、填充与百分比。

建议新增 `UI_GasCapacityGauge`，只接收显示比例、百分比文案和显示状态。实际气压、安全上限及超压判断继续由业务会话计算。保持超压时填充封顶、百分比保留真实值并标红的现有行为。

电池仪表外形不同，可以复用填充显示能力或使用独立变体，不必为了共用而强制改成相同轮廓。

### 5.7 系统内列表条目：后续批次

- MOD 六个条目的局部结构重复，适合建立 `UI_ModListItem`。
- 难度预设条目重复标题、说明和选中表现，适合建立 `UI_DifficultyPresetItem`。
- 两类条目先归各自业务目录，不强行抽象为万能列表行。
- MOD 拖拽、分页和身份绑定，难度选择和参数读取，继续由原控制器管理。
- 已有存档行、Buff 行、按键绑定行等独立模板优先保留与复用，不能仅因未放在 `Common` 就判定缺少公共化。

## 6. 迁移与构建器规则

1. 从一个代表性页面提取公共资源，明确哪些属性由公共资源负责，哪些允许实例覆盖。
2. 使用真正的嵌套 Prefab 或变体保存连接；正式资源保存后仍应保留来源关系。
3. 同步修改对应构建器，让后续重建也实例化公共资源，避免重新生成本地副本。
4. 迁移时保留或准确重接对象引用、节点绑定、业务事件与序列化字段，不能只替换可见层级。
5. 显式迁移已有页面，只处理本轮负责的节点与属性；不在编辑器启动或脚本重载时自动批量改资源。
6. 复用现有公共外观覆盖清理规则前，先确认组合控件的所有权范围。不能把整行的文案、值和外部布局一并清掉。
7. 保留现有资源路径和 GUID；新增资源提交对应 `.meta`。需要独立运行时加载的资源才按现有规则增加稳定键和 Addressables 配置。
8. 公共资源补建继续只创建缺失资产，不覆盖已人工编辑的公共 Prefab。
9. 新增公共结构后检查主题应用器是否重复写入内部外观，避免迁移后又产生不必要的视觉覆盖。

不处理旧存档或旧版本兼容，但必须保持当前页面的业务引用和交互完整。

## 8. 后续实现时的验收要点

本节是交给后续实现与用户验收的清单，本次未执行。

- 修改一个公共资源的字体、边框或内部间距，使用它的页面能继承；文案、范围、数值和业务事件保持各自配置。
- 重建一个已迁移页面后，公共嵌套关系仍存在，人工维护的公共资源不被重写。
- 设置页的保存、放弃、恢复默认、语言切换与页签选中正常。
- 列表滚动、长文本滚动、内容裁剪及手机安全区布局正常。
- 机器窗口关闭、拖动、输入透明、库存交互和槽位容量正常。
- 弹窗取消链、输入锁、手柄焦点与文本输入行为正常。
- 气罐仪表的空、满、超压及百分比显示正常。
- 后续涉及系统代码或资源改动时，按 `flatworld-lua-testing` Skill 与 `systems.catalog.json` 选择 `ui_settings` 及受影响的库存、制作等回归；覆盖缺口单独记录。

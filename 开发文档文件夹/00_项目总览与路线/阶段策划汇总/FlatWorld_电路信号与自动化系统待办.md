> 已有电力基础参考：[电力系统规划（完成）](../../05_工业机械与能源/电力系统规划(完成).md)。不要把 ItemWiki 网页里的模拟扩展当成游戏内已实装元件。

## 目标与已确定方向

用尽量少的基础元件，让玩家无需编程便能搭出定时开关、液位控制、自动充电、设备联动，甚至更复杂的逻辑电路。

- **基础物品暂定仅 5 类：信号线、信号器、与非门（NAND）、计时器、继电器。**
- **电力线与信号线分离**：电力线负责实际 W/J 的供需；信号线传控制信息，不直接供能。
- **信号器两种模式**：手动输出 0/1；监听设备公开的状态、比较阈值，再输出 0/1（借鉴 Minecraft 比较器的读取能力，不照搬其 0～15 强度）。
- **设备自己公开状态**：信号器不写“这是电池就读电量、这是水泵就读流量”的设备名单，也不为每个新物品增加分支。
- **NAND 为基础逻辑**：通过组合产生 NOT、AND、OR、XOR、锁存器、触发器和计数器，不强迫把它们都做成独立物品。
- **计时器保留独立物品**：避免玩家必须用复杂反馈才能做“1 秒 1 / 1 秒 0”。
- **继电器保留独立物品**：负责真实电力网络的接通/断开；机器自身的控制端口只负责运行/停止，两者不同。
- **首版信号线 1 位**。后续可扩展数据总线（优先考虑 8 位），但暂不制作任意位宽系统或大位数计算器。

## P0：首版最小闭环（待实现）

### 1. 信号网络

- [ ] 先核对最新的真实电线、电网、设备端口、存档与世界作用域实现，明确可复用接口和现有缺口。
- [ ] 增加独立于电网的 **1 位信号覆盖层 / 连通网络**，能够放置、拆除、跨区块连接；不因与电线同格而混线。
- [ ] 明确单网络多信号源的合并规则、线路交叉规则、无连接输入的默认值和拓扑变化后的刷新时机。
- [ ] 信号网络随所在世界运行、休眠、恢复和存档；不依赖可见 GameObject 或每帧扫描。

### 2. 信号器（手动 + 状态监听，合成一种物品）

- [ ] **手动模式**：玩家在面板中直接切换输出 0 / 1。
- [ ] **监听模式**：绑定邻接或选定设备 → 选择可监听属性 → 设置比较符与阈值 → 输出 0 / 1。
- [ ] 设计**统一的可观测状态接口/注册方式**：由设备或其功能模块提供状态 ID、显示名称、数据类型（布尔/数值）、单位、当前值及可用性。
- [ ] 库存模块公开数量/容量占比；电力模块公开储能/功率/供电状态；流体、温度、机械等模块按需公开自己的状态。**复用模块自动复用状态定义**，不按具体物品 ID 写特例。
- [ ] 信号器配置 UI 自动列出目标设备实际支持的属性；仅展示有效选项，无需玩家写代码。
- [ ] 对比规则先支持布尔真假，以及数值的 `<`、`>`、`=`（是否需要 `≤`、`≥`、迟滞阈值，见“待定细节”）。
- [ ] 设备拆除、换世界、属性消失或绑定失效时，清理监听并进入明确的失效状态，不能继续输出旧结果。
- [ ] 避免每个信号器的 `Update()` 轮询：离散状态优先变化通知；温度、转速等连续数值按机器模拟 Tick（现有机器通常 0.05 秒）统一采样。

### 3. 逻辑与时序

- [ ] **NAND 与非门**：两个 1 位输入、一个输出，验证完整真值表。
- [ ] 明确反馈网络的结算顺序和传播延迟，避免循环依赖、无限递归以及放置顺序影响结果。
- [ ] **计时器**：高电平持续时间、低电平持续时间可配置，至少支持 `1s 输出 1 → 1s 输出 0 → 循环`；可考虑“延时输出”作为同一物品的模式。
- [ ] 用 NAND 组合测试 NOT、AND、OR、锁存与基础计数；这些功能首版**不再增加独立物品**。

### 4. 电力控制

- [ ] **继电器**：输入 0 / 1，控制指定电力线路的接通或断开；线路拓扑及供电结果确实发生改变，不能只修改显示状态。
- [ ] 普通用电设备逐步提供统一的可选 **1 位控制输入端口**，例如启/停水泵、灯泡、自动门；不要求每种机器配置专用控制器。
- [ ] 明确控制端口未接信号、信号变 0、失去供电、拆线时的行为，尽量保持原设备无自动化时的默认体验。

## P1：场景、UI 与验证（待办）

- [ ] 完成信号器交互：显示目标设备、监听属性、当前值、条件、阈值及实时输出 0/1；让玩家能直观看懂为什么输出为 1。
- [ ] 电线、信号线、继电器有明确视觉区别；能快速查看网络的当前高低电平与故障状态。
- [ ] 示例 A：计时器 → 信号线 → 继电器 → 电灯，验证每秒亮灭切换。
- [ ] 示例 B：水箱液位低于 30% 开泵、高于 90% 停泵；用 NAND 记忆电路保持中间区间的状态。
- [ ] 示例 C：电池储能低于阈值触发控制行为，恢复至阈值后改变输出；测试设备状态实时更新。
- [ ] 验证拆线/移机、跨区块、世界休眠与恢复、保存重进、联机一致性（按对应系统现有测试能力分阶段执行）。
- [ ] 验证大量设备监听时的性能、状态变化通知和 Tick 批处理；禁止“每个监听器每帧遍历全世界”。

## P2：暂缓 / 可扩展

- [ ] **保留多位信号的架构扩展点**：允许日后增加独立于 1 位控制线的宽数据总线，讨论优先从 8 位（0～255）开始。
- [ ] 明确不同位宽的接线规则：不得把 8 位数字隐式当成普通布尔值；需要比较或取位元件/模式时再增加。
- [ ] 只有当远程传递电量百分比、设定温度、复杂自动化真正需要数值传输时，才实现 8/16/32 位或玩家自定义宽度。
- [ ] 信号中继、跨线器、调试探针、独立计数器和组合逻辑预设按实际操作成本再评估，不计入首版 5 种物品。
- [ ] 不继续制作 64/1000 位加法器示例；该网页演示已撤销，不能当作游戏生产目标。

## 实现前待确定的细节

- [ ] 信号器与被监听设备是“必须紧邻”，还是允许玩家在面板中指定一定范围内的目标？
- [ ] 同网多个信号源合并方式（逻辑 OR、冲突告警或禁止），及交叉信号线是否默认连通。
- [ ] 信号器阈值附近频繁跳变时，是否需要迟滞（例如低于 20% 开启、高于 30% 才关闭）。
- [ ] NAND 与计时器是否消耗实际电力？若消耗，额定功率与供电异常时如何处理？
- [ ] 信号网络的传播是每 Tick 一次，还是允许组合逻辑同 Tick 求稳态？反馈回路需有确定行为。
- [ ] 未来扩展 8 位数据时，传输的是无符号整数还是归一化数值；需要怎样的 1 位取值/比较适配？

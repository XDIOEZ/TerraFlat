# FlatWorld 电路信号与自动化系统待办

> 讨论更新：2026-11-06
> 状态：**已确定首版方案，尚未实装**。本文件只记录策划与待办，不代表游戏已有这些功能。
> 现有电力基础：[电力系统规划（完成）](../../05_工业机械与能源/电力系统规划(完成).md)。ItemWiki 电路实验室的信号元件目前属于网页模拟，不等于游戏内实现。

## 1. 首版目标与边界（已确定）

**只做一根能传递 1 位工作状态的信号线，直接连接电子设备，不需要中间的信号器或监听器。**

```text
电子设备（实际工作状态）
        ↓ 直接输出 0 / 1
      信号线
        ↓
  查看线路当前状态
```

- **1 = 正在工作，0 = 没有工作**。这里的“工作”指设备正在产生实际功能，不等于仅仅已接通电源或开关处于开启状态。
- 例：电灯实际发光、泵实际输送、电动机实际输出动力时为 `1`；停机、缺电、没有实际工作时为 `0`。电池仅在实际充电或放电时为 `1`，有剩余电量但待机仍为 `0`。
- 仅对能提供明确运行状态的设备开放信号输出；不支持的设备没有输出端口，不应被当成“始终输出 0”。
- **设备直接输出状态**，信号线只负责传递；不单独制作电量监听器、状态信号器等中间设备。
- **信号线与电线分离**：电线传输电力（W/J），信号线只传输 `0/1`，不提供工作电力。
- **首版只读，不控制设备**：信号线输出与显示工作状态；收到 `0` 或 `1` 不会反过来启动/关闭设备，避免引入控制端口和反馈回路。
- 首版位宽**固定 1 位**；`0` 和 `1` 是信号值，不是两种线缆规格。

## 2. 首版信号规则（待实现）

### 2.1 直接接线与网络

- [ ] 在现有世界机器和电网架构上增加独立的 **1 位信号覆盖层**，相邻信号线连成信号网；支持放置、拆除、跨区块与世界作用域。
- [ ] 电子设备可声明自己的信号**输出端口**；信号线接触该端口就能读取设备状态，不需要安装额外方块。端口位置随设备朝向变化。
- [ ] 电力线与信号线可在同一位置交叉但互不连通；首版同层交叉的信号线视为连通，不提供跨线桥。
- [ ] 同一信号网的多个设备采用简单 **OR 合并**：只要有一个设备输出 `1`，整条网络为 `1`；全部输出 `0` 或没有有效输出源时为 `0`。想区分设备就使用不同信号网。

### 2.2 工作状态来源

- [ ] 设备或其业务模块通过统一的只读工作状态接口提供 `正在工作`（布尔值）；信号网络只查询这个结果，不按电池、灯泡、水泵等物品 ID 写分支。
- [ ] 工作状态由实际业务结算决定，不能仅凭“已启用”“接上电网”或“电池尚有储能”推断。
- [ ] 设备停止、失去供电、被拆除或端口失效后，相关信号及时更新为 `0`；不得保留上一次的 `1`。
- [ ] 设备运行状态结算后统一刷新信号网；不为每根线或每台设备添加独立 `Update()` 扫描。

### 2.3 表现、保存与验收

- [ ] 查看设备端口或信号线时，能直接看到当前 `0/1`；电力线与信号线外观可区分。
- [ ] 信号线位置与网络连接随世界保存、休眠和恢复；当前 `0/1` 从设备实时状态重新计算，不额外保存一份可能过期的工作结果。
- [ ] 验证：电灯亮/灭、泵运行/停止、机器缺电、设备拆除、同网两设备 OR 合并、跨区块与存档恢复。只在游戏内真正验收后勾选。

## 3. 后续阶段（首版不做）

- [ ] **机器信号输入**：以后再决定是否让 `0/1` 控制设备启停，以及未接线时如何保持原行为。
- [ ] **信号器/监听器**：以后再考虑检测电量百分比、储罐液位、温度、库存等属性并做阈值比较。首版不需要这些物品。
- [ ] **自动化逻辑元件**：NAND、计时器、继电器、锁存器等均暂缓；不为它们预先增加复杂电路结算机制。
- [ ] **多位信号**：有实际需求时，再评估把信号从固定 1 位扩展为 **1～8 位**，传递电量、温度等数值；届时另定编码、位宽兼容与转换规则，不提前实现。
- [ ] 信号跨线桥、中继器、远程显示器等根据实际使用痛点再考虑。

---

**实施约束：** 第一阶段只实现“设备状态 → 1 位信号线 → 看到 0/1”的最小闭环。优先复用设备真实运行状态和世界机器调度，不改造现有电网供电规则；本次仅更新设计文档，没有修改游戏代码。

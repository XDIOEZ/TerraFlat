# FlatWorld 下一阶段开发指导：稳定基地、遗迹探索与双人闭环

> 制定日期：2026-07-30  
> 适用版本：旧“系统优化路线”完成后的内容生产阶段  
> 核心原则：**停止横向扩张底层系统，开始把现有系统组织成可持续游玩的完整游戏流程。**

---

## 1. 阶段判断

上一阶段已经解决了大量工程底座问题：

- 生物生成拥有生态预算、种群限制、时间补算和联机权威边界。
- 制作入口已经收敛到公共匹配与事务核心。
- 配方已切换为 manifest + JSON 分包，并可由 Excel 同步。
- 内容校验器可以在编辑阶段和正式构建前发现配置断链。
- 难度倍率已经接入战斗、生态、生存、生产和世界规则。
- 遗迹工具已经支持稳定成员 ID、容器槽位内容和确定性 GUID。
- 自言自语、新手生存引导和玩法进度事件已经具备正式基础。

因此，下阶段不应继续优先开发新的“大系统”。当前最重要的问题已经变为：

1. 玩家获得第一块铁后缺少连续、明确的成长目标。
2. 基地设施很多，但尚未形成必须相互依赖的稳定生产网络。
3. 世界生成技术较完整，正式探索内容仍不足。
4. 生存、天气、农业、战斗和遗迹尚未组成同一条风险—收益循环。
5. 单机功能较多，但需要通过完整 Host/Client 流程证明双人游戏真的可玩。

---

## 2. 下一阶段产品目标

本阶段目标定义为：

> **玩家从获得第一块铁开始，建立可以长期维持的基地，通过农业、储存、冶炼和装备升级抵抗环境与敌人，并主动探索三类遗迹获得进入高级工业阶段的关键资源。相同流程必须能够由两名玩家共同完成。**

目标循环：

```text
获得第一块粗铁锭
→ 制作首件金属工具或基地升级件
→ 建立燃料、食物和储存体系
→ 经历一次具有准备价值的恶劣天气
→ 根据环境线索发现遗迹
→ 承担战斗或资源风险
→ 带回稀缺物资或技术线索
→ 升级生产能力
→ 准备更远距离探索
```

本阶段结束时，玩家应当能够回答：

- 我的基地现在比出生时强在哪里？
- 为什么我要种植，而不是永远依赖野外采集？
- 为什么需要铁制工具和更高级设施？
- 为什么值得离开安全基地去探索遗迹？
- 下一阶段需要寻找什么？

---

## 3. 范围控制

### 本阶段必须完成

- 第一块铁之后的明确成长链。
- 基地设施的功能分工和资源循环。
- 一种完整可重复的农作物循环。
- 一套能够影响玩家决策的天气事件。
- 三类具有不同风险和奖励的遗迹。
- 单机完整存档恢复验证。
- 双人 Host/Client 完整纵向流程验证。
- 第一轮内容数值平衡和可玩性验收。

### 本阶段暂不扩展

- 完整太空探索。
- 多星球内容生产。
- 大型科技树。
- 传统任务列表和任务追踪 UI。
- 完整季节系统。
- 大规模自动化流水线。
- PvP、专用服务器和大型多人联机。
- 大量新生物或新武器类型。
- 理智、复杂营养、疾病等额外生存条。

若现有系统出现问题，只修复阻塞本阶段闭环的部分，不借机进行无关重构。

## 4. 推荐里程碑

## M1：第一块铁之后仍有目标

完成以下流程：

```text
铁矿
→ 粗铁锭
→ 熟铁锭
→ 第一件金属制品
→ 新生产能力
→ 遗迹探索需求
```

关键要求：

- `Ore_Iron → Ingot_RawIron → Ingot_WroughtIron` 必须成为真实可完成的连续生产链。
- 第一件金属制品不能只是数值更高，应当带来明显新能力。
- 玩家获得第一块粗铁锭后，通过自言自语和世界反馈获得下一目标。
- 不使用传统任务面板强制追踪。

建议首件金属制品优先级：

1. 提升采集效率或允许采集更高等级资源的工具。
2. 能提高基地生产效率的关键零件。
3. 用于防御夜间敌人的可靠武器。

不建议把首块铁立即消耗在纯装饰物或没有新能力的配方上。

---

## M2：形成可持续基地

基地必须从“摆放建筑”转变为“互相依赖的生产网络”。

推荐设施职责：

| 设施 | 核心职责 | 必须解决的问题 |
|---|---|---|
| 帐篷 | 休息、重生或时间管理 | 给基地提供身份和返回价值 |
| 木箱 | 分类储存 | 解决资源增长后的背包压力 |
| 工作台 | 复杂制作 | 区分手工制作和基地制作 |
| 火堆 | 烹饪、照明、基础热源 | 支撑首夜和基础食物处理 |
| 熔炉 | 矿石和金属加工 | 建立金属时代入口 |
| 耕地 | 稳定食物生产 | 降低对随机采集的长期依赖 |

验收标准：

- 每个设施至少拥有一个其他设施无法替代的作用。
- 玩家不会只依赖一个万能建筑完成全部生产。
- 设施成本不会形成循环依赖或关键资源死锁。
- 拆除、保存和重载后设施状态、库存和占地一致。
- 基地在夜晚和恶劣天气中具有明显安全价值，但不是绝对无风险区。

---

## M3：让世界值得离开基地

至少建立三类正式探索地点：

### 1. 猎人营地

主题：食物、生物和野外生存。

- 主要风险：狼群、视野受限、食物腐坏或返程压力。
- 主要奖励：处理后的食物、皮革类资源、基础武器或生态线索。
- 设计作用：连接生态、战斗、食物和基地储备。

### 2. 废弃矿工营地

主题：矿物、燃料和冶炼。

- 主要风险：敌对生物、狭窄地形、较远路程。
- 主要奖励：`Ore_Iron`、`Ore_Coal`、工具补给或冶炼提示。
- 设计作用：为金属时代提供高风险加速路径，但不能完全替代正常采矿。

### 3. 坠毁舱或古代设施

主题：长期目标和未知技术。

- 主要风险：强敌、极端环境或一次性机关。
- 主要奖励：高级工业所需的稀缺部件、蓝图线索或不可批量获取的关键材料。
- 设计作用：向玩家展示地面生存之外的长期方向，但本阶段不开放完整太空玩法。

遗迹通用规则：

- 每类遗迹必须有不同的外观轮廓、进入风险和奖励结构。
- 奖励分为保证奖励、随机奖励和叙事线索三层。
- 不允许一处遗迹直接跳过完整发展阶段。
- 不能只放空箱子或随机垃圾；每个正式遗迹都必须回答“玩家为什么来这里”。
- 使用既有结构成员 ID、固定槽位容器和内容哈希能力，不新建第二套遗迹掉落系统。

## 5. 明确开发任务清单

以下任务按执行顺序排列。一个 Agent 一次只领取一个任务，完成验收后再进入下一项。

## P0：先做完整纵向流程

### FW-NEXT-01：定义金属时代内容矩阵

**目标**：确定第一块铁之后的所有输入、产物、设施和用途。

交付内容：

- 列出 `Ore_Iron`、`Ingot_RawIron`、`Ingot_WroughtIron` 的来源和消耗去向。
- 为每种金属材料配置至少一个实际用途。
- 明确首件金属工具、首件金属武器和首个基地升级件。
- 检查现有 JSON 配方是否存在重复捷径、无用途产物或温度死锁。

验收：

- 所有金属材料都能获取、加工并被消耗。
- 不依赖管理员命令或遗迹必刷才能进入金属时代。
- 内容校验器无错误。

### FW-NEXT-02：完成“第一块铁”反馈

**目标**：让玩家知道自己完成了重要阶段，并理解下一步。

交付内容：

- 在权威制作/熔炼成功点发布稳定进度事件。
- 为本地玩家贡献“获得首块粗铁锭”等结构化 Fact。
- 使用自言自语 JSON 提示首件金属制品或遗迹方向。
- 将一次性进度写入现有扩展 JSON 存储，不扩展旧 MemoryPack 核心字段。

验收：

- 提前获得物品也能正确跳过前置步骤。
- 保存重载后不会重复播放一次性阶段台词。
- 远程玩家副本不会推进本地进度。

### FW-NEXT-03：梳理基地设施功能

**目标**：消除设施用途重复和无意义建筑。

交付内容：

- 建立帐篷、箱子、工作台、火堆、熔炉、耕地的职责表。
- 调整配方成本和前置资源。
- 确认每个设施的召唤器、世界实例、库存、存档和拆除流程。
- 检查建筑放置后对动态导航的影响。

验收：

- 六类设施均有独立用途。
- 放置失败不扣物品。
- 拆除失败不丢建筑或快照。
- 保存重载后设施不重复、不丢库存。

### FW-NEXT-04：完成单一农作物闭环

**目标**：先做一套真正完整的农业内容，不追求作物数量。

推荐流程：

```text
获得种子
→ 制作或准备耕地
→ 补充水分/肥力
→ 播种
→ 经历成长阶段
→ 成熟
→ 收获食物与少量种子
→ 再次种植
```

交付内容：

- 为首种作物选择唯一权威成长实现。
- 明确 `Mod_Seed`、`Mod_Grow`、`Mod_PlantGrow` 的保留、迁移或废弃边界。
- 生长只结算一次天气、耕地、肥力和难度倍率。
- 完成成长进度、阶段、成熟和收获的存档恢复。

验收：

- 一颗种子可以形成可重复循环，但不能无限指数增殖。
- 缺水或缺肥时行为清晰且有反馈。
- 成熟后不会重复生成无限产物。
- 区块卸载重载不会重置或重复结算成长。

### FW-NEXT-05：建立首个天气事件

**目标**：天气必须改变玩家计划，而不是只播放雨效。

第一版只要求完成“降雨过程”：

```text
天气预兆
→ 降雨开始
→ 持续阶段
→ 强度变化
→ 降雨结束
→ 环境恢复
```

影响范围：

- 环境温度。
- 耕地水分或作物成长。
- 玩家外出风险与回基地动机。
- 雨效、音效和自言自语反馈。

验收：

- 天气由权威端调度。
- 天气、强度、阶段和剩余时间可保存。
- 时间跳跃后能够正确结算，不漏掉或重复天气切换。
- 固定种子或注入配置时结果可测试。
- 不在每帧重复实例化或加载雨效资源。

### FW-NEXT-06：完成第一轮生存经济平衡

**目标**：保证食物、燃料、工具耐久和矿物成本互相支撑。

重点检查：

- 火堆和熔炉的燃料消耗。
- 木炭与直接使用木材的价值差异。
- 食物获取、加工和腐坏节奏。
- 石器到金属工具的效率提升。
- 农业成熟前玩家的食物来源。
- 死亡掉落是否会造成不可恢复的失败螺旋。

验收：

- 玩家不会因为单次随机缺失永久卡死。
- 金属工具具有可感知收益，但不让石器完全失去过渡价值。
- 农业能减少长期采集压力，但需要投入和维护。
- 困难模式增加压力，不通过简单延长无意义等待实现。

## P1：扩充探索内容

### FW-NEXT-07：制作猎人营地

- 制作至少一个正式模板和一个变体。
- 配置保证奖励、随机奖励和生态线索。
- 将附近敌人风险与营地奖励匹配。
- 验证旋转、镜像、结构清理、容器存档和内容哈希。

### FW-NEXT-08：制作废弃矿工营地

- 提供铁矿或燃料相关奖励。
- 奖励只能加速金属时代，不能完全替代采矿与冶炼。
- 使用环境、距离或敌人制造返程风险。
- 通过物件、容器内容或自言自语提示熔炼方向。

### FW-NEXT-09：制作坠毁舱或古代设施

- 提供长期目标线索和少量稀缺部件。
- 暂不开放完整火箭或多星球流程。
- 明确其奖励在高级工业中的未来用途。
- 若对应系统尚未开放，奖励说明必须避免误导玩家立即寻找不存在的配方。

### FW-NEXT-10：建立遗迹奖励分层

统一使用：

```text
保证奖励：证明探索不会完全落空
随机奖励：增加重复探索差异
关键线索：连接长期成长目标
```

验收：

- 三类遗迹奖励池有明显差异。
- 同一物品不会无理由出现在所有遗迹中。
- 容器槽位数量、堆叠上限和物品 ID 均通过统一内容校验。
- 固定世界种子下遗迹内容可重复验证。

### FW-NEXT-11：补充自然探索引导

不增加传统任务箭头。优先使用：

- 地形轮廓和道路痕迹。
- 夜间光源、烟雾或声音。
- 遗迹周边异常生成物。
- 角色自言自语中的观察和推断。
- 稀有资源分布形成的自然方向。

验收：

- 玩家不查看地图攻略也有机会发现首个遗迹。
- 提示提供方向感，但不直接暴露所有奖励。
- 同一提示不会高频重复。

## P2：双人、存档和发布质量

### FW-NEXT-12：验证双人基地流程

Host 与 Client 共同完成：

```text
采集
→ 制作
→ 放置基地设施
→ 操作容器
→ 点燃火堆或熔炉
→ 获取第一块铁
```

验收：

- 世界资源和生产结果仅由权威端结算一次。
- 两名玩家看到一致的建筑、库存、燃料、温度和熔炼状态。
- Client 断线重连后恢复正确世界状态。
- 远程副本不运行本地教程、自言自语、存档或 Item Tick。

### FW-NEXT-13：验证双人遗迹流程

- 两名玩家进入同一遗迹时不能重复生成容器奖励。
- 一个玩家拾取后，另一玩家立即看到权威结果。
- 遗迹敌人、死亡、掉落和生态补位只结算一次。
- 两名玩家分处不同区块时，Chunk 观察者并集保持正确。

### FW-NEXT-14：建立关键存档恢复矩阵

至少覆盖以下存档点：

1. 作物生长中。
2. 天气持续中。
3. 熔炉生产中。
4. 遗迹容器被部分拾取后。
5. 建筑放置后、拆除前。
6. 玩家已获得首块铁但尚未完成下一目标。
7. Host 世界中 Client 断线后。

验收：

- 恢复后不重复产出、不清空库存、不倒退一次性进度。
- 随机内容仍服从原世界种子和已保存状态。
- 旧存档缺少新字段时使用安全默认值。

### FW-NEXT-15：建立性能预算

重点场景：

- 双人分别探索不同方向。
- 多个 Chunk 同时加载和卸载。
- 基地内存在大量库存、建筑、作物和光源。
- 夜间存在多个 AI 感知和战斗目标。
- 降雨与其他视觉效果同时运行。

检查项：

- 主线程帧时间尖峰。
- GC Alloc。
- Item/Module Tick 数量。
- AI 感知批次。
- Chunk 加载队列。
- 雨效、光源和 UI 更新频率。

只优化真实热点，不进行无证据的全面重构。

### FW-NEXT-16：封装阶段验收版本

最终检查：

- 统一内容校验无错误。
- Unity Console 无编译错误和阻塞性异常。
- 受影响系统的冒烟测试保持通过。
- 新建世界和旧存档均可进入游戏。
- 单机与 Host/Client 均可完成目标流程。
- 未完成的太空或高级工业入口不误导玩家。

## 7. 当前立即推荐任务

> **先执行 `FW-NEXT-01：定义金属时代内容矩阵`。**

原因：

- 它决定现有矿物、熔炼、工具、建筑和遗迹奖励是否能够连成闭环。
- 它主要是配置和内容审计，不需要先扩展底层架构。
- 如果没有该矩阵，农业、天气和遗迹容易分别完成，却仍然不能形成游戏进程。
- 完成后可以明确哪些配方需要调整、哪些物品没有用途、哪些遗迹奖励真正有价值。

建议该任务最终产出一张表：

| 阶段 | 玩家目标 | 输入 | 设施 | 产物 | 新能力 | 下一目标 |
|---|---|---|---|---|---|---|
| 石器末期 | 找到铁矿 | 石器、食物 | 基础基地 | `Ore_Iron` | 可进入冶炼 | 准备燃料 |
| 粗铁阶段 | 熔炼铁矿 | 铁矿、燃料 | 熔炉 | `Ingot_RawIron` | 制作基础金属件 | 提高温度/加工 |
| 熟铁阶段 | 提纯金属 | 粗铁锭、燃料 | 高温熔炉 | `Ingot_WroughtIron` | 金属工具或设施升级 | 探索遗迹 |
| 探索阶段 | 获取稀缺部件 | 装备、补给 | 稳定基地 | 遗迹奖励 | 进入高级工业 | 长期目标 |

## 8. Agent 执行约束

每个开发 Agent 开始任务前必须：

1. 读取任务直接涉及的专项 Skill。
2. 阅读现有实现和资源，禁止仅凭文档猜测。
3. 明确权威数据源、存档边界和联机边界。
4. 只修改当前任务必需的脚本、Prefab、SO、JSON 或 Excel。
5. 新增内容时复用现有内容校验器。
6. 修改完成后同步更新涉及的专项 Skill。
7. 报告需要人工进行的实际游玩验证，不用删除或弱化现有测试。

每个任务的完成报告至少包含：

- 修改了什么。
- 玩家体验发生了什么变化。
- 哪些 ID、Prefab、JSON、Excel、SO 或存档字段发生变化。
- 单机和联机分别如何结算。
- 仍需人工验证什么。

## 9. 阶段完成判定

满足以下条件后，才能进入高级工业或太空阶段：

- 玩家能从新世界自然发展到第一件金属制品。
- 基地能够稳定提供储存、食物、燃料和生产能力。
- 天气至少一次真实改变玩家的准备或行动决策。
- 农业形成投入、维护和回报闭环。
- 世界至少有三类具有不同价值的正式遗迹。
- 单机保存重载不会破坏上述流程。
- 两名玩家能够共同完成同一流程，且不存在重复结算。
- 玩家完成遗迹探索后能够理解下一阶段长期目标。

阶段总原则：

> **下一步不是继续证明“系统能运行”，而是证明“这些系统组合起来是一款值得持续游玩的游戏”。**

## 1. 阶段判断

七月阶段记录称以下工程底座已建立；本轮仅对制作、配方和部分进度／作物配置作了静态核对，其余保留为历史记录，实施前必须复核：

- 生物生成拥有生态预算、种群限制、时间补算和联机权威边界。
- 制作入口已经收敛到公共匹配与事务核心。
- 配方已切换为 manifest + JSON 分包，并可由 Excel 同步。
- 内容校验器提供编辑阶段的检查入口；不据此重新增加自动构建阻断。
- 难度倍率已经接入战斗、生态、生存、生产和世界规则。
- 遗迹工具已经支持稳定成员 ID、容器槽位内容和确定性 GUID。
- 自言自语、新手生存引导和玩法进度事件已经具备正式基础。

因此，下阶段不应继续优先开发新的“大系统”。当前最重要的问题已经变为：

1. 玩家获得第一块铁后缺少连续、明确的成长目标。
2. 基地设施很多，但尚未形成必须相互依赖的稳定生产网络。
3. 世界生成技术较完整，正式探索内容仍不足。
4. 生存、天气、农业、战斗和遗迹尚未组成同一条风险—收益循环。
5. 单机先走通完整流程；双人能否成立留到独立的 Host/Client 验收阶段。

## 2. 下一阶段产品目标

本阶段目标定义为：

> **玩家从获得第一块铁开始，建立可以长期维持的基地，通过农业、储存、冶炼和装备升级抵抗环境与敌人，并探索矿工营地，带回原矿、燃料和冶炼笔记；其他遗迹后续扩展。先以单机形成完整体验，再单独验证两名玩家共同完成相同流程。**

目标循环：

```text
获得第一块粗铁锭
→ 制作首件金属工具或基地升级件
→ 建立燃料、食物和储存体系
→ 经历一次具有准备价值的恶劣天气
→ 根据环境线索发现遗迹
→ 承担战斗或资源风险
→ 带回稀缺物资或技术线索
→ 升级生产能力
→ 准备更远距离探索
```

本阶段结束时，玩家应当能够回答：

- 我的基地现在比出生时强在哪里？
- 为什么我要种植，而不是永远依赖野外采集？
- 为什么需要铁制工具和更高级设施？
- 为什么值得离开安全基地去探索遗迹？
- 下一阶段需要寻找什么？

## 3. 范围控制

### 本阶段必须完成

- 第一块铁之后的明确成长链。
- 基地设施的功能分工和资源循环。
- 一种完整可重复的农作物循环。
- 一套能够影响玩家决策的天气事件。
- 一个正式矿工营地及其原矿、燃料和笔记奖励链。
- 同版本单机完整存档恢复的人工验收。
- 第一轮内容数值平衡和单机可玩性验收。
- 为后续双人保留现有权威边界；双实例运行结果不作为当前单机策划定稿的前置。

### 本阶段暂不扩展

- 完整太空探索。
- 多星球内容生产。
- 大型科技树。
- 传统任务列表和任务追踪 UI。
- 完整季节系统不归本文件的“稳定基地”子阶段；其后按远古阶段策划实施，不能把这一条理解为取消四季需求。
- 大规模自动化流水线。
- PvP、专用服务器和大型多人联机。
- 大量新生物或新武器类型。
- 理智、复杂营养、疾病等额外生存条。

若现有系统出现问题，只修复阻塞本阶段闭环的部分，不借机进行无关重构。

## 4. 推荐里程碑

## M1：第一块铁之后仍有目标

完成以下流程：

```text
铁矿 → 粗铁锭 → 简易铁镐 → 稳定过渡采矿
铜矿＋锡矿 → 青铜锭 → 青铜镐 → 高级矿物
两条路线与陶器、农业并行 → 完善补给 → 探索遗迹
```

关键要求：

- `Ore_Iron → Ingot_RawIron → Pickaxe_RawIron` 是基础铁器路线；`Ingot_WroughtIron` 保留现有用途，不再强制所有玩家先精炼熟铁才允许做第一件金属工具。
- 铜、低阶铁、青铜的采矿能力目标递增；青铜不要求玩家先拥有铁镐。熟铁／钢的后续顺序另行细化，不能依据旧表直接定为本阶段必经步骤。
- 第一件金属制品不能只是数值更高，应当带来明显新能力。
- 玩家获得第一块粗铁锭后，通过自言自语和世界反馈获得下一目标。
- 不使用传统任务面板强制追踪。

建议首件金属制品优先级：

1. 提升采集效率或允许采集更高等级资源的工具。
2. 能提高基地生产效率的关键零件。
3. 用于防御夜间敌人的可靠武器。

不建议把首块铁立即消耗在纯装饰物或没有新能力的配方上。

## M2：形成可持续基地

基地必须从“摆放建筑”转变为“互相依赖的生产网络”。

推荐设施职责：

| 设施 | 核心职责 | 必须解决的问题 |
|---|---|---|
| 帐篷 | 休息、重生或时间管理 | 给基地提供身份和返回价值 |
| 木箱 | 分类储存 | 解决资源增长后的背包压力 |
| 工作台 | 复杂制作 | 区分手工制作和基地制作 |
| 火堆 | 烹饪、照明、基础热源 | 支撑首夜和基础食物处理 |
| 熔炉 | 矿石和金属加工 | 建立金属时代入口 |
| 耕地 | 稳定食物生产 | 降低对随机采集的长期依赖 |

验收标准：

- 每个设施至少拥有一个其他设施无法替代的作用。
- 玩家不会只依赖一个万能建筑完成全部生产。
- 设施成本不会形成循环依赖或关键资源死锁。
- 拆除、保存和重载后设施状态、库存和占地一致。
- 基地在夜晚和恶劣天气中具有明显安全价值，但不是绝对无风险区。

## M3：让世界值得离开基地

本轮只完成废弃矿工营地；以下猎人营地与古代设施保留为后续候选，不作为当前阶段验收门槛：

### 1. 猎人营地（后续）

主题：食物、生物和野外生存。

- 主要风险：狼群、视野受限、食物腐坏或返程压力。
- 主要奖励：处理后的食物、皮革类资源、基础武器或生态线索。
- 设计作用：连接生态、战斗、食物和基地储备。

### 2. 废弃矿工营地

主题：矿物、燃料和冶炼。

- 主要风险：敌对生物、狭窄地形、较远路程。
- 主要奖励：`Ore_Iron`、`Ore_Coal`、工具补给或冶炼提示。
- 设计作用：为金属时代提供高风险加速路径，但不能完全替代正常采矿。

### 3. 坠毁舱或古代设施（后续）

主题：长期目标和未知技术。

- 主要风险：强敌、极端环境或一次性机关。
- 主要奖励：高级工业所需的稀缺部件、蓝图线索或不可批量获取的关键材料。
- 设计作用：向玩家展示地面生存之外的长期方向，但本阶段不开放完整太空玩法。

遗迹通用规则：

- 每类遗迹必须有不同的外观轮廓、进入风险和奖励结构。
- 奖励分为保证奖励、随机奖励和叙事线索三层。
- 不允许一处遗迹直接跳过完整发展阶段。
- 不能只放空箱子或随机垃圾；每个正式遗迹都必须回答“玩家为什么来这里”。
- 使用既有结构成员 ID、固定槽位容器和内容哈希能力，不新建第二套遗迹掉落系统。

### FW-NEXT-02：完成“第一块铁”反馈

**目标**：让玩家知道自己完成了重要阶段，并理解下一步。

交付内容：

- 在权威制作/熔炼成功点发布稳定进度事件。
- 为本地玩家贡献“获得首块粗铁锭”等结构化 Fact。
- 使用自言自语 JSON 提示首件金属制品或遗迹方向。
- 将一次性进度写入现有扩展 JSON 存储，不扩展旧 MemoryPack 核心字段。

验收：

- 提前获得物品也能正确跳过前置步骤。
- 保存重载后不会重复播放一次性阶段台词。
- 远程玩家副本不会推进本地进度。

已存在[金属阶段台词配置](<C:/Users/CatStudio/Desktop/TerraFlat-master/Assets/Resources/Dialogue/Soliloquy/progression_metallurgy.json>)，因此本项从“从零增加”改为“核对完整链并补齐新目标”。第一块铁的实际判断要区分制作、拾取、容器转移与提前获得；一次性完成事实和台词播放标记分开，不能用一句话播完作为生产成功的证据。

建议反馈顺序：获得粗铁锭时提示绳子与木柄；完成简易铁镐后，提示改善补给或寻找铜锡。未见到锡矿或遗迹线索之前，不报出具体遗迹坐标，也不把“马上精炼熟铁”写成唯一目标。

### FW-NEXT-03：梳理基地设施功能

**目标**：消除设施用途重复和无意义建筑。

交付内容：

- 建立帐篷、箱子、工作台、火堆、熔炉、耕地的职责表。
- 调整配方成本和前置资源。
- 确认每个设施的召唤器、世界实例、库存、存档和拆除流程。
- 检查建筑放置后对动态导航的影响。

验收：

- 六类设施均有独立用途。
- 放置失败不扣物品。
- 拆除失败不丢建筑或快照。
- 保存重载后设施不重复、不丢库存。

设施分工的实现边界：

- 帐篷优先承担已有休息或重生功能；是否能挡雨、保温必须有实际庇护判定支持，不能凭“建了帐篷”直接给整片基地减伤。
- 木箱解决容量与整理，不额外承诺冷藏；普通储存和食物防腐分开设计。
- 手工制作已有 4 个输入槽，世界工作台已有 5 个输入槽，两者共用普通制作类别；不能宣称现有金属配方天然只能在工作台制作。工作站差异先来自容量和实际能力，新增专属配方限制须另列通用能力需求。
- 火堆负责基础饮食和取暖；熔炉负责达到矿物加工阈值。用燃料、升温和输入输出能力区分设施，不再增加一个无独立用途的万能炉。
- 耕地需要持续水肥投入，其回报是可预测产量；地面身份、种植状态与植物外观分别管理。

### FW-NEXT-04：完成单一农作物闭环

**目标**：先做一套真正完整的农业内容，不追求作物数量。

推荐流程：

```text
获得种子
→ 制作或准备耕地
→ 补充水分/肥力
→ 播种
→ 经历成长阶段
→ 成熟
→ 收获食物与少量种子
→ 再次种植
```

交付内容：

- 为首种作物选择唯一权威成长实现。
- 明确 `Mod_Seed`、`Mod_Grow`、`Mod_PlantGrow` 的保留、迁移或废弃边界。
- 生长只结算一次天气、耕地、肥力和难度倍率。
- 完成成长进度、阶段、成熟和收获的存档恢复。

验收：

- 一颗种子能够通过投入形成可重复循环；允许正常扩种，但扩种受土地、水肥、生长时间和保留收获物的成本限制，不通过存取或重载凭空增殖。
- 缺水或缺肥时行为清晰且有反馈。
- 成熟后不会重复生成无限产物。
- 区块卸载重载不会重置或重复结算成长。

首轮建议以萝卜为验收作物，复用当前独立植株、收获物和种子。当前静态配置为每株收获 1～2 个萝卜，25% 概率额外获得 1 颗种子，且 1 个萝卜可加工成 2 颗种子；可持续性应连同“留一部分收成取种”一起计算，不能只看随机掉种就认定种植必定断代。

普通作物现有主链已是独立成长、收获动作和视觉模块；树木等自然植物仍可保留自己的成长模块。旧任务提到的清理不是要求把所有植物强制塞进同一实现。耐温、死亡残留、跨季补算与开春恢复在远古策划统一细化。

### FW-NEXT-05：建立首个天气事件

**目标**：天气必须改变玩家计划，而不是只播放雨效。

第一版只要求完成“降雨过程”：

```text
天气预兆
→ 降雨开始
→ 持续阶段
→ 强度变化
→ 降雨结束
→ 环境恢复
```

影响范围：

- 环境温度。
- 耕地水分或作物成长。
- 玩家外出风险与回基地动机。
- 雨效、音效和自言自语反馈。

验收：

- 天气由权威端调度。
- 天气、强度、阶段和剩余时间可保存。
- 时间跳跃后能够正确结算，不漏掉或重复天气切换。
- 固定种子或注入配置时结果可测试。
- 不在每帧重复实例化或加载雨效资源。

建议的玩家流程：先以云色、雨声前兆或低频自言自语提示；降雨补充耕地水分，同时在缺乏遮蔽时增加体温管理压力；雨后不立刻清空土壤水分。首个事件不依赖玩家刚出门就强制触发，天气提示不播完也必须正常结算。

庇护必须能够通过实际规则判断才计入效果。若当前版本只有热源、没有屋顶遮雨，策划和物品说明先明确其能力，不把墙体围合自动等同于防雨房屋。

### FW-NEXT-06：完成第一轮生存经济平衡

**目标**：保证食物、燃料、工具耐久和矿物成本互相支撑。

重点检查：

- 火堆和熔炉的燃料消耗。
- 木炭与直接使用木材的价值差异。
- 食物获取、加工和腐坏节奏。
- 石器到金属工具的效率提升。
- 农业成熟前玩家的食物来源。
- 死亡掉落是否会造成不可恢复的失败螺旋。

验收：

- 玩家不会因为单次随机缺失永久卡死。
- 金属工具具有可感知收益，但不让石器完全失去过渡价值。
- 农业能减少长期采集压力，但需要投入和维护。
- 困难模式增加压力，不通过简单延长无意义等待实现。

经济评审采用统一口径：标准难度、一个玩家、正常时间倍率、从自然来源开始，分别记录采集耗时、工具损耗、可食用收获、用于留种的收获、燃料净消耗和返程成本。出生至第一块铁的 60～90 分钟仍是建议体验目标，需要人工结果修正，不能据此硬触发赠送或限时任务。

农业成熟前保留采集和狩猎来源；失败后先恢复基础水与食物，再取回或重做工具。基本石器和陶器不消耗遗迹专属部件。每个数字必须服务于具体选择，不能只用大幅增加材料消耗拉长时长。

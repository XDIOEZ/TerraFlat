# FlatWorld 远古阶段策划汇总：金属、陶器、四季与医药

> 整理日期：2026-09-08  
> 来源：本次游戏策划对话。  
> 状态：讨论纪要与方案评估；保存文档不代表已经实现或授权执行全部开发。  
> 约定：“已明确”记录用户表达的方向；“建议”是供后续选择的方案；具体数值、配方与未确定的规则保留待定。

## 1. 阶段目标

让玩家从春季开始建立生活基础，通过金属工具推进探索，通过陶器、饮水、制盐、农业和草药生产，为夏季与冬季提前准备。

核心体验是：**知道下一步需要什么，出门寻找资源，把收获带回基地加工，并在季节变化中感受到准备的价值。**

本阶段按游戏内部的“远古阶段”组织，不要求严格复刻现实历史年代。抗生素属于大后期医药方向；硝石、肥料和火药作为后续发展接口保留。

此前提到的废弃矿工营地、遗迹奖励和一次完整远行，仍是丰富探索内容的策划建议，不列为用户已确定的强制前置。

## 2. 发展路线总览

| 路线 | 主要流程 | 玩家得到的能力 |
|---|---|---|
| 通用绳材 | 藤蔓等原料 → 绳子 → 武器、工具等成品 | 用统一中间材料连接不同自然资源与下游制作 |
| 基础铁器 | 铁矿 → 冶炼粗铁 → 低阶铁镐 | 用一种矿物获得阶段性工具升级 |
| 青铜 | 铜矿＋锡矿 → 青铜 → 青铜镐 | 获得强于低阶铁镐的工具，开采高级矿物 |
| 材质墙体 | 铜、铁、青铜材料 → 对应墙体 | 延续木墙、石墙的围挡与建造用途 |
| 水上平台 | 木、石、铜、铁、青铜材料 → 对应平台 → 铺在水面 | 提供水上立足与建造空间，拆除后恢复原水面 |
| 陶器 | 铲子 → 河边或河流浅水区域采黏土 → 制坯 → 烧成陶罐 | 储水、批量处理饮用水、制盐 |
| 储粮 | 海水 → 制盐 → 腌制食物 → 冬季储备 | 降低冬季野外食物减少带来的压力 |
| 医药农业 | 野生草药 → 草药与种子 → 种植 → 收获 → 加工药品 | 建立可持续的基础药物供应 |
| 筛种农业（后续设想） | 狗尾巴草 → 采集种子 → 筛种 → 粮食作物种子 → 种植与留种 | 从野生植物发展出稳定粮食来源；原设想产出小麦，物种对应待定 |
| 树木与后期医药 | 新增柳树等树种 → 具有用途的材料 → 对应加工路线 | 扩展药物和后期生产内容 |
| 高级矿物 | 青铜镐 → 开采硝石 → 肥料、火药方向 | 扩展农业与后续工具、武器内容 |

这些路线可以相互支持，不预设为必须依次完成的单线科技树。

## 3. 金属工具与矿物

### 3.1 已明确的方向

- 铜镐已有基础内容，下一阶段提供铁器与青铜两条发展路线。
- 铁矿需要先冶炼成材料，再制作工具；“挖铁锭”在本策划中统一记作“采铁矿、炼铁锭”。
- 铁矿路线可以先做出低阶铁镐。
- 铜矿和锡矿用于制作青铜，再制成青铜镐。
- 工具能力的目标顺序为：**铜镐 ＜ 低阶铁镐 ＜ 青铜镐**。
- 青铜镐能开采硝石等更高级的矿物，升级应带来可见的新用途。

### 3.2 名称与路线建议

低阶铁镐暂称 **“简易铁镐”**：比“粗铁镐”“生铁镐”更容易表达它的过渡定位，正式名称仍可调整。

建议将铁器设计为原料种类较少的过渡选择，将青铜设计为需要寻找铜、锡两种资源的进阶选择。暂不规定玩家必须先做低阶铁镐，才能制作青铜镐。

“青铜更强”应优先体现在采矿能力和可开采矿物上；伤害、耐久、速度、体积与成本分别设计，不简单让所有属性一起增长。当前没有确定高阶铁镐、熟铁、钢与青铜之后的完整次序。

### 3.3 与当前内容的差异

静态核对发现，当前生铁镐的穿刺伤害为 21，青铜镐为 18，与这次希望的工具顺序不一致；青铜锭有冶炼配方，但本体配方目录尚未提供消费青铜锭的配方。

这说明后续需要调整工具能力与补齐青铜产物用途，不能把这份策划当成当前游戏已经具备的表现。伤害数值也不等同于已经存在完整的矿物开采等级限制，开采门槛需要单独核对。

### 3.4 通用中间材料：绳子

已明确：**藤蔓先加工成绳子，再用绳子制作武器、工具等需要绑扎或连接材料的成品**，不再让这些配方直接消耗藤蔓。

| 原料来源 | 加工产物 | 规划范围 |
|---|---|---|
| 藤蔓 | 绳子 | 当前优先采用的基础来源 |
| 干枯的稻草 | 绳子 | 后续扩展来源 |
| 柳树枝 | 绳子 | 与新增柳树相连的后续来源 |
| 柳树皮 | 绳子 | 与新增柳树相连的后续来源 |

不同原料统一产出同一种“绳子”，下游配方只要求绳子，不区分它由藤蔓、稻草还是柳树材料制成。以后新增可制绳的材料时，只需扩展原料到绳子的加工配方，不必为每种武器和工具重复增加对应配方。

静态核对确认，项目已有 `Rope` 物品、绳子图标引用，以及 **3 份藤蔓 → 1 份绳子**的配方；后续优先复用现有定义和素材。此处记录的是现有配方比例，不代表其平衡数值已定稿；新增来源的消耗量、产量、加工时间、设施和原料获取方式待定。

本条约束针对藤蔓在配方中充当绑扎、连接材料的用途；其他直接使用藤蔓的用途需按成品功能判断。此次仅记录策划方向，尚未调整游戏配方。

### 3.5 墙体扩展与可拆除的水上平台

按“与木墙、石墙效果类似”的上下文，将本次语音中的“铁枪、青铜枪”暂记为“铁墙、青铜墙”，“10平台”暂记为“石平台”；本条记录墙体和平台，不据此新增枪类武器需求。

| 类别 | 规划内容 | 基本用途 |
|---|---|---|
| 墙体 | 现有木墙、石墙；新增铜墙、铁墙、青铜墙 | 沿用现有格子墙的放置、阻挡、受损与移除机制 |
| 水上平台 | 木平台、石平台、铜平台、铁平台、青铜平台 | 铺在水面上形成可行走、可继续建造的支撑面 |

材质变化主要用于扩展外观、材料消耗和可配置属性；“效果类似”不等于生命值、防御、拆除速度与掉落数量全部相同，这些数值与材质强弱关系尚未确定。平台共用一套放置和移除规则，不为每种材质另写一套水面恢复逻辑。

#### 当前平台怎样实现

本次静态核对的现有 `WaterPlatform_Summoner` 是木板水上平台，走 `TileBuildingSystem.GroundPlacement` 的地表铺设流程：校验目标是水格后，直接把该格的 `GroundTileId` 改成平台地面，将标记设为可行走，并通知水面、岸线和导航更新。

**当前实现是替换水格地面，还不是保留水体的独立平台层。** `TileBuildingCell.ReplacedGroundCell` 保存的原格快照只用于放置过程中扣料失败时回滚，不能作为正式拆除及存档重载后恢复水面的保证；当前平台资源也没有启用受损拆除掉落配置。

#### 已明确的后续要求

- **平台拆除后必须重新露出原来的水面**，不能留下平台地面、空洞或被填成陆地的格子。
- 恢复的不只是水面图片，还包括原水体身份、水深等环境属性，以及对应的水域交互、通行与寻路行为。
- 保存退出、重新进入、离开区块后返回，再拆平台，也应满足同样的恢复要求。
- 平台存在时保留其下方的水体数据，玩家在平台上按支撑面通行；移除平台时撤销支撑面的作用。

#### 推荐的后续架构方向

建议采用 **基础水体层 → 可移除平台层 → 墙体或其他建筑** 的结构：水体继续作为底层权威数据，平台单独保存材质、位置及必要的耐久状态，通行和建筑查询按有效支撑面处理。季节积雪在表现上覆盖相应表面，不改变底下的水体身份。

这里的“平台层”包含可保存的玩法状态与查询规则，不只是多加一张 Tilemap。拆除只移除平台状态并刷新渲染、地块效果和导航，不依赖重新生成地图来猜测原水格，也不只保留一次性的放置回滚快照。

平台上仍有建筑、角色或物品时如何拆除，仍需明确；建议有建筑占用时先要求处理上方建筑，避免产生悬空建筑，但这条限制尚未定稿。平台是否可以损毁、拆除工具、材料返还比例和不同水域的铺设限制也待定。

后续应先完成一类平台的正式拆除与水体保留，再扩展五种材质内容。本次仅更新策划文档，平台架构与新增墙体、平台均尚未实施。

## 4. 陶器、饮水与盐

### 4.1 陶器生产

已明确的流程：**制作铲子 → 在河流附近采集黏土 → 制作陶坯 → 烧成陶罐**。

陶罐承担储水和批量烧水的用途，玩家应当有动力在夏季到来前完成这条路线。“陶坯”是整理生产步骤时采用的名称，具体物品拆分、烧制设施、燃料与温度均待定。

建议陶器与金属路线并行，避免为制作第一只储水陶罐而强制要求青铜镐。铲子的材质与制作门槛尚未确定。

### 4.2 两种水加工需要分开

- 游戏饮水路线：可处理的淡水 → 烧煮 → 饮用水 → 用容器储存。
- 制盐路线：海水 → 蒸发水分 → 获得盐。
- 海水不能因为“已经煮沸”就变为饮用水；若以后加入海水取淡水，应另设蒸馏、冷凝收集路线，本阶段尚未确定加入。

这里描述游戏内的资源与配方语义，不展开现实水处理工艺。

### 4.3 盐的两项明确用途

1. 腌制食物，延长保存时间，为冬季储粮。
2. 支持玩家在高温出汗后补盐，与体力上限变化相连。

腌制对象、保存时间、盐耗、加工等待时间和需要的容器尚未定数值；不预设所有物品都能腌制，也不预设腌制后永久不腐坏。

## 5. 四季、生存压力与农业

### 5.1 季节节奏

| 季节 | 已讨论的环境与压力 | 玩家主要准备 |
|---|---|---|
| 春季 | 新游戏从春天开始，开局活动区域约二十多摄氏度 | 生火、建基地、发展工具、陶器与种植 |
| 夏季 | 高温，出汗与耗水增加，缺水提高中暑风险 | 提前储备饮用水，及时补水、补盐 |
| 秋季 | 作为入冬前的准备阶段是策划建议 | 收获、留种、腌制、储备食物与药材 |
| 冬季 | 气温下降，出现降雪，受寒植物死亡，野外食物供应减少 | 消耗储粮、取暖、管理药材与种子储备 |

春季的开局温度不是把全世界所有群系统一设置为同一温度。各地保留气候差异，季节在当地环境温度基础上发挥作用；全年长度、各季节时长和温度曲线待定。

### 5.2 高温、饮水和缺盐

已明确：夏季出汗导致水分消耗加快；长期不补水存在中暑风险；**不新增无机盐状态条，缺盐通过体力上限下降来表现**。

整理建议：补盐后恢复受影响的体力上限，并给予玩家简洁、可理解的状态反馈。下降速度、上限最低值、恢复速度、补盐食物以及中暑效果均待定；缺盐损失不应被普通体力恢复悄悄抵消。

### 5.3 植物耐温

已明确：野生食物植物和玩家种植作物都应有耐温范围，温度过低或过高会导致死亡，冬季因此形成真实的食物压力。

建议采用可按植物类型配置的规则，草药也接入同一套机制；树木是否受同样的致死规则影响需要另定，不能把柳树等所有新增树种自动纳入“一入冬就死亡”的规则。

建议把生长减慢、受损和死亡区分开，并给出枯萎等可见提示；是否采用持续暴露后死亡、还是达到阈值立即死亡，尚未决定。

需要在后续策划中明确：死亡植株的残留与掉落、种子是否保留、开春如何恢复野生资源，以及离开区块期间如何计算生长和温度损伤，避免仅因玩家没有看着该区域就绕过冬季。

### 5.4 狗尾巴草与筛种育种（后续设想）

新增植物规划：**狗尾巴草**。用户希望后续加入一条通过筛种发展粮食作物的路线，原始设想为：**采集狗尾巴草 → 筛种 → 获得小麦种子 → 种植小麦 → 收获粮食并留种**。

这条路线的玩法价值是让玩家从常见野草开始，经过主动加工与选种，逐步建立粮食生产，而不只是在野外直接捡到成品作物种子。狗尾巴草的生成区域、采集方式和筛种操作尚未确定。

物种对应需要区分现实与游戏设定：若作为现实育种知识，“狗尾巴草筛种成小麦”这个说法是错的；青狗尾草对应的是谷子的驯化路线。若希望贴近现实，建议采用“狗尾巴草 → 筛种与培育 → 谷子”，并把小麦留给另一条作物路线；若保留小麦产出，应明确为游戏化设定。[中国农业大学：狗尾草与谷子的驯化研究](https://cab.cau.edu.cn/art/2022/4/7/art_24507_852455.html)

本次保留用户提出的小麦方案，同时记录谷子方案供后续选择，不擅自替换最终产物。筛种是单次加工还是多轮种植选育、是否存在概率、消耗数量、产量与所需工具均待定；暂不预设完整遗传模拟系统。

后续确定后，将这条路线接入既有播种、成长、收获、耐温与留种流程，并服务于冬季粮食储备；当前只记录为发展方向，尚未添加游戏植物或配方。

## 6. 草药、柳树与医药路线

### 6.1 已明确的草药循环

**自然界生成草药 → 采集药材并获得种子 → 播种 → 成长 → 收获药材与种子 → 加工成药品。**

草药是可种植的农作物，要同时具有野生来源和玩家种植来源；药材、种子、世界植株与加工成品应各有清楚用途。

第一种草药的名称、加工方法、产量、药效和治疗对象尚未确定。可讨论草药包、药膏等游戏物品，但它们是候选方案，不能直接作为已确定配方实施。

### 6.2 新树种与柳树

已明确希望新增几种树，**柳树是确定需要保留的树种**；柳树枝与柳树皮已列为后续制绳原料，其他树种暂未指定，生成区域、具体采集方式、产量和繁殖方式仍待定。

需要纠正：“柳树用来制作抗生素”这个说法是错的。柳树皮含水杨苷，与阿司匹林的发展有关；因此建议将柳树材料用于游戏中的止痛、退热药方向，而非当作抗生素原料。这是对药物类别的区分，游戏效果仍需独立设计。[NCCIH：柳树皮资料](https://www.nccih.nih.gov/health/providers/digest/nutritional-approaches-for-musculoskeletal-pain-and-inflammation-science)

### 6.3 分开的医药方向

| 阶段或方向 | 已明确内容 | 尚待确定或建议 |
|---|---|---|
| 基础草药 | 可采集、留种、种植、加工 | 首种草药、加工方式、基础药品与效果 |
| 柳树药材 | 增加柳树 | 建议采集树皮类材料，连接止痛、退热药方向 |
| 后期精制药物 | 保留医药发展空间 | 设施、成本、配方和作用对象 |
| 大后期抗生素 | 用户希望后期能够制作抗生素 | 独立原料与技术路线；不指定现实制备步骤 |

抗生素主要针对某些细菌感染，不能把它设计成与止痛药同义的“万能消炎药”；游戏中的恢复生命、缓解症状和处理感染应有明确分工。[NHS：抗生素用途](https://www.nhs.uk/medicines/antibiotics/)

策划建议：让草药种植与冬季药材储备相连；基础药品先解决少量清楚的游戏问题，不在本阶段一次性加入大量疾病与药物分类。

## 7. 降雪与积雪：方案评估

### 7.1 已明确的视觉目标

- 冬季需要有空中飘落的雪花效果。
- 降雪不局限于天然雪地群系，森林、草地等非雪地群系也可以下雪。
- 地面会覆盖积雪，树木、建筑和世界物品表面也希望有“盖了一层雪”的效果。
- 用户倾向增加独立雪覆盖层，而不是替换原来的地块。

建议降雪由天气和当地温度共同决定；允许非雪地群系降雪，不代表所有群系在冬季同时、无条件变成雪地。

### 7.2 两种方案比较

| 方案 | 优点 | 代价与问题 | 结论 |
|---|---|---|---|
| 把原 Tile 换成雪 Tile | 固定雪地地形容易制作 | 草地、耕地、道路等需要雪版与恢复规则；季节变化会混入地形变更；仍无法解决树冠、箱顶的覆雪 | 不推荐用作动态季节积雪的主方案 |
| 独立积雪覆盖层 | 保留底下地形，便于积累、融化和局部变化 | 需要设计覆盖遮罩、边缘和排序；单一平面图层不能自动贴合立体物件轮廓 | 推荐地面积雪采用此方向 |

Unity 的 Tilemap Renderer 提供排序层、层内顺序和批量渲染方式，可支持单独安排地表覆盖的绘制位置；这里的方案结论结合了项目现有的区块表现接口，不是 Unity 自动提供的完整积雪功能。[Unity 2022.3：Tilemap Renderer](https://docs.unity3d.com/cn/2022.3/Manual/class-TilemapRenderer.html)

### 7.3 推荐拆成三个表现部分

1. **空中降雪**：雪花粒子表现当前正在下雪，强度与天气相连。
2. **地面积雪**：独立的雪覆盖 Tilemap 或区块覆盖材质，保留地面与耕地原始身份；雪停后可以继续留雪，升温后逐渐融化。
3. **物件覆雪**：树冠、箱子、屋顶等使用各自的积雪遮罩或贴合轮廓的雪顶贴图；覆盖与物件一起排序，不能把全场物件简单盖在同一张置顶白色 Tilemap 下。

建议优先用覆雪遮罩在物件原材质中合成，复用原有遮挡和排序；少量特殊轮廓再配置雪顶贴图。是否所有物件都覆雪、是否包含角色和移动物品、建筑遮挡怎样定义，仍待确认。

**“加一层”指独立维护积雪状态与地表覆盖，不意味着新增一个全局 Sorting Layer 就能完成所有物件覆雪。**

### 7.4 结合现有架构的实现建议

以下是实现方向评估，不是本次已经完成的开发：

- 时间与天气负责季节、降水类型和强度，独立的积雪模块根据温度、降雪与时间推进覆盖状态，避免把所有规则堆进天气管理器。
- 积雪状态由世界模型或独立环境状态模块持有；Tilemap 和 Shader 读取状态负责显示，不作为积雪量的唯一数据来源。
- 地面覆盖可以沿用 `IChunkViewRenderer` 的绑定、解绑与增量刷新方式。现有 `ChunkEnvironmentTilemapRenderer` 已能读取环境层并按阈值显示瓦片，但渐进厚度、融雪和物件覆雪仍需扩展。
- 原地形不因临时覆雪而被改为天然雪地；水面、耕地和建筑的原有玩法保持由各自系统管理。结冰与积雪不是同一个机制，是否加入结冰另定。
- 自然雪地的基础外观与季节性新增积雪分开处理，不能在春季清除覆盖时把永久雪地也抹掉。
- 已由 `ActorRenderEffectController` 管理的渲染器应通过统一材质参数入口合成效果，避免覆雪覆盖现有受击、风摆、水体、作物裁剪和描边；其他静态物件需要明确接入同一覆盖数据的入口。
- 只更新活动区块与发生变化的区域，保留区块合批；评估额外覆盖与雪花对手机性能的成本，避免每格新增独立物体。
- 若积雪影响玩法，存档或离线补算必须能恢复一致的状态；离开世界、切换维度、对象回池时清理纯表现资源。地下是否下雪需遵守维度天气规则，不能把地表雪效带进矿洞。

推荐第一版先完成地面、代表性树木和一类建筑的覆雪，检查积累与融化效果，再决定扩展的物件范围；脚印、雪深减速、屋顶承重等尚未列为本阶段要求。

## 8. 建议开发顺序

本节只用于后续拆任务，不表示现在开始实现。

1. **统一绳材并补齐金属分支**：武器、工具的绑扎材料统一使用绳子，复用藤蔓制绳配方并预留其他原料来源；确定低阶铁镐名称，完成青铜工具用途、能力差异与高级矿物开采门槛。
2. **打通陶器与储水**：铲子、黏土、陶器、淡水加工、储水及海水制盐。
3. **形成夏季准备**：季节时间与温度、高温耗水、中暑和缺盐表现。
4. **形成冬季准备**：腌制储粮、植物耐温、留种与开春资源恢复。
5. **补齐基础医药**：一种可循环种植的草药、明确用途的基础药品，以及柳树材料方向。
6. **完成冬季视觉**：非雪地群系降雪、地面积雪、物件覆雪和融化。
7. **再讨论后期扩展**：硝石对应的肥料、火药完整链，以及独立的抗生素路线。

草药与冬季视觉可以作为后续独立任务规划，但本次没有创建实现任务或修改游戏系统。

狗尾巴草与筛种育种列为后续农业扩展候选，先确定产物和操作规则，再决定实施顺序。

墙体与水上平台列为后续建造任务：平台优先完成“保留底层水体、正式拆除、重载后仍可还原”的完整流程，再扩展材质；铜墙、铁墙、青铜墙复用现有格子墙机制。

## 10. 后续人工试玩关注点

实现对应内容后，再由实际游玩验证这些问题：

- 藤蔓等不同原料能否加工成同一种绳子，下游武器与工具是否统一使用它；初期制绳成本是否合理，是否仍有绕过绳子的绑扎配方。
- 玩家做完铜镐后，能否理解铁器与青铜两条路线的成本和收益，升级是否值得。
- 新墙体是否与木墙、石墙保持一致的放置和阻挡规则；各材质平台是否可行走、可建造，并在拆除后恢复原水面与水域效果。
- 水上平台在保存重进、区块重载之后能否正确拆除还原；平台上有建筑、角色或物品时，是否按已确定的规则处理。
- 夏季到来前是否有足够信息和时间制作陶罐；夏季的水、盐消耗是否形成准备价值。
- 冬天到来前是否能储备食物、药材和种子；植物死亡是否有预兆，春季是否仍有恢复途径。
- 草药是否可以从野生来源发展成可持续种植，药品效果能否与食物恢复区分。
- 非雪地群系能否自然降雪；地面、树木和建筑积雪是否协调，雪停和融雪是否连续。
- 覆雪后地面身份、建筑交互和物件前后遮挡是否正确；区块重载与重新进入世界后是否一致。

本次只新增策划文档，做静态内容核对；未运行游戏测试，也未进行 Unity 编译或控制台验证。后续代码实现按项目规则进行静态检查与 MCP 控制台检查，再交由用户人工试玩。

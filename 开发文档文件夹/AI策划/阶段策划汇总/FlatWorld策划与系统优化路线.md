# FlatWorld 策划与系统优化路线

> 整理日期：2026-07-29  
> 项目定位：Unity 2D 俯视角生存建造沙盒  
> 本文整理此前的策划讨论、系统审计、开发优先级和已经确定的设计方向，作为后续开发参考。

---

## 1. 产品定位

建议将 FlatWorld 的核心定位收束为：

> **支持 1～2 人游玩的持续世界生存沙盒。玩家从荒野求生开始，建立基地，发展农业和冶炼工业，探索遗迹，并最终获得离开星球的技术。**

该定位能够自然容纳项目已有的：

- 程序化世界与 Chunk 流送
- 长期存档
- 组合式 Item/Module 架构
- 生存、食物、温度和天气
- 制作、建造、农业和冶炼
- 战斗、AI 和动态导航
- 双人联机
- 火箭、太空与星球迁移

当前项目的主要问题不是缺少系统，而是：

1. 系统数量较多，但缺少统一的成长主轴。
2. 世界生成能力强，但探索地点和差异化奖励不足。
3. 生存维度较多，但成熟度和重要性不一致。
4. 配方、Prefab、GUID 和字符串 ID 容易发生内容断链。
5. 单机、联机和太空同时扩张，存在范围失控风险。

---

## 2. 推荐核心循环

```text
进入持续世界
→ 探索附近环境
→ 采集木材、石头、食物和基础资源
→ 管理生命、体力、饥饿和饮水
→ 制作基础工具与武器
→ 建立火堆、帐篷、箱子和工作台
→ 发展熔炼、加工和农业
→ 对抗动物与敌对生物
→ 探索生物群系和遗迹
→ 获得高级资源与关键技术
→ 扩建基地
→ 进入下一阶段循环
```

长期进度建议：

```text
荒野求生
→ 石器时代
→ 稳定基地
→ 农业与食物储备
→ 金属时代
→ 遗迹探索
→ 高级工业
→ 火箭与星球迁移
```

## 3. 已有系统成熟度判断

| 系统 | 当前判断 | 主要问题 |
|---|---|---|
| 世界生命周期与存档 | 较成熟 | 需要持续验证旧存档兼容和联机快照 |
| 程序地图与 Chunk 流送 | 较成熟 | 世界内容密度低于生成技术成熟度 |
| Item + Module 架构 | 较成熟 | 内容正确性依赖模块 ID、Prefab 和序列化接线 |
| 背包、快捷栏、装备 | 可玩/较成熟 | 仍需验证边界与联机一致性 |
| 制作系统 | 可玩但技术债较高 | 四套入口存在大量重复逻辑 |
| 建造系统 | 可玩/接近成熟 | 需要继续验证事务、联机和占地一致性 |
| 食物与腐坏 | 较完整 | 复杂度需要对应的反馈和引导 |
| 温度 | 功能存在 | 当前压力和实际用途可能不足 |
| 天气 | 原型/开发中 | 缺少正式自动天气循环 |
| 战斗 | 可玩 | 仍需数值、反馈和掉落链验证 |
| AI | 有一定深度 | 生成预算和世界生态节奏不完善 |
| 农业 | 可玩但实现分散 | 多套成长模块需要统一 |
| 遗迹 | 技术存在、内容不足 | 正式地点种类过少 |
| 双人联机 | 正式开发中 | 需要完整纵向流程的双实例验证 |
| 太空 | 原型 | 尚未与地面长期进度形成完整解锁链 |
| 难度系统 | 初版 | 当前主要差异集中在死亡掉落 |

## 4. 纵向切片：“第一块铁”

建议把首个完整版本的目标定义为：

```text
解决食物与饮水
→ 制作石器
→ 熬过第一夜
→ 建立帐篷、箱子和工作台
→ 找到矿物或遗迹线索
→ 建造熔炉
→ 获得第一块粗铁锭
→ 解锁下一阶段目标
```

目标体验时长建议为 **60～90 分钟**。

### 阶段划分

1. **落地求生**：认识移动、拾取、背包、饥饿和饮水。
2. **夜晚准备**：制作基础工具、取火工具和火堆。
3. **建立据点**：建造帐篷、箱子和工作台。
4. **进入金属时代**：寻找铁矿、准备燃料、使用熔炉。
5. **长期诱因**：通过遗迹、蓝图或特殊部件提示更远目标。

### 验收标准

- 新玩家无需外部攻略即可点燃火堆。
- 玩家能够解释工作台和熔炉的用途。
- 玩家知道死亡原因和改进方式。
- 出生区域不存在关键资源断档。
- 第一块铁出现后立即产生一个明确的新目标。
- 失败主要来自玩家决策，而不是资源随机性或系统信息缺失。

## 5. 自言自语系统设计

已确定使用**玩家控制角色的自言自语**承担世界内引导，而不是传统任务列表。

### 设计原则

- 角色表达观察、需求和计划，不朗读系统命令。
- 系统只在必要时显示按键等操作提示。
- 自言自语不暂停游戏，也不锁定玩家操作。
- 紧急生存反馈优先于教程和氛围台词。
- 角色不能知道其尚未接触过的信息。
- 自言自语不能代替生命、寒冷、中毒等关键 UI 警告。

示例：

不推荐：

> 按 B 键打开制作面板，然后制作石斧。

推荐：

> 这些材料应该能做把石斧。

旁边可以单独显示较弱的系统提示：

```text
[打开制作面板]
```

### 当前运行链

```text
ICharacterSpeechContextContributor
→ CharacterSpeechContext.Facts
→ ConfiguredSpeechProvider
→ Resources/Dialogue/Soliloquy/*.json
→ CharacterSpeechRequest
→ CharacterSoliloquyController
→ ScreenSpaceSpeechBubblePresenter
```

### 当前配置位置

```text
Assets/Resources/Dialogue/Soliloquy/
```

现有饥饿配置：

```text
Assets/Resources/Dialogue/Soliloquy/need_hunger.json
```

### JSON 配置方向

JSON 是自言自语内容、条件、优先级、显示时间、冷却和一次性标记的唯一配置来源。

支持的结构化条件操作符：

```text
Equal
NotEqual
Greater
GreaterOrEqual
Less
LessOrEqual
Exists
NotExists
```

不允许在 JSON 中执行任意 C#、脚本或自由表达式。

### 台词优先级

1. `Emergency`：濒死、严重饥饿等紧急状态。
2. `Critical`：正在恶化的危险状态。
3. `Need`：教程目标、普通生存需求。
4. `Ambient`：天气、环境和氛围感想。

## 6. 新手教程方向

> 当前状态：已经交由其他 Agent 制作，暂不作为后续主开发目标。

第一版教程范围已经收束为：

```text
移动与探索
→ 拾取两块石头
→ 打开背包
→ 制作 ChippedTool
→ 收集取火材料
→ 制作并放置 SparkMaker
→ 使用 Leaf 制造 FireSeed
→ 制作并放置 Bonfire
→ 使用 FireSeed 点燃 Bonfire
→ 教程完成
```

### 已核实的内容 ID

| 内容 | ID |
|---|---|
| 石头 | `Ore_Stone` |
| 打制石器 | `ChippedTool` |
| 木棍 | `Stick_Wood` |
| 木头 | `Log` |
| 叶子 | `Leaf` |
| 钻木取火工具召唤器 | `SparkMaker_Summoner` |
| 已放置钻木取火工具 | `SparkMaker` |
| 火种 | `FireSeed` |
| 火堆召唤器 | `Bonfire_Summoner` |
| 已放置火堆 | `Bonfire` |

### 教程设计边界

- 不实现传统任务面板。
- 不暂停游戏或强制锁定输入。
- 不生成教程专用资源。
- 不自动赠送材料。
- 允许玩家提前完成目标并自动跳步。
- 教程状态机负责进度，自言自语系统只负责表达。
- 教程进度与台词播放完成标记分开保存。

## 8. 当前系统优化优先级

新手教程暂不继续扩展后，建议按以下优先级优化系统。

## P0：优先处理

### 8.1 生物生成与生态预算系统

这是当前最推荐立即开发的模块。

#### 当前问题

- 基础生成表同时包含鸡、野猪和狼。
- 狼另有独立生成配置，可能重复投放。
- 基础生成权重总和超过 1，但当前实现按顺序累加判断，不是真正的归一化权重。
- 缺少按物种、区域和玩家周边限制的存活数量预算。
- 时间触发依赖狭窄容差窗口，时间跳跃可能漏掉生成。
- 缺少远距离休眠、回收和生态恢复规则。

#### 优化目标

```text
动物生成组
敌对生物生成组
夜间生物生成组
特殊里程碑生物生成组
```

增加：

- 权重归一化。
- 全局种群上限。
- 单物种上限。
- 玩家周边上限。
- 生物群系过滤。
- 昼夜和光照过滤。
- 火堆安全范围。
- 时间跨越补偿。
- 远距离休眠或回收。
- 死亡后的生态补位。

#### 验收标准

- 连续运行多个游戏日不会无限堆积生物。
- 实际生成分布符合配置权重。
- 睡觉或时间跳跃不会漏刷或重复刷。
- 敌人不会在玩家视野或已点燃火堆旁出现。
- 保存重载后不会重复处理已完成周期。

主要入口：

```text
Assets/5_Scripts/5-3_GamePlay/Manager/MonsterSpawnerManager.cs
Assets/5_Scripts/5-3_GamePlay/Spawner/SpawnerConfig.cs
Assets/Resources/Config/SpawnerConfig.asset
Assets/Resources/Config/SpawnerConfig_Wolves.asset
Assets/Resources/Config/SpawnerConfig_Ghost.asset
```

### 8.2 制作系统公共核心重构

当前四套制作入口存在大量重复逻辑：

```text
Mod_HandMade
Mod_HandCraftTable
Mod_MakeTable
Inventory_WorkBench
```

建议抽取统一核心：

```text
CraftingRecipeMatcher
CraftingTransaction
CraftingResult
CraftingService
```

统一处理：

- 配方匹配。
- 镜像配方。
- 输入数量校验。
- 输出空间预检查。
- 材料扣除。
- 产物添加。
- 制作成功事件。
- 单机与联机事务边界。

#### 验收标准

- 四种制作入口使用同一个制作事务。
- 失败制作不消耗材料。
- 空间不足时不发生部分产出。
- 多输出配方保持数量守恒。
- 单机和联机结果一致。
- 清除 `Mod_HandMade.GetDefaultTargetInventory()` 的未实现异常。

> 由于新手教程 Agent 可能正在修改制作成功事件，建议等教程改动合并后再开始此重构。

---

### 8.3 内容配置校验系统

需要建立一个统一编辑器检查入口，覆盖：

- 配方输入和输出 ID。
- 建筑召唤器和世界建筑关系。
- Spawner 生物 ID、权重和重复配置。
- 战利品表 ID。
- 生物群系生成物。
- 固定 Resources 路径。
- 重复物品 ID。
- 必填模块和 Prefab 引用。
- 物品显示名与描述污染。

校验器应只报告问题，不应未经确认自动修改资产。

#### 验收标准

- 一个菜单命令检查全部本体内容。
- 错误包含资源路径、字段名和错误 ID。
- 正式构建前不存在缺失引用和重复 ID。
- 配置错误在编辑阶段被发现，而不是进入运行时才暴露。

## P1：核心系统完善

### 8.4 自动天气循环

当前天气支持设置晴、雨和强度，但正式自动调度不足。

第一版建议只实现：

```text
晴
阴
雨
```

运行逻辑：

```text
根据星球/生物群系计算候选权重
→ 选择天气
→ 持续一段时间
→ 平滑过渡
→ 保存天气和剩余时间
```

验收重点：

- 天气不会频繁跳变。
- 保存重载后天气状态一致。
- 雨效、温度和植物生长使用同一权威天气。
- 自动测试可以注入固定天气。

---

### 8.5 农业和植物成长统一

当前存在：

```text
Mod_Seed
Mod_Grow
Mod_PlantGrow
```

需要明确唯一农业主链：

```text
种子
→ 耕地种植
→ 环境倍率
→ 成长阶段
→ 成熟
→ 收获
→ 种子与食物循环
```

其余实现应迁移、标记废弃或删除资源引用。

#### 验收标准

- 同一种植物只有一套成长数据。
- 天气、肥料和耕地倍率不会重复结算。
- 成熟后不会重复产出。
- 保存重载后成长进度一致。

---

### 8.6 遗迹和探索地点扩充

当前正式遗迹内容量明显不足。优先增加：

1. **猎人营地**：食物、皮革、狼群线索。
2. **废弃矿工营地**：矿物、工具和冶炼提示。
3. **坠毁舱或古代设施**：长期目标与稀有部件。

#### 设计原则

- 不继续盲目扩大世界面积。
- 每种地点必须拥有不同风险和奖励。
- 遗迹不能让玩家直接跳过完整发展阶段。
- 相同遗迹不能在近距离重复出现。

---

## P2：清理与后续优化

### 8.7 遗留与未完成代码清理

需要确认资源引用后处理：

- `Player.Act()` 直接抛出 `NotImplementedException`。
- `Mod_HealthPoints` 基本未实现，而正式生命系统是 `DamageReceiver`。
- `SceneChange.Interact_Update()` 仍抛出异常。
- `GameController.Load/Save()` 保留过时 TODO，而按键持久化由 `InputBindingService` 负责。
- `DamageReceiver.DropLoot()` 已有实现，但仍有过时 TODO。

处理方式应是：

- 活跃入口：正式实现或改为安全行为。
- 已被替代入口：标记废弃并移除资源引用。
- 纯死代码：确认无引用后删除。

不要只为了消除异常而补充没有设计依据的逻辑。

---

### 8.8 难度系统深化

难度不建议只使用敌人生命和伤害乘法，应影响：

- 死亡掉落。
- 敌人警觉范围。
- 夜间生态预算。
- 食物腐坏速度。
- 环境伤害宽容度。
- 存档回退规则。

该项应在生态、制作和农业稳定后进行。

## 9. 推荐开发顺序

当前建议：

```text
1. 生物生成与生态预算
2. 等教程合并后重构制作公共核心
3. 内容配置校验系统
4. 自动天气循环
5. 农业与植物成长统一
6. 遗迹与探索地点扩充
7. 遗留代码清理
8. 难度和联机平衡
9. 恢复太空长期内容开发
```

### 当前立即推荐

> **生物生成与生态预算系统**

原因：

- 与正在制作的新手教程冲突较少。
- 可以立即改善世界活力和威胁节奏。
- 可以消除生物无限堆积和重复刷新的风险。
- 为第一夜、探索、战斗、难度和联机平衡提供统一基础。

## 10. 版本范围控制

当前版本应保留：

- 生命、体力、饥饿、饮水。
- 昼夜、基础天气和温度。
- 采集、制作、建造、熔炼。
- 基础农业。
- 核心动物和敌对生物。
- 单机持续世界。

暂缓扩展：

- 理智系统。
- 复杂营养惩罚。
- 完整季节和特殊日。
- 大量新生产设施。
- 大范围新增联机同步。
- 完整太空玩法。

开发原则：

> 在现有核心循环形成完整、可理解、可验证的体验前，不继续横向堆叠新系统。

## 11. 策划验收总则

每个新系统或优化都应回答：

1. 玩家为什么需要它？
2. 它解决了当前循环中的什么问题？
3. 玩家如何发现并理解它？
4. 它带来了什么明确收益？
5. 它是否与已有系统形成闭环？
6. 完成后如何客观验证好不好用？

如果一个功能不能服务于：

```text
生存
成长
探索
基地建设
长期目标
```

中的至少一项，就不应进入当前版本的优先开发范围。

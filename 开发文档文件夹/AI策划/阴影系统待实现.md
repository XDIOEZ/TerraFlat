# 阴影系统待实现

## 目标

为 FlatWorld 增加一套随游戏时间变化的 **2D 风格化长投影系统**，让玩家、生物、建筑等世界物体能够像参考图一样，在地面上投射具有明确方向和长度的阴影。

目标不是做真实 3D 光照，而是在现有 Unity URP 2D 架构上实现稳定、低成本、符合俯视像素画面风格的伪 3D 投影。

---

## 当前项目已有基础

### 1. 实体脚底阴影

- 已有 `ActorShadowManager`。
- 当前阴影属于脚底静态阴影，只表达角色与地面的接触关系。
- 阴影透明度已经会读取 `DayTimeSystem` 的有效光照强度。
- 阴影实例独立放在场景级阴影根节点，不挂在 Runtime Item 层级下。
- 进入水体时已有隐藏脚底阴影的处理。

### 2. URP 2D ShadowCaster

- 已有 `Assets/2_Prefabs/Gameplay/Modules/Rendering/Shadow.prefab`。
- 该 Prefab 使用 `ShadowCaster2D`。
- 它适合局部 2D 光源遮挡，不应直接当成全局太阳长投影系统。

### 3. 昼夜光照

- `DayTimeSystem` 已经负责全局 `Light2D`。
- 游戏时间、昼夜光照强度、月光等信息已有统一入口。
- 新阴影系统应复用 `DayTimeSystem`，禁止再创建第二套独立时间或太阳状态。

---

## 推荐实现方向

采用 **“复制 Sprite 轮廓 + 自定义投影 Shader + 全局太阳方向参数”** 的方式实现。

不建议把全局太阳长阴影主要建立在 `ShadowCaster2D` 上，因为项目中的全局昼夜光属于 Global Light2D，而目标效果本质上是俯视 2D 中的方向性太阳投影。

长投影与现有脚底阴影应当是两个不同表现层：

- 脚底阴影：表达角色贴地、体积感。
- 长投影：表达太阳方向、时间变化和场景空间感。

二者可以同时存在，但职责必须分离。

---

## 待实现模块

### 一、太阳投影参数提供器

新增统一的太阳阴影参数来源，直接读取 `DayTimeSystem`。

负责输出：

- 当前太阳方向。
- 当前阴影方向。
- 当前阴影长度倍率。
- 当前阴影透明度。
- 日出、正午、日落阶段。

基本规则：

- 阴影方向始终与太阳方向相反。
- 正午太阳最高，阴影最短。
- 日出和日落太阳最低，阴影最长。
- 长度必须设置最大值，不能在太阳接近地平线时无限增长。
- 夜晚太阳阴影逐渐淡出，而不是突然关闭。
- 地下、固定光照维度等特殊世界应由维度规则决定是否显示太阳阴影。

建议把太阳参数同步成 Shader Global 参数，避免每个阴影实例重复计算昼夜数据。

---

### 二、长投影管理器

新增独立的场景级长投影管理器，例如：

`WorldShadowProjectionManager`

职责：

- 注册和注销需要投影的世界对象。
- 创建、回收阴影代理 Renderer。
- 维护独立的阴影根节点。
- 同步源 Sprite、动画帧、翻转、尺寸和可见状态。
- 将统一太阳参数交给阴影 Shader。
- 控制最大可见距离和屏幕外阴影更新策略。

禁止把这些逻辑继续堆进 `ActorShadowManager`。

`ActorShadowManager` 继续只负责脚底阴影。

---

### 三、长投影 Shader

新增项目自有 Shader，放入现有统一目录：

`Assets/9_Shaders/Shader/`

Shader 核心功能：

- 使用源 Sprite 的 Alpha 作为阴影轮廓。
- 以 Sprite 的脚底锚点为投影起点。
- 根据物体局部高度将顶点沿太阳反方向拉伸。
- 支持阴影长度、方向、颜色、透明度。
- 保持像素风轮廓，不做昂贵的实时模糊。
- 支持 SpriteRenderer 的翻转和动画换帧。
- 正确处理 SpriteRenderer 的逐 Renderer `_MainTex`。

第一版优先使用硬边或轻微软边，不做高成本半透明卷积模糊。

---

### 四、角色与动物接入

第一阶段接入：

- 玩家。
- 普通 AI 生物。
- 怪物。

要求：

- 阴影跟随角色移动。
- Sprite 动画换帧时阴影轮廓同步变化。
- SpriteRenderer `flipX/flipY` 正确同步。
- 不因为角色对象池停用留下孤立阴影。
- 不把阴影代理 Renderer 挂进角色自身层级，避免停用和回池生命周期冲突。

角色第一版只使用主体 SpriteRenderer 投影。

手持武器、多层衣物、头发等复合 Sprite 是否参与长投影，后续根据视觉效果再决定，避免第一版复杂度过高。

---

### 五、建筑与世界物体接入

第二阶段接入：

- 玩家建造的建筑。
- 树木和大型植物。
- 岩石等明显有高度的世界物体。
- 其他需要突出体积感的静态对象。

建筑应通过已有建筑生命周期或通用注册接口接入，不允许每种建筑单独写特殊阴影脚本。

需要支持可配置的“视觉高度系数”，因为不同 Sprite 的画面高度并不一定等于真实投影高度。

建议默认自动估算，并允许 JSON / Prefab 配置覆盖。

---

## 阴影长度规则

阴影长度不能简单线性映射游戏时间。

推荐使用近似太阳高度曲线：

- 日出：长。
- 上午：逐渐缩短。
- 正午：最短。
- 下午：逐渐拉长。
- 日落：长。
- 夜晚：淡出。

需要设置：

- 最小阴影长度。
- 最大阴影长度。
- 日出日落淡入淡出区间。
- 正午阴影保留比例。

这样可以保留参考图中的长阴影效果，同时避免早晚阴影横跨几十个格子。

---

## 阴影方向规则

太阳方向应与游戏时间统一。

建议：

- 早晨太阳从世界一侧升起，阴影指向相反方向。
- 正午阴影方向保持连续变化，不发生突然翻转。
- 下午阴影逐渐转向另一侧。
- 日落后太阳阴影淡出。

方向必须基于 **游戏时间**，不能使用 Unity `_Time`，否则暂停、跳时、读档和时间倍率改变后会与世界时间脱节。

---

## 月光阴影

第一版不做月光长投影。

原因：

- 月相亮度会变化。
- 月亮方向和太阳方向需要独立轨迹。
- 夜晚同时存在火把等局部光源，阴影关系会快速复杂化。

第一版夜晚只让太阳长阴影淡出，保留现有局部 Light2D / ShadowCaster2D 系统。

后续如果视觉收益明显，再单独设计月光方向性阴影。

---

## 局部光源关系

火把、灯具等局部 2D 光源继续使用 URP 2D Light / ShadowCaster2D 体系。

太阳长投影系统不负责模拟每一个局部光源产生的投影。

两套系统职责：

- 全局太阳：自定义风格化长投影。
- 火把 / 灯具：URP 2D 局部光与 ShadowCaster2D。

避免尝试用一个系统同时解决所有光源阴影问题。

---

## 水体规则

第一版需要单独确认最终美术规则。

建议默认：

- 角色脚底阴影继续沿用现有规则，进入水体隐藏。
- 太阳长投影属于世界投影，可以继续投射在地表和水面上。
- 如果水面上的黑色投影影响观感，再增加水面衰减或水体裁剪，而不是直接复用脚底阴影的隐藏逻辑。

---

## Sorting 规则

长投影必须使用独立阴影表现层，不能和角色主体抢 Sorting Order。

要求：

- 阴影永远位于角色和建筑主体下面。
- 阴影位于需要接收阴影的地面之上。
- 不进入 Runtime Item 的 SortingGroup 内。
- 不因为角色 Sorting Order 动态变化导致阴影跑到角色上方。

如果当前 Sorting Layer 无法稳定表达，需要增加专门的世界投影 Sorting Layer，而不是对每个对象硬编码 order。

---

## 性能规则

第一版设计时就限制成本：

- 共用一个阴影材质。
- 太阳方向和长度使用 Shader Global 参数。
- 阴影实例池化。
- 不为每个对象创建独立材质。
- 不在每帧调用全场景 `FindObjectsOfType`。
- 注册依赖 Item / Building 生命周期事件。
- 屏幕外或远距离对象降低更新频率或停止阴影表现更新。
- 不使用实时 RenderTexture 模糊生成阴影。

目标是在大量实体同时存在时仍能保持稳定性能。

## 实现阶段

### 阶段 1：最小原型

- 玩家长投影。
- 使用当前 Sprite 轮廓。
- 固定方向、固定长度。
- 验证 Shader 投影轮廓是否符合游戏画风。

### 阶段 2：接入昼夜

- 从 `DayTimeSystem` 获取游戏时间。
- 阴影方向随太阳移动。
- 长度随太阳高度变化。
- 日出日落淡入淡出。

### 阶段 3：通用实体

- 玩家、AI、怪物统一注册。
- 对象池生命周期处理。
- 动画 Sprite 同步。

### 阶段 4：建筑与大型世界物体

- 建筑统一注册。
- 支持视觉高度配置。
- 树木、岩石等静态物体接入。

### 阶段 5：表现优化

- 调整阴影颜色与透明度。
- 调整早晚最大长度。
- 处理水面表现。
- 调整不同高度对象的投影比例。
- 做远距离更新优化。

---

## 第一版明确不做

- 不做真实 3D 高度场。
- 不做实时光线追踪。
- 不让每个火把都生成这种长投影。
- 不做多光源阴影混合。
- 不做复杂环境遮挡投影。
- 不做月光方向性长阴影。
- 不为每种建筑单独编写阴影逻辑。

---

## 验收标准

完成后至少满足：

1. 玩家和生物移动时长阴影稳定跟随，不抖动。
2. 动画换帧时阴影轮廓同步。
3. 早晨和傍晚阴影明显较长。
4. 正午阴影明显缩短。
5. 阴影方向随一天时间连续变化，没有突然跳向。
6. 夜晚太阳阴影平滑消失。
7. 暂停、跳时、读档后阴影立即匹配当前游戏时间。
8. 大量实体存在时不产生大量材质实例和全场景扫描。
9. 对象回池、死亡、切换世界后不留下孤立阴影。
10. 火把等局部 2D 光照继续维持现有工作方式，不被太阳阴影系统破坏。

---

## 最终目标画面

整体效果应接近参考图中的风格：

- 阴影轮廓能看出来源物体。
- 有明确的太阳方向。
- 长度具有明显昼夜变化。
- 比真实物理阴影更风格化、更干净。
- 保持 FlatWorld 当前 2D 俯视画面的可读性，不为了真实感牺牲玩法信息辨识度。

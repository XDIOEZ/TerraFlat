## 1. 目标、范围与未决条件

### 1.1 已确认的需求

1. 支持 **10,000 VS 10,000，共 20,000 只独立生物参与战斗**，允许它们同时进入镜头。
2. 每只生物保持独立运行态，不用军团总血条或预录动画代替真实个体。
3. 玩家保留现有 GameObject 体系，通过桥接与 ECS 生物互相攻击。
4. 保留前后遮挡、入水染色／半透明／水线等既有表现，不能为了数量直接删除效果。
5. 提供能分阶段执行、验证和接手的方案，而不是只安装 Entities 包或创建空 System。
6. AI↔AI 感知保留空间格粗筛和 `BuildingOccupancyRegistry + TerrainCell` LOS，最终几何使用纯数据 Position + Radius/AABB 并尽量放入 Burst；只有玩家或必须依赖 GameObject 的对象通过 Bridge 保留 Collider2D。

### 1.2 建议采用的首轮边界

| 项目 | 建议基线 | 状态 |
| --- | --- | --- |
| 性能平台 | 先以 Windows PC 的独立 Player 为基线 | 目标硬件待确认 |
| 帧率 | 60 FPS 目标，不能在实测前保证 | 建议稿 |
| 生物碰撞 | 地形硬阻挡，生物软分离与拥挤处理 | 建议稿；严格刚体推挤另议 |
| 模拟 | 固定步长，移动与战斗先用 30 Hz 原型 | 待测参数，不是固定结论 |
| 美术 | 复用现有图片帧，制作可重复构建的动画数据 | 待实现，不生成新美术 |
| 世界 | 延续当前维度、循环拓扑、建筑占地和地形权威 | 必须兼容 |
| 联机 | 不改写现有服务器权威；批量同步单独验收 | 正式接入必做 |

“2 万只存活”“2 万只正在模拟”“2 万只可见”必须分别统计。不能让其中一项达到 2 万，就宣称三项都达到。镜头外降低表现成本是优化，但不能作为“2 万同屏”的替代证明。

### 1.3 不属于默认授权的工作

不默认升级 Unity，不默认更换 URP 2D，不默认删除旧 Actor 资源，不修改真实玩家存档，不自动提交或推送 Git。修改公共接口、存档格式、网络协议、第三方包及跨平台行为时，执行方仍须遵守当前会话的授权边界。

## 3. 技术路线与不可误解的限制

### 3.1 建议选型

- **模拟：Unity Entities + Jobs + Burst + Native Collections。** 使用数据组件与批量 Job，不把旧 MonoBehaviour 包装成 ECS 后继续逐只调用。
- **配置：现有 Actor／Item／Skill JSON → 校验、继承合并 → 共享只读运行定义。** 可采用 BlobAsset 或等价的 Native 只读表。[U03]
- **导航与碰撞：项目地形／建筑占地 + 共享路径场 + 自定义 2D 几何与局部移动。** 不要求两万套 Rigidbody2D、Collider2D。
- **表现：自定义批量精灵渲染 + GPU 实例数据 + 图集／纹理数组动画。** 优先验证 GPU Instancing；Indirect 是候选提交方式，不是保证兼容当前 URP 2D 的成品方案。[U04]
- **桥接：主线程适配器、只读数据快照、批量命中／结果事件。** 大量 AI 对 AI 战斗不得逐次回到 GameObject 层。

### 3.2 技术事实

托管 ECS 组件不能进入 Jobs 或 Burst；因此不能在热路径存取 Item、Collider2D、Transform、Animator、托管接口对象。[U01]

IJobEntity 可并行调度，但写成 System 不会自动获得正确的并行依赖；频繁开关的状态可采用状态字段或 Enableable Component，减少结构变更。[U02][U05]

Entities Graphics 的 1.4 分支文档对 URP 列出 Forward+ 支持，不应当作当前 Renderer2D 的即插即用替代品。网页分支会更新，实施时仍以本地 1.4.5 包和当前 Unity 版本核对。[U06]

RenderMeshIndirect 支持从缓冲区读取绘制参数，但会把一次提交的几何体整体用于剔除和排序，并要求平台支持 compute shader；它不替你完成逐实例透明排序或与旧 SpriteRenderer 混排。[U04]

ECS 与 Unity 物理可以共存。本文选择让大规模生物不依赖 Physics2D，是性能架构取舍，不是声称 Unity 不允许共存；也不把面向 3D 的物理方案直接当成现有 2D 物理的等价替代。

## 4. 架构与依赖边界

```text
现有 Manifest / Actor JSON / 技能与掉落配置
                │ 加载、合并、校验、能力转换
                ▼
      生物共享定义 + 动画描述资源
                │
                ▼
 ECS 运行态：感知 → 决策 → 导航 → 移动 → 命中 → 结算
                │                  │
                │                  └─ 死亡、掉落、存档、联机事件
                ▼
        只读渲染快照 → 批量渲染

 玩家 / 建筑 / 旧 Item
      ↕ 主线程桥接：身份、形状、攻击意图、结算结果
 ECS 外部目标代理（不是另一个有独立血量的玩家）
```

建议按职责分离契约／纯数据算法、ECS 模拟、Gameplay 适配、渲染与 Editor 导出工具。具体程序集数量由现有依赖决定，不为了形式预建大量空框架。

模拟程序集不得反向引用玩家、UI、网络具体实现和表现组件；Gameplay 适配层可以依赖模拟与旧系统。保持现有 WorldModel 的纯数据边界，不把 Entities 或 Unity 对象塞回后台世界生成代码。

配置能力通过注册表转换，例如“移动、逃跑、近战、饥饿、产蛋”，而不是一个狼专用 System 包办全部。未知能力必须在加载阶段明确报告，不静默忽略模块，假装物种已经完整迁移。

## 5. 身份、组件与配置数据

下表是建议的数据职责，不要求使用相同类型名。

| 数据 | 至少需要表达的内容 |
| --- | --- |
| ActorIdentity | 稳定实例 ID、定义 ID、世界／维度、运行时句柄及代际 |
| ActorMotion | 规范化位置、前一位置、速度、朝向、运动意图 |
| ActorBody | 阻挡形状、受击形状、体型、移动能力类别 |
| ActorBrain | 当前行为、目标句柄、威胁记忆、决策到期时间 |
| ActorVital | 当前生命、必要身体部位状态、死亡标记 |
| ActorAttack | 攻击序号、阶段、技能 ID、时间轴、已命中记录 |
| ActorStatus | Buff、饥饿、体力、氧气、生长等按能力组合的运行态 |
| ActorWater | 是否真实入水、有效淹没高度、必要过渡状态 |
| ActorVisual | 动作／帧信息、朝向、缩放、颜色与特效请求 |
| ExternalTargetSnapshot | 旧对象身份、形状、阵营、可受击状态及快照 tick |

设计要求：

1. 稳定 ID 用于存档、归因和网络；Entity 索引、GetInstanceID、指针不能作为持久身份。运行时引用检查 world epoch、维度与代际，防止对象池复用后命中另一对象。
2. 各物种共享基础配置；每只生物只保存变化部分。对冷数据、稀有能力使用独立组件／紧凑 Buffer，不为所有生物复制最大技能表或完整 JSON。
3. 各生物／攻击拥有可复现随机输入，禁止并行共享 UnityEngine.Random。固定种子不代表天然跨平台逐位确定性，联机仍以权威结果为准。
4. 运行定义从现有配置合并结果构建，保留继承、标签、Blood 资格、掉落表、难度及模块参数；不能按物种名硬编码。
5. 现有托管 CombatDamage 不直接进入 Burst 热路径；转换为无托管引用的数值结构，但保留四类伤害及既有计算语义。
6. 热重载必须在同步边界切换定义版本；旧 Job／GPU 仍引用的 Blob、Native 容器和资源不能提前释放。

## 6. 模拟节奏、线程与空间查询

### 6.1 一个模拟 tick 的建议顺序

```text
主线程冻结世界拓扑、地形版本、旧对象形状与输入命令
→ 基于一致快照进行感知与决策
→ 更新共享导航请求，产生移动意图
→ 地形约束、局部避让、位置积分
→ 更新供本 tick 命中使用的空间索引
→ 推进攻击窗口与投射物扫掠，产生命中事件
→ 按受击目标组织事件，完成各目标的权威结算
→ 主线程应用旧对象命中，收集结果；发布死亡与表现事件
→ 在明确安全点提交结构变化，形成下一状态及渲染快照
```

相同 tick 中感知用哪份位置、命中用哪份位置必须固定；不能混用 T 与 T+1 的随机结果。外部对象快照需匹配模拟时钟；物理帧、渲染帧与 ECS tick 的不同步必须显式处理。

移动与战斗可从 30 Hz 起步，画面插值；战斗决策可从 5～10 Hz、闲逛从 1～2 Hz 起步，并错开到期时刻。受伤、目标死亡、道路被堵允许提前唤醒决策。这些频率均为建议，不是已测结论。

短攻击窗检查本 tick 跨过的时间区间，不能仅判断当前时刻是否落在窗口内。高速移动／箭矢用扫掠，不能仅检测终点。暂停、变速和追赶补帧使用明确时钟；限制追赶次数后必须记录模拟落后，不能静默跳过伤害。

### 6.2 并行与生命周期

同一份 Native 数据的写入有明确依赖。邻居查询读位置快照，避免一边读取邻居一边无序改位置。不同受击目标可并行，同一目标必须由单一结算流程写入。

结构变化集中到明确安全点，可用 ECB；不能把 ECB 当成血量写入互斥器或命中顺序保证。Native 容器、GPU Buffer 和资源句柄必须明确所有者、容量增长策略、释放点与任务依赖。

避免每个 System 立即 Complete、每实体建立 Job、每帧重复分配 List／委托／JSON、不断增加减少组件。稳态模拟热路径以零托管 GC 分配为目标，实际记录不达标来源。

### 6.3 感知和密集空间索引

- 以世界／维度和规范化格坐标建立空间分区，附近候选经过阵营、距离、形状、LOS 精筛。保留目标记忆、目标大小对感知半径的影响与威胁优先级。
- LOS 使用地形 Blocking 信息和建筑离散占地，不在 Job 中调用 Physics2D 或访问 ChunkView。冻结可查询的地形页，跨页读取版本化数据。
- 大体型单位必须覆盖相交格或扩大查询范围，不能只登记中心后漏检边缘；搜索半径不能永远写死为九宫格。
- 单格过密时，感知／避让可使用有规则的候选预算与轮转；不能永久偏爱前几个索引。记录候选数、热点格占用和延迟。
- 实际伤害查询必须完整或遵循技能本身的目标上限，不能因缓冲区满而悄悄截断。无上限范围攻击采用可扩容／分块处理并报告超预算；不能把未完成结果当完成。

**当前已落地的过渡实现（用户补充要求）**：Actor 根级作者形状与当前 JSON 覆盖在定义加载时编译为共享 `PerceptionShape2D`；运行时只用位置/仿射变换生成世界圆或 AABB。既有空间格之后由 `BatchedPerceptionQueryJob` 完成最终几何确认，AI 结果不再调用 `Collider2D.bounds/ClosestPoint`。同步圆形查询与持续锁定复用同一几何；主线程仍保留原有整数格 LOS。玩家和必要的旧对象单独进入 `PerceptionColliderBridge`。

这是感知形状的明确近似：复杂体型使用 AABB，非均匀缩放圆使用包围圆；不能用于宣称精确伤害盒已经迁移。作者 Collider 元数据只在定义编译/旧 AI 结构变化时读取，运行时物理开关不再决定 Actor 感知体型；此改动也没有移除旧 AI 在移动、伤害等其他系统的 Physics2D 依赖。

## 7. 战斗桥接：玩家、旧对象与 ECS 生物

### 7.1 每个目标只有一个权威结算端

| 目标后端 | 生命权威 | 桥接职责 |
| --- | --- | --- |
| 旧玩家／旧建筑／旧 Item | 原有 DamageReceiver | 主线程提交统一攻击上下文并取回结果 |
| 已迁移 ECS 生物 | ECS 生命与战斗运行态 | 对外提供身份、只读状态和结果事件 |
| ECS 内的玩家受击代理 | 没有独立权威生命 | 仅供空间查询、选敌、几何命中 |
| ECS 生物的临时显示或交互外壳 | 不参与生命结算 | 不能重新装上会扣血、掉落的旧运行模块 |

不能同时计算两套血量再互相同步。旧后端迁移为新后端必须是一次明确的身份与运行态转移，不得两个后端同时参与 Tick。

### 7.2 建议的桥接契约

以下为待设计的纯数据消息，不是当前已存在 API：

| 消息 | 必须具备的信息 |
| --- | --- |
| CombatHandle | 稳定对象 ID、后端类型、代际、world epoch、维度 |
| AttackSource | 伤害物身份、Owner／施放者身份、阵营与数值来源 |
| AttackIntent | 攻击序号、技能与窗口、时间戳、攻击形状／扫掠轨迹、基础伤害、目标上限 |
| HitEvent | 来源、目标、攻击／窗口／脉冲序号、命中 tick、位置、必要类型信息 |
| DamageResult | 有效性、实际损失、分类型结算、部位命中、生命前后值、死亡信息 |
| DeathEvent | 唯一死亡事件 ID、死亡对象、归因、掉落所需确定性输入 |

桥接注册表保留“句柄 → 旧对象引用”的主线程映射；ECS Job 只看到值数据。失效、跨世界或代际不匹配的消息应被拒绝并计数。

攻击者已死亡但箭矢仍飞行时，合法归因仍需保留；不能因为无法查到源 GameObject 就把攻击变成无主伤害。也不能为纯 ECS 来源伪造一个 Item 或给每只 AI 补 GameObject。

### 7.3 改造现有 DamageReceiver 入口

当前 Hurt(IDamageSender) 不要求先发生 Collider 回调，但 attacker 的 Item 依赖贯穿阵营、难度、攻击者记录及后续事件；ResolveDamage 目前是私有结算方法。[P07][P08]

建议新增可表达两种后端的攻击上下文入口，旧 Hurt 保留适配转发；提取可共享的纯数值规则，再分别提交各自权威状态。必须追踪 FactionRelationService、受击规则、难度、减速、伤害事件订阅、击杀归因和网络通知，不能只加一个重载就宣告完成。

禁止绕过防御和部位结算直接改 Hp，也禁止把 attacker 设为 null 作为通用兼容方案。既有伤害物与 Owner 的身份区别必须保留，防自伤单独判断。

特别注意时间：原 Hurt 使用 Time.time 判断受伤间隔。如果多个模拟 tick 的事件在同一个主线程批次到达，不能让它们全部被错误视为同一攻击时刻。适配核心应支持明确的模拟时间语义，旧入口仍保持既有行为，不得通过修改全局 Time 来伪装。

### 7.4 双向攻击与旧物理共存

```text
AI → 玩家：外部玩家形状快照 → ECS 命中 → 主线程 DamageReceiver 结算
玩家 → AI：玩家武器窗口与真实形状 → ECS 查询 → ECS 目标结算
AI → AI：全部在 ECS 数据链内完成，不经过逐次 GameObject 适配
玩家 → 旧物体：保留原检测路径，但纳入统一攻击身份与去重规则
```

旧玩家 Collider 继续服务于原物理和交互。主线程导出真实形状、局部偏移、缩放、旋转及所属身份；AABB 只能用于粗筛，不能默认为精确受击形状。不支持的复杂形状必须明确处理策略，不能偷偷退成错误尺寸的圆。

玩家武器同时能命中旧物体与 ECS 生物时，**MaxAttackTargets 必须是整次攻击共同的额度**，不是旧世界三个加 ECS 世界三个。候选统一排序、预留／确认额度，Trigger、窗口起始重叠扫描和扫掠共用攻击序号与去重记录。

## 8. ECS 战斗结算与技能

攻击阶段至少区分前摇、有效窗口、后摇、冷却与中断。动作表现读取同一攻击时间线；Animator 曲线或渲染帧不再作为 ECS 生物伤害的权威时钟。

推荐并行产生命中，然后按目标分组、以明确稳定键逐笔结算。键应包括 tick、攻击来源、攻击序号和脉冲序号；具体同 tick 的同时死亡／中断语义先与旧玩法核对，不能由线程执行顺序决定。

必须保留以下规则：

- 四类伤害、难度、防御、受击倍率、受伤间隔、必要部位生命与装备耐久语义；不能先把所有攻击相加再扣一次甲。
- 0 表示有效但被完全抵消；负值／明确 Invalid 表示无效。数字、附加状态等订阅遵循原有效性规则。
- 同一次窗口不重复伤害同一目标；持续／多段攻击有独立脉冲身份，不能被一次性去重表误吞。
- 死亡状态先登记，再发布观察者事件；死亡、任务归因和掉落只产生一次。观察者异常不能阻断必需的权威收尾。
- 用结算后的实际分类型损失判定出血等效果，保持 Blood 标签规则；不能用原始伤害重新随机部位。
- 箭矢、冲撞、击退、范围技能与环境伤害使用相同身份和结算契约。旧投射物附着目标的逻辑也需要支持 ECS 句柄，不能继续要求目标 Item Transform。

提取通用技能能力与 Buff 执行器，配置负责数值及组合。必要的托管 MOD 回调放到明确边界，并登记“不支持大规模纯 ECS 执行”的能力；不能让两万单位在每个 tick 回调 Lua／MonoBehaviour 后仍宣称完成热路径迁移。

## 9. 导航、拥挤移动与循环世界

### 9.1 导航

复用当前“地形有效可走性与代价 + 建筑占地 → 导航脏区 → 共享搜索”的语义。把供 Job 使用的数据变成只读页／Native 快照，不直接把托管 GoalField 字典塞进 Job。

长距离移动共享战区目标、入口或走廊方向；近距离由个体选敌、选择接敌位置。不要让每只单位每帧都为一个移动中的敌人重建整张路径场。

共享缓存键至少考虑世界／维度、拓扑版本、目的区域、体型／通行能力／代价类别及相关地形版本。禁止让不能游泳与能游泳的单位无条件共享同一最优路径。

保留路径代价拒绝、请求取消和旧路径继续执行的现有语义；拒绝必须反馈决策，避免无限追击重试。不可达目标采用退避重试，不永久堵塞搜索队列。

水与水上平台按当前有效支撑面决定导航，不能因为底层仍是水就让平台不可走。未知／尚未就绪的地图页不是“免费通行”，应等候或取得所需数据租约。

### 9.2 局部移动

地形约束检测形状扫掠，不能只检查终点格；考虑体型、对角穿墙与击退。动态生物先采用局部软分离、优先级、队列／让行和接敌位置分配；允许少量短暂重叠属于建议取舍，不能隐瞒为严格碰撞。

狭窄通道、对向人流和被包围目标必须专门验证。接敌位置避免所有单位冲向一个中心点，附近无位置时应等待、换目标或改变行进方向。

### 9.3 拓扑与地图生命周期

Jobs 使用主线程冻结的 WorldTopologyDomain 值副本；按 WorldModel Skill，不能在 Job 中调用读取 SaveDataMgr 的 WorldTopologyRuntime。

感知、距离、LOS、导航、分离、攻击、投射物、插值都遵循同一循环域。跨边界插值走最短位移，不从整张地图中间划过。查询跨缝需规范化并去重，大半径覆盖多个镜像时同一实体只结算一次。

镜像只属于绘制记录，不产生第二个逻辑实体、Collider、血量或掉落。渲染镜像同步平移排序锚点、水线参考与附属物，不能只平移身体图片。

战斗区域通过模拟需求维持数据租约；ChunkView 隐藏不等于生物不存在。是否允许镜头外继续战斗应由模拟规则决定，不取决于 SpriteRenderer 是否启用。

## 10. 渲染与动画：先证明接入，再扩大数量

### 10.1 动画数据导出

复用现有走路、攻击、死亡等图片帧。Editor 导出器解析实际使用的 AnimationClip／AnimatorOverrideController 与 Actor 定义，生成可重复构建的动作表：帧引用、持续时间、循环规则、尺寸、Pivot、PPU、朝向、必要附属物姿态与语义标记。

现有帧不一定是等宽规则格，可能有图集旋转、裁边和不同 Pivot；必须存储真实 UV 与几何信息，或使用专用、规则化的导出图集。不能把整个原始 SpriteAtlas 当等分九宫格。

运行时每只生物只保留动作、开始 tick／时间、速度和相位，GPU 或批量 CPU 算出当前帧；个体动作不必同步。非循环死亡停在末帧，不能误取模回到第一帧。暂停、速度变化、读档和跨界插值有确定处理。

JSON／Manifest 和 Addressables 继续负责资源发现与句柄所有权；导出是编辑器构建步骤，不能在运行时从 sourcePrefab 反查全部动画。导出器必须列出不支持的曲线与事件，不静默漏掉攻击或附属动作。

### 10.2 批量绘制

建议使用共享矩形网格、共享材质、实例缓冲区、帧描述表和排序索引表。每实例只上传位置、方向、缩放、动作信息、颜色与水体等必要参数。

首版可由 Burst 在 CPU 完成可见性收集和排序，再批量上传；只有分析证明必要时才增加 Compute 剔除／排序。不要为了“全 GPU”强行引入同步读回或额外复杂性。

按透明顺序内的连续兼容区间合批；可用图集／同规格纹理数组降低跨物种换材质。一个物种不一定一批，两万只也不保证一次 draw call。使用紧致绘制 bounds、复用 Buffer，统计上传量和实际 draw 数。[U04]

大规模正式路径不得每只创建 Animator、SpriteRenderer 或 MPB。少量特殊对象可有显示适配器，但必须列明数量与职责；不能让数量随普通生物数线性增长。

### 10.3 前后遮挡与旧 SpriteRenderer 混排

保留 Sorting Layer 的排序值、Order、Render Queue、Y 轴锚点和 SortingGroup 的整体语义，再用稳定 ID 处理同位置平局。SortingLayer 的 ID 不等于排序值；不能按 ID 数字大小直接排序。[U07]

身体与装备／附属物保持一个外部排序组，组内保留相对顺序。不能因为换了一帧动画、受击染色或进入水中就让整只生物换到树冠前面。

需要实现统一的“世界显示项”调度：

```text
ECS 生物显示项 + 旧玩家／树木／建筑的显示适配项
→ 过滤世界、维度、相机与图层
→ 依据既有排序语义排序
→ 只合并顺序上连续且材质兼容的显示项
→ 在正确的 2D 光照上下文中按序提交
```

例如“后方狼 → 树 → 前方狼”必须保持这个顺序，不能先画所有狼再画树。旧对象可以保留玩法 GameObject，但参与混排的颜色绘制必须由同一调度规则接管／插入；需要防止旧原生路径再次绘制，阴影和法线用途则分别处理。

**实现难点不可省略：**独立调用 RenderMeshIndirect 或在全部 Sprite 之前／之后加一个 Pass，不能完成任意混排；仅改变 AI 的 Z 值也不能自动解决旧透明材质与水下半透明。[U04][U08]

首选研究“统一有序显示列表 + 受控的 2D 渲染接入”。若只能通过局部 Renderer2D 适配／受控本地包接入，应先说明影响并遵守授权；**禁止直接修改 Library/PackageCache 作为正式实现**。若当前公开扩展点不能满足要求，应登记具体阻塞，不伪装已经解决。

排序粗分桶、全局按材质重排、近处才正确等方案都会改变遮挡，只能作为明确讨论过的降级选项，不能默认采用。深度写入／Alpha Clip 可研究用于真正的不透明轮廓，但不能替代水下、树冠渐隐等真实透明混合。

### 10.4 Light2D 接入门槛

现有 URP 2D 按光照层批次绑定纹理、关键字并执行绘制。[P14] 实施方必须核实颜色、NormalsRendering、阴影、自发光、Light Blend Style 及相机栈需要的上下文。

仅添加 Universal2D 标签并不会自动采样正确的 2D 光照。不能在最后一层光照纹理仍绑定时画所有生物，也不能改成 Unlit 后把“能看见”当兼容成功。

先完成小规模“玩家 + 多物种 + 树 + 建筑 + 水 + 多盏 Light2D”的兼容性样例，再用同一条路径扩大至两万。纯色／无光照 GPU 基准只能证明基础吞吐，不能证明项目渲染集成完成。

## 11. 入水、颜色、阴影与其他表现

### 11.1 入水逻辑与表现分开

世界地形与有效支撑面提供环境输入，ECS 水中生存逻辑计算有效淹没高度、体力、氧气和移动影响；渲染只读这些结果。不能由 Shader 中“看起来淹到哪里”反过来扣体力或伤害。

专项 Skill 当前描述的生物水中规则包括浅水 0.3、深水漂浮维持、体力耗尽后下沉、超过 0.7 消耗氧气。实施前需读取 TileEffectReceiver 等实际入口，按现有规则移植，不把这些数字散落硬编码到渲染器，也不改写水格本身的深度。

### 11.2 保留当前入水观感

当前 WaterImmersionRenderEffect 与 Sprite-Lit-Master 已使用染色、透明度、柔化水线、波浪和平滑过渡。[P12][P13] 新后端应提取共享 HLSL 公式或等价实现，改为读取实例参数，不为每只 AI 保留原托管效果模块。

实例／共享配置至少提供：入水混合、世界水线 Y、身体参考高度、水下颜色与透明度、水线颜色／宽度、波浪参数、必要过渡状态。固定材质参数放共享表，动态实例值放缓冲区。

身体和旋转附属物共用同一角色世界水线与横向波浪参考；图集 UV 只负责采图，不能当身体归一化高度。尺寸、Pivot、成长缩放与动画帧边界必须参与正确坐标换算，避免变帧抖水线。

水下部分仍需透明顺序；禁止为省事把它改成硬裁剪或全部深度写入，也不能先在角色 Shader 染色一次再被另一个重复水层染色导致双重压暗。[U08]

进水／出水按状态边沿触发；相邻水格切换不重复播放落水事件。漂浮、下沉、死亡、休眠、读档、循环镜像恢复均保持一致。

### 11.3 表现预算

受击闪色、状态染色、溶解、必要轮廓等优先整合为实例数据；不为每种效果增加永久逐 AI 组件。脚底阴影采用批量显示记录，保持现有 Shadow 图层及水中显隐语义，不能给每只 AI 自动补 ShadowCaster2D。

伤害数字、声音、水花、脚印、睡眠标记采用池和可配置可见预算；距离外或重叠严重时允许合并／不展示装饰，但真实伤害、Buff、死亡和掉落必须完整。预算被命中时记录抑制计数，不每帧刷日志。

## 12. 生成、生态、模块与世界交互

### 12.1 运行态与显示态拆开

分别定义存在、存活、参与生态上限、正在模拟、可见、等待持久化和已注销。MonsterManager 的 activeInHierarchy 规则要经适配升级为明确的模拟状态查询，不能因为显示外壳回池就减少存活数。[P11]

统一生命周期注册源；原系统和 ECS 可以有后端注册表，但对外不能形成两套互相矛盾的生物总数。生成、死亡、卸载、跨维度和恢复各处理一次，退出世界等待相关 Job 完成后再释放。

批量实例化 ECS 预设／运行定义，分帧准备表现资源；动态场景和既有 GameWorld 生命周期仍由项目启动入口管理，不能悄悄创建第二个默认 ECS World 重复运行。

### 12.2 生物玩法不能只搬状态机

在迁移清单中逐一登记：移动、感知、威胁、睡眠、近战、远程、特殊技能、生命／身体部位、Buff、饥饿／回血、成长、产蛋、环境暴露、水中生存、交互、掉落及必要对话事件。

保留 Actor JSON 的物种差异、生态出生初始化与普通生成／读档的区别。UnboundedDailyGrowth、IgnorePopulationLimits 及回收保护的语义不得混淆。原模块功能未迁移的物种只能标记为部分支持，不能强制切换后悄悄丢功能。

### 12.3 交互与死亡产物

玩家焦点、选中白框、属性查看、技能锁定、任务和事件接受统一对象句柄，而不是必须获得 Item／Collider。空间查询后按当前交互语义排序，必要的 UI 表现才创建少量外壳。

死亡先记录权威死亡与掉落事务，再按需显示尸体／物品。可堆叠物按现有堆叠身份合并；带独立状态的物品不得无条件合并。显示限流不能丢掉落，生物销毁前必须保留掉落所需配置版本与随机输入。

尸体、插在身上的箭、漂流掉落物和保存中的对象不能被普通视觉回收路径误删。持续累积的轻量记录也必须有明确生命周期，不能用“没 GameObject”掩盖内存无界增长。

## 13. 存档、联机、MOD 与切换策略

### 13.1 存档

遵循现有前向升级与原子保存策略。保存稳定 ID、世界位置、生命、状态、必要计时进度与随机状态；不保存 Entity 句柄、GPU 实例索引、Collider 引用或旧静态配置快照。

在一致 tick 抓取不可变快照；后台只处理快照。恢复时先加载当前定义，再恢复运行态、重建句柄映射，最后恢复跨实体引用。找不到定义或无法表达的旧运行态必须给出明确处理，不静默删生物。

需检查旧 Actor 存档的既有加载适配点，提供明示的迁移方案；不能随意改变嵌套 MemoryPack 布局导致旧数据无法读取，也不能恢复已删除的配置模块。未理解的 MOD 数据按现有规则保留／拒绝，不擅自清空。

开发验证使用隔离临时数据，不能读取后覆盖真实玩家存档。不能承诺任意新格式都能回滚给旧客户端读取。

### 13.2 联机

服务端／房主模拟并结算；客户端接收相关区域的状态与事件，不运行第二套权威伤害、死亡和掉落。

保留现有 Mirror 会话和版本校验，增加 ECS 批量状态协议／适配，不为两万单位机械添加两万套 NetworkIdentity 或逐帧 RPC。消息包含稳定 ID、代际、世界标识、tick／序号；支持生成／销毁、晚加入、断线清理及乱序去重。

增量同步、量化、插值和兴趣区域分别配置。全部两万只同屏时，兴趣裁剪不能消除这些可见单位的带宽，必须实际统计每客户端流量、更新频率和延迟；本地两万达标不等于联机两万达标。

兼容现有维度限制：当前 Skill 规定维度切换仅离线，不能借迁移未经实现就解除联机限制。

### 13.3 配置与 MOD 能力

新增 ECS 能力转换器仍遵循当前 Manifest、定义 ID、模块注册和严格校验。维护“可纯数据转换／需受控主线程适配／暂不支持”的能力清单。未知托管扩展不能被静默忽略，也不能无预算地进入每单位热路径。

### 13.4 渐进迁移与回退

按定义／物种逐步选择旧后端或 ECS 后端，初期默认旧后端，专用开发入口选择 ECS。配置名由实际项目确定，不预设已有开关。

后端在生成／恢复时确定。同一实例禁止运行中直接翻转开关，除非已有一次性状态转移及取消旧订阅流程。回退保护主要针对未转正资源和隔离数据，不声称新存档可随时倒退。

关闭 ECS 时必须停止调度、释放 Native／GPU 数据、取消异步任务、注销代理并清理显示；不要留下旧世界事件命中下一次加载的同 ID 对象。

### 15.2 性能测量建议

下列数值是待确认的验收提案，不是现有性能：Windows 独立 Player、1920×1080、固定画质；预热后记录至少 5 分钟，P95 帧耗时目标不超过 16.7 ms，P99 目标不超过 33.3 ms。目标 CPU、GPU、内存、图形 API 与摄像机尺度必须在测试前登记。

至少覆盖“纯绘制基准、实际混排光照、陆地密集接战、水中密集接战、范围攻击、大量死亡”几组。不能只把镜头拉到生物仅剩一个像素，或只测空地图无光照，就宣称完整场景达标。

记录主线程、工作线程关键链、渲染线程与 GPU 耗时；CPU／GPU 可重叠，不把它们简单相加作为帧时间。区分每帧耗时与每模拟 tick 耗时。

必须记录：

- 起始数量、当前活体数、模拟数、可见数、镜像记录数、投射物与尸体／掉落数。
- 感知候选数、最密格数量、路径请求／共享缓存命中、拥挤处理开销。
- 命中队列容量、峰值、待处理长度、最旧事件延迟、失效／重复事件数量。
- Draw calls、三角形、Buffer 上传字节、透明覆盖开销、表现抑制数量。
- 托管分配、Native／GPU 内存、反复进出世界后的基线变化、模拟落后时间。

参考预算不等于删工作量：后排可少思考，所有有效伤害仍必须结算。每个攻击都命中全场的玩法本身可能产生巨大结果集，必须先明确玩法限制或容量方案，不能指望 ECS 消除真实需要处理的工作。

### 15.3 验证权限

遵守当前项目默认：静态复查、必要编译和 Unity Console 检查；不因本文包含测试清单就自动开启 PlayMode、压力测试、真实存档或联机进程。实际运行验证由用户授权或人工完成。

**只有静态通过／Console 无报错，不能标记“两万单位性能验收通过”。**没有运行权限时，功能、帧率、视觉与网络实测明确写“待验证”，交付复现步骤。

## 16. 禁止用来伪装完成的捷径

1. 只创建 Entity，但每只仍保留完整 Item、Animator、Collider 和旧 Module Tick。
2. 两万单位逻辑计数，镜头内实际只画几百只，却称两万同屏。
3. AI 对 AI 的每次伤害都通过主线程 GameObject 桥接执行。
4. 玩家和 ECS 代理各存一份可写生命，靠同步互相纠正。
5. 丢掉队列溢出的伤害、死亡或掉落，以换取平稳帧率。
6. 为了合批按物种／材质全局重排，破坏树木、建筑与水中透明遮挡。
7. 关闭 Light2D、入水或生物模块，然后把简化原型标成正式功能完整。
8. 在 Job 里调用 WorldTopologyRuntime、Physics2D 或访问托管 Unity 对象。
9. 把帧率依赖的 Animator 事件继续当作 ECS 战斗权威。
10. 静默修改旧存档／网络版本，或直接编辑 PackageCache 后当作可交付修改。
11. 未处理跨界查询去重、对象池代际和旧世界队列，造成重复命中或串档。
12. 没有实测，只凭 Entities、Burst 或 GPU Instancing 技术名称承诺 60 FPS。

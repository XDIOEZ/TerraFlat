# 世界物体渲染图层分配

本表规定世界物体的最终渲染位置，物理碰撞 Layer 不在本规则内。物品、机器、生物和批量表现共用当前定义的 `visual.sortingLayerName` 与 `sortingOrder`；没有显式覆盖的子定义继承父模板。

## 1. 世界图层

图层从后向前排列。先比较 Sorting Layer，再比较外层 Order；动态物体在两者相同时按脚点 Y 混排。一个物体的部件顺序只在自己的排序组内部比较，不能让不同物体的内部序号覆盖世界深度。

| 一级图层 | 用途 | 外层 Order | 配置来源 |
| --- | --- | ---: | --- |
| Tilemap | 太空背景星点 | -32768 | `world-background` |
| Default | 地形、海床、水面、平台、积雪、地形阴影、墙体与草花 | 0；内部队列按地表类别 | `terrainSortingLayer`、`batchProfiles` |
| Default | 地板、轨道、矿洞入口、流体管、电线、光纤等贴地物 | 0 | 物品 `visual`，使用地表材质或对应地面批次 |
| Default | 水中的鱼 | 0 | `underwater-creature` 环境覆盖及水下材质 |
| Shadow | 接触/太阳阴影、地面印记、水花、放置预览 | 0 / 1 / 40 / 1000 | `ground-shadow/mark/splash/preview` |
| MechanicalShaft | 输送带、传动轴、跨轴，以及独立传动轴端 | 0 | 本体 `visual`；轴端 `mechanical-connector` |
| Player | 地面载具 | 99 | 本体 `visual`、`vehicle` |
| Player | 玩家、生物、立体建筑、树木、矿山、普通物品、召唤器和掉落物 | 100 | 物品/Actor `visual`；内建玩家 `player` |
| Player | 升空船体与乘员 | 299 / 300 | `airborne-vehicle/passenger` 环境覆盖 |
| HeldFood | 正在进食的手持食物与咬取遮罩 | 0 | `held-food`；退出时恢复物品原排序 |
| Water | 保留给明确声明的独立水体覆盖资源 | 资源自身配置 | 普通地表水继续走 Default 水面批次，不重复绘制 |
| Paticle | 离体世界特效、闪电、相机范围内雨雪 | 0 | `world-effect` |

一级层沿用项目现有名字和顺序，`Paticle` 为现有名称。角色、树木和立体建筑保持同层同序，避免按物品类别拆开后失去相互遮挡。

全局类别和地表队列位于 `Assets/Resources/GameConfig/Rendering/default-rendering.json`；物品与生物分别通过各自 Manifest 发现，不依赖文件名或生成顺序分配图层。

## 2. 内容分配

2026-10-28 按启用 Manifest 和完整继承链统计：物品共 496 个定义，其中 23 个抽象模板、473 个有效物品；另有 13 个有效 Actor。全部有效内容都有明确的最终静态图层与顺序。

| 物品静态键 | 有效数量 | 分配 |
| --- | ---: | --- |
| Default / 0 | 10 | Flower；FluidPipe、LiquidPipe、ShipFiber、Wire_Copper、Wire_Hidden；MineEntrance、RailTrack、ShipFloor_Iron、ShipFloor_Refractory |
| MechanicalShaft / 0 | 4 | Shaft_Wood、CrossShaft、Conveyor_Wood、Conveyor_Cloth 的放置本体 |
| Player / 99 | 4 | 已有载具定义 |
| Player / 100 | 455 | 其余普通物品、树木/矿山、立体建筑、召唤器等 |

13 个 Actor 的静态键均为 Player / 100，根定义为 Chicken、WildBoar、Wolf、Ghost、SmallFish，其余继承。SmallFish 在水中由环境覆盖，下水不改定义，离水或被携带时恢复静态键。

召唤器是库存/手持物形态，不能直接继承放置本体的贴地图层。进入手持装备链后使用角色组内排序；弓上的箭、盾、鱼钩/饵、果实和附着状态特效按所属物体保留相对顺序。脱离主体的特效单独使用 world-effect。

## 3. 渲染后端约束

- 完整 Item 在装配和原位更新时持有当前视觉定义，注册、重新显示及池复用均以当前配置为准；最外层 SortingGroup 接收世界键，内部精灵保留部件相对序。
- 机器、自然资源和建筑行网格按行、真实一级图层及外层 Order 分批；贴地管线使用地表队列，不能借动态建筑队列越过墙体。附属果实跟随同一主体键。
- 草花是固定地表 BRG，配置须与地形层 / 0 一致，并由 GroundCover 批次控制地表内部队列；不支持的键在定义编译时明确拒绝。
- ECS 生物主体使用可设置 Sorting Layer / Order 的原生网格批次池，按真实键和相同脚点 Y 合批；不再只在 CPU 排序而让 BRG 忽略世界图层。可见生物的脚点越分散，批次数越多，压力场景性能需单独测量。
- 水下呈现、船体升空是状态覆盖，结束后恢复物品配置；投影、复制与起飞快照同时保留外层顺序和内部件顺序。
- 陆地复杂嵌套排序组保留原生绘制；水下仍使用既有合批，复杂嵌套在水中的画面尚未验收。
- UI 与对话气泡使用屏幕 Canvas，不进入世界 Y 排序。HUD 为 0、物品说明为 1999、设置窗口从 2000 起、全屏覆盖为 32000、指针拖拽物为 32767。

## 4. 新增内容与回归

新增内容先选最接近的模板，只有渲染位置不同才覆盖 `visual` 的两个字段。合法层名必须存在，Order 范围为 -32768～32767。渲染后端不能再次按 ID、模块类型或物品名字覆盖已声明的静态键。

规则入口为 `rendering_item_sorting_configuration`，检查完整目录、配置继承、特殊状态与各批处理键；真实现场沿 `rendering_gameplay` 检查船板、角色及附属效果。测试结果和视觉范围以本轮报告为准，不把配置完整当成画面或性能已验收。

本轮全量配置与继承静态检查通过，三个受影响程序集离线编译通过。Unity 正在用户 Play Mode，未触发编译刷新，未运行新增 Lua、真实场景或性能验收；当前运行画面不能视为新代码的结果。

# 重构宇宙坐标系统

> 状态：方案设计，尚未实施。

**一个星区就是一个场景。目标星区提前加载，玩家在边界自由航行、完成切换，走出目标侧过渡区后才释放旧场景。**

## 1. 核心规则

- 一个星区容纳一个完整恒星系，或者是一片空域。太阳系是一个场景，左边的天狼星系是另一个场景。
- 恒星系的全部轨道都在自己的星区内，外围留出航行空间。空域也可以有空间站、飞船和物品。
- **单人平时只加载当前星区的场景资源，不预加载周围一圈。** 只提前加载前往方向的目标星区；边界过渡期间保留源、目标两份场景资源。未加载的星区继续按游戏时间推进数据。
- 玩家在当前星区正常移动，镜头跟随，不再每帧把玩家的显示坐标归零。离船漂浮、惯性等现有玩法沿用。
- **过渡区里，边界两侧距离很近的玩家和物体仍能互相看见、射击、碰撞和交互。** 星区归属不同，不会把实际相邻的物体隔开。

## 2. 边界过渡怎么进行

**过渡区是一段可以正常活动的空间。** 玩家可以继续前进、转向、停留或返回，输入、镜头和惯性全程保持正常；环境表现随着位置逐渐衔接。

以“从太阳系飞向左侧的天狼星系”为例：

```text
在太阳系内向左航行，提前加载天狼星区
    ↓ 正常情况下，到达太阳系左侧边界时目标已准备好
跨过边界，进入天狼星区右侧的过渡区
    ↓ 玩家继续自由移动，太阳系场景资源仍保留
走出天狼星区这一侧的过渡区，正式进入内部
    ↓ 太阳系没有其他使用者时，保存并卸载它
```

换区按切换那一刻的最新状态迁移，保留速度、物品和飞船状态；整船及船内乘员一起迁移，船内布局和相对位置保持完整。物体始终只有一份身份，避免重复生成或丢失。

**跨过星区边界，只切换归属和坐标，不立即卸载旧场景。** 玩家进入天狼星区后，直到走出天狼星区这一侧的过渡区，才允许释放太阳系资源。期间折返可以直接复用仍保留的太阳系场景，避免边界附近来回加载。

提前加载期间，玩家继续自由航行；跨界前折返就取消迁移。**即使场景资源没加载好，也不能限制前进、冻结速度、加空气墙或接管航线。** 运动、碰撞和交互所需的数据先准备好，画面资源随后补齐；必要时暂用简化表现，玩家按原有规则继续前进。

联机服务器释放旧星区的场景资源，还要满足：没有玩家留在其中，也没有其他玩家的跨区过渡仍在使用它。

**整个过程由玩家自己操控，不切到加载页，也不播放接管角色的过场动画。**

## 3. 坐标、存档和后台运行

**位置 = 星区编号 + 星区内的位置。**

例如：`太阳系星区 (0, 0)，区内位置 (100, 200) 米`。

- 星区编号决定加载哪个场景、保存到哪个区域。
- 星区内沿用双精度位置和速度，Unity 画面使用本场景的局部坐标。需要时再调整局部显示/物理原点，避免精度问题。
- 到左侧邻区时，星区横编号减一，区内位置换算到目标右侧；其他方向同理。切换场景不重置速度。
- 星系、星球、维度和飞船使用稳定身份，避免同名星球的存档互相覆盖。物品和玩家造成的变化按所属星区保存。
- 卸载只释放场景资源，不删除星区数据；再次进入时恢复最新状态。新格式直接统一，不做旧存档兼容。
- **游戏运行期间，无人星区的星体、无人船和机器继续推进数据，场景资源保持卸载。** 不能因玩家离开就暂停航行、加工或燃料消耗；后台可降频或按时间差结算，但要保留正常规则和必要事件。

## 4. 联机怎么加载和同步

**同星区的玩家共用该星区的服务器场景和状态；不同星区分别加载。各玩家端以所在星区为当前场景，边界过渡时额外保留源、目标场景资源。**

| 玩家位置 | 服务器的场景加载情况 |
| --- | --- |
| 两人都在太阳系内部 | 一份太阳系场景 |
| 一人在太阳系，一人在天狼星系 | 一份太阳系场景 + 一份天狼星系场景 |
| 两人进入天狼星系，但仍有人在过渡区 | 共用天狼星系场景，继续保留太阳系资源 |
| 两人都走出天狼星系的过渡区 | 太阳系没有其他使用者后，保存并卸载 |

- 服务器保留有玩家活动或仍被跨区过渡使用的星区，同一星区共用一份场景，不为每个玩家复制一份。
- 房主同时承担服务器职责时，可以持有多个星区场景，本地画面仍显示自己所在的星区。
- **继续沿用数据同步方式。** 玩家、飞船和物品带上星区身份。正常同步本星区附近的实体；过渡区同时同步相邻星区距离足够近的实体，由服务器确认移动、射击、碰撞和操作。
- 玩家跨界时更新场景归属和同步对象。某个人换区不能让其他玩家跟着换，也不能卸载仍有玩家或过渡使用者的星区。
- 客户端走出目标侧过渡区后，可以释放自己保留的旧场景资源；服务器是否卸载该星区，要看所有玩家的使用情况。
- 边界两侧按真实宇宙位置判断距离和接触，不能只按场景过滤；服务器统一结算跨界交互，确保一次碰撞、伤害或拾取只处理一次。远处星区仍独立管理，相同的局部坐标不会造成错误碰撞。

## 5. 分几步做

以下都是待做任务：

- [ ] **坐标与身份：** 星区编号、区内坐标、边界换算、全局星体和地表地址。
- [ ] **单人换区：** 提前准备目标数据和场景，完成自由航行、资源未就绪时的连续运动与交互，以及整船迁移；走出目标侧过渡区后再释放旧场景。
- [ ] **星区存档与后台运行：** 保存星区修改，场景卸载后继续推进星体、无人船和机器数据；重新进入时恢复最新状态。
- [ ] **联机换区：** 同星区共享状态，按玩家与过渡区需要加载场景；接上跨边界可见、射击、碰撞和交互，切换时更新同步归属。

实现时需要调整的参数：

- **星区多大：** 装下完整太阳系和外围留白，同时保证局部交互精度。
- **过渡区怎么做：** 提前加载距离、两侧过渡区宽度、环境衔接方式和跨界交互范围；正常情况下提前准备好，异常时仍保持自由航行。
- **后台计算开销：** 各类数据的更新频率和结算方式，避免为后台运行加载完整场景，也避免改变游戏结果。

- `UniverseState`、`SpaceSessionState`、`WorldAddress`：加入星区身份，拆开全局宇宙目录与单星区状态；星区编号用 `long`，区内位置用 `double`。

- 现有太阳系配置中，海王星轨道半长轴为 93000 游戏米。星区边长 256000 米只是候选，尚未确定。不能只改 `metersPerUnityUnit` 就认为所有物理和画面都完成了缩放。
- 场景采用异步附加加载，必要的运动、碰撞与交互数据先于画面资源可用。跨界更新归属，玩家和飞船仍只有一份权威状态；旧场景资源保留到玩家走出目标侧过渡区，再按使用情况释放。
- 联机采用公共管理场景 + 按需加载的星区场景；边界邻近实体共用权威距离/接触查询，不能直接用 Scene 隔离代替跨界规则。切换只影响迁移的玩家或整船，不让其他玩家一起换区。

# 重构宇宙坐标系统

> 状态：方案设计，尚未实施。

**把宇宙分成格子，玩家可以一直飞；游戏只加载附近，坐标太远的问题在底层处理。**

## 1. 玩家会感觉到什么

- 可以从太阳系直接飞向其他恒星系，途中可能经过空域，不用找“星系出口”。
- 玩家、飞船和散落物各自运动。离船后照样靠惯性漂浮，沿用现有玩法。
- 在星系内正常移动，镜头跟着玩家，不再每帧把玩家的显示坐标归零。
- 跨星区时航行继续，位置、速度、船内乘员和交互保持连续。资源没加载好时可以用过渡画面遮一下，目标是视觉无缝，不承诺所有设备都完全无卡顿。

## 2. 宇宙怎么分、怎么加载

**一个星区就是一个格子，里面放一个完整恒星系，或者是一片空域。一个恒星系不拆到多个格子。**

所有行星轨道都要装在所属格子里，外围还要留出航行空间。空域也可以有空间站、流浪物体和飞船。

以玩家所在格为中心，预加载周围八格：

```text
  空域   │ 比邻星系  │ 空域
─────────┼───────────┼─────────
 天狼星系│太阳系/玩家│ 空域
─────────┼───────────┼─────────
  空域   │   空域    │其他星系
```

上图只是布局示意。实际星系位置由固定配置或种子决定。

| 范围 | 加载内容 |
| --- | --- |
| 玩家附近 | 完整角色、船体、交互和碰撞 |
| 周围八格 | 先准备星区资料和远景，靠近时再加载细节 |
| 更远的地方 | 保留导航信息和必要的后台状态，不生成 Unity 画面对象 |

九宫格是加载范围，不是同时运行九份完整物理世界。玩家向右跨一格，窗口就向右滑：左列卸载、右列预加载，其余六格复用。高速航行时要更早准备前方内容。

太空主场景持续保留，星区内容按需进出；卸载画面不删除状态。星区由稳定配置或种子生成，玩家造成的变化单独保存。地表、洞穴仍按独立世界处理。

## 3. 坐标怎么记

**真实位置 = 星区编号 + 星区内的位置。**

例如：`星区 (2, -1)，格内位置 (100, 200) 米`。

- **真实坐标：** 用整数编号找到星区，用双精度记录格内位置和速度，供运动、联机和存档使用。
- **显示坐标：** Unity 只显示玩家附近的内容，以当前观察星区为原点。太远的东西用简化远景，精细碰撞只在附近进行。

跨格时换算星区编号和格内位置，同时调整本地显示原点。**这只是换一套坐标记法，物体没有瞬移，速度也不重置。** 如果同一星区内部仍有精度问题，可以使用更近的显示/物理原点；恒星系仍完整属于原来的星区。

边界处必须守住两条规则：

1. 一艘船、一个物体始终只有一份真实状态。整船跨格不能拆开，乘员、船内布局和接触状态一起保留；也不能重复模拟、掉落或存档。
2. 格线两侧距离很近的玩家和飞船，仍能看见、射击、碰撞和对接。边界附近来回移动，也不能造成反复加载和画面跳动。

## 4. 联机和存档怎么处理

- **服务器管整个宇宙，各客户端加载自己的附近。** 活跃范围由所有玩家的位置共同决定，不围着房主的镜头转。
- 联机同步星区编号、真实位置和速度。服务器检查移动及操作权限，客户端负责输入和画面平滑；Unity 的显示坐标不当作宇宙地址。
- 是否互相同步，要同时看星区和实际距离，不能只看“是不是同一格”。
- 玩家可以分别待在不同星系、空域或地表；某个人换场景或断线，不能让其他玩家和无人船的模拟停掉。
- 星区、星系、星球、维度和飞船都有稳定身份。地表地址包含星系与星球身份，避免不同星系的同名星球互相覆盖存档。
- 远处无人船按规则继续航行；降低模拟频率也不能改变结果。新格式直接统一，不做旧存档兼容。

## 5. 分几步做，还有什么没定

以下都是待做任务，勾选只代表对应阶段已完成，不代表整套方案已经落地。

- [ ] **先做坐标基础：** 星区编号、跨格换算、相邻格距离、全局星体与地表身份。
- [ ] **再做单机航行：** 正常移动、显示原点切换、九宫格加载，打通整船和离船玩家的跨格旅行。
- [ ] **接上多星区与存档：** 拆开全局宇宙服务和单个星区状态，统一时间来源，保存各区变化与后台航行。
- [ ] **最后接联机：** 服务器模拟、多玩家加载范围、跨边界交互，以及逐玩家地表/太空迁移和加载异常恢复。

开发前还要确定：

| 问题 | 决定什么 |
| --- | --- |
| 一个格子多大？ | 装下完整太阳系和外围留白，同时保证附近碰撞精度 |
| 星际旅行要多久？ | 普通飞行的距离与速度，以及是否另加曲速/跃迁玩法 |
| 边界和远处算多少？ | 跨格碰撞范围、大船支持、无人船模拟和加载开销 |

这些参数先留空，按实际效果决定。曲速/跃迁如果加入，要另定移动规则；加载过渡和显示坐标调整本身不会缩短真实航程。

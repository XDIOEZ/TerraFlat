# 重构宇宙坐标系统

> 状态：方案设计，尚未实施。

**一个星区就是一个场景，玩家到边界就换区，用过渡画面接起来，类似 RPG 换地图。**

## 1. 核心规则

- 一个星区容纳一个完整恒星系，或者是一片空域。太阳系是一个场景，左边的天狼星系是另一个场景。
- 恒星系的全部轨道都在自己的星区内，外围留出航行空间。空域也可以有空间站、飞船和物品。
- **单人只实时加载玩家所在的星区，不预加载周围星区。** 其他星区只保留数据，等玩家进入时再加载。
- 玩家在当前星区正常移动，镜头跟随，不再每帧把玩家的显示坐标归零。离船漂浮、惯性等现有玩法沿用。
- 交互、射击和碰撞在当前星区场景内进行，跨星区通过换场景完成。

## 2. 怎么换区

以“从太阳系飞向左侧的天狼星系”为例：

```text
太阳系内向左航行
    ↓ 到达左侧边界
显示过渡画面，记录玩家或飞船状态
    ↓ 加载并切换到天狼星区场景
从天狼星区右侧的对应位置进入
    ↓ 场景准备好，结束过渡
继续航行
```

换区时保留速度、物品和飞船状态；整船及船内乘员一起迁移，船内布局和相对位置保持完整。物体始终只有一份身份，避免重复生成或丢失。

旧星区没有玩家后，保存状态并卸载；仍有其他玩家时继续运行。加载没完成就保持过渡，失败时恢复原场景及迁移前的状态。

**过渡负责遮住加载过程，不需要沿途持续加载相邻星区，也不要求两个星区之间连续进行碰撞模拟。**

## 3. 坐标和存档怎么记

**位置 = 星区编号 + 星区内的位置。**

例如：`太阳系星区 (0, 0)，区内位置 (100, 200) 米`。

- 星区编号决定加载哪个场景、保存到哪个区域。
- 星区内沿用双精度位置和速度，Unity 画面使用本场景的局部坐标。需要时再调整局部显示/物理原点，避免精度问题。
- 到左侧邻区时，星区横编号减一，区内位置换算到目标右侧；其他方向同理。切换场景不重置速度。
- 星系、星球、维度和飞船使用稳定身份，避免同名星球的存档互相覆盖。物品和玩家造成的变化按所属星区保存。
- 卸载只释放场景，不删除星区数据；再次进入时恢复。新格式直接统一，不做旧存档兼容。

## 4. 联机怎么加载和同步

**同星区的玩家共用该星区的服务器场景和状态；不同星区分别加载，各玩家端只加载自己所在的星区。**

| 玩家位置 | 服务器实时运行的星区场景 |
| --- | --- |
| 两人都在太阳系 | 一份太阳系场景 |
| 一人在太阳系，一人在天狼星系 | 一份太阳系场景 + 一份天狼星系场景 |
| 两人都去了天狼星系 | 共用一份天狼星系场景；太阳系保存后卸载 |

- 服务器按实际有人活动的星区加载，同一星区只运行一份，不为每个玩家复制一份。
- 房主同时承担服务器职责时，可以持有多个星区场景，本地画面仍显示自己所在的星区。
- **继续沿用数据同步方式。** 玩家、飞船和物品带上星区身份，实时实体按所属场景同步给同星区玩家，由服务器确认移动和操作。
- 玩家换区时更新场景归属和同步对象。某个人换区不能让其他玩家跟着换，也不能卸载仍有玩家的星区。
- 不同星区的实体各自在自己的场景中交互，坐标数字相同也不会发生串区碰撞或错误同步。

## 5. 分几步做

以下都是待做任务：

- [ ] **坐标与身份：** 星区编号、区内坐标、边界换算、全局星体和地表地址。
- [ ] **单人换区：** 每次运行当前星区，接上边界触发、过渡画面、玩家/整船迁移和失败恢复。
- [ ] **星区存档：** 保存、卸载、重新进入时恢复该星区的物品、飞船和玩家修改。
- [ ] **联机换区：** 按玩家所在星区加载服务器场景，同区共享、异区隔离，切换时更新同步归属。

还没定的细节：

- **星区多大：** 装下完整太阳系和外围留白，同时保证局部交互精度。
- **过渡怎么表现：** 淡入淡出、飞行画面或其他效果，以及加载失败时的提示。
- **无人星区如何结算：** 时间、无人船等是否需要后台数据计算，另行定规则；不因此加载无人星区的实时场景。

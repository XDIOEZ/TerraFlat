# 重构宇宙坐标系统

> 状态：方案设计，尚未实施。范围：太空坐标、跨星系旅行、九宫格流送、多人联机与存档身份。
>
> 目标：宇宙在玩家眼中连续、可以从一个恒星系直接飞往另一个恒星系；底层按星区分段加载和重置局部坐标，不把整个宇宙塞进 Unity 的 `float` 坐标系。

## 1. 设计目标与边界

- 玩家、飞船、散落物、星体都有独立的真实运动状态；玩家离船后继续以自身速度漂浮，不依靠“移动整个世界”来代替物理模拟。
- 玩家在同一个恒星系内正常移动，镜头跟随玩家；**不再每帧强制将玩家的显示坐标归零**。
- 离开当前星区时滑动九宫格窗口，并将本地表现坐标切换到新星区的原点。跨格前后位置、速度、角度、碰撞和镜头保持连续。
- 太阳系、比邻星系及星际空域使用统一的可寻址星区模型。星际空域可以为空，也可以存在流浪物体、空间站等内容。
- 多人共享同一套服务器权威宇宙状态，但各客户端按自己的位置加载周边内容，不会因为坐标数字相同就发生跨星区碰撞或错误同步。
- “视觉无缝”优先：允许异步预加载、LOD 与星际飞行过渡表现；未准备好时允许遮蔽加载，不承诺每种硬件环境都绝对无卡顿。

### 1.1 已核实的现状

| --- | --- |

## 2. 核心方案：星区坐标 + 局部世界

### 2.1 坐标身份

将逻辑空间位置表达为：

```text
UniversePosition {
    SectorX: long       // 星区网格横坐标
    SectorY: long       // 星区网格纵坐标
    LocalX: double      // 在星区内的局部游戏米
    LocalY: double
}

空间内容身份：
SectorId = (SectorX, SectorY)
StarSystemId = 稳定星系 ID（星际空域可以为空）
BodyId = 星系内稳定星体 ID
PlanetWorldId = StarSystemId + BodyId + DimensionId
```

- `SectorId` 解决无限平面寻址；`StarSystemId` 解决星系内容身份；`BodyId` 与地表维度身份分别维护，不能只靠本地名字区分。
- 同一星区内星系按已有 `UniverseSimulation` 规则运行；星际空域使用相同位置、速度与碰撞接口。
- 一个星区可以是完整恒星系或星际空域。**九宫格是流送网格，不是“同时必须存在九个恒星系”**。
- 跨格只是规范化坐标：若局部位置超出星区边界，则修改星区索引并换算局部值；世界位置在数学上连续。不得把过界视为重新出生或重置速度。
- `SectorSize`、精度安全半径及恒星系放置余量由配置与测试决定，暂不写死数值；必须容纳现有太阳系轨道和飞船活动范围。

### 2.2 真实坐标和显示坐标分开

- **服务器：** 使用 `(SectorX, SectorY, LocalX, LocalY)` 和双精度速度进行权威运算；无须移动全宇宙 GameObject。
- **客户端：** 选择当前观察星区作为表现原点，将目标星区相对偏移和局部位置转换成 Unity `Vector2/Vector3`。
- 普通移动只改变玩家自身和镜头位置；进入相邻星区后，按星区跨度统一重定位本地显示对象（玩家、船体、星体、粒子、摄像机、Collider 等）。
- 重定位只影响表现层；真实坐标、速度、航线、库存、星体轨道和网络身份完全不变。
- 邻区远景使用星图/LOD/代理绘制；超出可靠 `float` 范围的物体不参与 Unity 近场碰撞，也不把巨大坐标直接传给 Transform。
- 不能只移动视觉根节点而遗漏 Physics2D、镜头缓存、Trail/粒子、鼠标交互、音源或插值历史；重定位时必须统一处理。

## 3. 九宫格流送与看似无限的宇宙

以玩家所在星区为中心维护 3×3 观察窗口，例如：

```text
 [ -1,+1 ] [ 0,+1 ] [ +1,+1 ]
 [ -1, 0 ] [ 玩家  ] [ +1, 0 ]
 [ -1,-1 ] [ 0,-1 ] [ +1,-1 ]
```

- **中心星区：** 完整角色、船体、可交互物及近场物理表现。
- **周边八格：** 优先读取星区目录、星系位置、远景和边界附近必要实体；按距离升级为完整内容，**不是同时加载九份完整恒星系及物理世界**。
- **更远星区：** 默认仅保留目录/种子、导航目标和需要后台运行的权威状态；不生成 Unity 表现。
- 玩家向右跨一格后，窗口整体右移：左列卸载、右列预取，其余六格复用，不需要清空整个宇宙。
- 预加载时机由位置、航向、速度和实际资源完成情况决定；高速飞行要提前扩大预取范围或启动过渡表现。
- 星区内容根据稳定 ID/种子确定性生成，玩家修改写到该星区的持久差量；卸载表现不等于销毁状态。

### 3.1 无缝星际旅行流程

```text
玩家/飞船在太阳系内航行
  → 前方邻区预加载星空、内容元数据和近场实体
  → 越过星区边界：原子换算坐标，保留速度/乘员/船体
  → 九宫格滑动，旧内容渐退，新内容渐入
  → 经过一个或多个星际空域
  → 邻近比邻星系时逐步加载其星体、远景及物理内容
  → 无缝进入比邻星系，恢复完整交互
```

- 让玩家感觉进入一个连续大场景；**不必每跨一格调用一次 `LoadSceneMode.Single`**。
- 推荐保留一个持久太空主场景，星区视觉内容按需挂载/卸载；只有星球地表、洞穴等独立世界使用已有场景迁移思想。
- 需要替换大型表现模块时，可以异步加载/卸载附加 Scene 或资源；加载没有准备好就使用星云、深空或跃迁特效掩护，**不能在服务端偷偷改变位置**。
- 普通跨格飞行保留连续空间距离；跃迁/曲速如以后加入，另定义明确的移动规则，不与九宫格坐标重置混为一谈。

### 3.2 边界不能断裂

- 玩家、整船、残骸和自由漂浮物可能横跨两格。它们只有**一份权威身份**，邻区表现可以有代理，不能重复模拟/掉落/存档。
- 跨格时船体拓扑、船内本地格、乘员、接触姿态和速度保持完整，不能把飞船拆成两个星区对象。
- 靠近边界的两个玩家或两艘船仍需互相看见、射击、接触与对接；不能用“不同星区就永远不碰撞”的规则。
- 跨格碰撞由统一邻域查询或接缝附近共享物理作用域处理；如果服务端使用隔离 Physics Scene，需额外设计跨场景接触，不能只依赖每个 Scene 内的 Physics2D。
- 给边界切换设置滞回或稳定归属规则，避免在边界附近反复重定位、加载和卸载。

## 4. 多人联机：一个权威宇宙，多套局部画面

- 服务端按 `SectorId` 管理星区状态、飞船运动、乘员、资源与持久化；不同玩家所在星区取**观察者集合的并集**决定活跃/休眠范围，不以房主摄像机为中心。
- 每名客户端各有自己的观察星区与九宫格窗口，不同步 `ViewOrigin` 或 Unity Transform 作为真实宇宙地址。
- 网络位置消息包含星区身份、局部双精度位置/速度及版本/时间戳；服务器验证对应玩家身份、控制权限与运动合法性。
- 同星区或跨边界近距离实体进入彼此可见范围；远处玩家、飞船和物体不必持续发送近场状态。兴趣管理必须同时考虑**星区身份和真实距离**。
- 飞船驾驶输入由拥有权限的玩家发给服务器；服务器模拟整船，再发布权威结果。非驾驶/离船玩家独立发送移动输入并获得自己的运动结果。
- 玩家分别处于太阳系、星际空域、比邻星系或星球地表时，不能因客户端换场景影响其他人的服务端模拟。
- Mirror 的 Additive Scenes / Scene Interest Management 可借鉴**实例隔离和选择性同步**，但单纯按 Scene 过滤会漏掉跨星区边界可见和碰撞的实体，不能直接替代星区距离规则。

## 5. 系统职责与改造入口

| 模块 | 目标职责 | 现有相关入口 |
| --- | --- | --- |
| 宇宙寻址 | 星区坐标规范化、邻接查询、唯一空间与星体 ID | `UniverseState`、`WorldAddress` |
| 星区目录/生成 | 决定空域、恒星系模板、种子及其布局 | `SpaceCatalog`、`solar-system.json` |
| 权威运行时 | 按星区保存和调度模拟，摆脱“只有一个全局星系”限制 | `SpaceSession`、`UniverseSimulation` |
| 玩家/飞船移动 | 全部在真实坐标中模拟；跨格后保留惯性和承载关系 | `ShipPassengers`、`ShipFlightSimulation`、`Mod_Mover.Space` |
| 客户端流送 | 九宫格预加载、显示原点、LOD、表现挂载与释放 | `SpaceMgr`、`ShipPieceView`、`Planet` |
| 世界迁移 | 地表/洞穴/太空与逐玩家过渡，不全局重置会话 | `DimensionManager`、`GameManager.Space` |
| 联机协议 | 玩家与飞船的星区位置、服务器权威及边界兴趣管理 | `NetworkWorldPlayer`、`FlatWorldGameNetworkManager` |
| 存档 | 星区世界状态、船/乘员归属、空域差量和后台航行 | `SpaceSessionState`、`SaveDataMgr` |

**设计约束：** `SpaceSession.Current`、`SpaceMgr` 和 `SpaceCatalog.LoadDefault()` 目前带有单例/单配置假设；要让多人同时处于不同星系，需把“全局宇宙服务”和“某个星区的状态实例”拆开。无需为每一格复制整个游戏管理器。

## 6. 分阶段实施清单

### 阶段 A：纯数据坐标与边界

- [ ] 定义星区 ID、局部坐标、规范化规则、相邻格距离和唯一星体/地表地址。
- [ ] 用离线测试验证正负坐标、斜角过界、连续高速跨多格、极大格索引、边界来回移动。
- [ ] 根据太阳系轨道外延、船体尺寸、最小交互/碰撞尺寸决定格边长和精度预算，避免仅凭 `metersPerUnityUnit` 缩放全部游戏。

### 阶段 B：单机太空正常移动与九宫格

- [ ] 保留已有双精度物理，停止每帧将玩家显示位置强制归零；相机正常跟随。
- [ ] 按星区重定位表现对象，并复核 Physics2D、镜头、碰撞、音效、粒子、交互及渲染。
- [ ] 完成九宫格滑动预加载和远景 LOD；普通飞船可从太阳系跨空域进入另一恒星系。
- [ ] 验证离船漂浮、船内走动、整船过界、散落物、自动导航、碰撞与对接不跳帧、不丢状态。

### 阶段 C：多星区权威与存档

- [ ] 将单个 `SpaceSessionState.Universe` 的运行管理改为多星区实例/索引；保留统一全局宇宙时钟或明确各星区时间来源。
- [ ] 后台飞船继续按规则推进；远区降频/休眠不能偷偷冻结飞船、重复消费资源或跳过必要的接触结算。
- [ ] 星区、恒星系、星球/维度及飞船状态独立保存与恢复，避免不同星系同名星球覆盖存档。

### 阶段 D：联机与逐玩家世界迁移

- [ ] 新增太空星区坐标消息，禁止复用地表 `Vector3 + NormalizePosition`。
- [ ] 服务器验证驾驶、离船移动、跨格移动、建造/拾取和碰撞；客户端仅负责本地输入与平滑显示。
- [ ] 实现多观察者九宫格、跨边界兴趣管理及同船多人；一人在太阳系、一人在比邻星系可以同时活动。
- [ ] 联机玩家各自切换地表/太空，不让单人的场景加载或断线停止其他玩家和无人船模拟。

### 阶段 E：视觉无缝及回归

- [ ] 处理高速旅行中预加载不足的过渡效果和异常恢复；正常情况下不出现黑屏或全场景重建。
- [ ] 检查两名玩家从相反方向接近跨格接缝，仍能相遇、开火、碰撞、对接和拾取。
- [ ] 覆盖断线重连、读档恢复、跨格中死亡/重生、跃迁失败、后台无人船、零速度及高速跳格。
- [ ] 观察 CPU、GC、星区加载峰值、消息量、首帧卡顿及内存；按实测预算调整流送和精度阈值。

## 7. 待定参数与开发时需要先确认的问题

1. **格子宽度及表现精度：** 既要容纳现有太阳系（海王星轨道配置半长轴 93000 米），又不能让局部 Unity `float` 的碰撞与微小零件失去精度；应以实测确定，必要时将“星系占用范围”和“物理流送星区”拆开。
2. **航行尺度：** 跨星系要玩家真实飞过多个空域，还是允许额外的曲速/跃迁玩法？两者可以共存，但不能用缩放渲染坐标来偷改服务器距离。
3. **跨格碰撞范围：** 需要定义近场边界重叠宽度、船体大尺寸支持及物理查询的预算。
4. **远处模拟成本：** 无人船和长期航线何时全精度计算、何时允许确定性简化，必须在不改变游戏结果的前提下决策。
5. **现有地表世界地址：** 星系内行星的世界键和存档是否需要一次性换成全局身份；项目尚未发布，可优先统一新格式而非为旧版本留复杂兼容层。

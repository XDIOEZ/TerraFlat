本轮交付约定：用户明确不需要实机测试，因此只做代码审查、编译与提交差异检查；第 17 节玩法、性能指标保持未验证。实现清单勾选只表示代码接入，不代表运行结果通过。

## 1. 核心目标

~~~text
没变化
→ 不计算

抽水 / 放水 / 挡水结构变化
→ 唤醒附近液体

有变化
→ 按固定 Liquid Tick 继续算

稳定
→ 休眠
~~~

第一版只做格子液体流动，不做真实流体物理。

---

## 2. 使用现有数据

继续使用：

~~~text
LiquidDepth     = 当前液体深度，0~1
LiquidTypeIndex = 运行时液体编号
LiquidId        = JSON / MOD / 存档使用的稳定名字
~~~

不要再创建第二套液体深度。

---

## 3. Liquid Tick

- 单独做 Liquid Tick，不直接绑 Unity FixedUpdate。
- 默认 5Hz，必要时再调到 10Hz。
- 没活动液体时完全不跑。
- 一帧不要无限补算历史 Tick。
- 掉帧时宁可液体慢一点，也不要一帧跑很多次。

唤醒当前格时，一起唤醒：

~~~text
自己 + 左右上下
~~~

第一版不做斜角流动。

---

## 4. 流动规则

比较相邻格液面：

~~~text
液面高度 = 地面高度 + LiquidDepth
~~~

地面高度：

~~~text
世界坐标 + Seed + 冻结生成规则
→ Chunk 加载时算一次
→ 放进 GroundHeightCache
→ Chunk 卸载后丢掉
~~~

当前通过 `ChunkTerrainData.TryGetSurfaceElevation` 读取冻结生成规则产出的高度，在区块被实验器接入时缓存一次；无地表高度层的洞穴按平底处理。不再采样一套独立 Noise，也不通过液深反推地面高度。

不写进存档。

流动：

~~~text
液面差 = A液面 - B液面

液面差很小
→ 不流

液面差明显
→ A 往 B 流
~~~

建议初版：

~~~text
候选转移量 = 液面差 × 0.5 × FlowSpeed / 4
~~~

四邻格共享松弛预算，避免高低液面在相邻 Tick 之间反复交换。再统一统计每格的候选总流出和总流入，按来源存量、目标容量缩放同一条边的转移量；不能只给每条边单独限量。

限制：

- 不超过来源已有 LiquidDepth。
- 目标 LiquidDepth 不超过 1。
- 小于最小变化值时忽略。
- FlowSpeed 做成配置。
- 不按最小变化阈值清零残液；浮点舍入只允许机器精度误差，不能主动丢弃液量。

---

## 5. 必须分两步计算

不要边算边改。

正确流程：

~~~text
第一步
→ 读取 Tick 开始时的数据
→ 算每格流入 / 流出多少

第二步
→ 全部算完
→ 统一写回 LiquidDepth
~~~

公式：

~~~text
新深度 = 旧深度 + 流入 - 流出
~~~

这样不会因为计算顺序不同而得到不同结果，也方便以后上 Job / Burst。

---

## 6. 活动格和休眠

每个 Chunk 记录：

~~~text
ActiveCells
ActiveCount
~~~

规则：

- 少量格变化：只算活动格。
- 一个 16×16 Chunk 大部分格都活动：直接扫描整个 256 格。
- 连续几次没有明显变化：休眠。
- 邻格以后再变化：重新唤醒。

---

## 7. 液体和阻挡

第一版：

~~~text
相同液体
→ 可以流动

液体 → 空格
→ 可以流入

不同液体
→ 暂时互相挡住
~~~

不同液体在同一 Tick 竞争一个空格时，按稳定 `LiquidId` 的序确定唯一接收类型，不按活动格遍历顺序决定。

LiquidDepth = 0 后，可以清掉这一格的 LiquidTypeIndex。

至少这些东西挡液体：

- 实心墙。
- 明确声明挡液体的 Blocking 地块 / 建筑。

水上平台默认不挡下面的水。

建筑 / MOD 显式挡水使用 `WorldLiquidFlowObstacles.Register(owner, cells)`；拆除、开闸或 Unload 调用 `Unregister(owner)`。当前不把所有建筑导航占地自动当成挡水，也未新增水坝物品或建筑 JSON 字段。

不要用 Collider 判断液体是否能通过。

以后需要时再加：

~~~text
blocksLiquid = true / false
~~~

---

## 8. 跨 Chunk

Chunk 边界不能卡水。

~~~text
Chunk A 最右格
→ 正常检查 Chunk B 最左格
~~~

如果邻 Chunk 没准备好：

- 不直接写不存在的数据。
- 请求 / 保持必要的邻 Chunk 数据。
- 数据准备好后继续流动。
- 稳定后释放额外占用。

统一使用世界格坐标，不写第二套边界算法。

跨边界复用当前维度的种子、冻结 Profile 和世界拓扑。邻区完成后先恢复存档差量及建筑，再恢复流动；循环世界接缝使用规范化坐标。

---

## 9. 海洋保护

不能因为海里一个抽水机，就把整个世界都唤醒。

第一版：

~~~text
玩家附近 / 被修改区域
→ 正常模拟

远处没被修改的自然海洋
→ 保持生成状态
~~~

以后做围海、水坝时，再增加封闭水域检测。

实验默认从外部抽水、放水、挡水变化或显式唤醒开始；自然静水不会仅因加载就全量启动。每次外部唤醒开放修改点周围 2 圈 Chunk，同时活动及等待租约最多 25 个、同时邻区加载最多 2 个。模拟传播不会自行扩大这个范围；范围外暂按封闭边界处理，不表示真实无限海洋行为。

## 10. 批量更新

这是最重要的性能要求：

> 可以逐格计算，但不能逐格刷新。

不要：

~~~text
改一格
→ 发 Changed
→ 刷 BRG
→ 再改下一格
~~~

应该：

~~~text
一个 Liquid Tick 全部算完
→ 收集 DirtyCells
→ 按 Chunk 合并
→ 统一写回
→ 统一通知
~~~

然后：

- BRG 批量刷新。
- Navigation 批量更新。
- FlowField / AIECS 批量更新。
- 存档只标记数据变化，不在 Tick 里写磁盘。

当前单格 `SetLiquid` 保留既有 `Changed` 契约；模拟使用 `SetLiquidBatch(..., deferNotification: true)` 写回，所有 Chunk 完成后再 `PublishLiquidBatch`。批次观察者订阅 `LiquidBatchChanged`，不会收到逐格模拟通知。借用的格索引只在同步回调期间有效，不得留到下一帧。

BRG 将本块和相邻块的脏格去重至 `LateUpdate` 刷新；Navigation 每个批次重新登记该 Chunk，共享 FlowField / AIECS 继续消费原有导航脏块。地表植被也在批次结束后处理浸没和露出。

---

## 11. 绘制更新

~~~text
没变化
→ 不刷新

有变化
→ Liquid Tick 结束后刷新一次

持续流动
→ 每个 Liquid Tick 刷一次变化区域

稳定
→ 停止模拟和刷新
~~~

Shader 负责视觉平滑，不需要每帧模拟液体。

---

## 12. Navigation

LiquidDepth 的小数变化不要每次马上重算导航。

第一版：

~~~text
Liquid Tick 结束
→ 批量通知 Navigation
~~~

如果以后还太频繁，再只处理重要变化：

- 无液体 ↔ 有液体。
- 跨过浅水 / 深水阈值。
- 跨过现有玩法使用的深度档位。

阈值复用现有玩法规则。

## 13. 动态流向

根据这一 Tick 的真实转移量，顺便计算：

~~~text
LiquidFlowX
LiquidFlowY
~~~

给：

- 漂浮物。
- 玩家水流推动。
- 水面 Shader。

LiquidFlow 不进存档。

动态流向由 `ChunkMgr.TryGetExperimentalLiquidFlow` 读取，单位为本 Tick 转移液深 / 秒。漂浮物入口 `TryGetRuntimeWaterCurrent` 已优先读取动态流，Shader 使用同一来源；玩家推动可复用查询接口，本轮不新增玩家移动机制。休眠、关闭实验或换世界后清零。

现有 riverFlow / riverFlowX / riverFlowY 继续作为天然河流水文数据，第一版不强行合并。

---

## 14. 存档

Liquid 模拟不能每 Tick 写磁盘。

正式保存时，只保存和 Seed 原始世界不同的液体格：

~~~text
格子位置
LiquidId
LiquidDepth
~~~

加载：

~~~text
Seed 生成原世界
→ 覆盖抽放液及模拟造成的 Liquid 差量
→ 实验已启用时再唤醒修改格
~~~

不保存：

- LiquidTypeIndex。
- LiquidFlow。
- GroundHeightCache。

---

## 15. 运行时数据

~~~text
每个活动 Chunk：

GroundHeightCache   临时地面高度
ActiveCells         需要继续算的格
PendingDepthDelta   本 Tick 准备增减多少
DirtyCells          本 Tick 真正变化的格
~~~

LiquidDepth / LiquidTypeIndex 继续放在 ChunkTerrainData。

不要给每个液体格创建 GameObject。

## 18. 第一版不做

- 不同液体混合。
- 真实水压。
- 波浪物理。
- 浅水方程。
- 涡流。
- 蒸发 / 降雨守恒。
- 无限范围海洋实时模拟。
- 每帧 Liquid 模拟。

第一版只做好：

~~~text
事件唤醒
→ 固定 Liquid Tick
→ 邻格流动
→ 批量写回
→ 批量刷新
→ 稳定后休眠
~~~

## 19. 实验启停与版本取舍

### 19.1 开关与观察入口

- `ChunkMgr` Inspector：勾选“实验：液体流动（默认关闭）”下的开关；代码字段为 `enableExperimentalLiquidFlow`。
- 代码 / MOD：`ChunkMgr.SetExperimentalLiquidFlowEnabled(true)` 启用，传 `false` 关闭；可传 `LiquidFlowSettings`，参数在启用时复制并校验。
- 静水对照：显式调用 `WakeExperimentalLiquidFlow(worldPosition)`，或通过既有 `WorldLiquidSystem.TrySet/TryPump` 修改液体。
- 诊断：`LiquidFlowExperiment` 暴露 Tick 数、活动格/Chunk、等待 Chunk 和最近转移次数；Profiler 标记为 `FlatWorld.ExperimentalLiquidFlow.Tick`。
- 关闭实验会停止计算、清空动态流向并释放额外租约；不会撤销已经发生的液深变化。默认 Prefab 和存档格式均不改为自动开启。

### 19.2 保留、关闭与撤回

| 取舍 | 处理方式 | 影响 |
| --- | --- | --- |
| 只保留通用基础 | 只采纳第 20 节的基础提交 | 保留批写与批量刷新，不引入实验时钟或流动 |
| 保留代码继续评估 | 采纳实验提交，开关保持关闭 | 正式世界维持原行为，需要时在实验世界开启 |
| 进入正式版本 | 先决定接受范围边界、性能和玩法表现，再单独提交默认策略变更 | 本轮不会自动作出这个决定 |
| 放弃实验 | 未合并时不采纳实验分支；已经合并时按依赖逆序撤销实验提交 | 基础分层保留，通用批量提交可独立保留 |

实验保存仍使用 `LocalPosition + LiquidId + LiquidDepth`，关闭或撤回代码不会把已保存的水体恢复到实验前。对比与放弃实验使用独立世界或实验前的存档副本；代码回退不能替代存档恢复。

已公开的历史使用新的 `revert` 提交撤销；选择性采纳使用 `cherry-pick` 并保留依赖顺序，不把“任意单个核心提交都可独立运行”当成前提。参考 [Git cherry-pick](https://git-scm.com/docs/git-cherry-pick) 与 [Git revert](https://git-scm.com/docs/git-revert)。

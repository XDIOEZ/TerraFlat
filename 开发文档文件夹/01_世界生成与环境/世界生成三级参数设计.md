# TerraFlat 世界生成三级参数设计

## 1. 系统定位

本文档记录两类内容：

1. **现实世界中有直接物理含义的量或状态**，例如高度、温度、液体深度、自转周期。
2. **当前 TerraFlat 已经真实实现并正在使用的物理量或状态**。

三级参数只描述**世界本身正在拥有的物理量**，不描述生成算法、工程结构、分类标签或位置描述。

正文中的三级参数表只记录**当前真实实现**。所有尚未完成的设计统一放到本文末尾的“待实现”章节，避免把现状和目标混在一起。

---

## 2. 三级定义

| 等级 | 定义 | 典型内容 |
| --- | --- | --- |
| **1级：基础物理参数** | 星球或世界直接持有的基础物理参数，不要求全部进入同一条地表生成链 | 海平面、基础温度、自转周期、公转周期、轴倾角、轨道离心率 |
| **2级：静态物理场** | 世界生成后按位置保存、在同一自然世界基线下保持稳定的物理场 | 地形高度、地理温度、降水、水分、风向、河流水文、天然雪深 |
| **3级：运行时物理状态** | 会随着时间、天气、玩家行为或局部环境变化的当前物理状态 | 当前环境温度、当前风力、当前水流、液体深度、季节积雪 |

这三级只表示物理状态的依赖层次，不要求所有量都采用现实单位。

当前项目中部分物理量仍使用归一化值，例如高度、降水、水分、风力和液体深度。它们有现实物理含义，但目前还没有统一换算为米、毫米降水量、m/s 等真实单位。

---

## 3. 1级：基础物理参数

只保留当前项目已经存在的直接物理参数。

| 物理参数 | 当前实现 | 当前含义 |
| --- | --- | --- |
| **海平面** | `terrain.seaLevel` → `ChunkGenerationSettingsSnapshot.SeaLevel` | 高度低于海平面时进入天然海水区域 |
| **星球基础温度** | `PlanetData.GlobalTemperature` | 星球整体环境温度基准，当前默认 26℃ |
| **自转周期** | `TimeData.RotationPeriodSeconds` | 自转一周所需时间，直接决定一天长度；当前默认 1440 游戏秒 |
| **公转周期** | `TimeData.OrbitalPeriodSeconds` | 公转一周所需时间，直接决定一年长度；当前默认 34560 游戏秒 |
| **轴倾角** | `TimeData.AxialTiltDegrees` | 控制季节冷热强弱，并让越靠近极区的季节温差越明显；当前默认 23.44° |
| **轨道离心率** | `TimeData.OrbitalEccentricity` | 控制远近日点冷热差，并按开普勒第二定律产生季节长度不对称；当前默认 0.0167 |

### 当前实现边界

- 当前维护中的时间系统以 `TimeData` 的自转周期、公转周期为权威，不再依赖旧 Space 场景的星体 Transform 参数。
- `DayLength` 只是自转周期的兼容读取入口，不再拥有独立数值。
- 一年包含的游戏天数固定由 `公转周期 ÷ 自转周期` 得出；默认是 `34560 ÷ 1440 = 24` 天。
- 四季总长度必须始终等于公转周期对应的一年；各季具体长度由离心率按轨道速度重新分配。
- 当前只暴露离心率，不额外暴露近心点方向；近日点固定在冬季中段、远日点固定在夏季中段。
- 轴倾角不作为静态地形参数写入生成温度层，只在运行时季节温度上按当前位置接近极区的程度产生更强或更弱的季节差。

## 4. 2级：静态物理场

这些数据已经真实写入生成后的世界或地形环境层。

| 物理场 | 当前实现 | 当前含义 |
| --- | --- | --- |
| **地形高度** | 环境层 `height` | 每格地形的相对高度 |
| **地理温度** | 环境层 `temperature.celsius` | 世界生成得到的当地摄氏温度基线，生成后保持不变 |
| **降水** | 环境层 `precipitation` | 当前是世界生成得到的长期降水水平，仍由独立基础降水场和地形降雨修正产生 |
| **环境湿润度** | 环境层 `moisture` | 当前表示当地环境/地表湿润程度，由降水、低地和河漫滩等合成，并被群系、生态和农田等系统消费 |
| **静态风向** | 环境层 `windX` / `windY` | 世界生成得到的当地风向单位向量 |
| **河流流量** | 环境层 `riverFlow` | 天然河流的相对流量 |
| **河流流向** | 环境层 `riverFlowX` / `riverFlowY` | 天然河流的下游方向 |
| **河流水面高度** | 环境层 `riverSurfaceLevel` | 天然河流生成时的水面高度 |
| **天然积雪深度** | 环境层 `snow.depth` | 世界生成得到的天然积雪厚度 |
| **天然液体深度** | `ChunkTerrainData` Liquid 层 | 海洋、河流、湖泊、地下水、岩浆等生成后的液体深度 |

---

### 地理温度不变量

`temperature.celsius` 是二级静态地理温度，**生成后不随时间变化**。

季节、天气和局部冷热源等运行时变化只能改变三级的**当前环境温度**，不能回写二级地理温度。

## 5. 3级：运行时物理状态

这些状态会在游戏运行中继续变化。

| 物理状态 | 当前实现 | 当前含义 |
| --- | --- | --- |
| **当前环境温度** | `TemperatureMgr.TryGetAmbientTemperature` | 地理温度叠加星球基温差、季节、天气和局部冷热源后的实际环境温度 |
| **当前全局风力** | `PlanetData.WindStrength` / `WeatherMgr` | 当前星球风力强度，现阶段使用 0～1 归一化值 |
| **当前水流方向** | `ChunkMgr.TryGetRuntimeWaterCurrent` | 玩家当前所在水体的实际运行时流向 |
| **当前水流量** | `RuntimeWaterCurrentSample.Flow` | 当前水体的运行时相对流量 |
| **当前液体深度** | `WorldLiquidSystem` / Liquid 层 | 可被抽取、流动或其他玩法改变的液体深度 |
| **季节积雪量** | `PlanetData.SeasonalSnow` | 随季节、温度和降雪变化的积雪状态 |
| **季节温差** | `time-system.json` 的四季温度偏移 | 当前季节对环境温度施加的摄氏温差 |
| **天气温差** | `RainTemperatureOffset` / `CloudyTemperatureOffset` / `StormTemperatureOffset` | 当前天气对环境温度施加的摄氏修正 |

## 6. 当前实际依赖关系

这里只记录当前代码已经存在的直接关系：

| 输入物理量 | 输出物理量 / 状态 | 当前关系 |
| --- | --- | --- |
| 地形高度 + 海平面 | 天然液体深度 | 决定海洋格及其初始液体 |
| 基础降水场 + 静态风向 + 上风地形 | 降水 | 当前先生成基础降水，再叠加迎风增雨与背风雨影 |
| 降水 + 低地程度 + 河漫滩 | 环境湿润度 | 当前 `moisture` 的主要生成关系；海洋格另有最低湿度保底 |
| 降水 + 地形高度 | 河流径流 | 当前 `heightDriven` 河网把降水转成径流并沿低处累计汇流 |
| 地理温度 + 星球基础温度 + 季节温差 + 天气温差 + 局部冷热源 | 当前环境温度 | `TemperatureMgr` 合成最终环境温度 |
| 河流流量 + 河流流向 | 当前水流量 + 当前水流方向 | 运行时水流查询复用天然水文，并允许动态流动覆盖 |
| 天然液体深度 | 当前液体深度 | 生成值作为初始状态，运行时可继续修改 |
| 天然积雪深度 + 季节积雪 | 当前地表积雪深度 | `WorldSnowSystem` 合成最终地表雪深 |
| 自转周期 | 一天长度 | `DayLength = RotationPeriodSeconds` |
| 公转周期 + 自转周期 | 一年天数 | `YearLengthDays = OrbitalPeriodSeconds / RotationPeriodSeconds` |
| 轴倾角 + 当前季节 + 极区接近程度 | 当地季节温差 | 倾角越大、越靠近极区，季节冷热差越明显 |
| 轨道离心率 + 公转进度 | 额外冷热差 | 按当前轨道距离的辐照变化产生远近日点温差 |
| 轨道离心率 + 一年天数 | 各季节长度 | 按开普勒第二定律计算四段轨道所占时间，近日点附近季节更短、远日点附近季节更长 |

## 7. 待实现

本章只记录已经讨论并确定、但尚未完成的目标。实现完成并核实后，再把对应结论移回前面的“当前实现”章节。

### 7.1 静态气候与水文主链重构

参考 Azgaar Fantasy Map Generator 的“湖泊先于气候、风传播临时湿气、河流只做局部湿润反馈”思路，但实现必须适配 TerraFlat 的 Chunk 按需生成、Wrapped 地图和 Infinite 地图。

目标生成链：

```text
地形高度 + 海平面
        ↓
       海洋

地形低洼盆地 + 世界坐标 + Seed
        ↓
  气候前基础湖泊

海洋 + 气候前基础湖泊
        ↓
风向传播临时 humidity
        ↓
临时 humidity + 地理温度
        ↓
地形抬升 / 雨影只做局部修正
        ↓
地理降水 precipitation
        ↓
地形高度 + 降水
        ↓
径流 → 河流 → 水文湖泊
        ↓
河流 / 湖泊 / 海洋
        ↓
局部环境湿润反馈 moisture
        ↓
群系 / 草层 / 生态 / 自然地表
```

实现约束：

- `precipitation` 改为稳定的二级地理降水层，是气候阶段真正保存的长期降水结果。
- 删除“先独立生成 `precipitation`，再主要由它定义 `moisture`”作为气候主因果链的职责。
- 独立 `climate.precipitation` 随机噪声退出正式降水来源；不规则降水应来自水体分布、风向传播、地理温度和地形抬升/雨影。
- 降水的核心输入是**临时湿气 + 地理温度**；静态风向负责输送湿气，不作为降水公式里额外重复计算的一份“湿度参数”。
- 山地影响保留为迎风抬升和背风雨影修正，不把“地形高度”误写成第三套湿度。
- 河流由最终地理降水形成的径流与地形汇流继续产生；河流生成完成后**不重新跑一遍全局气候**。
- 湖泊分两类处理：气候前可以由稳定地形盆地确定的基础湖泊先成为水汽源；降水/径流形成的水文湖泊属于后续水文结果。
- 河流只对周边最终环境湿润度做局部反馈，不反向触发第二遍完整降水和河网生成。

### 7.2 临时湿气与 `moisture` 的职责

未来不把“大气湿度”保存成一张独立长期物理层。

- 降水生成阶段使用临时变量 `humidity` 表示风当前携带的水汽，只在计算过程中存在，不写入 `ChunkTerrainData`。
- 风经过海洋或气候前湖泊时增加临时湿气，经过陆地并形成降水时消耗临时湿气。
- 现有 `moisture` 环境层保留，但语义收敛为**最终环境湿润度**，主要服务群系、草层、生态、自然地表与现有农业读取。
- `moisture` 可以由地理降水和附近海洋、河流、湖泊共同抬高，但它不再作为全局降水生成所依赖的长期“大气湿度层”。
- 农田浇水等玩家运行时水量继续保留农业自己的状态，不要求用二级 `moisture` 承载全部玩法水量。

### 7.3 Wrapped / Infinite 风场与湿气传播

风场必须继续是世界坐标上的确定性结果，不能依赖 Chunk 加载顺序。

- Wrapped 世界继续使用周期风场，地图接缝两侧的 `windX/windY` 必须连续。
- Infinite 世界使用 `世界坐标 + Seed` 直接确定风向，需要哪里计算哪里，不存在“从世界边缘吹进来”的起点。
- 风场优先采用“大尺度主导风 + 小尺度确定性扰动”，避免完全随机区域方向产生过多局部死循环。
- 湿气传播必须是**有限距离**的局部计算，不能沿风无限追踪到“世界边缘”。
- Wrapped 世界的湿气追踪必须有最大距离/最大步数，并检测已经访问过的宏观格，防止绕世界反复循环。
- Infinite 世界同样只追踪有限距离，因此生成任意远处 Chunk 时不需要先生成从原点到该 Chunk 之间的地图。

### 7.4 Chunk / Region 连续性

Region 只允许作为**缓存边界**，不能成为气候或水文的物理边界。

- 高度、地理温度、风向等能够写成 `F(worldX, worldY, seed)` 的基础场优先直接按世界坐标采样，天然保证跨 Chunk / Region 连续。
- 需要邻域数据时，优先按绝对世界坐标做确定性邻域重算，不要求目标邻居 Chunk 已经加载。
- 只有真正昂贵、会被多个 Chunk 复用的宏观气候/水文结果才进入有界 Region 缓存。
- Region 可以使用 Halo / Padding 读取外圈数据，但只提交自己的核心区；禁止一个 Region 或 Chunk 在生成时写邻居的最终数据。
- 相邻 Region 的重叠计算必须使用相同 `WorldSeed + 世界绝对坐标 + Profile + Topology`，让同一坐标无论从哪一侧计算都得到同一结果。
- 如果某个阶段确实必须读取前一阶段的邻居结果，再引入 Multi-pass / 阶段屏障；不要为了方便把所有生成都改成互相等待。
- 生成结果不能依赖 Chunk 请求顺序、加载方向或玩家先从哪边探索世界。

### 7.5 性能目标

- 不照搬 Azgaar 的“整张地图从边界扫到另一边”，TerraFlat 必须保持 Chunk 按需生成。
- 不做无限收敛的“气候 → 水文 → 气候 → 水文”循环，也不做两遍完整河网。
- 主流程固定为“基础水体 → 一次气候 → 一次完整水文 → 一次局部环境湿润反馈”。
- 气候传播优先在低分辨率宏观格上完成，再向 Chunk / Tile 采样；具体宏观格尺寸和传播距离由实现阶段压测确定，不在本文写死。
- 纯数学批量阶段优先复用现有 Burst / 数组计算方式；共享宏观结果复用有界缓存和邻区预热。
- 任何优化都不能牺牲固定 Seed、跨 Chunk 接缝、Wrapped 接缝和联机生成一致性。

### 7.6 其他已确定的未来物理职责

- 海平面继续作为稳定平均海面基准，并参与海拔、海洋深度和沿海环境计算。
- 星球基础温度作为长期热平衡基准，不直接承担季节、昼夜、天气和局部热源变化。
- 自转周期作为昼夜周期唯一物理真源，并决定太阳照射位置的日内移动速度。
- 公转周期与轴倾角共同决定全年太阳直射位置变化；轴倾角决定直射点南北移动范围。
- 轨道离心率与公转进度共同决定恒星距离和辐照差，只影响三级当前温度，不回写二级地理温度。
- `temperature.celsius` 永久保持当地长期地理温度基线；太阳照射、季节、公转辐照、天气和局部冷热源都只叠加到三级当前环境温度。
- 静态 `windX/windY` 表示长期背景风向；运行时实际风可以再叠加天气、季节和局部环境。
- 天然河流流量、流向和水面高度作为水文基线；运行时允许降雨、融雪、蒸发、抽取和水工继续改变实际水量与流向。
- 天然积雪作为长期自然雪盖基线；季节降雪、融雪和玩家堆雪继续属于三级状态。
- 当前环境温度最终应统一叠加季节、太阳照射位置/入射角、公转辐照、天气及局部冷热源。
- 当前天气温差继续作为短期大气过程的三级修正，并可逐步与风、云量和实时降水强度联动。

## 8. 参数收录规则

以后向三级参数增加内容时同时满足以下条件：

1. 在现实世界中有直接物理含义。
2. 当前项目已经有真实数据字段、环境层或运行时状态。
3. 有实际系统读取或修改这个量。
4. 不是另一个物理量的纯归一化副本、分类标签或算法控制项。

未实际实现的物理量不进入本三级参数表。

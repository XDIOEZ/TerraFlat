# TerraFlat 世界生成三级参数设计

## 1. 系统定位

本文档只记录两类内容：

1. **现实世界中有直接物理含义的量或状态**，例如高度、温度、液体深度、自转周期。
2. **当前 TerraFlat 已经真实实现并正在使用的物理量或状态**。

三级参数只描述**世界本身正在拥有的物理量**，不描述生成算法、工程结构、分类标签或位置描述。表格中的“未来期待含义”只记录该物理量未来希望承担的真实物理职责，**不代表当前已经实现**。

---

## 2. 三级定义

| 等级 | 定义 | 典型内容 |
| --- | --- | --- |
| **1级：基础物理参数** | 星球或世界直接持有的基础物理参数，不要求全部进入同一条地表生成链 | 海平面、基础温度、自转周期、公转周期、轴倾角、轨道离心率 |
| **2级：静态物理场** | 世界生成后按位置保存、在同一自然世界基线下保持稳定的物理场 | 地形高度、地理温度、降水、水分、风向、河流水文、天然雪深 |
| **3级：运行时物理状态** | 会随着时间、天气、玩家行为或局部环境变化的当前物理状态 | 当前环境温度、当前风力、当前水流、液体深度、季节积雪 |

这三级只表示物理状态的依赖层次，不要求所有量都采用现实单位。

当前项目中部分物理量仍使用归一化值，例如高度、降水、水分、风力和液体深度。它们有现实物理含义，但目前还没有统一换算为米、毫米降水量、m/s 等真实单位。

---

## 3. 1级：基础物理参数

只保留当前项目已经存在的直接物理参数。

| 物理参数 | 当前实现 | 当前含义 | 未来期待含义 |
| --- | --- | --- | --- |
| **海平面** | `terrain.seaLevel` → `ChunkGenerationSettingsSnapshot.SeaLevel` | 高度低于海平面时进入天然海水区域 | 继续作为稳定的平均海面基准，并参与海拔、海洋深度与沿海环境计算 |
| **星球基础温度** | `PlanetData.GlobalTemperature` | 星球整体环境温度基准，当前默认 26℃ | 作为星球长期热平衡的全局基准，不直接承担季节、昼夜、天气或局部地热变化 |
| **自转周期** | `TimeData.RotationPeriodSeconds` | 自转一周所需时间，直接决定一天长度；当前默认 1440 游戏秒 | 作为昼夜周期唯一物理真源，并决定太阳照射点随日内时间的移动速度 |
| **公转周期** | `TimeData.OrbitalPeriodSeconds` | 公转一周所需时间，直接决定一年长度；当前默认 34560 游戏秒 | 作为年份与季节进度唯一物理真源，并与轴倾角共同决定全年太阳直射位置变化 |
| **轴倾角** | `TimeData.AxialTiltDegrees` | 控制季节冷热强弱，并让越靠近极区的季节温差越明显；当前默认 23.44° | 决定全年太阳直射点南北移动范围，从而影响三级运行时温度的季节性太阳辐照差 |
| **轨道离心率** | `TimeData.OrbitalEccentricity` | 控制远近日点冷热差，并按开普勒第二定律产生季节长度不对称；当前默认 0.0167 | 与公转进度共同决定恒星距离和辐照强弱，影响三级运行时温度而不改写地理温度基线 |

### 当前实现边界

- 当前维护中的时间系统以 `TimeData` 的自转周期、公转周期为权威，不再依赖旧 Space 场景的星体 Transform 参数。
- `DayLength` 只是自转周期的兼容读取入口，不再拥有独立数值。
- 一年包含的游戏天数固定由 `公转周期 ÷ 自转周期` 得出；默认是 `34560 ÷ 1440 = 24` 天。
- 四季总长度必须始终等于公转周期对应的一年；各季具体长度由离心率按轨道速度重新分配。
- 当前只暴露离心率，不额外暴露近心点方向；近日点固定在冬季中段、远日点固定在夏季中段。
- 轴倾角不作为静态地形参数写入生成温度层，只在运行时季节温度上按当前位置接近极区的程度产生更强或更弱的季节差。

## 4. 2级：静态物理场

这些数据已经真实写入生成后的世界或地形环境层。

| 物理场 | 当前实现 | 当前含义 | 未来期待含义 |
| --- | --- | --- | --- |
| **地形高度** | 环境层 `height` | 每格地形的相对高度 | 作为稳定地形海拔基线，继续参与气候、水文与地热等物理场计算 |
| **地理温度** | 环境层 `temperature.celsius` | 世界生成得到的当地摄氏温度基线，生成后保持不变 | 保持为**永久不变的当地长期温度基线**；季节、太阳照射点、昼夜、天气、地热和局部热源都不得回写本层，只能在三级温度上叠加 |
| **降水** | 环境层 `precipitation` | 当地长期降水水平 | 表示长期平均降水气候基线；短期降雨、季节雨量变化留给三级动态环境 |
| **环境水分** | 环境层 `moisture` | 当地地表环境的湿润程度 | 表示自然地理形成的基础湿润程度；运行时土壤含水、降雨和蒸发另行叠加 |
| **静态风向** | 环境层 `windX` / `windY` | 世界生成得到的当地风向单位向量 | 表示长期背景风向；实际当前风再受天气、季节和局地环境影响 |
| **河流流量** | 环境层 `riverFlow` | 天然河流的相对流量 | 作为天然水系的基础流量，运行时可叠加降雨、融雪等动态入流 |
| **河流流向** | 环境层 `riverFlowX` / `riverFlowY` | 天然河流的下游方向 | 继续作为天然下游方向基线，只有真实地形或水工改变时才需要动态修正 |
| **河流水面高度** | 环境层 `riverSurfaceLevel` | 天然河流生成时的水面高度 | 作为天然河道基准水位，运行时水量变化可在其上形成实际水位 |
| **天然积雪深度** | 环境层 `snow.depth` | 世界生成得到的天然积雪厚度 | 作为长期自然雪盖基线，季节降雪、融雪和玩家堆雪继续放在三级状态 |
| **天然液体深度** | `ChunkTerrainData` Liquid 层 | 海洋、河流、湖泊、地下水、岩浆等生成后的液体深度 | 作为天然初始液体状态，后续由流动、抽取、降水和蒸发等运行时过程继续改变 |

---

### 地理温度不变量

`temperature.celsius` 是二级静态地理温度，**生成后不随时间变化**。

正确的温度层级应是：

```text
二级：地理温度 temperature.celsius（不变）
                ↓
三级：当前环境温度
      + 星球基础温度修正
      + 季节温度
      + 当前太阳照射位置 / 入射角
      + 公转距离造成的辐照变化
      + 天气温差
      + 地热
      + 局部冷热源
```

因此季节变冷、白天太阳直射、地下或火山地热升温，都只能改变三级的**当前环境温度**，不能污染二级地理温度。

## 5. 3级：运行时物理状态

这些状态会在游戏运行中继续变化。

| 物理状态 | 当前实现 | 当前含义 | 未来期待含义 |
| --- | --- | --- | --- |
| **当前环境温度** | `TemperatureMgr.TryGetAmbientTemperature` | 地理温度叠加星球基温差、季节、天气和局部冷热源后的实际环境温度 | 成为统一的最终温度层：在不变的地理温度上继续叠加季节、太阳照射点/入射角、公转辐照变化、天气、地热及局部冷热源 |
| **当前全局风力** | `PlanetData.WindStrength` / `WeatherMgr` | 当前星球风力强度，现阶段使用 0～1 归一化值 | 与背景风向、天气和昼夜/季节热力差共同形成实际风场强度 |
| **当前水流方向** | `ChunkMgr.TryGetRuntimeWaterCurrent` | 玩家当前所在水体的实际运行时流向 | 由天然水文方向和实时水位/流量共同决定，允许水工和地形改变实际流向 |
| **当前水流量** | `RuntimeWaterCurrentSample.Flow` | 当前水体的运行时相对流量 | 叠加降雨、融雪、蒸发、抽取及上下游来水，成为实时水量状态 |
| **当前液体深度** | `WorldLiquidSystem` / Liquid 层 | 可被抽取、流动或其他玩法改变的液体深度 | 统一承载自然与玩家行为造成的真实运行时水位/液位变化 |
| **季节积雪量** | `PlanetData.SeasonalSnow` | 随季节、温度和降雪变化的积雪状态 | 完全依据三级当前温度与实时降雪/融雪推进，不反向修改地理温度 |
| **季节温差** | `time-system.json` 的四季温度偏移 | 当前季节对环境温度施加的摄氏温差 | 由公转进度、轴倾角和当前位置的太阳辐照差自然推导，作为三级温度修正而不是二级地理温度 |
| **天气温差** | `RainTemperatureOffset` / `CloudyTemperatureOffset` / `StormTemperatureOffset` | 当前天气对环境温度施加的摄氏修正 | 继续作为短期大气过程对三级当前温度的修正，并可逐步与风、云量和降水强度联动 |

## 6. 当前实际依赖关系

这里只记录当前代码已经存在的直接关系：

| 输入物理量 | 输出物理量 / 状态 | 当前关系 |
| --- | --- | --- |
| 地形高度 + 海平面 | 天然液体深度 | 决定海洋格及其初始液体 |
| 地理温度 + 星球基础温度 + 季节温差 + 天气温差 + 局部冷热源 | 当前环境温度 | `TemperatureMgr` 合成最终环境温度 |
| 河流流量 + 河流流向 | 当前水流量 + 当前水流方向 | 运行时水流查询复用天然水文，并允许动态流动覆盖 |
| 天然液体深度 | 当前液体深度 | 生成值作为初始状态，运行时可继续修改 |
| 天然积雪深度 + 季节积雪 | 当前地表积雪深度 | `WorldSnowSystem` 合成最终地表雪深 |
| 自转周期 | 一天长度 | `DayLength = RotationPeriodSeconds` |
| 公转周期 + 自转周期 | 一年天数 | `YearLengthDays = OrbitalPeriodSeconds / RotationPeriodSeconds` |
| 轴倾角 + 当前季节 + 极区接近程度 | 当地季节温差 | 倾角越大、越靠近极区，季节冷热差越明显 |
| 轨道离心率 + 公转进度 | 额外冷热差 | 按当前轨道距离的辐照变化产生远近日点温差 |
| 轨道离心率 + 一年天数 | 各季节长度 | 按开普勒第二定律计算四段轨道所占时间，近日点附近季节更短、远日点附近更长 |

---

## 7. 参数收录规则

以后向三级参数增加内容时同时满足以下条件：

1. 在现实世界中有直接物理含义。
2. 当前项目已经有真实数据字段、环境层或运行时状态。
3. 有实际系统读取或修改这个量。
4. 不是另一个物理量的纯归一化副本、分类标签或算法控制项。

未实际实现的物理量不进入本三级参数表。

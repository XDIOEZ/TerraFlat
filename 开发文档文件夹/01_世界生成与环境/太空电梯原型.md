# 太空电梯原型

太空电梯连接一座地面终端和一座固定的太空站台。玩家可以运货，也可以随电梯往返；站台使用现有船体建筑系统，玩家到站后可以继续铺地板、加墙和安装设备，把它扩建成自己的小型空间站。

本文记录第一版的规则和代码边界。它是可继续扩展的原型，玩法、画面和操作感受由用户验收。

## 一、第一版规则

- 每个星球地表只建立一条电梯线路，连接自己的太空站台和一份货舱。
- 在同一星球别处再次建立线路会被拒绝，并提示原线路位置；原地重建终端只接回原线路，保留旧货物和扩建站台，不再赠送一套新站台。
- 同一份货物随电梯往返。地面端和太空端不会各生成一箱副本。
- 货舱停在当前端时才能装卸；途中不能装卸，远端需要先召回。
- 发车后进入倒计时，到站时结束本次行程。空舱也可以运行，方便另一端召回。
- 玩家可以预约随行。倒计时结束且乘坐条件仍满足时，再切换到另一端。
- 玩家走开会取消自己的乘坐预约，货运继续；不会把已走开的玩家强行传走。
- 普通单人模式内部也会启动本机 Host，电梯必须支持这条正式流程；远程客户端运输暂未开放，拒绝时返回实际原因。
- 第一版尚未接电力消耗、运输成本、缆绳动画和途中车厢场景。

## 二、如何使用

1. 在工作台用 **20 个熟铁锭 + 5 个铜板**制作“太空电梯”，也可以在创造背包或 GM 中按名称查找。放置物品 ID 是 `SpaceElevatorTerminal_Summoner`。
2. 把终端放到星球地面，靠近后按 **F**。首次交互建立线路和初始站台。
3. 面板左边是玩家库存，右边是货舱。点击左边装货，点击右边卸货；“切换背包”和翻页按钮用于查看其他库存及槽位。
4. 选择“发送货舱”只运货；选择“乘坐前往”后留在终端旁等待，到站后玩家前往另一端。
5. 货舱不在当前端时，选择“召回货舱”。在太空端使用同一终端往返、装卸，并通过现有建造操作扩建站台。

初始平台为 **5×5 地板**，外围有墙和一扇门，并有一份初始空气。固定站台地板支持正常步行，后续破口、空气消耗和设备仍由现有船体环境规则处理；初始空气不是无限供氧。

## 三、固定站台与扩建

站台与普通飞船共用部件、地板支撑、占地、库存、机器和表现系统。电梯只负责生成最初的小站台、固定位置和运输，不另做一套空间站建造规则。

- 站台通过锚定信息固定在目标星体附近，不能作为普通飞船点火开走。
- 玩家使用现有的太空建造操作扩建，仍然遵守地板连接、占地和部件安装规则。
- 电梯终端是地面和站台的连接入口，不能在连接仍有效时随意拆掉。
- 扩建后的地板、墙、设备和库存仍归站台船体保存。
- 固定站台不支持驾驶、起降、导航或船体对接；断开的扩建部分按现有规则成为独立部分，不复制固定锚点。

## 四、职责划分

| 部分 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 电梯状态 | 两端身份、站台身份、货舱所在端、目的端、剩余时间和货物快照 | 游戏对象、面板与动画 |
| 行程规则 | 发车条件、时间推进、到站与当前端能否装卸 | 创建玩家或建筑 |
| 会话接入 | 查找实际终端、持有真实货舱、运输请求、乘坐预约和场景迁移 | 另算库存容量或重写建造规则 |
| 船体锚定 | 固定站台的位置和移动边界 | 识别货物、装卸或玩家按钮 |
| 交互面板 | 显示当前状态，发出装卸、发车、召回或乘坐请求 | 直接复制物品或宣告请求成功 |

数据只由正式会话维护。界面显示正式操作返回的结果和拒绝原因，不能把按钮点击成功当成运输成功。

## 五、货物与存档

- 运行时由电梯持有真实库存，复用现有物品转移和容量规则。
- 装卸保留物品的实例状态，设备里的内容不能因运输恢复成模板默认值。
- 货舱按槽位保存正式物品快照，空槽保留位置。
- 电梯连接、货舱位置和正在进行的行程随太空会话保存。
- 玩家乘坐通过现有地面/太空生命周期进入目的端，不直接把当前对象挪到一个伪造场景。
- 暂停与离线时间不额外补算运输进度，遵循现有太空模拟时间规则。

以下代码路径相对于 `Assets/5_Scripts/`：

| `5-5_UI/Gameplay/SpaceElevatorPanelView.cs` | 正式面板控件引用 |

玩法参数在 `Assets/Resources/Config/Space/space-gameplay.json`，第一版默认：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `ElevatorTravelSeconds` | 12 | 单程运行秒数 |
| `ElevatorStationClearanceMeters` | 100 | 站台原点距星球表面的余量 |
| `ElevatorCargoSlots` | 24 | 货舱格数 |
| `ElevatorCargoMaxWeightKg` | 2000 | 总载重，千克 |
| `ElevatorCargoMaxVolumeLiters` | 4000 | 总容积，升 |

物品定义为 `Assets/StreamingAssets/GameConfig/Items/shells/space_elevator.json`；配方为 `Assets/StreamingAssets/GameConfig/Recipes/crafting/space_elevator.json`。面板资源是 `Assets/2_Prefabs/2-1_UI/Gameplay/Crafting/UI_SpaceElevator.prefab`，重建入口在 `Assets/Editor/FlatWorld/PrefabBuilders/UI/RuntimeUIPrefabBuilder.SpaceElevator.cs`。

## 七、后续完善顺序

1. 补齐用户实际操作中发现的装卸、召回、乘坐与扩建问题。
2. 接入电网需求、运输载重和运行成本；这些作为电梯运行条件扩展，不塞进普通库存规则。
3. 增加正式美术、缆绳和车厢表现；表现读取行程进度，不反过来决定货物到站。
4. 补齐远程客户端的权威运输请求、乘员归属和真实回执，再开放远程联机运输。
5. 按需要扩展多车厢、自动物流、运行队列和设备升级。

## 八、验证范围

新增规则入口是 `GameplayTests/Systems/Space/elevator_rules.lua`，案例 ID 为 `space_elevator_rules`。它通过正式生产接口采样，由 Lua 断言本机权限、行程往返、途中封舱、库存守恒、容量拒绝、设备身份、内存快照、扩建原点和断桥后的锚点归属。

这些独立规则不覆盖实际建站、同星球重复拒绝、原地重绑、玩家走开取消预约、真实场景迁移、磁盘读档、原生物理碰撞或面板操作；不能把已有太空场景案例当作新增电梯流程已被测过。

本轮不运行 Lua 或 PlayMode 测试，不暂停、停止或刷新用户正在运行的 Unity。静态检查、离线 C# 编译和控制台记录分别说明，不能算作场景切换、实际装卸、存档重载、扩建、联机或画面已经验收。

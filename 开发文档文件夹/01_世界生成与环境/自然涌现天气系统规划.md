# FlatWorld 自然涌现天气系统规划

## 1. 系统定位

通过地形、地表水分、温度和空气运动的持续作用，让云、雨雪、雾、风与雷电自然形成，并允许玩家行为改变局部天气。

天气名称只用于描述当前现象。自然天气不再由“随机抽取晴天、阴天、暴雨”或固定天气阶段链决定。

本文为待实现方案。2026-10-06 核对了当前工作树的相关入口，不代表以下机制已经实现或通过游戏内验收。首轮采用粗网格、两层空气的简化模型；网格尺寸、单位换算、公式和数值仍需确定。

### 1.1 核心玩法目标

```text
玩家点燃森林 → 火场持续释放热量
                    ├→ 地表水分蒸发 → 地面变干、水汽进入空气
                    └→ 热空气上升 → 周围近地空气补入
                                         ↓
                       水汽被抬升、输送，冷却后凝结成云
                                         ↓
                             云水积累，条件合适时降雨
                                         ↓
                         地面补水、降温，可能抑制燃烧
```

- 这条链是模拟结果，不是“烧森林后触发下雨”的专用事件。
- 只有风和水汽不足以保证下雨，还需要抬升或冷却、凝结及云水积累。
- 干燥地区的大火可能主要产生热风和烟；湿润地区在供水、热量和空气条件合适时更容易形成云。
- 降水可能出现在下风向，可能在到达地面前蒸发，也可能不足以灭火。
- 小火把不能仅因中心温度很高就制造大范围降雨；影响要同时受热输出、面积、持续时间和供水量约束。

大型火灾推动湿空气上升、冷却并形成火积云或火积雨云，有现实参考，但游戏应采用可调的简化规则。[NOAA：野火产生天气](https://www.nesdis.noaa.gov/news/earth-orbit-wildfires-spawn-severe-weather)

| --- | --- |

| 雨雪、雾、云层光照和风已有表现入口 | 改为读取当地要素，不按单一天气类型启停全部效果 |

## 3. 固定地理基础与世界初始化

### 3.1 固定生成输入

| 固定输入 | 用途 |
| --- | --- |
| 世界种子、生成规则版本及冻结配置 | 重建一致的地理基础 |
| 世界尺度、坐标换算、拓扑 | 确定距离、边界及环绕关系 |
| 高度生成规则、基准海平面 | 形成地形、海岸、汇水与空气抬升条件 |
| 纬度、日照与季节规则 | 确定长期受热条件；规则固定，当前日照随时间变化 |
| 岩土材质分布、土层厚度 | 确定储水、渗漏和受热特性 |
| 可选地下地质与地热分布 | 为地下水通路、火山、温泉等提供基础，后续扩展 |

- 生成高度是地形生成的结果，也是后续水文、气候和生态生成的输入。
- 坡度、坡向和汇水方向由高度推导，不分别随机生成互相矛盾的数据。
- 保水容量、渗透率、热容量优先由材质和厚度配置推导。
- 玩家若能挖填或替换材质，应保存地形差量并使相关派生缓存失效。

### 3.2 现有海平面的含义

当前 [地表 Profile](../../Assets/Resources/Config/WorldModel/ChunkGenerationProfile_Surface.asset) 中 `terrain.seaLevel = 0.5`，它是归一化高度阈值。生成器用它判断海陆，海水初始深度另用公式计算。

- 不能直接将 `0.5` 解释为米制海拔，也不能把当前液体深度直接当成空气抬升高度。
- 首轮需明确地形高度差到模拟高度差的换算，供空气抬升和冷却计算共用。
- 基准海平面属于生成输入；河湖当前水量、水面变化属于运行态。

### 3.3 长期气候初始化

```text
固定生成输入 → 地形与材质 → 长期气候、水文估计
                                  ↓
                         初始水分、冰雪与生态
                                  ↓
                         运行时天气持续演变
```

- 首轮允许用长期气候估计初始化世界，不要求从无水无云状态模拟多年。
- 生成时的气温和降水分布是气候基准，不是永远不变的当前温度与降雨。
- 群系用于初始生态与内容分布，不能每步把雨林补满水，也不能强制沙漠始终干燥。
- 一场雨不会立刻改变群系；长期生态变化另行规划。

## 4. 地表水分与冰雪

### 4.1 储水与湿度

- 地表水分应有统一的储水量和容量语义，湿度由“当前水量 / 当前保水容量”派生。
- 当前 `moisture` 的 0～1 值可继续作为查询和显示接口，不能仅凭这个比例决定能蒸发多少水。
- 储水容量不同的两块地，即使湿度比例相同，可释放的水量也不同。
- 降雨、浇水、融雪等增加可用水；蒸发、植物取水、渗漏和径流减少或转移水。
- 蒸发水量必须从地表或液体储量扣除，并以对应换算增加大气水汽；干透后不能继续提供水汽。
- 超出容量的水必须有去向，例如地表积水、邻格径流或地下渗漏；具体分配规则待定。
- 农业与自然土地共用水量修改入口。农业水量和湿度显示不能作为两套独立水源参与计算。

### 4.2 群系初始差异

| 环境 | 初始化方向 | 运行时允许的变化 |
| --- | --- | --- |
| 沙漠 | 初始水分偏低 | 降雨、灌溉后可以变湿，之后按当地条件干燥 |
| 热带雨林 | 长期降水条件支持较高初始水分 | 干旱、火灾和排水后仍会变干 |
| 雪原 | 液态可用水少，冰雪储量单独记录 | 融化后可以形成湿地、积水或径流 |

- 雪原不能直接当作总水量很少的沙漠；冻结和液态水不足要分开表达。
- 冰雪融化需要热量，蒸发带走热量；首轮至少保留这两种作用方向及预算限制。
- 现有雪深表示覆盖厚度，接入水量循环前必须定义雪深到水量的换算，避免凭空补水或重复扣雪。

冻结土壤会限制水分流动，融雪又可能提高当地土壤水分，可作为上述区分的参考。[NSIDC：雪与土壤水分](https://nsidc.org/learn/parts-cryosphere/snow/why-snow-matters)

## 5. 地表与空气的热量交换

- 分开表达地表温度、近地空气温度与上层空气温度，不能把火焰中心温度直接赋给整片大气。
- 热源提供单位模拟时间内的热输入或有上限的等效热输出，并明确覆盖范围。
- 现有 `celsiusOffset` 是温度增量，不是功率；接入时需要扩展热源契约或定义受限换算，不暗中改变旧参数语义。
- 地表按材质热容量吸收日照和热源输入，再与空气交换热量。
- 地表升温可以增强蒸发和热空气抬升，但蒸发量同时受可用水、可用热量及空气干湿条件限制。
- 热源移除后，模拟中的热量逐渐散去；可重建热源缓存不能替代持久化热状态。
- 云层遮光、降水、蒸发与凝结的热反馈只结算一次。不得继续叠加一份同义的固定“雨天降温”。
- 一个模拟步统一读取上一步状态、计算交换量、提交新状态，避免温度查询与天气查询递归互调。
- 角色和作物继续通过统一环境采样读取结果，不各自重新模拟天气。

## 6. 局部空气、风和水汽输送

### 6.1 首轮空间模型

首轮建议在地表上覆盖粗网格，每个大气单元包含近地与上层两组状态。一格大气覆盖多格地面，尺寸待定。

| 状态 | 作用 |
| --- | --- |
| 近地、上层空气温度 | 蒸发、浮升、冷却和凝结 |
| 各层水汽含量 | 水分的可输送储量 |
| 各层水平气流 | 输送热量、水汽和云水 |
| 层间抬升与交换强度 | 将近地空气送入上层，形成局部循环 |
| 简化压力或浮升势 | 计算局部气流的驱动力；具体选择待定 |
| 云水储量 | 形成遮光和降水的来源 |
| 对流活动与雷电积累状态 | 为后续闪电调度提供条件 |

### 6.2 风的形成与运动

- 温差通过浮升及简化压力变化影响空气运动，不用“温差符号直接等于风向”的规则。
- 热区空气上升时，周围近地空气可以补入；上层空气按本层气流继续输送。
- 地形对气流提供阻挡、偏转或抬升，首轮选用有限的简化规则。
- 背景气流可以来自长期气候或缓慢变化的边界条件，不能每帧随机跳风向。
- 空气输送必须同步搬运相应热量、水汽和云水，不能只移动雨粒子而不移动状态。
- 传输量受来源储量和步长限制；每对相邻单元一次转移必须一出一入，不能遍历顺序改变结果。
- 火场造成的局部气流叠加在背景气流上，不直接改成全星球风力。

## 7. 云、降水、雾与雷电

### 7.1 凝结和云层

- 水汽在冷却等条件下超过空气的容纳能力时，逐渐转为云水。
- 云水可随上层气流移动，在条件变化后重新蒸发，不能只有增加没有消散。
- 云覆盖和厚度从云水及分布推导；云多不保证立即下雨。
- 对流和地形抬升影响云的发展，首轮不模拟完整云微物理。

### 7.2 降水

- 云水储量、凝结与发展条件共同决定降水率；不能由天气名称反推雨量。
- 开始和停止条件应有缓冲或不同门槛，避免雨在临界值每步反复开关。
- 降水扣除云水；到达地面的部分补入地表，途中蒸发部分返回相应空气层。
- 当地温度决定首轮雨雪转换；雨夹雪、冰雹等留待后续。
- 雨雪判定不能只读本地镜头位置，角色、农田和不同区域都应采样所在地状态。
- 雨停后，土壤湿度、积水和积雪保留各自的消退过程。

### 7.3 雾

- 近地空气达到凝结条件时形成雾；与高处云层分别处理。
- 雾可以和降水共存，不能沿用“Fog 与 Rain 二选一”的权威状态。
- 升温、蒸发或空气混合改变雾浓度，具体规则需调参。

### 7.4 闪电和雷声

- 闪电是单次事件，不能把持续雷电活跃度直接当作每帧闪光。
- 云的发展、对流和水分条件推动雷电积累；一次放电后扣减积累并满足最短间隔。
- 权威端决定事件编号、位置和世界时刻；客户端据此播放闪光和雷声。
- 雷击伤害、点燃可燃物是可选玩法扩展，不属于首轮默认已确定内容。

雷暴需要水汽、抬升和不稳定条件，可以参考这个因果关系设计简化对流规则。[NWS：雷暴形成条件](https://www.weather.gov/spotterguide/ingredients)

## 8. 光照、表现和玩法消费

- 昼夜系统提供基础日光和月光，云层提供透光与太阳投影衰减，闪电提供短时闪光。
- 云层作用只结算一次，不在引用场景递归中重复乘算；火把等局部灯光保持独立。
- 雨雪粒子、水花、雨声读取镜头附近的降水及气流，雾遮罩读取当地雾浓度。
- 生物淋湿、农田补水、植物生长与积雪结算读取各自所在地的具体要素，不读取一个全局天气名称。
- GameObject 与 ECS 消费相同采样结果，避免一套认为暴风有雨、另一套认为无雨。
- 风影响草木、风浪和设施时，明确它们读取的是当地风还是区域平均风。
- 天气名称和标签从状态派生，可同时显示“有风、下雨、起雾”；玩法判断使用要素本身。
- 冒烟不等于空气水汽，烟尘也不能直接当作云水；烟尘与凝结核影响后续再扩展。
- 抑制天气的维度关闭当地暴露与表现，不清空地表世界的模拟状态。

## 9. 配置、事件与自然变化

### 9.1 配置表达规律

| 配置组 | 需要表达的规律 |
| --- | --- |
| 地理与材质 | 尺度、储水容量、渗透率、热容量等 |
| 水热交换 | 蒸发效率、热交换速度、融化与凝结换算 |
| 空气运动 | 浮升响应、阻力、混合、地形抬升、背景气流 |
| 云与降水 | 凝结、蒸发、降水效率、门槛及缓冲 |
| 雷电 | 积累、释放、最短间隔及位置选择 |
| 时间与性能 | 固定步长、活动范围、补算预算、同步频率 |

- 不把“每天有多少概率阴天”作为自然天气核心参数。
- 随机扰动使用固定种子和缓慢连续变化，作用于驱动力或事件时机，不直接随机切换天气类型。
- 浇水、抽水和火灾通过统一水量与热输入接口改变环境，不另写专用的“生成雨”分支。
- 剧情和 GM 可以临时修改指定要素，但必须标明来源、范围、优先级与结束条件。
- 不同要素可同时受作用；同一要素的冲突由明确的合成规则解决，不沿用全天气互斥组。
- 临时作用结束后回到持续演变的自然状态，不强制切为晴天。
- 人工增加水量或热量的调试与剧情操作必须显式标记为外部输入，便于核对预算。

## 10. 模拟推进、存档与联机

### 10.1 时间和空间预算

- 使用固定游戏时间步和绝对模拟时刻，不依赖帧率或客户端随机数。
- 各单元通过旧状态快照结算，再统一提交；输送、凝结和反馈顺序须确定。
- 不按每帧遍历全世界地块，也不为了天气查询同步加载地形 Chunk。
- 大气单元的生命周期与渲染 Chunk 分开；离开火场或云团不能令天气立即消失。
- 首轮建议保留粗尺度背景状态，在玩家和扰动附近细化交换；活动范围和粗细边界换算待定。
- 未加载地形需要可补算的水分与热状态摘要，不能从默认群系值重新初始化已有区域。
- 睡眠和长时间跳时应分步或采用明确的等效补算，并有工作量上限；不能只拿最终雨量结算整个区间。
- 环绕世界的地表与大气边界共用坐标归一化规则，接缝传输保持连续。
- 边界输入、输出、渗漏和耗水要有明确去向，截断范围不能悄悄丢失或创造储量。

### 10.2 保存与复制

- 地表水量、农业修改和冰雪变化进入正常地形/区块差量，不能只存镜头附近的表现状态。
- 大气持久化保存模拟时刻、温度或热状态、水汽、云水、气流及必要随机/雷电状态。
- 可由材质推导的容量、可重建的空间索引不重复作为运行态权威数据保存。
- 单机与 Host/服务器统一负责模拟；普通 Client 只应用快照和事件，不扣水、不自行生成雷击伤害。
- 快照带世界、区域和时刻标识，首次进房直接恢复当前状态；客户端可插值表现，不改变水量与热量结算。
- 将当前单个星球天气快照扩展为区域要素状态，具体存档布局和网络消息待实现阶段确定。
- 本规划不要求旧存档兼容；新世界初始化和新格式存档恢复仍必须完整。

## 11. 首轮实现顺序

- [ ] 明确地形高度、地块面积、游戏时间、水量与热量的换算关系。
- [ ] 统一自然土地与农业的储水权威，建立降雨、蒸发、灌溉及冰雪交换入口。
- [ ] 建立粗网格近地/上层空气状态、固定步推进、邻格输送和采样接口。
- [ ] 接入日照、地表热源与受限热输出，完成蒸发、抬升、凝结和降水反馈。
- [ ] 将已有云层光照、风、雨雪和雾表现改为当地要素驱动。
- [ ] 同步迁移潮湿 Buff、农业、GameObject/ECS 植物和积雪消费，去除重复水热结算。
- [ ] 替换普通天气固定阶段与每日随机天气事件，调整剧情/GM 的按要素作用方式。
- [ ] 完成区域存档、睡眠跳时、未加载区域补算、环绕接缝与联机恢复。
- [ ] 完成首轮游戏内验收后，再接入雷电和长期生态等扩展。

首轮优先跑通“热量—水汽—云水—降水—地表水分”闭环。不一次加入完整三维流体、气旋、冰雹、土壤侵蚀或地下水流模拟。

## 12. 游戏内验收

以下是待执行验收项，不是已经完成的测试。使用确定种子和明确初始条件，通过真实游戏操作、环境数据和截图观察结果；编译或 JSON 检查不能替代这些验收。

| 场景 | 应核对的结果 |
| --- | --- |
| 小热源与大面积热源对比 | 影响规模由总热输入和范围决定，不只看最高温度 |
| 干燥地区与湿润地区加热 | 蒸发受剩余水量限制；不能保证两者都下雨 |
| 固定供水和热输入的局部区域 | 可观察水汽增加、抬升、凝结及后续变化，能核对水量去向 |
| 带背景风的湿热区域 | 热量、水汽和云团向下风向输送，雨区可与热源位置不同 |
| 移除热源 | 温度逐渐回落，已生成云水继续演变，不立即清空 |
| 降雨、浇水、抽水和蒸发组合 | 同一份地表水量增减，没有农业与天气重复计数 |
| 雪原受热 | 融雪先消耗对应雪储量，水进入地表或径流，再按条件蒸发 |
| 雾与雨共存 | 两种效果可独立存在，关闭一个不清空另一个 |
| 离开区域、读档、睡眠跳时 | 环境状态连续，未加载区域不重置或按最终天气补错整段时间 |
| 世界环绕接缝 | 风、水汽和云水传输无断层、重复或损失 |
| Host 与 Client 分处不同区域 | 各自看到当地天气，权威水量与天气状态一致 |

## 13. 后续待规划

- 地块距离与模拟高度的单位，以及大气网格尺寸、上下层有效高度。
- 地表水量、冰雪水当量、热容量和热输出的游戏单位。
- 当前农业储水与自然地表储水统一后的具体数据布局。
- 浮升、压力、气流、凝结和降水的首轮公式及稳定性限制。
- 未加载区域摘要、粗细边界、后台补算与睡眠跳时预算。
- 长期气候初始化是否需要短暂预演，以及初始水量和背景输送如何配置。
- 植被含水量、蒸腾、烟尘、燃烧蔓延与降雨灭火的接入边界。
- 雷电伤害、引燃、声音传播、雨夹雪和冰雹是否纳入后续玩法。
- 区域采样对现有风浪、设施及全局 UI 的具体接口调整。
- 存档分区、网络快照粒度及目标设备的性能预算。
